RAID 5: Block-Interleaved Distributed Parity

How one XOR parity block per stripe protects a whole stripe, where RAID 5 puts the parity, how a failed disk is rebuilt, what happens when two disks fail, and why updating one block costs four disk transfers. Includes Question w1-4 and the RAID 4/5 exam questions.

1. RAID 5 and RAID 4 (slide 17)

Mirroring works but spends half the disks on copies. RAID 5 protects the data with only one disk's worth of extra space, using parity.

RAID level 5: block-interleaved distributed parity
Block-interleaved means striped by blocks. Distributed parity means the parity blocks are spread over all the disks. RAID 5 partitions data and parity among all N + 1 disks, instead of storing data in N disks and parity in 1 disk as RAID 4 does.
RAID level 4
Block striping over N data disks plus one dedicated parity disk holding every parity block (textbook §13.4.7).
Parity block
A block computed from the data blocks of its stripe, from which any one missing block of the stripe can be rebuilt (Section 2).

Why spread the parity? Every write anywhere in the array must also update its stripe's parity block (Section 5). In RAID 4 all parity blocks live on one disk, so that disk takes part in every write and becomes the bottleneck: with N data disks it receives N times as many writes as any data disk. RAID 5 rotates the parity from stripe to stripe so the parity work is shared by every disk.

The placement rule. With 5 disks, each stripe holds 4 data blocks and 1 parity block. The parity block Pk for blocks 4k, 4k+1, 4k+2, 4k+3 is stored on disk k mod 5; the data blocks fill the other disks in order.

Slide 17 example: how many disks for RAID 5?

You need 8 TB of storage and have 2 TB disks. The data needs 8 ÷ 2 = 4 disks; RAID 5 adds one disk's worth of parity: 5 disks. In general, N disks in RAID 5 give N − 1 disks of usable space.

2. Parity and XOR (slide 18)

The slide: “Parity block j stores XOR of bits from block j of each disk.” It rests on one operation.

XOR (exclusive or, ⊕)
On two bits: 1 if they differ, 0 if they are equal. On many bits: 1 if the number of 1s is odd, 0 if it is even. Also called the modulo-2 sum.
aba ⊕ b

Three algebra rules make RAID work (textbook §13.4.7): XOR is commutative and associative, x ⊕ 0 = x, and x ⊕ x = 0, so XOR-ing the same value twice cancels it.

To compute a parity block, line up the data blocks of the stripe and XOR them column by column. Real blocks have thousands of bits; four bits show the idea.

After this, every column (four data bits plus the parity bit) contains an even number of 1s. That is the whole trick.

3. Recovery from a single disk failure (slide 18)

The slide's rule: to recover data for a block, compute the XOR of bits from all other blocks in the set, including the parity block. Why it works: each column has an even number of 1s, so a missing bit must be whatever makes the count even again, which is exactly the XOR of the other bits. The same rule rebuilds a lost parity block, so it does not matter whether the failed disk held data or parity.

To rebuild a whole failed disk, the system repeats this for every stripe: in each stripe the failed disk held one block (data or parity), and the XOR of the surviving blocks of that stripe gives it back. While the disk is missing, the array keeps working in degraded mode: a read of a lost block is answered by computing it on the fly from the other disks of its stripe, which is slower than a normal read.

What will happen if two disks fail simultaneously? (slide 18)

Data is lost. Each stripe has one parity block, which gives one equation per bit column. With one unknown block the equation can be solved. If two disks fail, a stripe that had blocks on both of them has two unknowns, and many pairs of values satisfy the single equation, with no way to tell which pair is right. RAID 5 survives exactly one disk failure (RAID 6, Chapter 8, survives two).

5. Updating one block (slide 19)

When a data block changes, its stripe's parity is no longer correct and must be recomputed and written too. The slide gives two ways.

Way 1, read-modify-write (for a small write). Use the old parity block, the old value of the block and its new value:

new P = old P ⊕ old B ⊕ new B

XOR-ing old B into the parity cancels its old contribution (x ⊕ x = 0), and XOR-ing new B adds the new one. This needs 2 block reads (old B, old P) and 2 block writes (new B, new P), however many disks the array has.

The slide's example says “updating block B2 of D2”, but in the slide's own picture B2 is on D3 (D2 holds B1); its parity P0 is on D0. The procedure is the same either way.

This is the small-write penalty of RAID 5: four transfers where RAID 1 needs two. The simulator above animates it with real bits.

Way 2, recompute from the new values (for large sequential writes). If a whole stripe is being written anyway (all of B0, B1, B2 and B3 are new), there is nothing to read: compute P0 directly as B0 ⊕ B1 ⊕ B2 ⊕ B3 from the new values and write five blocks. The slide notes this is more efficient for writing large amounts of data sequentially. That is why RAID 5 suits large sequential writes and is slow for small random updates.

Question w1-4 (worked answer)

You have been given six disks of 8 TB each. (a) What are the effective storage capacities in RAID 0, RAID 1 and RAID 5? (b) Explain why 4 blocks need to be transferred to update 1 block in RAID 5.

(a) Raw capacity is 6 × 8 = 48 TB.

LevelRuleCalculationEffective capacity
RAID 0all disks hold data6 × 848 TB
RAID 1half the disks are mirrors(6 ÷ 2) × 824 TB
RAID 5one disk's worth is parity(6 − 1) × 840 TB

(For comparison, RAID 6 would give (6 − 2) × 8 = 32 TB.)

(b) Changing a data block makes its stripe's parity wrong, so the parity must be updated with it. Without reading the other data blocks of the stripe, the system:

  1. reads the old data block (1st transfer),
  2. reads the old parity block (2nd transfer),
  3. computes new parity = old parity ⊕ old data ⊕ new data in memory,
  4. writes the new data block (3rd transfer),
  5. writes the new parity block (4th transfer).

2 reads + 2 writes = 4 block transfers. The old values must be read because the XOR needs them to remove the old data's contribution from the parity.

BUET QBank · CSE 303 | L-3/T-1 | 2016–17 · 15 marks

In RAID level 4, one redundant disk is used regardless of how many data disks there are. When any block is written, the redundant disk must also be updated. Briefly explain an optimal policy for updating the redundant disk with an example (consider 1 byte of data is written). Explain the logic behind adopting such a policy.

Show worked answer

Naive policy. Read the corresponding blocks of all the other data disks, XOR them with the new block, and write the new parity. With n data disks this costs 1 write of the data + (n − 1) reads + 1 write of the parity = n + 1 disk I/Os, which grows with the array.

Optimal policy (read-modify-write). Look only at the old and new versions of the block being written:

  1. read the old value of the data block;
  2. read the corresponding block of the redundant disk;
  3. write the new data block;
  4. write new parity = old parity ⊕ old data ⊕ new data.

Always 4 disk I/Os, however many data disks there are.

Example (one byte per block, textbook Examples 13.9–13.10). Data disks: disk 1 = 11110000, disk 2 = 10101010, disk 3 = 00111000; redundant disk 4 = 01100010. Disk 2 is rewritten to 11001100.

  • old ⊕ new = 10101010 ⊕ 11001100 = 01100110: the bit positions that changed (2, 3, 6, 7).
  • new parity = 01100010 ⊕ 01100110 = 00000100.
  • Check: 11110000 ⊕ 11001100 ⊕ 00111000 = 00000100. Every column again has an even number of 1s.

Logic. old data ⊕ new data marks exactly the positions where the data changed. In each such position the count of 1s among the data disks changes by one, from even to odd or back, so flipping the same positions of the parity restores even parity. Algebraically, P = D₁ ⊕ … ⊕ Dₙ, and since x ⊕ x = 0, P ⊕ D_old ⊕ D_new removes the old term and adds the new one. The other data disks never need to be read, which keeps the cost at 4 I/Os and leaves them free for other requests.

DB QB · 19-20 1c · 10 marks  |  BUET QBank · CSE 215 | L-2/T-2 | 2019–20 · 10 marks

Explain the data recovery mechanism for single disk failure in RAID level 5 with an example.

Show worked answer

Principle. Each stripe's parity block is the XOR of its data blocks, so every bit column of a stripe has an even number of 1s. If one disk fails, each stripe loses one block (data or parity), and that block equals the XOR of all the other blocks of the stripe, parity included.

Example. The slides' 5-disk layout (Figure 1), with 4-bit blocks B0 = 1010, B1 = 0110, B2 = 1100, B3 = 0011 in stripe 0, so P0 = 1010 ⊕ 0110 ⊕ 1100 ⊕ 0011 = 0011 (on D0). Disk D2 fails; it held B1 (stripe 0) and B5 (stripe 1).

  • Stripe 0: B1 = B0 ⊕ B2 ⊕ B3 ⊕ P0 = 1010 ⊕ 1100 ⊕ 0011 ⊕ 0011 = 0110, the original B1.
  • Stripe 1: B5 = B4 ⊕ P1 ⊕ B6 ⊕ B7 (read from D0, D1, D3, D4).
  • Stripe 2: D2 holds P2 = B8 ⊕ B9, recomputed from D0 and D1.

Procedure. (1) The failed disk is detected and the array runs in degraded mode: a read of a block on the failed disk is answered by XOR-ing the rest of its stripe. (2) A replacement disk is installed. (3) The rebuild goes stripe by stripe, computing each lost block from the surviving disks and writing it to the new disk. (4) When every stripe is done, the array is fully protected again. During the rebuild every surviving disk must be read completely, so the array is slower, and a second failure before the rebuild finishes would lose data.

DB QB · Jan 20 4a · 15 marks  |  BUET QBank · CSE 215 | L-2/T-2 | 2018–19 · 15 marks

Describe the storage mechanism, data read and update of data block for RAID level 5 storage with a set of 4 disks: D0, D1, D2 and D3; and a relation with 8 blocks: B0, B1, B2 … B7. Describe the full recovery mechanism of all blocks of D1, if disk D1 fails.

Show worked answer

Storage. 4 disks: each stripe holds 3 data blocks and 1 parity block; Pk = XOR of stripe k's data blocks, on disk k mod 4. 8 blocks need ⌈8/3⌉ = 3 stripes.

P0 = B0 ⊕ B1 ⊕ B2, P1 = B3 ⊕ B4 ⊕ B5, P2 = B6 ⊕ B7 (the empty slot on D3 counts as all zeros).

Read. A block is read directly from its disk; no parity is involved. Bi is found from the layout (e.g. B4 is in stripe 1 on D2). Reads of blocks on different disks run in parallel, and a scan of the relation uses all four disks.

Update of one block (say B4): read old B4 (D2) and old P1 (D1); compute new P1 = old P1 ⊕ old B4 ⊕ new B4; write new B4 and new P1. That is 2 reads + 2 writes = 4 block transfers. If a whole stripe is rewritten (B3, B4, B5 together), P1 is simply recomputed from the new blocks, with no reads.

Recovery of D1. D1 holds B0 (stripe 0), P1 (stripe 1) and B7 (stripe 2). A new disk replaces D1 and each block is rebuilt as the XOR of the rest of its stripe:

  • B0 = P0 ⊕ B1 ⊕ B2 (read D0, D2, D3);
  • P1 = B3 ⊕ B4 ⊕ B5 (read D0, D2, D3; recomputing the parity);
  • B7 = B6 ⊕ P2 (read D0 and D2).

Each rebuilt block is written to the new D1; after the third stripe the array is fully protected again. Try it in the simulator above with 4 disks, 8 blocks, fail disk 1.

Note: the question bank's answer uses a different parity rotation (P0 on D3), so its D1 holds B1, B4 and P2. The recovery method is the same; the layout here follows the slides' rule.

DB QB · 18 CT3 2 · 3+2 marks

You have been given 8 disks of 4 TB each and the customer relation has blocks (B0, B1, B2, B3, B4, B5, …, B14). Show the storage of the customer relation using a RAID level 5 storage system. Explain how data will be recovered if blocks B6 and B7 are corrupted but there is no disk failure.

Show worked answer

Storage. 8 disks: 7 data blocks + 1 parity block per stripe, Pk on disk k mod 8. 15 blocks need 3 stripes. Usable capacity = 7 × 4 = 28 TB.

Recovery of B6 and B7. A corrupted block is detected when it is read (each sector carries a checksum that no longer matches). B6 is in stripe 0 (on D7) and B7 is in stripe 1 (on D0): they are in different stripes, so each stripe has only one bad block and each is recovered on its own from its stripe:

  • B6 = P0 ⊕ B0 ⊕ B1 ⊕ B2 ⊕ B3 ⊕ B4 ⊕ B5;
  • B7 = P1 ⊕ B8 ⊕ B9 ⊕ B10 ⊕ B11 ⊕ B12 ⊕ B13.

The recomputed values are written back over the corrupted blocks (or to spare sectors). No disk needs replacing. Had both corrupted blocks been in the same stripe, RAID 5 could not have recovered them.

Summary: RAID 5 stripes blocks and adds one XOR parity block per stripe, placed on disk k mod n for stripe k so that parity work is spread over all disks (RAID 4 keeps it on one disk, a write bottleneck). Usable space is n − 1 disks. Any one lost block of a stripe is the XOR of all its other blocks, so one disk failure is recoverable; two failures lose the stripes that had blocks on both. A small update costs 2 reads + 2 writes (new P = old P ⊕ old B ⊕ new B); full-stripe writes compute parity from the new data without reads.
