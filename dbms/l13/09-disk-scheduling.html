Speeding Up Disk Access: Disk-Arm Scheduling and the Elevator Algorithm

The slides stop at single requests, but several exam questions ask how a disk should order many waiting requests. This chapter teaches the ways to speed up a disk system and the scheduling algorithms FCFS, SSTF, SCAN (the elevator), C-SCAN, LOOK and C-LOOK, with two tools that animate them on your own input.

1. Ways to speed up a disk system (textbook §13.3)

An average random block access takes around 10 ms. If requests arrive faster than that, they queue up and wait, and the waiting time can be much larger than the access time itself. The textbook lists five ways to cut the average time per access and so raise throughput (block accesses per second):

  1. Organise data by cylinders. Put blocks that are accessed together on one cylinder (or adjacent cylinders). Then only the first access needs a seek and a rotational latency; the rest run at the full transfer rate. Reading a whole cylinder of the Megatron 747 this way takes about 139 ms instead of about 11 s for the same 1024 blocks scattered at random (Example 13.4).
  2. Use several disks. Several independent arms can serve several requests at once, and striping (Chapter 5) speeds up large reads.
  3. Mirror disks. Besides protecting data (Chapter 6), two copies let two reads proceed at once, from whichever copy's head is closer.
  4. Schedule the disk arm. When several requests wait, choose the order that keeps arm movement small. This chapter.
  5. Prefetch and buffer. If the blocks a query will need can be predicted (e.g. a scan), load them into main-memory buffers before they are asked for (also called double buffering). This also gives the scheduler more requests to choose from.

2. The scheduling problem

Disk-arm scheduling
Choosing the order in which pending requests are served so that the head moves as little as possible. It is done by the disk controller, the operating system or the DBMS, and is allowed only when the requests are independent (they come from different transactions or are prefetches), so their order does not matter.
Total head movement
The sum of the distances (in tracks or cylinders) between successive head positions. Seek time grows with distance, so less movement means less time.

The running example (the standard textbook one): cylinders 0–199, the head at cylinder 53 moving towards higher cylinders, and the queue 98, 183, 37, 122, 14, 124, 65, 67.

FCFS (first come, first served)
Serve requests in arrival order. Fair and simple, but the head may zig-zag across the disk: 640 cylinders in the example.
SSTF (shortest seek time first)
Always serve the pending request closest to the current head position. Much less movement (236), but a request far from where the head is busy may wait indefinitely: starvation.
SCAN (the elevator algorithm)
The head sweeps in one direction to the end of the disk, serving every request it passes, then reverses and sweeps back, like a lift serving floors on its way up and then on its way down.
LOOK
SCAN, but the head turns around at the last request in the current direction instead of running on to the end of the disk. The textbook's description of the elevator algorithm (“when the heads reach a position where there are no requests ahead of them in their direction of travel, they reverse direction”) is this variant.
C-SCAN (circular SCAN)
Serve requests only while moving in one direction. At the end of the disk the head returns at once to the other end without serving anything, then sweeps again in the same direction. Waiting times are more uniform than SCAN's, because every cylinder is visited once per cycle.
C-LOOK
C-SCAN that turns at the last request and jumps back only as far as the lowest pending request.

4. The elevator algorithm with arrival times (textbook §13.3.5)

In a real disk, requests keep arriving while others are being served, and each access also needs rotational latency and transfer time. The textbook's model:

  • Seek time from one cylinder to another = (a fixed start/stop time) + (distance ÷ cylinders per ms). For the Megatron 747: 1 ms + 1 ms per 4000 cylinders. A request on the cylinder where the head already is needs no seek.
  • Each access adds average rotational latency plus transfer time (4.17 + 0.13 = 4.3 ms for the Megatron 747).
  • When an access finishes, the scheduler looks at the requests that have arrived by then and picks the next one in the current direction; if there is none ahead, it reverses.

The tool starts with the textbook's Example 13.6: head at 8000; requests 8000, 24000, 56000 at time 0; 16000 at 10 ms; 64000 at 20 ms; 40000 at 30 ms. The elevator finishes them at 4.3, 13.6, 26.9, 34.2, 45.5 and 56.8 ms. Switch to FCFS to see 4.3, 13.6, 26.9, 42.2, 59.5, 70.8: FCFS goes back to 16000 too early.

Suppose a Megatron 800 disk has the following pending disk requests (listed by track number). If the head is currently at track 71 and moving towards the higher track number, calculate average disk seek times for both the SCAN and C-SCAN algorithms. Disk requests: 21, 98, 12, 80, 85 and 10.

Show worked answer

No timing data is given for the “Megatron 800”, so seek time is measured as seek distance in tracks (time is proportional to it). The number of tracks is not given either; SCAN and C-SCAN run to the end of the disk, so assume tracks 0–99 (the largest request is 98). Sorted requests: 10, 12, 21, 80, 85, 98.

SCAN (up to the end, then back):

71 → 80 → 85 → 98 → 99 → 21 → 12 → 10

Distances 9 + 5 + 13 + 1 + 78 + 9 + 2 = 117 tracks, i.e. (99 − 71) + (99 − 10). Average per request = 117 ÷ 6 = 19.5 tracks.

C-SCAN (up to the end, return to track 0, sweep up again):

71 → 80 → 85 → 98 → 99 → (return) 0 → 10 → 12 → 21

Distances 28 up + 99 return + 21 up = 148 tracks; average = 148 ÷ 6 ≈ 24.67 tracks. If the return jump is not counted (it is fast and reads nothing), 49 tracks, average ≈ 8.17.

For comparison, LOOK (turning at 98) needs 27 + 88 = 115 (average 19.17) and C-LOOK needs 27 + 88 + 11 = 126. If the disk had tracks 0–199, SCAN would need (199 − 71) + (199 − 10) = 317. To turn distance into milliseconds, multiply by the time per track (or use a seek formula such as 1 ms + distance ÷ 500 if one is given). Check every number with the animator above (queue 21, 98, 12, 80, 85, 10; head 71; up; last cylinder 99).

BUET QBank · CSE 303 | L-3/T-1 | 2013–14 · 5 marks

What are the different ways to improve the performance of a disk-based system?

Show worked answer
  1. Place data accessed together on the same cylinder (or adjacent cylinders), so a scan pays one seek and one latency and then reads at the full transfer rate.
  2. Use multiple disks: more arms serve more requests at once; striping spreads large reads over all disks.
  3. Mirror disks: two copies let two reads run in parallel (and protect the data).
  4. Disk-arm scheduling, e.g. the elevator algorithm, to reduce the seek distance when many requests wait.
  5. Prefetching and large-scale buffering: read blocks into memory before they are needed and keep frequently used blocks in the buffer, avoiding disk accesses altogether.

Related measures from the slides: read whole blocks (4–16 KB) rather than sectors, prefer sequential to random access, and use faster media such as flash SSDs for hot data.

BUET QBank · CSE 303 | L-3/T-1 | 2013–14 · 5 marks

Write down the pros and cons of an elevator algorithm.

Show worked answer

Pros.

  • Much less head movement than FCFS: requests are served in cylinder order along a sweep, so average seek time drops and throughput rises.
  • The more requests wait, the better it works: the seek per request approaches the minimum (track-to-track) seek time.
  • No starvation: every request is served within at most two sweeps, unlike SSTF, which can postpone a distant request forever.
  • Simple to implement: keep the queue sorted by cylinder and a direction flag.

Cons.

  • Unequal waiting: a request just behind the head waits for the head to reach the end and come back; cylinders in the middle are passed twice per cycle and the ends only once (C-SCAN fixes this).
  • Gains little when only one or two requests are pending, and cannot be used when requests must be performed in a fixed order.
  • Requests are not served in arrival order, so individual response times are less predictable than with FCFS.
  • Plain SCAN wastes movement running to the end of the disk when no request is there (LOOK fixes this).

Summary: Disk systems are sped up by keeping related data on one cylinder, using several disks, mirroring, scheduling the arm and prefetching. FCFS serves requests in arrival order; SSTF picks the nearest (low movement, possible starvation); SCAN, the elevator, sweeps to one end and back serving requests on the way; LOOK turns at the last request; C-SCAN and C-LOOK serve in one direction only and jump back. With arrival times, the elevator decides after each access among the requests that have arrived, using seek = start/stop time + distance ÷ speed, plus latency and transfer per access.
