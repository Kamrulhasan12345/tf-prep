Exam Topics Beyond the Slides: Disk Failures, Stable Storage, RAID 6 Codes, Buffers

Past papers ask about things Lec 13's slides do not cover: the kinds of disk failure, stable storage, how to design RAID 6 schemes from parity-check matrices (the textbook's Hamming-code method), and how blocks move between disk, buffer and a transaction. Each topic is taught briefly here, then the exam questions are answered.

1. Kinds of disk failure (textbook §13.4)

Intermittent failure
A read or write of a sector fails, but succeeds if tried again. The controller simply retries (up to some limit).
Media decay
Bits of a sector are permanently corrupted, so it can never be read correctly again.
Write failure
A write neither succeeds nor leaves the old contents readable, e.g. because the power failed in the middle of writing the sector.
Disk crash (head crash)
The whole disk suddenly and permanently becomes unreadable.
Checksum
Extra bits stored with each sector, computed from its data bits, used to tell a good read from a bad one. The simplest is one parity bit: 1 if the data has an odd number of 1s, so that data + parity always has an even number of 1s. Example: 01101000 has three 1s, parity bit 1, stored as 011010001. Any single-bit error makes the count odd and is detected. With n independent check bits the chance of missing a random massive error is 1/2n.

Checksums turn the first three kinds of error into “this sector is bad” signals; retrying handles intermittent failures, stable storage (Section 2) handles media decay and write failures, and redundancy across disks (RAID) handles crashes.

How likely is data loss? Disk failure rates are measured by the mean time to failure. The textbook's Example 13.8: if each disk fails with probability 10% per year and a failed mirror is replaced and copied in 3 hours (1/2920 of a year), data is lost only if the second disk fails during those 3 hours: probability 0.1 × 1/2920 = 1/29,200 per failure. A pair has a failure about every 5 years, so the mean time to data loss is 5 × 29,200 = 146,000 years.

2. Stable storage (textbook §13.4.3–13.4.4)

Stable storage
A way of organising a disk so that a value X is never lost to media decay or to a failed write. Sectors are used in pairs: X is stored twice, in a “left” copy XL and a “right” copy XR, ideally on different disks, each with enough checksum bits that a bad copy is always recognised.

Writing policy. (1) Write X into XL and read it back to check that its status is good; if not, rewrite, and after a set number of failed tries treat the sector as decayed and substitute a spare sector. (2) Only then do the same for XR.

Reading policy. Read XL; if it is bad, read XR; alternate between them until a good value is returned. X is unreadable only if both copies stay bad after many tries.

Why it works: the two copies are never being written at the same moment. If one copy decays, the other is read. If the power fails while XL is being written, XL is bad but XR still holds the old value; if it fails after XL is done, XL holds the new value. Either way, after the failure we get a consistent value (old or new) and repair the other copy from it. Databases use stable storage for the log, which must survive every failure.

3. RAID 6 with parity-check matrices (textbook §13.4.9)

Chapter 8 described RAID 6 with P and Q, where Q needs Reed–Solomon arithmetic. The textbook shows a scheme that uses only XOR, built from a Hamming code. Number the disks 1 to 7: disks 1–4 hold data, disks 5–7 are redundant, and a 3 × 7 matrix of 0s and 1s says which disks each redundant disk checks:

Rule: in each row, the XOR of the disks that have a 1 in that row must be all zeros. So each row is a little RAID 4 group: disk 5 = 1 ⊕ 2 ⊕ 3, disk 6 = 1 ⊕ 2 ⊕ 4, disk 7 = 1 ⊕ 3 ⊕ 4. The matrix has three properties:

  1. every possible non-zero column of three bits appears exactly once, so all columns are different;
  2. redundant disks have a single 1 in their column;
  3. data disks have at least two 1s.

Reading data disks is normal. Writing a data block: compute old ⊕ new, and XOR that into every redundant disk that has a 1 in a row where the written disk has a 1.

Recovering two failed disks a and b. Their columns are different, so some row r has a 1 for one of them (say b) and a 0 for the other. In that row b is the only unknown, so b = XOR of the other disks with a 1 in row r. Now only a is missing; any row where a has a 1 gives it. The animation runs the textbook's Example 13.14 (8-bit blocks, disks 2 and 5 fail).

The general construction. With k redundant disks, write every non-zero column of k bits: 2k − 1 columns. The k columns with a single 1 are the redundant disks and the other 2k − k − 1 are data disks. Since all columns are distinct and non-zero, any 2 failures can be recovered. In coding terms, the code has minimum distance 3, and a code of minimum distance d survives d − 1 simultaneous disk failures. To survive 3 failures, any 3 columns must be linearly independent (no 3 of them XOR to zero), which needs distance 4.

4. Disk, buffer and a transaction's work area

Physical blocks
Blocks on disk.
Buffer blocks
Copies of disk blocks held in the main-memory buffer, managed by the buffer manager.
input(B), output(B)
Transfer block B from disk into the buffer, or from the buffer back to disk.
Work area
A private area of memory for each transaction Ti, holding its local copies xi of the data items it uses.
read(X), write(X)
read(X) assigns the value of X from its buffer block to the local variable xi (calling input first if the block is not in the buffer). write(X) assigns xi to X in its buffer block (again inputting the block first if needed). Neither one writes to disk; output(B) happens later, when the buffer manager decides (to free space, at a checkpoint, or because the recovery protocol forces it).

BUET QBank · CSE 303 | L-3/T-1 | 2011–12 · 8 marks

What are the different types of disk failures? How does a DBMS handle a disk crash?

Show worked answer

Types (Section 1): (1) intermittent failure, where a read or write fails but succeeds when retried; (2) media decay, where bits of a sector are permanently corrupted; (3) write failure, where a write neither completes nor leaves the old value readable, e.g. after a power cut; (4) disk crash, where the whole disk becomes unreadable. Checksums detect bad sectors; retries handle intermittent errors; stable storage handles decay and failed writes.

Handling a disk crash.

  1. Redundancy (RAID). With mirroring (RAID 1) the system keeps running from the mirror and copies it onto the replacement disk. With parity (RAID 4/5) each lost block is the XOR of the other blocks of its stripe; with RAID 6 even two simultaneous crashes are recoverable. Data is lost only if more disks fail than the scheme tolerates before the rebuild finishes, which is very unlikely (mean time to data loss of the order of 100,000 years for mirrored disks in the textbook's example).
  2. Backup and log. If the redundancy is not enough, the DBMS restores the most recent archival dump (backup) of the database, kept on tertiary storage such as tape, and then uses the log, kept on stable storage (often mirrored, on a different disk), to redo the changes of the transactions that committed after the dump.
BUET QBank · CSE 303 | L-3/T-1 | 2016–17 · 10 marks

What is stable storage? Briefly explain the idea of reading and writing policy in stable storage.

Show worked answer

Stable storage is storage organised so that information is never lost to media decay or to a write that fails midway (e.g. at a power failure). It is implemented by keeping every value X in a pair of sectors, XL and XR (preferably on different disks), each protected by checksum bits so that a bad copy is always detected.

Writing policy. Write X into XL; read it back and check the checksum; if bad, write again; after several failures assume media decay and use a spare sector instead. Only after XL is good, repeat the same for XR.

Reading policy. Read XL; if it is bad, read XR; keep alternating until a good copy is returned. Only after a large number of failures is X declared unreadable.

Why this is safe. Media failure: if one copy decays, the other is still good (both decaying is extremely unlikely). Write failure: if the crash happens while writing XL, XL is bad and XR still has the old value; if it happens after XL was written, XL has the new value. Either way a correct (old or new) value is obtained, and the other copy is repaired from it. The DBMS keeps its log on stable storage for this reason.

DB QB · 17-18 1a · 16 marks  |  BUET QBank · CSE 215 | L-2/T-2 | 2017–18 · 16 marks

Viru Sahastrabudhhe has taught different RAID levels to Farhan. To check whether Farhan has understood RAID levels or not, Viru has given a system with six data disks numbered from 1 to 6 to Farhan and asked him to answer the following questions: (i) Design a RAID level 6 scheme for the given data disks using the minimum number of redundant disks possible. You are not allowed to use any data disk as a redundant disk for the design. (ii) Describe the recovery process of your designed system if Disk 1 and Disk 3 fail simultaneously. (iii) Describe the recovery process of your designed system if disks 1, 3 and 6 fail simultaneously. Now, write down the correct and complete answer that Farhan should provide in reply to Viru's tricky (i) question.

Show worked answer

(i) Design. Using the textbook's XOR (Hamming-code) construction, each disk gets a distinct non-zero column of k bits, the redundant disks get the columns with a single 1, and data disks get columns with at least two 1s. With k = 3 redundant disks there are only 2³ − 3 − 1 = 4 such data columns, too few for 6 data disks. So the minimum is k = 4 redundant disks (disks 7–10), which allows up to 11 data disks; choose 6 of the 11 columns. The tricky part is to choose them so that (iii) also works:

disk12345678910
row 11100101000
row 21011000100
row 30110010010
row 40001110001

Redundant disks: disk 7 = D1 ⊕ D2 ⊕ D5; disk 8 = D1 ⊕ D3 ⊕ D4; disk 9 = D2 ⊕ D3 ⊕ D6; disk 10 = D4 ⊕ D5 ⊕ D6 (bit by bit, for every block). All 10 columns are distinct and non-zero, so any two simultaneous failures are recoverable. A write to a data disk updates the two redundant disks of its rows with old ⊕ new.

(ii) Disks 1 and 3 fail. Row 1 contains disk 1 but not disk 3, so D1 = D2 ⊕ D5 ⊕ D7. Row 3 contains disk 3 but not disk 1, so D3 = D2 ⊕ D6 ⊕ D9 (or, once D1 is known, D3 = D1 ⊕ D4 ⊕ D8 from row 2). Both are rebuilt block by block on replacement disks.

(iii) Disks 1, 3 and 6 fail. A two-failure code does not guarantee recovery from three failures (e.g. disks 1, 2 and 3 together could not be recovered, because their columns 1100 ⊕ 1010 ⊕ 0110 = 0000). But this design was chosen so that disks 1, 3 and 6 can be:

  • row 1 contains only disk 1 of the three: D1 = D2 ⊕ D5 ⊕ D7;
  • row 4 contains only disk 6 of the three: D6 = D4 ⊕ D5 ⊕ D10;
  • now only disk 3 is missing: D3 = D1 ⊕ D4 ⊕ D8 (row 2) or D2 ⊕ D6 ⊕ D9 (row 3).

So all three are recovered. In general, a set of failed disks is recoverable exactly when their columns are linearly independent (no subset of them XORs to zero).

Note: the question bank's answer uses the P+Q (Reed–Solomon) form of RAID 6 with 2 redundant disks. That is valid if Galois-field arithmetic is allowed, and 2 is then the minimum, but such a design cannot recover from the three failures in (iii). The question's “tricky” part points to the textbook's XOR construction above.

Find a RAID level 6 scheme with 15 disks, four of which are redundant.

15 = 2⁴ − 1, so this is the Hamming-code scheme with k = 4: write all 15 non-zero columns of 4 bits. Disks 1–11 (columns with two or more 1s) hold data; disks 12–15 (one 1 each) are redundant.

row 2111011001100100

Redundant disks (XOR, bit by bit):

  • disk 12 = D1 ⊕ D2 ⊕ D3 ⊕ D4 ⊕ D6 ⊕ D7 ⊕ D8
  • disk 13 = D1 ⊕ D2 ⊕ D3 ⊕ D5 ⊕ D6 ⊕ D9 ⊕ D10
  • disk 14 = D1 ⊕ D2 ⊕ D4 ⊕ D5 ⊕ D7 ⊕ D9 ⊕ D11
  • disk 15 = D1 ⊕ D3 ⊕ D4 ⊕ D5 ⊕ D8 ⊕ D10 ⊕ D11

Reading: from the data disks directly. Writing data disk j: XOR old ⊕ new into each redundant disk whose row has a 1 in column j. Recovery: all columns are distinct, so for two failed disks a and b find a row where exactly one of them has a 1; rebuild that one from the other disks of the row, then rebuild the other from any row containing it. Example: disks 1 and 2 fail; row 4 contains disk 1 but not 2, so D1 = D3 ⊕ D4 ⊕ D5 ⊕ D8 ⊕ D10 ⊕ D11 ⊕ D15; then D2 from row 1. The scheme survives any 2 simultaneous failures (minimum distance 3), with 11 of 15 disks holding data.

Note: the question bank's answer builds a Reed–Solomon code with four check blocks that survives 4 failures. That needs Galois-field arithmetic; the XOR scheme the question refers to (15 = 2⁴ − 1 disks, 4 redundant) tolerates 2.

BUET QBank · CSE 303 | L-3/T-1 | 2011–12 · 15 marks (similar: CSE 215 | L-3/T-1 | 2012–13)

Find a RAID level 6 scheme with ten disks, such that it is possible to recover from the failure of any three disks simultaneously. You should use as many data disks as you can.

Show worked answer

Condition. With an XOR parity-check matrix, any 3 failed disks can be rebuilt exactly when every 3 columns are linearly independent: no column is zero, no two are equal, and no three XOR to zero (minimum distance 4).

How many redundant disks? One redundant disk per row. With 4 rows, at most 8 columns can have the property (it is achieved by the 8 columns with an odd number of 1s, and no set of 9 works), so 10 disks need 5 redundant disks, leaving 5 data disks.

Design. Give every disk a column with an odd number of 1s in 5 bits: redundant disks 6–10 get the five single-1 columns; data disks 1–5 get five columns with three 1s. The XOR of two odd-weight columns has even weight (and is non-zero if they differ); the XOR of three has odd weight, so it is never zero. Hence any 3 columns are independent.

disk12345678910
row 11111110000
row 21110001000
row 31001100100
row 40101000010
row 50010100001

Redundant disks: D6 = D1 ⊕ D2 ⊕ D3 ⊕ D4 ⊕ D5; D7 = D1 ⊕ D2 ⊕ D3; D8 = D1 ⊕ D4 ⊕ D5; D9 = D2 ⊕ D4; D10 = D3 ⊕ D5. (All 120 triples of failed disks were checked by program to be recoverable.)

Recovery example. Disks 1, 2 and 3 fail. Row 3 contains only disk 1 of them: D1 = D4 ⊕ D5 ⊕ D8. Row 4 contains only disk 2: D2 = D4 ⊕ D9. Row 5 contains only disk 3: D3 = D5 ⊕ D10.

Note: the question bank's answer uses a Reed–Solomon code with 3 redundant and 7 data disks. That is possible with Galois-field arithmetic (any 3 check blocks can then cover 3 failures), but with XOR parity checks, as in the textbook's RAID 6 section, 5 data disks is the maximum for 10 disks.

DB QB · 20-21 4a · 10 marks

Show the relationship among memory buffer, transaction work area and disk storage and explain how data A is read from disk for a transaction and data B is written to the disk for a transaction.

Show worked answer

Relationship (see the animation in Section 4). The database is on disk as physical blocks. The main-memory buffer holds copies of some blocks (buffer blocks). Each transaction Ti has a private work area with local copies of the items it uses. Blocks move between disk and buffer by input(B) and output(B); items move between buffer and work area by read(X) and write(X).

Reading A (A is in block BA), read(A) by Ti:

  1. If BA is not in the buffer, the buffer manager executes input(BA), copying the block from disk into a free buffer frame (writing out a victim block first if the buffer is full).
  2. The value of A in the buffer block is copied into Ti's local variable ai. Ti now works on ai.

Writing B (B in block BB), write(B) by Ti:

  1. If BB is not in the buffer, input(BB) first.
  2. The value of Ti's local bi is copied into B in the buffer block, which is now dirty (different from disk).
  3. Later the buffer manager executes output(BB), writing the whole block to disk: when the frame is needed, at a checkpoint, or when the recovery protocol requires it (e.g. the log records describing the change must reach stable storage first). Until then the new value of B exists only in volatile memory.

Summary: Disks fail intermittently, by media decay, by failed writes, or by crashing; checksums detect bad sectors. Stable storage keeps each value in two sectors written one after the other and read alternately, so an old or new value always survives. RAID 6 can be built with XOR alone from a parity-check matrix whose columns are distinct (2 failures) or have every 3 independent (3 failures); with k redundant disks the Hamming scheme supports 2k − k − 1 data disks. A transaction reads and writes items in its own work area; read/write move values between work area and buffer, input/output move whole blocks between buffer and disk.
