Disk Performance: Access Time, Blocks and IOPS

How long one disk read takes, where each millisecond goes, why databases read whole blocks, and why sequential access is so much faster than random access. A calculator lets you plug in any disk. Includes the Megatron disk exam questions.

1. Access time = seek time + rotational latency (slide 8)

Chapter 2 showed the three physical steps of a read. Slide 8 gives them names and numbers.

Access time
The time from when a read or write request is issued to when data transfer begins. access time = seek time + rotational latency
Seek time
The time to reposition the arm over the correct track. Typical disks: 4 to 10 ms on average.
Rotational latency
The time for the sector to be accessed to appear under the head, once the head is on the right track.
Transfer time
The time to actually read or write the data once it starts passing under the head: block size ÷ transfer rate. The data-transfer rate is how many bytes per second the disk delivers once positioned.

So the total time to read one block is

time for one block = seek time + rotational latency + transfer time

The textbook (§13.2.3) calls this whole sum the latency of the disk; the slide reserves “access time” for the first two parts. In exam answers, write the formula out so the reader sees which parts you include.

Average seek time

The seek time depends on how far the arm moves. Moving to the next track takes about a millisecond (mostly starting and stopping the arm); moving across the whole disk takes the worst-case seek time, perhaps 10–20 ms. Requests land on random tracks, so what matters is the average.

  • The slide's rule: average seek time is ½ the worst-case seek time. Use it when you are given only the worst-case (maximum) seek time.
  • The textbook's rule: if the head goes from a random track to another random track, the average distance is ⅓ of the way across the disk. When a question gives a seek formula such as “1 ms to start and stop plus 1 ms per 500 cylinders”, plug in one third of the cylinders.

The two rules do not contradict each other: the textbook's is about distance, the slide's is a rule of thumb about time that already allows for the fixed start/stop cost. Question 17-18 1d below shows both.

Rotational latency

One full rotation takes 60,000 ms ÷ rpm. If the head arrives just after the sector passed, the wait is a full rotation; if just before, almost nothing. On average the sector is half a rotation away:

average rotational latency = ½ × (60,000 ÷ rpm) ms

The slide's “4 to 11 milliseconds on typical disks (5400 to 15,000 rpm)” is the time of one full rotation: 60,000 ÷ 15,000 = 4 ms and 60,000 ÷ 5400 ≈ 11.1 ms. The average latency is half of that, 2 to 5.6 ms. Adding seek and latency, the slide's overall latency is 5 to 20 ms depending on the disk model.

2. Disk blocks (slide 9)

Disk block
A logical unit for storage allocation and retrieval: a run of consecutive sectors that the database always reads or writes as a whole. Typically 4 to 16 kilobytes. A block is also called a page.

Why not read single sectors, or huge chunks? The block size is a trade-off, and the slide names both sides:

  • Smaller blocks: more transfers from disk. Every request pays a seek and a rotational latency of several milliseconds, while transferring 4 KB takes only a few hundredths of a millisecond. Reading a relation in tiny pieces pays that fixed cost far too many times.
  • Larger blocks: more space wasted due to partially filled blocks. The last block of a file, and blocks that lost records to deletions, are only partly used. The bigger the block, the more bytes such holes waste, and the more useless bytes are read when only one record is needed.

3. Sequential and random access (slides 9–10)

Sequential access pattern
Successive requests are for successive disk blocks, for example a full scan of a relation stored contiguously. A disk seek is required only for the first block; after that the blocks arrive one after another as the disk turns.
Random access pattern
Successive requests are for blocks that can be anywhere on the disk, for example looking up individual records through an index. Each access requires a seek and a rotational latency, so the effective transfer rate is low: most of the time is wasted in seeks.
IOPS (I/O operations per second)
The number of random block reads a disk can support per second. With t ms per random block, IOPS = 1000 ÷ t. Current magnetic disks manage 50 to 200 IOPS.

The difference is enormous for large reads. With the numbers of Figure 1, 1000 random blocks take 1000 × 8.21 ms ≈ 8.2 seconds, but 1000 sequential blocks take 8.17 + 1000 × 0.039 ≈ 47 ms. This is why database systems try hard to store related data contiguously and why query algorithms prefer scans of whole files to many scattered lookups when a large fraction of the file is needed.

DB QB · 19-20 1a · 5 marks  |  BUET QBank · CSE 215 | L-2/T-2 | 2019–20 · 5 marks

Explain disk access time and its implication in DBMS.

Show worked answer

Disk access time is the time from issuing a read or write request until data transfer begins: access time = seek time + rotational latency. To read a block we also pay the transfer time, so one block costs seek + rotational latency + transfer.

  • Seek time: moving the arm to the right track/cylinder; 4–10 ms on average (average ≈ ½ of the worst case).
  • Rotational latency: waiting for the sector to come under the head; on average half a rotation, e.g. 4.17 ms at 7200 rpm.
  • Transfer time: block size ÷ transfer rate; e.g. 4 KB at 100 MB/s ≈ 0.04 ms.

Example: 4 ms + 4.17 ms + 0.04 ms ≈ 8.2 ms per random block, about 120 IOPS. Main memory answers in about 100 ns, so one disk access costs as much time as roughly 100,000 memory accesses.

Implications for a DBMS:

  1. Cost is measured in block I/Os. CPU work on a block in memory is negligible next to fetching it, so query plans are compared by the number of disk blocks they read and write.
  2. Data is moved in blocks (4–16 KB), so one seek and one latency are shared by many records.
  3. Sequential access is preferred. Only the first block of a sequential run needs a seek, so related records are stored together (clustering, files sorted on a key, a relation on adjacent cylinders).
  4. Indexes are shallow and wide. A B+ tree has a large fan-out so a lookup needs only 3–4 block reads.
  5. Buffering: frequently used blocks are kept in a main-memory buffer to avoid repeated disk reads.
  6. Parallel disks (striping, RAID) and good disk-arm scheduling reduce the waiting time further (Chapters 5–9).
BUET QBank · CSE 303 | L-3/T-1 | 2016–17 · 2 marks

What are the components of disk latency?

Show worked answer

Disk latency (the time to read or write one block) = seek time + rotational latency + transfer time.

  1. Seek time: moving the head assembly to the cylinder holding the block.
  2. Rotational latency: waiting for the first sector of the block to rotate under the head (on average half a rotation).
  3. Transfer time: reading or writing the block's sectors (and the gaps between them) as they pass under the head.

A small amount of disk-controller processing time may be added, but it is negligible compared with the mechanical delays.

Show worked answer

Average time = average seek + average rotational latency + transfer time. Take each part in turn.

Transfer time. The block size does not change, so the transfer time is always 0.5 ms.

Rotational latency. It ranges from 0 (the block is just arriving) to 15.6 ms (a full rotation: the block has just passed). Every position is equally likely, so the average is half a rotation: 15.6 ÷ 2 = 7.8 ms.

Seek time. The minimum is 0 (already on the right cylinder) and the maximum 17.4 ms (across all 8192 cylinders). The Megatron 747's seek rule, given in the companion question 17-18 3b, is 1 ms to start and stop plus 1 ms per 500 cylinders: 1 + 8191/500 = 17.38 ≈ 17.4 ms, which matches the table. A random seek moves on average ⅓ of the way across the disk:

average seek = 1 + (8192 ÷ 3) ÷ 500 = 1 + 5.46 = 6.46 ms

average time = 6.46 + 7.8 + 0.5 ≈ 14.76 ms

If only the table is used with the slide's rule of thumb (average seek ≈ ½ of the worst case = 8.7 ms), the estimate is 8.7 + 7.8 + 0.5 = 17.0 ms. State which rule you use; the first one uses all the data of the disk.

Note: the question bank's answer takes the average seek as 17.4 ÷ 3 = 5.8 ms (total 14.1 ms). That is wrong: the ⅓ applies to the distance, and the 1 ms start/stop cost is paid on every seek however short, so it must not be divided by 3.

BUET QBank · CSE 303 | L-3/T-1 | 2016–17 · 5 marks

The Megatron 777 disk has the following characteristics: ten surfaces with 10,000 tracks each; tracks hold an average of 1000 sectors of 512 bytes each; the disk rotates at 10,000 rpm; the time to move the head n tracks is 1 + 0.001n milliseconds. (a) What is the capacity of the disk? (b) What is the maximum seek time? (c) What is the average rotational latency?

Show worked answer

(a) capacity = surfaces × tracks × sectors × bytes = 10 × 10,000 × 1000 × 512 = 51,200,000,000 bytes = 51.2 GB (47.68 GB if 1 GB = 230 bytes).

(b) The longest move is from the outermost to the innermost track, 9999 tracks: 1 + 0.001 × 9999 = 10.999 ≈ 11 ms.

(c) One rotation = 60,000 ÷ 10,000 = 6 ms, so the average rotational latency = 6 ÷ 2 = 3 ms (the maximum is 6 ms).

BUET QBank · CSE 303 | L-3/T-1 | 2013–14 · 7 marks

The Megatron 747 disk has the following characteristics: 4 platters providing 8 surfaces; 8192 tracks per surface, 256 sectors per track, 512 bytes per sector; the disk rotates at 3840 rpm (one rotation every 15.6 ms); average seek time 6.5 ms; transfer rate 10 MB/s. (a) What is the capacity of a single track and what is the size of the entire disk? (b) What is the average read time of 4096 bytes of data?

Show worked answer

(a) One track = 256 sectors × 512 bytes = 131,072 bytes = 128 KB. The disk = 8 surfaces × 8192 tracks × 131,072 bytes = 8,589,934,592 bytes = 8 GB (233 bytes; 8.59 × 109 bytes).

(b) average read time = average seek + average rotational latency + transfer time:

  • average seek = 6.5 ms (given);
  • average rotational latency = 15.6 ÷ 2 = 7.8 ms;
  • transfer = 4096 bytes ÷ 10 MB/s = 4096 ÷ 10,485,760 s ≈ 0.39 ms (0.41 ms if 1 MB = 106 bytes).

6.5 + 7.8 + 0.39 ≈ 14.7 ms

Check with the calculator above: 3840 rpm, seek 6.5, block 4 KB, 10 MB/s gives 14.703 ms.

Summary: Access time = seek time + rotational latency; reading a block adds the transfer time (block size ÷ transfer rate). Average rotational latency is half a rotation, ½ × 60,000/rpm ms. Average seek is about ½ the worst case (slide), or the time to move ⅓ of the way across (textbook formula). Data moves in blocks of 4–16 KB: small blocks mean more transfers, large blocks waste space. Sequential access pays one seek for many blocks; random access pays a seek per block, so a magnetic disk manages only 50–200 IOPS.
