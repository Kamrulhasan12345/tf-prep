Physical Storage Media and the Storage Hierarchy

Where a database actually lives: the kinds of storage a computer has, how they differ in speed, cost and reliability, and how they stack into a hierarchy. Answers the slide's discussion question about disk-based and in-memory DBMSs.

1. Where this lecture fits (slide 2)

The second half of the course looks inside the database system. Slide 2 lists the plan: first storage (how bytes sit on disks, this lecture and Lec 14), then indexing and hashing (how to find records quickly, Lec 15), then query processing algorithms. Everything later depends on one fact from this lecture: reading data from a disk is extremely slow compared with working on it in memory. So the cost of a database operation is mostly the number of disk reads and writes it does.

2. Volatile and non-volatile storage (slide 3)

A computer stores data on several different physical devices, called physical storage media. The first way to divide them is by what happens when the power goes off.

Volatile storage
Loses its contents when the power is switched off. Main memory (RAM) and the CPU cache are volatile.
Non-volatile storage
Keeps its contents when the power is switched off. Magnetic disks, flash memory (SSDs, USB sticks), optical disks and magnetic tape are non-volatile. The slide also counts battery-backed main memory: ordinary RAM with a battery that keeps it powered during an outage, so it behaves as non-volatile.

This matters for a database because a committed transaction must survive a crash. Anything that exists only in volatile memory is gone after a power cut, so the database must get its data onto non-volatile storage before it can promise that the data is safe.

The slide lists three factors that decide which medium to use for which data:

  1. Speed with which data can be accessed. Cache answers in nanoseconds; a tape library may take minutes.
  2. Cost per unit of data, for example taka or dollars per gigabyte. The faster the medium, the more each byte costs.
  3. Reliability: how likely the data is to be lost through power failure, a crash of the device, or physical wear.

No single medium wins on all three, which is why every computer combines several of them.

3. The storage hierarchy (slide 4)

Arranging the media from fastest (and most expensive per byte) at the top to slowest (and cheapest) at the bottom gives the storage hierarchy. The slide groups the six levels into three bands.

Primary storage
The fastest media, but volatile: cache (small memory on the CPU chip) and main memory (RAM). The CPU can work directly only on data in primary storage.
Secondary storage (on-line storage)
The next level: non-volatile, with moderately fast access. Examples are flash memory and magnetic disks. It is called on-line because it is always connected and ready to be read without anyone doing anything. Databases keep their data here.
Tertiary storage (off-line storage)
The lowest level: non-volatile but slow to access. Examples are magnetic tape and optical storage (CD, DVD, Blu-ray). It is called off-line because a tape or disc may need to be loaded into a drive, by a robot or a person, before it can be read. It is used for archival storage: backups and old data that must be kept but is rarely read.

The levels one by one

Cache. A few megabytes of very fast memory built into the processor. The hardware manages it automatically; the database cannot control it directly.

Main memory. The RAM where programs and the data they work on live while running. Access takes around 100 nanoseconds. It is volatile and costs far more per gigabyte than disk, so a large database usually does not fit in it. The database keeps a buffer in main memory: a set of disk blocks that have been copied into RAM so they can be used.

Flash memory. Non-volatile memory built from transistors that hold their charge without power. It is used in USB sticks, phones and solid-state drives (SSDs), which are flash memory packaged to look like a disk. Flash has no moving parts, so reading a block takes tens of microseconds instead of milliseconds. Writing is more awkward: a page of flash cannot be overwritten in place. It must first be erased, and erasing works on a large group of pages at once. Each location also survives only a limited number of erase cycles, so the drive spreads writes around (this is called wear levelling). Flash costs more per byte than magnetic disk but is much faster, which is why it sits between main memory and disk in the hierarchy.

Magnetic disk. Spinning platters coated with magnetic material, read by a moving head. It is the classic home of a database: large, cheap per byte, non-volatile, and directly connected. Each access takes milliseconds because parts must physically move. Chapters 2–4 look inside it.

Optical disk. Data is written as tiny marks read by a laser (CD, DVD, Blu-ray). It is slower than magnetic disk and mostly used for distributing data or archiving it.

Magnetic tape. A long strip of magnetic tape on a reel. Tape is very cheap per byte and lasts for years, but it can only be read sequentially (from the start towards the end), so getting to data in the middle can take seconds to minutes. It is used for backups and archives.

How data moves between levels

The CPU can only use data that is in primary storage. So when a query needs a record that is on disk, the block containing it is copied up the hierarchy. When data changes, it eventually has to be copied back down to non-volatile storage to be safe. The animation follows one read.

Discussion (slide 4): two types of DBMS

There are two types of DBMS: disk-based and main-memory based. Which part of the memory is concerned with (a) a disk-based DBMS, (b) an in-memory DBMS?

(a) Disk-based DBMS. The database itself lives in secondary storage (magnetic disks or flash SSDs). Main memory holds only a buffer of the blocks currently in use. Because the database is far larger than memory, blocks keep moving between disk and buffer. The dominant cost is the number of disk I/Os, so everything is designed to reduce them: block-sized pages, indexes such as B+ trees with a high fan-out, buffer replacement policies, and keeping related data together. Tertiary storage holds backups.

(b) In-memory (main-memory) DBMS. The whole working database is kept in primary storage, main memory. Queries never wait for a disk read, so performance depends on CPU and cache efficiency instead of disk I/O. Main memory is volatile, so an in-memory DBMS still writes a log and periodic checkpoints (snapshots) to secondary storage. After a crash it reloads the snapshot and replays the log. So the non-volatile secondary storage is still needed, but only for durability, not for answering queries.

Quick check

Summary: Storage is volatile (lost at power-off: cache, main memory) or non-volatile (kept: flash, magnetic disk, optical disk, tape). Speed, cost per byte and reliability decide where data goes. The hierarchy has three bands: primary (cache, main memory: fast, volatile), secondary or on-line (flash, magnetic disk: where databases live), and tertiary or off-line (optical, tape: archives). A disk-based DBMS keeps the database on secondary storage and buffers blocks in memory; an in-memory DBMS keeps it in main memory and uses secondary storage only for the log and checkpoints.
