One-Pass Algorithms for Union, Intersection, Difference, Product and Join

All the binary one-pass algorithms share one plan: keep the smaller relation in memory with a search structure, then stream the larger one past it a block at a time. This chapter gives each operation's rule, its cost B(R) + B(S) and its memory condition, lets you animate any of them on your own tuples, and answers the exam question on S − R.

1. Bag union: no memory needed (slide 45)

Bag
A multiset: a collection in which the same tuple may occur several times. SQL tables are bags unless DISTINCT is used. A set has no duplicates.
Bag union R ∪B S
Keeps all tuples of both: a tuple occurring m times in R and n times in S occurs m + n times in the result (SQL's UNION ALL).

Algorithm: copy every tuple of R to the output, then copy every tuple of S. Disk I/Os: B(R) + B(S). Memory: M = 1 suffices, whatever the sizes, because nothing is stored: pipelining lets the output leave one tuple at a time (this is the union iterator of Chapter 5).

2. The general plan for the other binary operations

Every other binary operation needs to compare tuples of R with tuples of S, so one of them must be in memory. Following the slides, assume B(S) < B(R), so S is the one we store:

  1. Read S into M − 1 buffers and build a main-memory search structure on it (a hash table or balanced tree). The search key is the entire tuple for ∪, ∩ and −, and the join attributes Y for the join.
  2. Read R one block at a time into the one remaining buffer (the M-th), and handle each tuple of R using the structure.

Disk I/Os = B(R) + B(S)   ·   Memory: min(B(R), B(S)) < M

"At least one of R and S must fit in M − 1 buffers." The exact condition is min(B(R), B(S)) ≤ M − 1.

3. The rules, operation by operation (slides 46–54)

Set union R ∪ S (slides 46–48)

R and S are sets; the union keeps one copy of each tuple that occurs in both.

  • Read S into M − 1 buffers, build the structure (key = entire tuple), and copy all tuples of S to the output.
  • Read R a block at a time. For each tuple of R: if it is not in S, copy it to the output; if it is in S, do not copy it (it was already output as part of S).

Set intersection R ∩ S (slide 49)

  • Read S into M − 1 buffers with the structure (key = full tuple).
  • Read each block of R. For each tuple of R: if it is in S, copy it to the output; otherwise do not.

Set difference (slide 50, and the textbook for the other direction)

Difference is not commutative, so the two directions differ. S is in memory in both.

  • R − S (slide 50): read R a block at a time; for each tuple of R, if it is not in S, copy it to the output; if it is in S, do not.
  • S − R (textbook): read R a block at a time; for each tuple t of R, if t is in S, delete t from the in-memory copy of S; otherwise do nothing. After all of R, copy the tuples of S that remain to the output.

Bag intersection (slides 51–52)

For bags, an element appears in R ∩B S the minimum of the number of times it appears in R and in S. Example: {a, a, a, b} ∩B {a, a, b, b, c} = {a, a, b}.

  • Assume B(S) < B(R) and B(S) ≤ M − 1. Read S into M − 1 buffers and build a hash table whose key is the full tuple value, storing with each distinct tuple a count = the number of times it occurs in S. (Duplicates are not stored separately, so S often shrinks.)
  • Read R one block at a time. For each tuple t of R: if t is in S and its count is positive, decrease the count by one and copy t to the output; if the count is zero (or t is not in S), do nothing.

Cartesian product R × S (slide 53)

  • Read S into M − 1 buffers; no special data structure is needed, since every pair is output.
  • Read R one block at a time; concatenate each tuple of R with each tuple of S in memory, and send each concatenated tuple to the output.

The processor time per R tuple is large (it meets every S tuple), but so is the output, so the time per output tuple is small.

Natural join R(X, Y) ⋈ S(Y, Z) (slide 54)

Notation: Y is all the attributes R and S have in common, X the rest of R's attributes, Z the rest of S's.

  • Read S into M − 1 buffers and build a search structure on S with search key = Y.
  • Read each block of R into the one remaining buffer. For each tuple t of R, find the tuples of S that agree with t on all attributes of Y, concatenate each with t, and send the result to the output.

An equijoin works the same way after renaming; a theta-join is a product or equijoin followed by a selection.

Exam questions

DB QB · 17-18 1c · 6 marks  |  BUET QBank · CSE 215 | L-2/T-2 | 2017–18 · 6 marks

Write the steps of a one-pass algorithm for finding S − R, where number of records in relation R is smaller than the number of records in relation S.

Show worked answer

R is the smaller relation, so R is the one kept in memory (here it plays the role that S plays on the slides), and S is streamed. The result keeps the tuples of S that are not in R. Assume B(R) ≤ M − 1 (R fits in memory).

  1. Read R block by block into M − 1 buffers. Build a main-memory search structure (hash table or balanced tree) whose search key is the entire tuple.
  2. Read S one block at a time into the remaining buffer.
  3. For each tuple s of the current block of S: look s up in the structure. If s is in R, discard it. If s is not in R, copy it to the output.
  4. Repeat until all blocks of S have been processed.

Cost: each block of R and S is read once: B(R) + B(S) disk I/Os. Memory: B(R) < M (at least B(R) + 1 buffers, plus an output buffer if it is counted).

To check it with the animation above, remember that the tool always calls the in-memory relation S and the streamed one R. So the bank's R goes in the tool's "S" box and the bank's S in the "R" box, and the operation is the tool's "R − S". With memory relation {b, c, e} and streamed relation {a, b, c, d} the output is {a, d}.

Variation: if S were the smaller relation, keep S in memory, delete from it every tuple that appears in R while R is streamed, and output what remains of S at the end (the textbook's S − R algorithm). The cost is the same.

Summary: bag union copies R then S with one buffer. Every other binary operation reads the smaller relation S into M − 1 buffers with a search structure (whole tuple for set operations, join attributes for ⋈, counts for bag ∩, nothing for ×) and streams the larger relation R through the last buffer. Cost B(R) + B(S); condition min(B(R), B(S)) < M. For S − R with S in memory, matching tuples are deleted from memory and the survivors are output at the end.
