Naming, Adding, Dropping and Disabling Constraints

A constraint you want to change later needs a name. This chapter covers the CONSTRAINT keyword (slide 51, with its three examples repaired for Oracle), ALTER TABLE … ADD / DROP CONSTRAINT and DROP ASSERTION (slide 52), and the Oracle practice around them: what happens when existing rows break a new constraint, ENABLE and DISABLE, and how to find constraints in Oracle's data dictionary.

1. Giving names to constraints (slide 51)

"Why give names? In order to be able to alter constraints." To drop or change a constraint you must say which one, and the handle is its name. Add the keyword CONSTRAINT and a name in front of any constraint, column or table form:

ssn CHAR(9) CONSTRAINT ssnIsKey PRIMARY KEY                    -- slide 51 (1); the slide writes CHAR(50)

If you do not name a constraint, Oracle invents a name such as SYS_C007123. It appears in error messages (ORA-02290: check constraint (SCOTT.SYS_C007123) violated), where it tells you nothing, and to drop the constraint you would first have to look the name up in the data dictionary (section 5). A good name says what was violated: ORA-02290: check constraint (SCOTT.POSITIVEPRICE) violated. A common convention is table_column_type, e.g. emp_dept_fk, pc_price_ck. Names must be unique within a schema (all tables together), and Oracle stores them in upper case.

Slide 51's other two examples need repairs before Oracle accepts them:

Slide 51 (2): CONSTRAINT ninedigits CHECK (VALUE >= 100000000 AND VALUE <= 999999999)

VALUE is the keyword of a domain constraint in standard SQL: CREATE DOMAIN SSNType AS INT CHECK (VALUE BETWEEN …) defines a reusable type, and VALUE stands for "the value of whatever column has this type". Oracle has no CREATE DOMAIN, and in a table CHECK there is no VALUE; write the column name:

ssn NUMBER(9) CONSTRAINT ninedigits CHECK (ssn BETWEEN 100000000 AND 999999999)

Slide 51 (3): CONSTRAINT rightage CHECK (age >= 0 OR status = "dead")

In SQL, double quotes mark an identifier (a column or table name), not a string. Oracle reads "dead" as a column called dead and fails with ORA-00904: "dead": invalid identifier. String literals take single quotes: status = 'dead'. Read as a rule: the age must be non-negative unless the person is dead (perhaps age is stored as a negative number of years since death, or is meaningless then). It is a tuple-based CHECK because it uses two columns.

2. ALTER TABLE … ADD / DROP CONSTRAINT and DROP ASSERTION (slide 52)

ALTER TABLE Product DROP CONSTRAINT positivePrice;
ALTER TABLE Product ADD CONSTRAINT positivePrice CHECK (price >= 0);
DROP ASSERTION assert1;

The pair of ALTER statements is how you change a constraint: there is no "modify constraint", so you drop the old one and add the new one under the same name. (The slide's Product has a price column; in this lecture's Product(maker, model, type) the price lives in PC, Laptop and Printer, so read it as one of those.) DROP ASSERTION removes an assertion; it is standard SQL, and like CREATE ASSERTION it does not exist in Oracle.

Oracle's ALTER TABLE can add every kind of table constraint, and has a few extra forms:

ALTER TABLE PC ADD CONSTRAINT pc_pk PRIMARY KEY (model);
ALTER TABLE PC ADD CONSTRAINT pc_model_fk FOREIGN KEY (model) REFERENCES Product(model) ON DELETE CASCADE;
ALTER TABLE PC ADD CONSTRAINT pc_slow_ck CHECK (speed >= 2.0 OR price <= 800);
ALTER TABLE PC MODIFY (ram NOT NULL);        -- NOT NULL is a column property: MODIFY, not ADD
ALTER TABLE PC DROP PRIMARY KEY;             -- no name needed for the primary key
ALTER TABLE Product DROP CONSTRAINT product_pk CASCADE;   -- also drops the foreign keys that reference it

Adding a constraint to a table that already has rows

When a constraint is added, Oracle checks every existing row first (this is called validating the constraint). If any row breaks it, the ALTER fails and nothing is added:

Constraint addedExisting rows break itOracle error
CHECKsome row makes the condition falseORA-02293: cannot validate (…) - check constraint violated
PRIMARY KEY / UNIQUEduplicate values (or NULL for a primary key)ORA-02437: cannot validate (…) - primary key violated; ORA-02299: cannot validate (…) - duplicate keys found (UNIQUE); ORA-01449 if a primary-key column holds NULL
FOREIGN KEYdangling valuesORA-02298: cannot validate (…) - parent keys not found
NOT NULL (MODIFY)a NULL in the columnORA-02296: cannot enable (…) - null values found

So the routine is: find the offending rows with a query (the negation of the condition, exactly as in Chapters 5 and 6), fix or delete them, then add the constraint. Exercise 5 practises this.

3. Disabling and enabling constraints (Oracle)

The slides do not cover this, but you meet it in every Oracle project. A constraint can be switched off without dropping it, and switched on again later:

ALTER TABLE Department DISABLE CONSTRAINT dept_head_fk;    -- rows are no longer checked
-- … bulk load or repair data …
ALTER TABLE Department ENABLE CONSTRAINT dept_head_fk;     -- re-validates ALL rows (ORA-02298 if some dangle)
ALTER TABLE Department ENABLE NOVALIDATE CONSTRAINT dept_head_fk;  -- check only future changes

Why disable? Loading millions of rows is faster without a check per row, and loading tables that refer to each other is easier when the order does not matter. The danger: while a constraint is disabled, bad rows can get in, and ENABLE (which by default means ENABLE VALIDATE) then fails until they are fixed. ENABLE NOVALIDATE skips the old rows, which leaves the database in a state where the rule is not guaranteed for them. A primary key or unique constraint that is disabled also loses its index (by default), and you cannot disable a primary key that enabled foreign keys still reference unless you write DISABLE CONSTRAINT … CASCADE.

4. Constraints in Oracle's data dictionary

Oracle records every constraint in the view USER_CONSTRAINTS (and the columns involved in USER_CONS_COLUMNS). The column CONSTRAINT_TYPE is a letter: P primary key, U unique, R foreign key ("referential"), C check (NOT NULL constraints are also stored as type C, with search condition "COL" IS NOT NULL). R_CONSTRAINT_NAME gives, for a foreign key, the name of the primary/unique key it references, DELETE_RULE is NO ACTION, CASCADE or SET NULL, and STATUS is ENABLED or DISABLED.

SELECT constraint_name, constraint_type, search_condition, status
FROM   user_constraints
WHERE  table_name = 'DEPARTMENT';          -- table names are stored in upper case

Summary: Name constraints with CONSTRAINT name … so that errors are readable and the constraint can be dropped. Change a constraint by ALTER TABLE t DROP CONSTRAINT name then ADD CONSTRAINT name …; existing rows must satisfy a new constraint or the ALTER fails. Oracle can also DISABLE/ENABLE a constraint, lists constraints in USER_CONSTRAINTS (types P, U, R, C), and has no domains, assertions or DROP ASSERTION. Fix slide 51 for Oracle: no VALUE keyword, single quotes for strings.
