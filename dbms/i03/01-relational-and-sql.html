SQL and Relational Databases

What SQL is, where it came from, how relational and non-relational databases differ, and how SQL splits into a data definition part (DDL) and a data manipulation part (DML). This chapter also introduces the four basic operations every database supports: Create, Read, Update and Delete.

2. Two kinds of databases (slides 3–5)

Relational database
A database that organizes data into one or more tables. Each table has named columns and a set of rows, and a key (a column or set of columns whose value is unique in every row) identifies each row.
Non-relational (NoSQL) database
A database that organizes data in some structure other than tables: key-value pairs (a value looked up by a key, like a hash map), documents (self-describing records in JSON or XML), or graphs (nodes connected by labelled edges).

This course is about relational databases, and the rest of the book uses them only. The slide's "Link" on slide 5 points to an article comparing the two; the main points are: relational systems give a fixed schema, a powerful standard query language (SQL) and strong consistency guarantees; non-relational systems give flexible schemas and easy horizontal scaling for very large or loosely structured data, usually at the cost of a weaker query language.

3. What SQL is (slide 6)

SQL
Structured Query Language: the standard language for defining, querying and changing data in a relational database. It was first called SEQUEL (Structured English QUEry Language) at IBM; the name was shortened for trademark reasons. The slide recommends the pronunciation "S-Q-L"; "sequel" is also common in industry.
Declarative language
A language in which you state what result you want and the system works out how to compute it. SQL is declarative: SELECT name FROM Students WHERE gpa > 3.5 says nothing about loops, files or indexes. The DBMS's query optimizer chooses the method (Lectures 13–15 show what happens underneath).

4. A short history (slide 7)

  • 1970s, IBM. E. F. Codd at IBM published the relational model in 1970. IBM built the first relational prototype, System R, whose query language became SQL; its commercial successor is DB2. Other early systems had their own languages: Ingres used QUEL, Digital had the Relational Database Operator, ISBL was a relational-algebra language, and the dBase family ran on PCs.
  • 1979, Oracle. Relational Software Inc. (later renamed Oracle) shipped the first commercial SQL database. This course uses Oracle.
  • 1980s, standardisation. The slide says the ISO standard came in 1984. The first SQL standard was actually published by ANSI in 1986 and adopted by ISO in 1987 ("SQL-86"); it had many gaps but was adopted everywhere.
  • 1992, SQL-92. The big revision that is still the core of every SQL system.
  • 1999, SQL:1999. Added triggers, recursive queries and object features. Oracle conforms to the core of SQL:1999.
  • 2003, SQL:2003. The slide calls it the current standard, which was true when the slide was written. Later revisions are SQL:2006, 2008, 2011, 2016 and SQL:2023. No product implements all of any standard; every system has its own dialect, and Oracle's is the one used in this book.

5. The four basic operations: CRUD (slide 8)

Every database system, relational or not, must support four operations on stored data, remembered as CRUD. In SQL each one is a single statement:

Notice that "Create" in CRUD means creating data (rows). Creating a table is a different kind of statement, which leads to the DDL/DML split.

6. The two halves of SQL: DDL and DML (slide 9)

Data Definition Language (DDL)
The statements that create, change and remove the structure of the database: tables, their attributes (columns) and their constraints. The main DDL statements are CREATE TABLE, ALTER TABLE and DROP TABLE. This lecture teaches DDL.
Data Manipulation Language (DML)
The statements that work on the data inside tables: querying (SELECT) and modifying (INSERT, UPDATE, DELETE). Lectures 4 and 5 teach DML.

Oracle's documentation also names two smaller groups that the slides do not list: transaction control (COMMIT, ROLLBACK) and data control (GRANT, REVOKE, which give and take away permissions; see Lec 05 Chapter 5). One practical difference matters in Oracle: every DDL statement commits the current transaction automatically, while DML changes stay uncommitted until you issue COMMIT.

Summary: a relational database stores data in tables of rows and columns, with a key identifying each row; non-relational databases use key-value pairs, documents or graphs. SQL (originally SEQUEL, from IBM's System R) is the standard, declarative language for relational databases; Oracle shipped the first commercial SQL product in 1979. Every database supports CRUD: INSERT, SELECT, UPDATE, DELETE. SQL's DDL defines structure (CREATE/ALTER/DROP TABLE) and its DML queries and changes data (SELECT, INSERT, UPDATE, DELETE).
