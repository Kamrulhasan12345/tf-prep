Character and Number Types

How Oracle stores strings (CHAR and VARCHAR2) and numbers (INTEGER, REAL, FLOAT and NUMBER(p, s)), when to choose which, and exactly what happens when a value is too long or has too many digits. An interactive calculator lets you test any NUMBER(p, s) column.

1. CHAR: fixed-length strings (slide 15)

CHAR(n)
A fixed-length character string of exactly n characters. Syntax: CHAR[(maximum_size)]; the square brackets mean the size is optional, and CHAR alone means CHAR(1). Examples: name CHAR(40), gender CHAR.

The slide gives the two rules for a value that does not have exactly n characters:

  • Shorter: padded with blanks at the right. Storing 'kamal' (5 characters) in CHAR(10) stores 'kamal␣␣␣␣␣' (␣ marks a blank). The column always uses 10 characters of space.
  • Longer: rejected. Storing 'kamal hossain' (13 characters) in CHAR(10) fails with Oracle error ORA-12899 ("value too large for column"). Oracle never silently cuts a string.

2. VARCHAR2: variable-length strings (slide 16)

VARCHAR2(n)
A variable-length string of up to n characters. Only the actual characters are stored (plus a small length field), so 'kamal' in VARCHAR2(10) uses 5 characters of space. Standard SQL calls this type VARCHAR(n); Oracle's name is VARCHAR2. Example: address VARCHAR2(100).
  • The size is required. VARCHAR2 without (n) is a syntax error (the slide: "VARCHAR → not permitted").
  • Too long is rejected, exactly as for CHAR (ORA-12899).
  • No padding. Trailing blanks are stored only if you typed them.
  • In Oracle, VARCHAR is accepted as a synonym, but Oracle reserves the right to change its meaning, so always write VARCHAR2. The largest allowed size is 4000 bytes (32767 if the database is configured with extended string sizes).

3. CHAR or VARCHAR2? (slide 17)

Slide 17 sums up the trade-off: VARCHAR2 wastes no memory, because short values take less space; CHAR is slightly faster to process, because every value has the same length, so the system never has to read a length field or move records around when a value grows. Then it asks two questions.

Question (worked answer): which type for a password? For a first or last name?

Names: VARCHAR2. Name lengths vary a lot ("Ali" vs "Mohammad Ashraful Islam Chowdhury"). With CHAR(50) every short name would carry dozens of padding blanks: wasted space on every row, and the blanks come back in query output and must be trimmed when names are joined into strings. So first_name VARCHAR2(30), last_name VARCHAR2(30).

Passwords: it depends on what is stored. A well-designed system never stores the password itself; it stores a hash of it, and a hash function produces a fixed-length result (for example SHA-256 gives 64 hexadecimal characters). Fixed length is exactly what CHAR is for: pwd_hash CHAR(64) wastes nothing and gets CHAR's speed. If plain passwords of varying length had to be stored, VARCHAR2 would be the right choice: with CHAR, 'abc' is stored as 'abc␣␣␣…', and Oracle's blank-padded comparison (Lec 04, Chapter 3) would treat the passwords 'abc' and 'abc ' as equal.

Rule of thumb: CHAR for values that always have the same length (gender 'M'/'F', a 2-letter state code, a 13-digit ISBN, a fixed-length hash); VARCHAR2 for everything else.

4. Number types (slide 18)

Slide 18 lists three number types "like C". In Oracle they are all stored by one internal number format, and their sizes are given in binary digits of precision:

TypeWhat it is in OraclePrecisionUse for
INT / INTEGERNUMBER(38): whole numbers only38 decimal digits ≈ 126 bitscounts, years, IDs
REALFLOAT(63)63 binary digits ≈ 19 decimal digitsmeasurements where tiny rounding is acceptable
FLOATFLOAT(126)126 binary digits ≈ 38 decimal digitsthe same, more precision

Unlike C's int, an Oracle INTEGER is not a 32-bit machine word: it holds up to 38 decimal digits. A value with a fraction stored in an INTEGER column is rounded to a whole number.

5. Fixed-point decimals: NUMBER(p, s) (slides 19–20)

NUMBER(p, s)
Oracle's exact decimal type (standard SQL: DECIMAL(p, s)). Precision p is the total number of significant digits (1 to 38). Scale s is the number of digits after the decimal point; a negative scale rounds to the left of the decimal point (tens, hundreds, …). NUMBER(p) means NUMBER(p, 0); plain NUMBER stores any value as given, up to 38 significant digits (the slide: "only NUMBER → any fraction").

Storing a value takes two steps, and the slide's example follows them exactly:

  1. Round the value to s decimal places (half away from zero). With s = −2, round to the nearest hundred.
  2. Check the size: the rounded value may have at most p − s digits before the decimal point. If it has more, Oracle rejects the value (ORA-01438).
stored = round(value, s)    allowed only if |stored| < 10p − s

The animation applies both steps to the slide's value 7,456,123.89 (9 digits, 2 after the point).

Notice the difference between the two kinds of "too many digits": too many digits after the point are silently rounded away, while too many digits before the point make the insert fail. Losing a cent is acceptable; turning 7 million into something else is not.

Summary: CHAR(n) is fixed length: short values are blank-padded, long ones rejected. VARCHAR2(n) is variable length, needs a size, stores only the characters, and also rejects long values. Use CHAR for always-same-length data, VARCHAR2 for the rest. INTEGER is NUMBER(38); REAL and FLOAT are binary floating point with 63 and 126 bits of precision. NUMBER(p, s) rounds the value to s decimals (negative s rounds left of the point) and then rejects it if it needs more than p − s digits before the point.
