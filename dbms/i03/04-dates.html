Dates in Oracle

The DATE type, how Oracle turns strings into dates (implicitly with its default format, or explicitly with TO_DATE), how it turns dates back into text (TO_CHAR and format masks), why '01-JAN-74' means 1974 but '01-JAN-14' means 2014, and what arithmetic is allowed on dates.

1. The DATE type (slide 21)

DATE
A data type for calendar dates. In standard SQL a DATE holds year, month and day, and a date constant is written DATE 'YYYY-MM-DD', for example DATE '1994-10-21'. In Oracle a DATE also stores a time of day (hours, minutes, seconds); when you give only a date, the time is midnight, 00:00:00.

Slide 21 adds a dob DATE column to the Student table:

CREATE TABLE Student (
    name     CHAR(50),
    id       NUMBER(10),
    gender   CHAR(1),
    dob      DATE,
    address  CHAR(100),
    gpa      FLOAT
);

Oracle accepts the standard literal DATE '1994-10-21'. The literal is always year-month-day with dashes, whatever the session's settings, which makes it the safest way to write a constant date.

2. Oracle's default format and the RR rule (slide 22)

When a string is put where a DATE is expected, Oracle converts it using the session's default date format, NLS_DATE_FORMAT. In a standard English installation that format is DD-MON-RR: two-digit day, three-letter month, and a two- or four-digit year. The slide calls it "DD-MON-YYYY or DD-MON-YY"; strings in either form are accepted, and if you use this format you do not need TO_DATE:

CREATE TABLE foo (n NUMBER, d DATE);
INSERT INTO foo VALUES (1, '01-JAN-1974');   -- 1  01-01-1974
INSERT INTO foo VALUES (2, '01-JAN-74');     -- 2  01-01-1974
INSERT INTO foo VALUES (3, '01-JAN-2014');   -- 3  01-01-2014
INSERT INTO foo VALUES (4, '01-JAN-14');     -- 4  01-01-2014

Rows 2 and 4 are the interesting ones: the two-digit years 74 and 14 land in different centuries. That is the RR rule (the last line of slide 24):

RR (two-digit year with a century window)
A two-digit year is placed in the 100-year window around the current year. For any current year from 2000 to 2049: 00–49 → 2000–2049 and 50–99 → 1950–1999. So 74 → 1974, 14 → 2014, 06 → 2006.
YY (two-digit year, current century)
A two-digit year always gets the current century: in 2026, TO_DATE('01-JAN-74', 'DD-MON-YY') is 1 January 2074.

Relying on the default format is convenient but fragile: another session can have a different NLS_DATE_FORMAT, and then the same INSERT fails or stores a different date. In programs and exam answers, prefer DATE 'YYYY-MM-DD' or an explicit TO_DATE.

3. TO_DATE: string to date (slide 23)

TO_DATE(string, 'format')
Converts a string to a DATE, reading the string according to the format mask. The mask is built from the elements in the table of slide 24 (Oracle has over 40). Punctuation such as -, / and spaces in the mask matches the same punctuation in the string.
TO_DATE('1994-10-21', 'YYYY-MM-DD')     -- 21 October 1994
TO_DATE('1994-OCT-21', 'YYYY-MON-DD')   -- 21 October 1994
TO_DATE('94-OCT-21', 'RR-MON-DD')       -- 21 October 1994 (94 → 1994 by RR)

(The slide writes the masks as 'YYYY –MM-DD' with a space and a long dash; those are typing artefacts. Write the punctuation exactly as it appears in the string.)

The animation shows how Oracle reads a string with a mask: each mask element consumes the matching part of the string.

5. TO_CHAR: date to string (slide 25)

TO_CHAR(date, 'format')
Formats a DATE as a string using the same mask elements. It is how you control how dates are displayed.
TO_CHAR(dob, 'YYYY-MM-DD')      →  1994-10-21
TO_CHAR(dob, 'YYYY-MON-DD')     →  1994-OCT-21
TO_CHAR(dob, 'YY-MONTH-DD')     →  94-OCTOBER  -21     (slide shows 94-OCTOBER-21)

One correction to slide 25: MONTH pads the name with blanks to the length of the longest month name, SEPTEMBER (9 letters), so OCTOBER is followed by two blanks. To suppress the padding, add the FM ("fill mode") modifier: TO_CHAR(dob, 'YY-FMMONTH-DD') gives 94-OCTOBER-21.

It does not pad MONTH. It shows unformatted dates as YYYY-MM-DD, where Oracle would show 21-OCT-94.)

6. Date arithmetic (slide 26)

  • Comparison: two dates can be compared with = <> < > <= >=; earlier dates are smaller. WHERE dob < DATE '2002-01-01' finds people born before 2002.
  • Subtraction of two dates gives the number of days between them, as a NUMBER; leap years are counted correctly. Because Oracle dates carry a time, the result can have a fraction (half a day = 0.5).
  • Date ± integer gives a date that many days later or earlier: hire_date + 30.
  • No other arithmetic: adding two dates, or multiplying or dividing a date, is an error (what would 21 October + 5 March mean?).
  • SYSDATE returns the current date and time of the database server.
SELECT DATE '2024-03-01' - DATE '2024-02-01' FROM dual;   -- 29 (2024 is a leap year)
SELECT DATE '2024-02-25' + 7 FROM dual;                   -- 03-MAR-24
SELECT name, (SYSDATE - dob) / 365.25 AS age_years FROM Students;

Summary: a DATE holds a date (and, in Oracle, a time). Write constants as DATE 'YYYY-MM-DD' or with TO_DATE(string, mask); strings in the default format DD-MON-RR are converted implicitly. RR puts two-digit years 50–99 in the 1900s and 00–49 in the 2000s; YY always uses the current century. TO_CHAR(date, mask) formats dates for output (MONTH is blank-padded; FM removes the padding). Dates can be compared, subtracted (giving days) and shifted by a number of days; SYSDATE is the current date and time.
