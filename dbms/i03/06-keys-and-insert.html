Keys, PRIMARY KEY, UNIQUE and INSERT

What a key is and how to find one (including the slide's "What is the key here?" question), how to declare a primary key and UNIQUE attributes in CREATE TABLE, what the DBMS does when an INSERT breaks them, and the full and partial forms of INSERT.

1. Keys (slide 35)

Key
A minimal set of attributes whose values identify a tuple uniquely: no two tuples of the relation may agree on all of them. "Minimal" means that if you remove any attribute from the set, it stops being unique.
Superkey
Any set of attributes that identifies tuples uniquely, minimal or not. Every key is a superkey; adding attributes to a key gives a superkey that is not a key. (Sukarna sir's lectures on functional dependencies use the same terms.)

The red line on slide 35 is the most important part: a key is decided by considering every relation instance that could ever legally exist, not only the rows the table happens to contain now. The current data can prove that something is not a key (by showing two rows that agree on it), but it can never prove that something is a key. That decision comes from the meaning of the data.

In slide 35's Product(p_name, price, manufacturer), p_name is the key: each product name is used once. manufacturer is not a key (GizmoWorks makes two products), and neither is price: slide 37's version of the table shows Gizmo and Widget both at 19.99. (Slide 35 shows Widget at 29.99 and slide 37 at 19.99; the change is deliberate, to make the point that two products can share a price.)

2. What is the key here? (slide 36)

Question (worked answer): the key of Course(dept, number, section, instructor)

Options: A. dept   B. dept, number   C. dept, number, section   D. dept, number, section, instructor. The slide's answer is C. Check each option against the data, then against the meaning:

  • A (dept): MATH appears three times. Not unique, so not a key.
  • B (dept, number): (MATH, 101) appears twice, sections A and B. Not a key.
  • C (dept, number, section): all five combinations differ, and by meaning a course offering has one row per section, so it stays unique for any legal data. Removing any attribute breaks uniqueness (B already fails; (dept, section) fails with (MATH, A) twice; (number, section) fails with (101, A) twice). So it is minimal: a key.
  • D (all four): unique, because it contains C, but not minimal: instructor can be dropped. D is a superkey, not a key.

3. Primary keys (slide 37)

Primary key
The one key chosen to identify the rows of a table. Every table should have one. The DBMS then enforces two rules: (1) no two rows have the same primary-key value, and (2) no primary-key attribute is NULL. An INSERT or UPDATE that would break either rule fails.

In schema notation the primary key is underlined: Product(p_name, price, manufacturer). In Oracle, the duplicate case fails with ORA-00001: unique constraint violated and the NULL case with ORA-01400: cannot insert NULL.

There are two ways to declare a primary key in CREATE TABLE (textbook §2.3.6):

-- (1) after the attribute
CREATE TABLE Product (
  p_name       VARCHAR2(20) PRIMARY KEY,
  price        NUMBER(7,2),
  manufacturer VARCHAR2(20)
);
-- (2) as a separate item
CREATE TABLE Product (
  p_name       VARCHAR2(20),
  price        NUMBER(7,2),
  manufacturer VARCHAR2(20),
  PRIMARY KEY (p_name)
);

Form (1) only works for a one-attribute key. A key of several attributes must use form (2).

4. Class exercises: Movie and MovieStar (slides 38–41)

Class exercise (worked answer): the key of Movie(title, year, length, genre)

The title alone is not a key, because films are remade under the same title: King Kong was made in 1933 and again in 2005 (our sample table contains both). Two films with the same title in the same year are not expected, so (title, year) is the key. Neither attribute alone is unique, so the pair is minimal. Slide 39's declaration, with the composite key as a separate item:

CREATE TABLE Movie (
    title   VARCHAR2(50),
    year    INTEGER,
    length  INTEGER,
    genre   CHAR(10),
    PRIMARY KEY (title, year)
);

(The slide omits the final semicolon; it is needed when several statements are run together.)

Class exercise (worked answer): the key of MovieStar(name, address, gender, birthdate)

The key is name. Gender and birthdate are obviously shared by many people, and two stars could live at one address. Actors' unions do not let two members register the same professional name, so name identifies a star (the textbook makes the same assumption). Slide 41:

CREATE TABLE MovieStar (
    name       VARCHAR2(50),
    address    VARCHAR2(50),
    gender     CHAR(1),
    birthdate  DATE,
    PRIMARY KEY (name)
);

5. UNIQUE attributes (slides 42–43)

UNIQUE
A constraint declaring that an attribute (or set of attributes) must have distinct values in every row. It declares another key besides the primary key. Unlike a primary key, a UNIQUE attribute may be NULL, and more than one row may have NULL there, because NULL is not equal to anything, including another NULL.

Slide 43 adds a username to Students. Each student who has a username must have a different one, but a student may have none yet:

CREATE TABLE Students (
    sid       CHAR(10),
    name      VARCHAR2(50),
    email     VARCHAR2(50),
    gpa       FLOAT,
    dob       DATE,
    username  CHAR(5) UNIQUE,
    PRIMARY KEY (sid)
);

6. Adding data with INSERT (slide 44)

INSERT INTO <table_name> [(a1, a2, …, an)] VALUES (v1, v2, …, vn);
Full insert
No attribute list: one value for every attribute, in the order the attributes were declared in CREATE TABLE.
Partial insert
An attribute list in brackets, followed by one value for each listed attribute, in the list's order. Attributes that are not listed get their default value, which is NULL unless a DEFAULT was declared (Lec 05, Chapter 4).
-- full inserts: Student(id, first_name, last_name, city, state)
INSERT INTO Student VALUES ('S123456789', 'John', 'Doe', 'Houston', 'TX');
INSERT INTO Student VALUES ('S111111111', 'Mary', 'Jones', 'Houston', 'TX');
-- partial insert: city and state become NULL
INSERT INTO Student (id, first_name, last_name)
VALUES ('S987654321', 'Jane', 'Smith');

A partial insert must still give every attribute that may not be NULL, in particular the primary key. Listing the attributes is also good practice for full inserts: the statement keeps working if someone later adds a column or changes the column order.

Summary: a key is a minimal set of attributes that is unique for every legal instance; data can disprove a key but never prove one. Each table picks one primary key: no duplicates, no NULLs; declare it after the attribute (single attribute) or as PRIMARY KEY (a, b) (any size). UNIQUE declares another key that forbids duplicates but allows NULLs. INSERT gives either all values in declaration order, or a column list and matching values; unlisted columns become NULL (or their DEFAULT).
