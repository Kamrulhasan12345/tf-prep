NULL and the CREATE TABLE Statement

What NULL means and the three situations it stands for; the general form of CREATE TABLE and the classic syntax mistake on slide 31; which parts of SQL care about upper and lower case; the naming conventions this course follows; and a worked answer to Activity 1.

1. NULL: a missing value (slides 27–28)

NULL
A special marker meaning "no value here". Any attribute of any type (number, string, date) can be NULL unless a constraint forbids it. NULL is not zero, not a blank and not the string 'NULL': it is the absence of a value.

The slides use the schema Students(sid: string, name: string, email: string, gpa: float, dob: date) and list three different reasons a value can be missing:

  1. The value does not exist. A student who has no email address: there is nothing to record.
  2. The value exists but is unknown. Every student has a date of birth, but this one's is waiting for verification, so we cannot record it yet.
  3. The value is not applicable to this record. A Level-1 Term-1 student has no GPA yet; the attribute does not apply to them.

SQL uses the same single NULL for all three, so the database itself cannot tell them apart; the meaning lives in the application. The animation marks each kind in our sample Students table.

Three facts about NULL that you will need in every later lecture:

  • You cannot test for NULL with =. Any comparison with NULL (even NULL = NULL) gives the truth value UNKNOWN, not TRUE, so WHERE email = NULL returns no rows. Use IS NULL and IS NOT NULL. Lec 04 Chapter 8 explains the three-valued logic behind this.
  • Arithmetic with NULL gives NULL: gpa + 1 is NULL when gpa is NULL.
  • In Oracle, the empty string '' is NULL. Inserting '' into a VARCHAR2 column stores NULL. (Most other systems, and the playground's SQLite, keep '' and NULL separate.)

2. The general form of CREATE TABLE (slides 29–31)

CREATE TABLE <tableName> (
    attribute1  type1,
    attribute2  type2,
    …
    attributeN  typeN
);

The table name is followed by a parenthesised, comma-separated list of attribute declarations, each an attribute name followed by its type. Later items in the list can also be constraints, such as PRIMARY KEY (…) (Chapter 6). Slide 31 gives an example:

CREATE TABLE Product (
    maker VARCHAR2(10),
    model NUMBER(10),
    type  VARCHAR2(10),      ← this comma is an error
);

Slide error: the comma after the last attribute

Slides 31 and 33 end the last attribute with a comma. Oracle then expects another attribute name and finds ), so it reports ORA-00904: invalid identifier. Commas separate items; the last item has none. The correct statement is:

CREATE TABLE Product (
    maker VARCHAR2(10),
    model NUMBER(10),
    type  VARCHAR2(10)
);

Run both versions in the playground below to see the error and the fix.

3. What is case-sensitive (slide 32)

  • Keywords are case-insensitive: SELECT, Select and select are the same.
  • Table and attribute names are case-insensitive: Product and product name the same table. (Oracle stores unquoted names in upper case, PRODUCT.)
  • String constants are case-sensitive: 'Seattle' and 'seattle' are different values, so WHERE city = 'seattle' does not find Seattle.
  • String constants use single quotes: 'abc' is a string. "abc" is not a string in SQL: double quotes make a quoted identifier, a table or column name that keeps its exact case (and may contain spaces). WHERE name = "Ayesha" looks for a column called Ayesha and fails.

4. Naming conventions (slide 33)

SQL does not require any particular style, but a consistent one makes statements easy to read. The course convention:

ItemConventionExamples
SQL commands (keywords)all capitalsCREATE TABLE, SELECT
Table namesstart with a capital; each later word capitalisedProduct, MovieStar
Attribute namesstart lower case; later words capitalised or joined by underscoresmaker, certNo or cert_no
Data typesall capitalsCHAR, VARCHAR2

Avoid naming a column with an Oracle reserved word such as NUMBER, DATE, ORDER or GROUP: CREATE TABLE Course (number NUMBER(3)) fails. This is why our sample Course table calls slide 36's "number" column num.

5. Activity 1: create the student database (slide 34)

Activity 1 (worked answer)

Create a table for Students(sid: string, name: string, email: string, gpa: float, dob: date).

Choose a concrete Oracle type for each abstract type. Student IDs at BUET have a fixed length (7 digits, kept as a string so leading zeros and the ID's structure are preserved), so CHAR fits (CHAR(7) would be exact; the slides use CHAR(10), which also leaves room for longer ID formats); names and emails vary, so VARCHAR2; GPA is a real number, so FLOAT (or NUMBER(3,2), which stores exactly two decimals); the birth date is a DATE.

CREATE TABLE Students (
    sid    CHAR(10),
    name   VARCHAR2(50),
    email  VARCHAR2(50),
    gpa    FLOAT,
    dob    DATE
);

This is the same as slide 43's version without the username column and the key. A complete design also declares the key, PRIMARY KEY (sid), which is the topic of Chapter 6.
