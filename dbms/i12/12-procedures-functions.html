Exam Topics Beyond the Slides: Stored Procedures and Functions in PL/SQL

Triggers are one kind of stored program; the question bank also asks you to write stored procedures and functions. This chapter teaches just enough PL/SQL to write them (blocks, variables, SELECT INTO, IF, loops, cursors, exceptions, parameters), traces a procedure step by step, and answers the bank's four questions.

1. PL/SQL blocks

PL/SQL
Oracle's procedural extension of SQL: variables, IF, loops and exception handling around ordinary SQL statements. Trigger bodies are PL/SQL. The SQL standard's version is called SQL/PSM (persistent stored modules), textbook §9.4.
Block
The unit of PL/SQL code: an optional DECLARE section for variables, a BEGIN … END; section of statements, and an optional EXCEPTION section for error handlers. A block without a name is an anonymous block; it runs once and is not stored.
SET SERVEROUTPUT ON            -- SQL*Plus / SQL Developer: show DBMS_OUTPUT text

DECLARE
  v_count  NUMBER;                       -- a variable
  v_name   instructor.name%TYPE;         -- same type as the column instructor.name
BEGIN
  SELECT COUNT(*) INTO v_count FROM instructor WHERE dept_name = 'Physics';
  IF v_count = 0 THEN
    DBMS_OUTPUT.PUT_LINE('No physicists');
  ELSIF v_count = 1 THEN
    DBMS_OUTPUT.PUT_LINE('One physicist');
  ELSE
    DBMS_OUTPUT.PUT_LINE(v_count || ' physicists');
  END IF;
EXCEPTION
  WHEN OTHERS THEN
    DBMS_OUTPUT.PUT_LINE('Error: ' || SQLERRM);
END;
/

2. Stored procedures

Stored procedure
A named PL/SQL block stored in the database, with parameters, that you call explicitly. It performs actions (queries, updates, output) and returns nothing directly, though OUT parameters can pass values back.
Parameter modes
IN (default): a value passed in, read-only. OUT: the procedure assigns it and the caller receives it. IN OUT: both. Parameter types are written without a size (VARCHAR2, not VARCHAR2(20)).
CREATE OR REPLACE PROCEDURE raise_dept (
  p_dept IN  instructor.dept_name%TYPE,
  p_pct  IN  NUMBER,
  p_rows OUT NUMBER) IS
BEGIN
  UPDATE instructor SET salary = salary * (1 + p_pct / 100)
  WHERE dept_name = p_dept;
  p_rows := SQL%ROWCOUNT;              -- rows changed by the last SQL statement
END raise_dept;
/

-- calling it
DECLARE n NUMBER;
BEGIN
  raise_dept('Physics', 10, n);
  DBMS_OUTPUT.PUT_LINE(n || ' salaries raised');
END;
/
EXEC raise_dept('Physics', 10, :n)    -- SQL*Plus shorthand, with a bind variable :n

The IS/AS keyword starts the declaration section (no DECLARE inside a procedure). Whether to COMMIT is usually left to the caller, so that a procedure can be part of a bigger transaction.

3. Stored functions

Stored function
Like a procedure, but it returns a value with RETURN, so it can be used inside expressions, including SQL queries: SELECT f(x) FROM …. A function called from a SQL query may not modify the database.
CREATE OR REPLACE FUNCTION dept_avg (p_dept IN VARCHAR2) RETURN NUMBER IS
  v NUMBER;
BEGIN
  SELECT AVG(salary) INTO v FROM instructor WHERE dept_name = p_dept;
  RETURN v;
END;
/
SELECT name, salary, dept_avg(dept_name) FROM instructor;   -- used in SQL
SELECT dept_avg('Physics') FROM dual;                        -- dual: Oracle's one-row table

DB QB · 24-25 6a · 12 marks  |  BUET QBank · CSE 215 | L-2/T-1 | 2024–25 Q1 · 12 marks

Consider the following relational database schema: Planet(planet_id, name, type, distance_sun_au), planet_id is the primary key; Moon(moon_id, name, planet_id, diameter_km), moon_id is the primary key, and planet_id is a foreign key referencing Planet(planet_id).

(i) Write an SQL function total_moons() that returns a single integer value representing the total number of moons possessed by all planets. Then write the SQL statement to call the function.
(ii) Find the names of all planets whose name contains a substring that starts with "Ma", then has exactly two unknown characters, and ends with "s".

Show worked answer

(i)

CREATE OR REPLACE FUNCTION total_moons RETURN NUMBER IS
  v_total NUMBER;
BEGIN
  SELECT COUNT(planet_id) INTO v_total FROM Moon;
  RETURN v_total;
END total_moons;
/

SELECT total_moons() AS total FROM dual;

The function has no parameters, so it is declared without brackets (calling it with or without () both work). COUNT(planet_id) counts the moons that belong to a planet; if planet_id is declared NOT NULL this is the same as COUNT(*). SELECT … INTO with an aggregate always returns exactly one row, so no NO_DATA_FOUND handler is needed (an empty Moon table gives 0). It can also be called from PL/SQL: BEGIN DBMS_OUTPUT.PUT_LINE('Moons: ' || total_moons); END;.

(ii) In LIKE, % matches any string (including the empty string) and _ exactly one character. "Contains a substring Ma, two characters, s" is therefore:

SELECT name
FROM Planet
WHERE name LIKE '%Ma__s%';

Mars does not match: between "Ma" and "s" it has only one character (r). In the sample data below, Matisse (Ma-ti-s) and Magus Prime (Ma-gu-s) match. Oracle's LIKE is case-sensitive, so "ma" in lower case would not count; the playground's SQLite ignores case for ASCII letters, which is why the sample data has no such names.

DB QB · Jan 20 7 · 10 marks  |  BUET QBank · CSE 215 | L-2/T-2 | 2018–19 · 10 marks

Write a procedure named IncreaseOrDecrease which takes an employee id as input. If the salary of the employee is greater than the average salaries of all the departments except for his/her own, but less than the average salary of his/her own department, then the procedure will increase his/her salary by 10%. Otherwise, it will decrease his/her salary by 5%. During the execution, as output, it will print "Increasing Salary", or "Decreasing Salary", accordingly. (Schema: the Oracle HR schema, employees(employee_id, first_name, …, salary, …, department_id, …).)

Show worked answer

Reading the condition. "Greater than the average salaries of all the departments except his/her own" most naturally means: compute each other department's average salary; the employee must earn more than every one of them, i.e. more than the largest of those averages. (A second reading compares with the single average of all employees outside the department; the bank's answer uses that one. State which you use; the procedure changes in one query.)

CREATE OR REPLACE PROCEDURE IncreaseOrDecrease (
  p_emp_id IN employees.employee_id%TYPE) IS
  v_salary   employees.salary%TYPE;
  v_dept     employees.department_id%TYPE;
  v_own_avg  NUMBER;
  v_other    NUMBER;
BEGIN
  SELECT salary, department_id INTO v_salary, v_dept
  FROM employees WHERE employee_id = p_emp_id;

  SELECT AVG(salary) INTO v_own_avg
  FROM employees WHERE department_id = v_dept;

  SELECT MAX(AVG(salary)) INTO v_other          -- largest other-department average
  FROM employees
  WHERE department_id <> v_dept
  GROUP BY department_id;
  -- second reading instead:  SELECT AVG(salary) INTO v_other
  --                          FROM employees WHERE department_id <> v_dept;

  IF v_salary > v_other AND v_salary < v_own_avg THEN
    UPDATE employees SET salary = salary * 1.10 WHERE employee_id = p_emp_id;
    DBMS_OUTPUT.PUT_LINE('Increasing Salary');
  ELSE
    UPDATE employees SET salary = salary * 0.95 WHERE employee_id = p_emp_id;
    DBMS_OUTPUT.PUT_LINE('Decreasing Salary');
  END IF;
EXCEPTION
  WHEN NO_DATA_FOUND THEN
    DBMS_OUTPUT.PUT_LINE('No employee with id ' || p_emp_id);
END IncreaseOrDecrease;
/

SET SERVEROUTPUT ON
EXEC IncreaseOrDecrease(103)

Notes for full marks: %TYPE anchors the variable types to the columns; SELECT INTO with the employee's id returns one row or raises NO_DATA_FOUND, which is handled; Oracle allows the nested aggregate MAX(AVG(salary)) with GROUP BY; if the employee's department is the only one, v_other is NULL, the comparison is unknown, and the ELSE branch (decrease) runs, which matches "otherwise". The two updates run inside the caller's transaction (the bank's version adds COMMIT, which is allowed in a procedure but takes the decision away from the caller).

Check the logic on the sample data with the tracer above: employee 103 (7400 in a department averaging 7633.33, other averages 4500 and 6750) is raised under both readings, while employee 101 (6000) is cut under the first reading (6000 < 6750) but raised under the second (6000 > 5625).

DB QB · 17-18 8b · 10 marks  |  BUET QBank · CSE 215 | L-2/T-2 | 2017–18 · 10 marks

Consider the following schema: Movie(title, year, filmType, inColor, studioId), Studio(studioId, name, address). Write a stored procedure that takes as input the name of a studio and a year. It then counts and prints the number of black and white movies produced by that studio in the specified year.

Show worked answer

Assume inColor holds 'T' for colour and 'F' for black and white (the textbook stores it as a boolean; in Oracle a CHAR(1) 'T'/'F' is the usual encoding, as for Printer.color in slide 46).

CREATE OR REPLACE PROCEDURE CountBWMovies (
  p_studio IN Studio.name%TYPE,
  p_year   IN Movie.year%TYPE) IS
  v_count NUMBER;
BEGIN
  SELECT COUNT(*) INTO v_count
  FROM Movie m JOIN Studio s ON m.studioId = s.studioId
  WHERE s.name = p_studio
    AND m.year = p_year
    AND m.inColor = 'F';

  DBMS_OUTPUT.PUT_LINE(p_studio || ' produced ' || v_count ||
                       ' black and white movie(s) in ' || p_year);
END CountBWMovies;
/

SET SERVEROUTPUT ON
EXEC CountBWMovies('MGM', 1939)

COUNT(*) always returns one row, so the SELECT INTO cannot raise NO_DATA_FOUND; an unknown studio simply prints 0. On the sample data below the call prints "MGM produced 2 black and white movie(s) in 1939".

BUET QBank · CSE 303 | L-3/T-1 | 2016–17 · 10 marks

Write constructor functions for the car rental SQL:99 schema (Trucks, Sports car, Bus) and insert statement to insert data into the tables.

Show worked answer

The schema this question refers to is not reproduced in the bank, so assume a supertype of vehicles with three subtypes. In SQL:99's object-relational model, a user-defined type (UDT) can inherit from another (UNDER), a table can be declared as a table OF a type (each row is an object of that type), and every UDT gets a system-generated constructor function with the type's name and no arguments, which returns a new object with all attributes NULL. A user-defined constructor takes attribute values and fills them in (textbook style):

CREATE TYPE VehicleType AS (
  regNo     VARCHAR(10),
  make      VARCHAR(20),
  model     VARCHAR(20),
  dailyRate DECIMAL(8,2)
) NOT FINAL;

CREATE TYPE TruckType     UNDER VehicleType AS (capacityTons DECIMAL(5,1), axles INT) FINAL;
CREATE TYPE SportsCarType UNDER VehicleType AS (topSpeed INT, convertible CHAR(1)) FINAL;
CREATE TYPE BusType       UNDER VehicleType AS (seats INT, hasAC CHAR(1)) FINAL;

CREATE TABLE Trucks     OF TruckType;
CREATE TABLE SportsCars OF SportsCarType;
CREATE TABLE Buses      OF BusType;

CREATE FUNCTION TruckType(r VARCHAR(10), mk VARCHAR(20), md VARCHAR(20),
                          rate DECIMAL(8,2), cap DECIMAL(5,1), ax INT)
RETURNS TruckType
BEGIN
  DECLARE t TruckType;
  SET t = TruckType();          -- system constructor: all attributes NULL
  SET t.regNo = r;  SET t.make = mk;  SET t.model = md;  SET t.dailyRate = rate;
  SET t.capacityTons = cap;  SET t.axles = ax;
  RETURN t;
END;

CREATE FUNCTION SportsCarType(r VARCHAR(10), mk VARCHAR(20), md VARCHAR(20),
                              rate DECIMAL(8,2), spd INT, conv CHAR(1))
RETURNS SportsCarType
BEGIN
  DECLARE s SportsCarType;
  SET s = SportsCarType();
  SET s.regNo = r;  SET s.make = mk;  SET s.model = md;  SET s.dailyRate = rate;
  SET s.topSpeed = spd;  SET s.convertible = conv;
  RETURN s;
END;

CREATE FUNCTION BusType(r VARCHAR(10), mk VARCHAR(20), md VARCHAR(20),
                        rate DECIMAL(8,2), n INT, ac CHAR(1))
RETURNS BusType
BEGIN
  DECLARE b BusType;
  SET b = BusType();
  SET b.regNo = r;  SET b.make = mk;  SET b.model = md;  SET b.dailyRate = rate;
  SET b.seats = n;  SET b.hasAC = ac;
  RETURN b;
END;

INSERT INTO Trucks     VALUES (TruckType('DHA-T-1001', 'Tata', 'LPT 1613', 3500.00, 10.0, 2));
INSERT INTO SportsCars VALUES (SportsCarType('DHA-S-2001', 'Porsche', '911', 25000.00, 293, 'F'));
INSERT INTO Buses      VALUES (BusType('DHA-B-3001', 'Hino', 'AK1J', 9000.00, 40, 'T'));

A subtype's object has the supertype's attributes first, then its own, which is why each constructor sets regNo, make, model and dailyRate too. In Oracle, which this course uses, the same schema is written with CREATE TYPE vehicle_t AS OBJECT (…) NOT FINAL; and CREATE TYPE truck_t UNDER vehicle_t (…);. Oracle generates an attribute-value constructor automatically, so INSERT INTO Trucks VALUES (truck_t('DHA-T-1001', 'Tata', 'LPT 1613', 3500, 10, 2)); works without writing any function; a custom one is declared in the type as CONSTRUCTOR FUNCTION truck_t(…) RETURN SELF AS RESULT and implemented in CREATE TYPE BODY, assigning SELF.attr := … and ending with RETURN;.

Summary: A PL/SQL block is DECLARE / BEGIN / EXCEPTION / END. SELECT … INTO needs exactly one row (NO_DATA_FOUND, TOO_MANY_ROWS); := assigns; IF … ELSIF … END IF; DBMS_OUTPUT.PUT_LINE prints. A procedure (CREATE OR REPLACE PROCEDURE p(x IN type) IS … BEGIN … END; /) is called with EXEC and returns nothing; a function adds RETURN type and RETURN value and can be used in SQL (SELECT f() FROM dual). Triggers run by themselves; procedures and functions are called.
