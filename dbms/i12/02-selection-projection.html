Selection (σ) and Projection (π)

The two unary operators: σ picks rows, π picks columns. This chapter works through the slides' examples (one of which has a wrong output), shows how σ and π map to WHERE and SELECT DISTINCT, and answers the slides' two "are these equivalent?" questions.

1. Selection σ (slides 6–7)

Selection σc(R)
Returns the tuples of R that satisfy the condition c. The result has the same schema as R and at most as many tuples. The condition is checked on one tuple at a time.
Condition (predicate)
A Boolean expression built from attributes of R and constants with the comparisons =, <, ≤, >, ≥, <> (slide 6), combined with AND (∧), OR (∨) and NOT (¬).

Slide 6 writes the SQL and the RA side by side for the schema Students(sid, sname, gpa):

SELECT *
FROM Students
WHERE gpa > 3.5;

σgpa>3.5(Students)

The WHERE clause becomes the subscript of σ, and SELECT * means no column is removed, so there is no π. Two more examples from the slide: σSalary>40000(Employee) keeps the employees earning more than 40000, and σname='Smith'(Employee) keeps the employees named Smith. Text constants go in single quotes, numbers do not.

Slide 7's example, step by step

Slide 7 applies σSalary>40000 to a three-row Employee relation and shows a two-row result containing only Smith and Fred. That output is wrong: John earns 200000, and 200000 > 40000, so John also passes. The correct result contains all three employees. (The slide's output would be right for the condition Salary > 400000, which is probably what was meant.) Step through both:

Compound conditions

A selection condition may combine tests: σdept_name='Physics' ∧ salary>90000(instructor) keeps Physics instructors who earn more than 90000. Two laws follow directly from the definition (textbook §16.2.3), and the optimizer uses them all the time:

  • σc1 ∧ c2(R) = σc1(σc2(R)) = σc2(σc1(R)). A conjunction can be split into a cascade of selections in either order (slide 34 shows the "either order" part as a tree).
  • σc1 ∨ c2(R) = σc1(R) ∪ σc2(R). A disjunction is the union of the two selections.

2. Projection π (slides 8–9)

Projection πA1,…,An(R)
Keeps only the attributes A1, …, An of every tuple of R, then removes duplicate tuples (slide 8: "eliminates columns, then removes duplicates"). The output schema is (A1, …, An).

The slide's examples: πSSN,Name(Employee) has output schema Answer(SSN, Name); for Students, πsname,gpa(Students) corresponds to

SELECT DISTINCT sname, gpa
FROM Students;

The word DISTINCT matters. Without it SQL keeps duplicate rows (SQL works with bags), while π never does (RA works with sets, Chapter 1).

Slide 9's example: duplicates disappear

Slide 9's Employee has three employees, all named John, two of whom earn 200000. After keeping only Name and Salary, two tuples are identical, so π keeps one of them: the result has 2 tuples, not 3.

So a projection can only shrink a relation: if R is non-empty, 1 ≤ |πL(R)| ≤ |R|. If L contains a key of R, no two tuples can collide and |πL(R)| = |R| exactly. That is why projecting onto SSN (a key) never loses rows, while projecting onto Name can.

3. Operators compose (slides 10–11)

Because σ and π both return relations, they can be nested. Slide 10 asks how to write this query in RA:

SELECT DISTINCT sname, gpa
FROM Students
WHERE gpa > 3.5;

Slide 10: how do we represent this query in RA? Are the two expressions logically equivalent?

The standard translation reads the SQL from the inside out: FROM gives the relation, WHERE becomes σ, SELECT DISTINCT becomes π on top:

πsname,gpa(σgpa>3.5(Students))

The slide's second expression is σgpa>3.5(πsname,gpa(Students)). Yes, the two are equivalent. The projection keeps gpa, so the selection can still test it, and a row passes the test before the projection exactly when its projected copy passes it after. In general:

σc(πL(R)) = πL(σc(R)) whenever every attribute used in c is in L.

Slide 11: the same question for SELECT DISTINCT sid, sname … WHERE gpa > 3.5

The translation is πsid,sname(σgpa>3.5(Students)). The slide's alternative σgpa>3.5(πsid,sname(Students)) is not equivalent; in fact it is not even a valid expression. The inner projection throws gpa away, so the outer selection refers to an attribute that no longer exists. (The slide crosses out the ⇕ arrow for this reason.) Type select[gpa > 3.5](project[sid, sname](Students)) into the evaluator below to see it rejected.

The lesson: you may move σ above π only if π keeps every attribute σ needs. The safe order, and the one a translator produces, is σ first, π last.

Summary: σc(R) keeps the tuples satisfying c (WHERE); πL(R) keeps the attributes L and removes duplicates (SELECT DISTINCT). A SQL block translates to πselect-list(σwhere(from-relations)). σ and π commute only when π keeps the attributes σ tests.
