Modifying Rows with UPDATE

The UPDATE statement: which rows change (WHERE), how they change (SET, which may compute the new value from the old one), and how to choose the rows through another table. Worked through the slides' examples and three exam questions.

1. The UPDATE statement (slide 12)

UPDATE <table_name>
SET    <attribute_name1> = <v1>, <attribute_name2> = <v2>, …
WHERE  …;
UPDATE
Changes the values of some columns in the rows of one table for which the WHERE condition is TRUE. The SET clause lists one or more assignments column = expression, separated by commas. The expression may be a constant, NULL, or a formula using the row's current values (price = price - 100). Without WHERE, every row is changed.
UPDATE Student
SET    city = 'Austin', state = 'TX'
WHERE  id = 'S123456789';

John Doe moves to Austin: in the one row with that id, two columns change; the other columns and all other rows are untouched. Choosing the row by its primary key guarantees that at most one row changes.

Two rules about SET that are easy to get wrong:

  • All expressions use the old values. In SET a = b, b = a, both right-hand sides are computed from the row as it was before the statement, so the two values are swapped (unlike two assignments in C).
  • Assignments are separated by commas, not AND. SET city = 'Austin' AND state = 'TX' is a different (and in Oracle invalid) statement.

2. Manufacturer A buys manufacturer B (slide 13)

Change all products made by B so they are now made by A.

UPDATE Product
SET    maker = 'A'
WHERE  maker = 'B';

Only Product stores the maker, so one statement is enough: B's four products (1004, 1005, 1006, 2007) now belong to A. PC and Laptop refer to products by model, which has not changed. (This is the advantage of storing each fact in one place.)

3. Changing values computed from old values (slides 14–15)

For each laptop made by manufacturer B, add one inch to the screen size and subtract $100 from the price.

UPDATE Laptop
SET    screen = screen + 1, price = price - 100
WHERE  model IN (SELECT model
                 FROM   Product
                 WHERE  type = 'laptop'
                 AND    maker = 'B');

Laptop does not know who made a laptop, so the rows are chosen through Product, as in the DELETE examples: the subquery returns B's laptop models, {2007}. For that row, the new screen is the old screen plus 1 (13.3 → 14.3) and the new price the old price minus 100 (1429 → 1329).

BUET QBank · CSE 303 | L-3/T-1 | 2011–12 · 5 + 5 marks

A database schema consists of four relations: Product(maker, model, type), PC(model, speed, ram, hd, price), Laptop(model, speed, ram, hd, screen, price), Printer(model, color, type, price).

(a) Delete all laptops made by a manufacturer that does not make printers.
(b) Assume that manufacturer A bought manufacturer B. Change all products made by B so that they are now made by A.

Show worked answer

(a) This is slides 10–11. The laptop's facts are in Product (maker, type) and in Laptop (specifications); remove them from both. The makers of printers are SELECT maker FROM Product WHERE type = 'printer'.

DELETE FROM Product
WHERE  type = 'laptop'
AND    maker NOT IN (SELECT maker
                     FROM   Product
                     WHERE  type = 'printer');

DELETE FROM Laptop
WHERE  model NOT IN (SELECT model
                     FROM   Product
                     WHERE  type = 'laptop');

The first statement removes the laptop rows of makers without printers from Product (on the textbook data: A, B, F, G, models 2004–2010). The second then removes from Laptop every model that Product no longer lists as a laptop. The order matters: the second statement uses the cleaned Product. (Equivalently, delete from Laptop first with WHERE model IN (SELECT model FROM Product WHERE type = 'laptop' AND maker NOT IN (…printer makers…)), then from Product.)

(b) This is slide 13. The maker is stored only in Product:

UPDATE Product
SET    maker = 'A'
WHERE  maker = 'B';

PC, Laptop and Printer refer to products by model, which does not change, so nothing else needs updating. On the textbook data, 4 rows change (1004, 1005, 1006, 2007).

Note: the question bank deletes only from Laptop in (a). That leaves Product claiming that A, B, F and G still make laptops 2004–2010; delete from both tables as the slides do.

BUET QBank · CSE 215 | L-2/T-1 | 2024–25 · 18 marks (parts a and b)

Consider the following relational database schema: employee(employee_name, street, city), works(employee_name, company_name, salary), company(company_name, city), manages(employee_name, manager_name). Write SQL statements for the following:

(a) Give a 20% salary rise to employees who are managers.
(b) Delete all tuples in the works relation for employees of the company "Sonali Bank". Note that works.employee_name is a foreign key referencing employee(employee_name), manages.employee_name is a foreign key referencing employee(employee_name), manages.manager_name is a foreign key referencing employee(employee_name).
(c) Design a trigger such that whenever a manager's salary is updated, all employees managed by that manager receive a 10% salary increase.

Show worked answer

(a) Salaries are stored in works. An employee is a manager if their name appears as a manager_name in manages:

UPDATE works
SET    salary = salary * 1.2
WHERE  employee_name IN (SELECT manager_name
                         FROM   manages);

salary * 1.2 is a 20% rise computed from the old salary. A manager who manages several people appears several times in the subquery's result, but IN only asks whether the name is in the list, so each manager's row is raised once. (DISTINCT in the subquery is allowed but unnecessary.) A manages row whose manager_name is NULL (an employee with no manager) does no harm: that NULL is not equal to any employee name, so it raises nobody.

(b)

DELETE FROM works
WHERE  company_name = 'Sonali Bank';

The foreign keys all point from works and manages to employee. Deleting rows of works (a referencing, "child" table) can never violate them, because no table refers to works. The employee rows themselves are not deleted, so the employees still exist (they just no longer work at Sonali Bank), and their manages rows remain valid.

(c) needs a trigger, which belongs to Lecture 12 (Relational Algebra, Triggers); see that lecture's chapter on triggers for the full answer.

The bank's answers to (a) and (b) are correct.

Summary: UPDATE T SET c1 = e1, c2 = e2 WHERE cond changes columns of the rows where cond is TRUE; without WHERE, every row. Each expression may use the row's old values, and all are computed from the old row. Rows can be chosen through another table with IN (SELECT …). A fact stored in one place (the maker, in Product) needs one UPDATE.
