Deleting Rows with DELETE

The DELETE statement, with and without a WHERE clause; deleting rows chosen through another table with IN (SELECT …) and NOT IN (SELECT …); and why, when a fact is stored in two tables, the order of the two DELETE statements matters. Ends with a fully worked exam question that combines a bulk insert and a delete.

1. The DELETE statement (slide 7)

DELETE FROM <table_name>;                     -- unconditional
DELETE FROM <table_name> WHERE <condition>;   -- conditional
DELETE
Removes from one table every row for which the WHERE condition is TRUE. Without a WHERE clause it removes all rows; the table itself (its schema) remains, empty. DELETE removes whole rows: there is no "delete one column of a row" (set it to NULL with UPDATE instead).
DELETE FROM Student;                  -- every student is removed
DELETE FROM Student WHERE id = '121';  -- only the student with id 121

The WHERE clause works exactly as in a query: the condition is tested on each row, and rows where it is FALSE or UNKNOWN stay. A good habit before any DELETE is to run the same WHERE in a SELECT first, to see which rows will go. (In Oracle, a DELETE can be undone with ROLLBACK until it is committed.)

2. Delete all PCs with less than 100 GB hard disk (slides 8–9)

A PC's facts live in two tables: its specifications in PC, its maker and type in Product. Deleting "the PC" means deleting from both, so the slide uses two statements:

DELETE FROM Product
WHERE  model IN (SELECT model
                 FROM   PC
                 WHERE  hd < 100);

DELETE FROM PC
WHERE  hd < 100;
x IN (SELECT …)
The IN test of Lec 04, Chapter 7, with the list produced by a query (a subquery). The inner query runs first and returns a column of values; the condition is TRUE for rows whose x is one of them. Subqueries are taught fully in Lecture 11; here they are only used as lists.

The subquery returns the models with small disks, 1003 and 1013 (both 80 GB). The first statement removes those two rows from Product; the second removes the same two from PC.

Why the order of the two statements matters (worked answer)

Product has no hd column, so the first statement must find the models through PC. If PC were cleaned first, the subquery SELECT model FROM PC WHERE hd < 100 would then return nothing, and the Product rows for 1003 and 1013 would never be deleted. So: delete from the table that is used to find the rows last.

If PC.model were declared a foreign key referencing Product.model (Lecture 6), the slide's order would fail instead: Oracle refuses to delete a Product row while a PC row still refers to it (ORA-02292). Then you must delete from PC first and find the Product rows another way, for example DELETE FROM Product WHERE type = 'pc' AND model NOT IN (SELECT model FROM PC);, or declare the key ON DELETE CASCADE.

3. Delete all laptops made by a manufacturer that does not make printers (slides 10–11)

DELETE FROM Product
WHERE  type = 'laptop'
AND    maker NOT IN (SELECT maker
                     FROM   Product
                     WHERE  type = 'printer');

DELETE FROM Laptop
WHERE  model NOT IN (SELECT model
                     FROM   Product
                     WHERE  type = 'laptop');

Read the first statement inside out. The subquery lists the makers of printers: D, E and H. A laptop row is deleted if its maker is not in that list. The laptop makers are A, B, E, F and G, so the laptops of A, B, F and G go (models 2004–2010, seven rows) and E's laptops (2001–2003) stay.

The second statement then cleans Laptop: after the first statement, Product lists only 2001, 2002 and 2003 as laptops, so every Laptop row whose model is not among them is deleted. Again the order matters: it relies on Product already being cleaned.

The subquery in the first statement reads the same table, Product, that is being deleted from. As with INSERT … SELECT, SQL evaluates the condition for every row against the table as it was before the statement (textbook §6.5.2), then deletes; the result does not depend on the order in which rows are visited.

BUET QBank · CSE 215 | L-2/T-2 | 2021–22 · 10 marks

Consider the following relational database schema:

Product(maker, model, type), PC(model, speed, ram, hd, price), Laptop(model, speed, ram, hd, screen, price)

Write SQL DML queries to reflect the following:
(a) Insert the fact that for every PC there is a laptop with the same manufacturer, speed, ram, and hard disk, a 17-inch screen, a model number 1100 greater and a price $400 more.
(b) Delete all laptops made by a manufacturer that does not make PCs.

Show worked answer

(a) The laptop's specifications go into Laptop and the (maker, model, type) fact into Product, because the manufacturer is stored only in Product. Two bulk inserts:

INSERT INTO Product (maker, model, type)
SELECT maker, model + 1100, 'laptop'
FROM   Product
WHERE  type = 'pc';

INSERT INTO Laptop (model, speed, ram, hd, screen, price)
SELECT model + 1100, speed, ram, hd, 17, price + 400
FROM   PC;

Each SELECT produces one row per PC; its columns line up with the listed target columns. Inserting into Product first is required if Laptop.model is a foreign key referencing Product.model (the parent row must exist before the child row). On the textbook data, 13 rows are added to each table (models 2101–2113).

(b) "Makers that make PCs" = SELECT maker FROM Product WHERE type = 'pc'. A laptop is deleted if its maker is not in that set. Delete from Laptop first (while Product still says which models are laptops of which maker), then from Product:

DELETE FROM Laptop
WHERE  model IN (SELECT model
                 FROM   Product
                 WHERE  type = 'laptop'
                 AND    maker NOT IN (SELECT maker
                                      FROM   Product
                                      WHERE  type = 'pc'));

DELETE FROM Product
WHERE  type = 'laptop'
AND    maker NOT IN (SELECT maker
                     FROM   Product
                     WHERE  type = 'pc');

On the textbook data the PC makers are A, B, C, D and E; the laptop makers F and G make no PCs, so laptops 2008, 2009 and 2010 are deleted from both tables (if (a) has been run first, its new laptops belong to PC makers and all stay).

Note: the question bank's answer for (b) deletes only from Laptop and leaves the three Product rows behind (it mentions this as optional). Since "the laptop" is described by both tables, delete from both, as slides 10–11 do. Its inner query also omits type = 'laptop'; that is harmless only because Laptop contains only laptop models.

Summary: DELETE FROM T WHERE cond removes the rows where cond is TRUE; without WHERE it empties the table but keeps it. Rows to delete can be chosen through another table with col IN (SELECT …) or NOT IN (SELECT …). When a fact is spread over two tables, delete from both, and delete last from the table the other statement uses to find its rows (or, with foreign keys, children first).
