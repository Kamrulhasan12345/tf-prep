INSERT, Bulk Insert and Copying a Table

Lecture 5 covers the three statements that change data. This chapter is about adding rows: one at a time with VALUES, many at once by inserting the result of a query, and creating a whole new table from a query (CREATE TABLE … AS SELECT), which is how a table is copied, with or without its data.

1. The products database

All of Lecture 5 works on the textbook's products database (Garcia-Molina, Ullman, Widom, Figs. 2.20–2.21). The slides show part of it; the playground holds all of it:

  • Product(maker, model, type): who makes each model, and whether it is a pc, laptop or printer. model is the key, unique across all product types.
  • PC(model, speed, ram, hd, price): speed in GHz, RAM in MB, hard disk in GB.
  • Laptop(model, speed, ram, hd, screen, price): as PC, plus screen size in inches.
  • Printer(model, color, type, price): color is 'T' or 'F'; type is laser or ink-jet.

Note that a model's maker is stored only in Product. To know who made laptop 2007 you must look it up in Product: this is why several statements in this lecture contain a query inside them.

2. INSERT … VALUES, reviewed (slide 2)

INSERT INTO <table_name> [(a1, a2, …, an)] VALUES (v1, v2, …, vn);

A full insert gives a value for every attribute in declaration order; a partial insert lists the attributes it gives, and the rest become NULL or their DEFAULT (Lec 03, Chapter 6). One INSERT … VALUES adds exactly one row.

INSERT INTO Student VALUES ('S123456789', 'John', 'Doe', 'Houston', 'TX');
INSERT INTO Student VALUES ('S111111111', 'Mary', 'Jones', 'Houston', 'TX');
INSERT INTO Student (id, first_name, last_name) VALUES ('S987654321', 'Jane', 'Smith');

3. Bulk insert: saving a query's result (slide 3)

INSERT INTO … SELECT
Inserts every row returned by a query into an existing table. The query replaces the VALUES list: 
INSERT INTO <existing_table_name>
SELECT …;

INSERT INTO <existing_table_name> (a1, a2, …, an)
SELECT …;
The query must return as many columns as the table has (or as are listed), in the same order and of compatible types. It may return zero, one or many rows.
CREATE TABLE … AS SELECT
Creates a new table whose columns are the query's output columns (same names and types) and fills it with the query's rows: 
CREATE TABLE <new_table_name> AS
SELECT …;
Oracle calls this a CTAS statement (Create Table As Select).

4. Worked example: a laptop for every PC (slides 4–5)

Insert the fact that for every PC there is a laptop with the same manufacturer, speed, ram and hard disk, a 17-inch screen, a model number 1100 greater and a price $500 more.

Two tables must change: Laptop gets the specifications, and Product gets the (maker, model, 'laptop') facts, because the maker is stored only there. Each is one bulk insert:

INSERT INTO Laptop
SELECT model + 1100, speed, ram, hd, 17, price + 500
FROM   PC;

INSERT INTO Product
SELECT maker, model + 1100, 'laptop'
FROM   Product
WHERE  type = 'pc';

How to read the first statement: the SELECT runs over PC and computes, for every PC row, one output row whose six values line up with Laptop's six columns (model, speed, ram, hd, screen, price). The constant 17 fills screen for every row. A SELECT list may contain expressions and constants, not only column names. The second statement takes the maker of every PC from Product and adds a laptop row with the shifted model number.

Two questions the slides raise implicitly (worked answers)

Does the second statement see its own new rows? It reads Product and inserts into Product. SQL's rule (textbook §6.5.1) is that the query is evaluated completely before any row is inserted. So the 13 new laptop rows are not themselves read by WHERE type = 'pc' (they are laptops anyway), and in general an INSERT … SELECT on the same table never loops on its own output.

Can the new model numbers clash with existing ones? PCs are 1001–1013, so the new laptops are 2101–2113. Existing laptops are 2001–2010, so there is no clash here. If some PC model + 1100 already existed in Laptop or Product, the primary key would reject the whole INSERT statement (Oracle undoes all rows of a failed statement).

5. Copying a table (slide 6)

Create a duplicate copy of the Laptop table.

CREATE TABLE Laptop2 AS
SELECT *
FROM   Laptop;

SELECT * returns every column and every row, so Laptop2 gets Laptop's columns (names and types) and a copy of all its rows. The copy is independent: later changes to Laptop do not affect Laptop2.

To copy only the schema (the columns, no rows), add a condition that no row can satisfy. The table is still created from the query's column list, but the query returns zero rows:

CREATE TABLE Laptop3 AS
SELECT *
FROM   Laptop
WHERE  1 = 0;

Two details matter in exam answers:

  • Constraints are not copied, except NOT NULL. The new table has no primary key, no UNIQUE, no foreign keys, no indexes and no defaults. Add them afterwards with ALTER TABLE if needed.
  • A partial copy uses an ordinary query: CREATE TABLE BigLaptop AS SELECT model, screen FROM Laptop WHERE screen >= 17;

DB QB · 21-22 3a · 5 marks  |  BUET QBank · CSE 215 | L-2/T-2 | 2021–22 · 5 marks  |  BUET QBank · CSE 303 | L-3/T-1 | 2015–16 · part (d) of a 19-mark question

Show SQL command to create a duplicate copy of table named Student. What the command will be if we just want to copy the schema not the data of Student table?

(CSE 303 2015–16 (d) asks the same for a table R: "Show the DDL to create a copy of a table R including the schema. What is the DDL if we just want to copy the schema and not the tuples?")

Show worked answer

Full copy (schema and data):

CREATE TABLE Student_Copy AS
SELECT * FROM Student;

The SELECT returns all columns and all rows of Student; CREATE TABLE … AS creates Student_Copy with the same column names and data types and inserts those rows.

Schema only (no data):

CREATE TABLE Student_Schema AS
SELECT * FROM Student
WHERE  1 = 0;

The condition 1 = 0 is false for every row, so the query returns no rows; the table is still created from the query's column list, so it has Student's columns and is empty.

Note: in Oracle only the columns, their data types and NOT NULL constraints are copied. Primary keys, UNIQUE, CHECK and foreign-key constraints, defaults, indexes and triggers are not; re-create them with ALTER TABLE if they are needed. For table R the commands are the same with R in place of Student.

(The question bank also mentions CREATE TABLE … LIKE and SELECT … INTO. Those are MySQL/PostgreSQL and SQL Server forms; Oracle does not support them.)

Summary: INSERT … VALUES adds one row. INSERT INTO T [(cols)] SELECT … adds every row of a query; its columns must line up with T's, and may be expressions or constants. The query is evaluated fully before rows are inserted. CREATE TABLE T AS SELECT … creates and fills a new table: SELECT * copies a table, and WHERE 1 = 0 copies only its columns. Only columns, types and NOT NULL are copied, not keys or other constraints.
