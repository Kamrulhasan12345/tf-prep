UNION, INTERSECT and MINUS

Some questions combine the answers of two separate queries: "PCs or laptops", "both PCs and laptops", "laptops but not PCs". SQL's set operators do this. This chapter introduces the computer-products database used in the rest of the course, explains union compatibility, and works the three questions of slide 24 with a Venn-diagram animation.

1. The computer-products database (slide 24)

From here on the slides use a database of computer products, taken from the course textbook (Garcia-Molina, Ullman and Widom, Exercise 2.4.1):

Product (maker, model, type)                 -- type is 'pc', 'laptop' or 'printer'
PC      (model, speed, ram, hd, price)
Laptop  (model, speed, ram, hd, screen, price)
Printer (model, color, type, price)        -- used from Lecture 10 on

Product says who makes each model and what kind of product it is. PC, Laptop and Printer hold the technical details, one row per model; their model is a foreign key to Product.model. Model numbers are unique across all makers and types. Speed is in GHz, ram in MB, hd in GB, screen in inches. The playgrounds load the textbook's full sample data: 30 products from 8 makers (A to H), 13 PCs, 10 laptops and 7 printers.

Slide 23 is a joke picture: two photos of the same actor, combined with ∪ and with ∩. It is there to fix the two ideas before the definitions: a union puts together everything from both sides, an intersection keeps only what both sides have in common.

2. Union (slides 25–26)

Union, A ∪ B (SQL: UNION)
All rows that are in the result of the first query, or of the second, or of both. Duplicates are removed (Chapter 6 explains UNION ALL, which keeps them).
Union-compatible
Two query results can be combined by UNION, INTERSECT or MINUS only if they have the same number of columns and the corresponding columns have compatible types (slide 25: "tables must be compatible ... have the same attributes"). The result takes its column names from the first query.

Find the model number and price of all PCs and Laptops made by manufacturer 'B'. PCs and laptops live in different tables, so we need one join per table and then glue the two answers together (slide 26):

SELECT PC.model, PC.price
FROM   Product, PC
WHERE  Product.model = PC.model
AND    Product.maker = 'B'
UNION
SELECT Laptop.model, Laptop.price
FROM   Product, Laptop
WHERE  Product.model = Laptop.model
AND    Product.maker = 'B';

Both halves return (model, price), so they are union-compatible. Note the prefixes: model is a column of Product and of PC, so it must be qualified. Maker B makes PCs 1004, 1005, 1006 and laptop 2007, so the answer has 4 rows. We could not have written this with a single join of Product, PC and Laptop: a product is never both a PC and a laptop, so such a join would return nothing.

3. Intersection (slides 27–28)

Intersection, A ∩ B (SQL: INTERSECT)
The rows that appear in the results of both queries (duplicates removed).

Find those manufacturers that sell both PCs and Laptops.

SELECT maker FROM Product WHERE type = 'pc'
INTERSECT
SELECT maker FROM Product WHERE type = 'laptop';

The first query lists makers of PCs (A, B, C, D, E), the second makers of laptops (A, B, E, F, G). The makers in both are A, B, E.

Question (worked answer): why not just write WHERE type = 'pc' AND type = 'laptop'?

Because WHERE tests one row at a time, and no single Product row has type equal to both 'pc' and 'laptop'. The condition is always false and the query returns nothing. "Sells both" is a fact about two different rows of the same maker. INTERSECT compares the two sets of makers; the same question can also be answered with a self-join (FROM Product p1, Product p2 WHERE p1.maker = p2.maker AND p1.type = 'pc' AND p2.type = 'laptop', with DISTINCT), with IN, or with EXISTS (Lecture 11).

4. Difference (slides 29–30)

Difference, A − B (Oracle: MINUS; standard SQL: EXCEPT)
The rows in the result of the first query that are not in the result of the second. Order matters: A − B ≠ B − A.

Find those manufacturers that sell Laptops, but not PCs.

SELECT maker FROM Product WHERE type = 'laptop'
MINUS
SELECT maker FROM Product WHERE type = 'pc';

Laptop makers {A, B, E, F, G} minus PC makers {A, B, C, D, E} = {F, G}. Oracle calls this operator MINUS; the SQL standard (and PostgreSQL, SQL Server, SQLite) calls it EXCEPT, and Oracle 21c and later accept EXCEPT as a synonym. In the exam, write MINUS.

Rules that apply to all three operators

  • Each side is a complete SELECT with its own FROM and WHERE. The operator sits between them.
  • The two sides must be union-compatible; Oracle reports ORA-01789: query block has incorrect number of result columns otherwise.
  • An ORDER BY may appear only once, at the very end, and sorts the combined result.
  • UNION, INTERSECT and MINUS remove duplicates (Chapter 6). In Oracle they all have equal precedence and are evaluated left to right; use parentheses to force another order.

Exam questions

DB QB · 20-21 5a · 15 marks  |  BUET QBank · CSE 215 | L-2/T-2 | 2020–21 · 24 marks

You have been analysing data from a social networking site and have derived the following relation which captures topics discussed by various users: Discussion(user1, user2, topic). The relation contains a tuple (u1, u2, t) every time a user u1 discussed a topic t with user u2. To avoid duplicate entries, user1 always precedes user2 in alphabetical order.

(a) Write a SQL query that returns all topics discussed by Pori and Himu but not discussed by Pori and Misir Ali.
(b) Write a SQL query that returns the number of topics discussed by more than 10 pairs of users.

Show worked answer

Reading the schema. Each pair is stored with the alphabetically smaller name in user1. 'Himu' < 'Pori', so their discussions are stored as user1 = 'Himu', user2 = 'Pori'. 'Misir Ali' < 'Pori', so those are stored as user1 = 'Misir Ali', user2 = 'Pori'. Also note "a tuple every time": the same (pair, topic) can occur many times.

(a) A set difference: topics of the first pair minus topics of the second pair. MINUS also removes the repeated topics.

SELECT topic FROM Discussion
WHERE  user1 = 'Himu' AND user2 = 'Pori'
MINUS
SELECT topic FROM Discussion
WHERE  user1 = 'Misir Ali' AND user2 = 'Pori';

(b) For each topic, count the distinct pairs that discussed it, keep the topics with more than 10 pairs, then count those topics. Grouping and HAVING are taught in Lecture 10; the idea is "one group per topic, then a condition on the group".

SELECT COUNT(*) AS num_topics
FROM  (SELECT topic
       FROM  (SELECT DISTINCT user1, user2, topic FROM Discussion)
       GROUP BY topic
       HAVING COUNT(*) > 10);

The innermost DISTINCT reduces repeated discussions of the same pair and topic to one row, so COUNT(*) per topic counts pairs, not discussions. An equivalent HAVING is COUNT(DISTINCT user1 || '/' || user2) > 10 on the raw table.

Note: the question bank's answer for (b) groups the raw table and uses HAVING COUNT(*) > 10. That counts discussions, and the question says there is a tuple every time a pair discusses a topic, so a single pair talking about one topic eleven times would wrongly count. It also writes ) AS PopularTopics, and Oracle does not allow AS before a subquery alias. On the sample data below (invented: 8 users, 4 topics), the topic "exams" has 16 tuples but only 9 distinct pairs: the correct answer is 2 (cricket, politics), the bank's query gives 3.

Summary: UNION, INTERSECT and MINUS (EXCEPT in standard SQL) combine the results of two complete queries that are union-compatible (same number of columns, compatible types). UNION gives rows in either, INTERSECT rows in both, MINUS rows in the first but not the second. They answer "or", "both" and "but not" questions that span different rows or different tables, which a single WHERE clause cannot express. All three remove duplicates.
