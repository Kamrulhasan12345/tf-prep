Tuple Variables and Self-Joins

When two joined tables have a column with the same name, or when a table must be joined with itself, we need names for the rows we are talking about. These names are tuple variables (aliases). This chapter answers slide 21's "which address?", explains slide 21's Oracle note "no AS", and animates slide 22's self-join, including the trap of listing each pair twice.

1. Which address? (slides 20–21)

The schema now is

Person  (pname, address, worksfor)
Company (cname, address)

Both tables have a column called address. The task on slide 20: find those persons whose address is the same as the company address (the company they work for). Slide 21's first attempt,

SELECT pname, address
FROM   Person, Company
WHERE  worksfor = cname;

does not run. With two tables in FROM, address could mean Person.address or Company.address, and Oracle refuses with ORA-00918: column ambiguously defined. The fix is to qualify it with the table name, which also lets us state the real condition (person's address = company's address):

SELECT Person.pname, Company.address
FROM   Person, Company
WHERE  Person.worksfor = Company.cname
AND    Person.address = Company.address;

Slide 21 stops at the join condition and only shows how to qualify columns; the extra line AND Person.address = Company.address is what the task of slide 20 actually asks for.

2. Tuple variables (aliases)

Writing the full table name before every column is tiring. SQL lets us give each table in FROM a short name:

Tuple variable (table alias, correlation name)
A name declared after a table in the FROM clause. In the nested-loop meaning of a query (Chapter 2), it is the loop variable that ranges over that table's rows: x stands for "the current Person row".
SELECT x.pname, y.address
FROM   Person x, Company y            -- Oracle: no AS here
WHERE  x.worksfor = y.cname
AND    x.address = y.address;

The slide writes Person AS x, Company AS y and marks it with the bubble "No 'AS' in Oracle". That is correct and worth remembering for exams: standard SQL (and PostgreSQL, MySQL, SQLite) allows AS before a table alias, but Oracle gives ORA-00933: SQL command not properly ended. Oracle does allow AS before a column alias (SELECT price*quantity AS sales). (The playground runs on SQLite, which accepts both forms, so it will not catch this mistake for you.)

3. Joining a table with itself (slide 22)

Find those pairs of persons who have the same addresses.

Now both rows we compare come from Person. One loop variable cannot hold two rows at once, so we name Person twice with two tuple variables. Each acts as an independent copy of the table:

SELECT x.pname, y.pname, x.address
FROM   Person x, Person y
WHERE  x.pname <> y.pname
AND    x.address = y.address;
Self-join
A join of a table with itself, using two tuple variables. It compares rows of the same table with each other: pairs of persons, an employee and his manager, two PCs with the same speed.

Two remarks on slide 22. First, the slide prints the not-equal operator as < > with a space; that is a typesetting slip, and in SQL it must be written <> (or !=) with no space. Second, the condition x.pname <> y.pname stops a person from being paired with himself, but it still lets each pair appear twice, once in each order. Watch the animation with our sample data (invented addresses): Karim, Nabila and Mitu share "45 Dhanmondi".

Question (worked answer): how do we list each pair only once?

Replace <> by <. Of the two orderings (Karim, Nabila) and (Nabila, Karim), exactly one has the first name alphabetically smaller, so exactly one survives; and x.pname < y.pname is false when x and y are the same row, so self-pairs are still excluded.

SELECT x.pname, y.pname, x.address
FROM   Person x, Person y
WHERE  x.pname < y.pname
AND    x.address = y.address;

With three people at one address there are 3 · 2 = 6 ordered pairs but only 3 unordered pairs: (Karim, Mitu), (Karim, Nabila), (Mitu, Nabila). The same trick answers the classic exam question "find pairs of PC models with the same speed and RAM; list each pair once" (p1.model < p2.model).

Self-join on a foreign key: employees and their managers

The most common self-join in exams uses a foreign key that points to its own table. In the question bank's HR schema, EMPLOYEE has a column MANAGERID that holds the EMPLOYEEID of the employee's manager. To print each employee next to the manager's name, give EMPLOYEE two roles:

SELECT e.LASTNAME AS employee, m.LASTNAME AS manager
FROM   EMPLOYEE e, EMPLOYEE m          -- e = the employee, m = the manager
WHERE  e.MANAGERID = m.EMPLOYEEID;

Read the join condition as "e's manager is m". Mixing up the roles (writing e.EMPLOYEEID = m.MANAGERID but printing the wrong side) is exactly the bug in a question-bank "find the fault" question, worked in Lecture 10, Chapter 3. King has no manager (MANAGERID is NULL), so he does not appear: NULL = anything is never true. Lecture 09's outer joins can keep him.

Summary: when two FROM tables share a column name, qualify it (Person.address). A tuple variable (alias) is a short name for a table in FROM and is the loop variable of the nested-loop meaning; Oracle forbids AS before a table alias. A self-join names one table twice with two aliases to compare its rows with each other. Use <> to exclude self-pairs and < to list each unordered pair once. A foreign key to the same table (MANAGERID → EMPLOYEEID) is joined the same way, with one alias per role.
