Sets, Bags and the ALL Keyword

SELECT keeps duplicates, but UNION, INTERSECT and MINUS throw them away. This chapter explains why, computes the slides' T1/T2 example by counting, introduces UNION ALL, INTERSECT ALL and EXCEPT ALL with their a + b, min(a, b) and max(0, a − b) rules, and sorts out what Oracle actually supports. A small tool lets you try your own bags.

1. Set operators remove duplicates (slide 31)

Recall from Chapter 2 that a SQL table or query result is a bag: the same row may occur several times. Slide 31 points out an asymmetry: unlike the SELECT operator, UNION, INTERSECT and MINUS remove duplicates. They convert bags to sets first and then return sets, not bags.

The slide's example uses two one-column tables:

T1: 1, 2, 2, 2, 3, 4, 4
T2: 2, 3, 4, 4, 4, 5

Converted to sets, T1 = {1, 2, 3, 4} and T2 = {2, 3, 4, 5}. Then

QueryResult (slide 31)Why
T1 UNION T21, 2, 3, 4, 5every value in either set, once
T1 INTERSECT T22, 3, 4values in both sets
T1 MINUS T21values of T1's set not in T2's set

Why the difference between SELECT and the set operators? Removing duplicates needs a sort or a hash of the whole result, which is expensive, so plain SELECT does not do it unless you ask (DISTINCT). The set operators must compare rows between two results anyway, and their natural definitions come from set theory, so the SQL standard defines them on sets by default.

2. Keeping duplicates with ALL (slides 32–35)

If you want duplicates you add the keyword ALL. The bag versions are defined by counting. Suppose a value appears a times in the first result and b times in the second:

OperatorTimes the value appears in the resultSlide
UNION ALLa + b33
INTERSECT ALLmin(a, b)34
EXCEPT ALL (MINUS ALL)max(0, a − b)35

Think of the values as physical cards. UNION ALL pours both piles together. INTERSECT ALL pairs a card from one pile with an equal card from the other and keeps one card per pair. EXCEPT ALL lets each card of the second pile cancel one equal card of the first; whatever is left of the first pile is the answer (never fewer than zero).

So slide 32's results are T1 UNION ALL T2 = 1, 2, 2, 2, 2, 3, 3, 4, 4, 4, 4, 4, 5 (13 values = 7 + 6), T1 INTERSECT ALL T2 = 2, 3, 4, 4, and T1 EXCEPT ALL T2 = 1, 2, 2.

Slides 33–35 apply the same rules to the computer database. For example

SELECT maker FROM Product WHERE type = 'pc'
UNION ALL
SELECT maker FROM Product WHERE type = 'laptop';

lists each maker once per PC and once per laptop it makes: A appears 3 + 3 = 6 times, B 3 + 1 = 4 times, and so on (23 rows in total, one per PC and laptop). With INTERSECT ALL, A would appear min(3, 3) = 3 times and B min(3, 1) = 1 time; with EXCEPT ALL, A would appear max(0, 3 − 3) = 0 times and B max(0, 3 − 1) = 2 times.

3. What Oracle supports (slide 36)

Slide 36: Oracle doesn't support INTERSECT ALL and MINUS ALL. Only UNION ALL is supported. That is true of the Oracle versions this course has used (up to Oracle 19c), and it is the answer expected in the exam. For completeness: Oracle 21c (2021) added INTERSECT ALL, MINUS ALL and EXCEPT ALL. Note also that the slides write EXCEPT ALL, the standard SQL name, because Oracle never had a MINUS ALL to show. The playground's SQLite engine likewise supports only UNION ALL.

When a bag intersection or difference is needed in an Oracle version without them, a standard trick is to number the copies of each value with ROW_NUMBER() (an analytic function, see beyond the slides), so that the second 4 becomes the row (4, 2). Those numbered rows are all distinct, so plain INTERSECT / MINUS on them behave exactly like the ALL versions:

-- T1 INTERSECT ALL T2, written without INTERSECT ALL
SELECT x FROM (
    SELECT x, ROW_NUMBER() OVER (PARTITION BY x ORDER BY x) AS copy FROM T1
    INTERSECT
    SELECT x, ROW_NUMBER() OVER (PARTITION BY x ORDER BY x) AS copy FROM T2
) ORDER BY x;

Summary: SELECT returns bags, but UNION, INTERSECT and MINUS first turn both inputs into sets and return a set. Adding ALL keeps duplicates by counting: UNION ALL gives a + b copies, INTERSECT ALL min(a, b), EXCEPT ALL max(0, a − b). Oracle (up to 19c, as the slides say) supports only UNION ALL; INTERSECT ALL and MINUS ALL can be emulated by numbering the copies with ROW_NUMBER().
