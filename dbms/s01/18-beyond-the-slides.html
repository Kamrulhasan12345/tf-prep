Exam Topics Beyond the Slides: Fourth Normal Form and the Normal-Form Hierarchy

The slides mention 4NF only in passing (“we will not cover in details”), and the syllabus stops at §3.6.2. One exam question asks for BCNF, 3NF and 4NF and how they relate, so this chapter gives the minimum needed: MVD rules, the 4NF definition and decomposition, and the textbook's comparison table.

1. A few rules for MVDs (book §3.6.3)

  • Trivial MVDs. X ↠ Y holds in every relation if Y ⊆ X, or if X ∪ Y is all of R's attributes (swapping the Y-part of two tuples that agree on X just swaps the tuples).
  • FD promotion. Every FD X → Y is an MVD X ↠ Y (Chapter 15).
  • Complementation. If X ↠ Y, then X ↠ Z where Z is all attributes not in X or Y. For AvailableShirts, shirt_code ↠ size gives shirt_code ↠ color.
  • Transitivity holds for MVDs, but splitting does not: name ↠ street city does not give name ↠ street (a street belongs with its city).

2. Fourth normal form (book §3.6.4)

4NF
R is in 4NF if, whenever X ↠ Y is a nontrivial MVD, X is a superkey. It is the BCNF condition applied to MVDs. Keys are still defined by FDs only.

Since every FD is an MVD, a 4NF relation has no BCNF violation either: 4NF ⇒ BCNF ⇒ 3NF. AvailableShirts is in BCNF but not 4NF: shirt_code ↠ size is nontrivial (shirt_code ∪ size is not all of R, and size ⊄ shirt_code), and shirt_code is not a superkey.

Decomposition into 4NF (Algorithm 3.33) mirrors BCNF: find a 4NF violation X ↠ Y; split R into R₁ = X ∪ Y and R₂ = X ∪ (R − X − Y); find the dependencies of each piece and repeat. The MVD itself guarantees the join is lossless. For AvailableShirts: violation shirt_code ↠ size gives (shirt_code, size) and (shirt_code, color): slide 61's decomposition. In each piece the remaining MVD covers all attributes, so it is trivial and both pieces are in 4NF.

All three decompositions are lossless. In practice designers aim for BCNF, fall back to 3NF when BCNF would lose an FD they must enforce, and check for independent multivalued facts (4NF) separately.

BUET QBank · CSE 303 | L-3/T-1 | 2010–11 · 17 marks

Define BCNF, 3NF, and 4NF. Describe relationships among these normal forms.

Show worked answer

BCNF: R is in BCNF if for every nontrivial FD X → Y on R, X is a superkey of R. Example: Movies2(title, year, length, genre, studioName) with key {title, year}.

3NF: R is in 3NF if for every nontrivial FD X → Y, either X is a superkey or every attribute of Y − X is prime (a member of some candidate key). Example in 3NF but not BCNF: Bookings(title, theatre, city) with theatre → city and title city → theatre (city is prime).

4NF: R is in 4NF if for every nontrivial MVD X ↠ Y (Y ⊄ X and X ∪ Y ≠ R), X is a superkey. Example in BCNF but not 4NF: AvailableShirts(shirt_code, size, color) with shirt_code ↠ size; it has no nontrivial FD (so BCNF), but shirt_code is not a superkey. Its 4NF decomposition is (shirt_code, size), (shirt_code, color).

Relationships:

  • Containment: every 4NF relation is in BCNF (an FD is a special MVD, so a BCNF violation would be a 4NF violation), and every BCNF relation is in 3NF (its first clause already holds). 4NF ⊂ BCNF ⊂ 3NF; the examples above show both inclusions are strict.
  • Redundancy: 3NF may keep some FD redundancy (theatre → city repeats the city); BCNF removes all redundancy caused by FDs; only 4NF also removes redundancy from independent multivalued facts.
  • Decomposition: all three can be reached by lossless decompositions. 3NF synthesis always preserves FDs; BCNF and 4NF decompositions may lose some.

Summary: 4NF requires every nontrivial MVD to have a superkey on the left; it removes the redundancy of independent set-valued facts that BCNF misses, and is reached by splitting on a violating MVD X ↠ Y into XY and X(R − X − Y). 4NF ⊂ BCNF ⊂ 3NF; only 3NF guarantees FD preservation, only 4NF removes MVD redundancy.
