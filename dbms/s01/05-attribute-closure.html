The Closure of a Set of Attributes

The closure X⁺ is everything that X determines. It is the single most useful computation in design theory: it decides whether an FD follows, whether a set is a key, and whether a relation is in BCNF. This chapter gives the algorithm, animates the slides' example, and provides a calculator for your own FDs.

1. Definition (slide 24)

Closure {A₁, …, Aₙ}⁺
Given a set of attributes {A₁, …, Aₙ} and a set S of FDs, the closure {A₁, …, Aₙ}⁺ is the set of all attributes B such that every relation satisfying the FDs in S also satisfies A₁A₂…Aₙ → B. In words: all attributes that A₁…Aₙ functionally determine, given S.

A₁, …, Aₙ are always in their own closure, because A₁A₂…Aₙ → Aᵢ is a trivial FD. Think of X⁺ as “if I know the values of X in a tuple, which other values in that tuple am I forced to know?”

2. The algorithm (slide 25)

closure(X = {A₁, …, Aₙ}, S):
  Step 1. Split the FDs of S so each has one attribute on the right side.
  Step 2. X⁺ := {A₁, …, Aₙ}.
  Step 3. Repeatedly find an FD  B₁B₂…Bₘ → C  such that
            all of B₁, …, Bₘ are in X⁺  but  C is not;
          add C to X⁺.
  Step 4. When no FD can add anything, X⁺ is the answer.

Why it stops. Each round adds at least one attribute and nothing is ever removed. R has finitely many attributes, so after at most |R| additions no FD can fire.

Why it is right (intuition). Every addition is a transitivity step: X determines all of B₁…Bₘ, and B₁…Bₘ determines C, so X determines C. Conversely, when the algorithm stops, one can build a two-tuple instance that agrees exactly on X⁺ and differs elsewhere; it satisfies every FD in S, so X determines nothing outside X⁺. (The full proof is book §3.2.5, outside the syllabus.)

3. Slide 26's example

Relation with attributes A, B, C, D, E, F and FDs AB → C, BC → AD, D → E, CF → B. Compute {A, B}⁺.

  • Step 1: split BC → AD into BC → A and BC → D. S = {AB → C, BC → A, BC → D, D → E, CF → B}.
  • Step 2: X = {A, B}.
  • Step 3: AB → C adds C, X = {A, B, C}. BC → A adds nothing (A is already in). BC → D adds D, X = {A, B, C, D}. D → E adds E, X = {A, B, C, D, E}. CF → B can never fire: F is not in X.
  • Step 4: {A, B}⁺ = {A, B, C, D, E}.

4. Does an FD follow? (slide 27)

To test whether A₁A₂…Aₙ → B follows from S: compute {A₁, …, Aₙ}⁺. If it contains every attribute of B, the FD follows; otherwise it does not.

Slide 27: test AB → D and D → A (FDs AB → C, BC → AD, D → E, CF → B)

AB → D: {A, B}⁺ = {A, B, C, D, E} contains D, so AB → D follows. The chain is AB → C, then BC → D.

D → A: {D}⁺: start with D; D → E adds E; no other FD has its left side inside {D, E}. {D}⁺ = {D, E}, which does not contain A, so D → A does not follow. Concretely, the two tuples (a₁, b, c, d, e, f) and (a₂, b′, c′, d, e, f′) agree exactly on D and E, satisfy all four FDs (check: no FD's left side is shared by them except D → E, which they obey), and differ on A.

Try both tests in the tool: put AB -> D or D -> A into the “Optional” box. Chapter 6 uses the same closure to find keys.

DB QB · 17-18 7a · 10 marks  |  BUET QBank · CSE 215 | L-2/T-2 | 2017–18 · 10 marks

Write the steps to compute the closure of a set of attributes with respect to a set of functional dependencies (FD). Let us consider a relation with attributes A, B, C, D, E, F. Suppose that this relation has the FD's: AB → C, BC → AD, D → E, CF → B. Find the closure of {A, B}, that is {A, B}⁺.

Show worked answer

Steps (input: a set of attributes X and a set S of FDs):

  1. Split every FD in S so that its right side is a single attribute.
  2. Initialize X⁺ = X.
  3. Repeatedly look for an FD B₁…Bₘ → C with all B's in X⁺ and C not in X⁺; add C to X⁺.
  4. Stop when no FD can add an attribute; the current X⁺ is the closure. (It terminates because X⁺ only grows and R is finite.)

Computation. Split: S = {AB → C, BC → A, BC → D, D → E, CF → B}.

RoundFD usedReasonX⁺
start––{A, B}
1AB → CA, B ∈ X⁺{A, B, C}
2BC → DB, C ∈ X⁺ (BC → A adds nothing){A, B, C, D}
3D → ED ∈ X⁺{A, B, C, D, E}
4noneCF → B needs F, which is never added{A, B, C, D, E}

{A, B}⁺ = {A, B, C, D, E}. Since F is missing, {A, B} is not a superkey of R.

BUET QBank · CSE 303 | L-3/T-1 | 2016–17 · 6 marks

Given a set F of functional dependencies on r₁(A, B, C, G, H, I): A → B, A → C, CG → H, CG → I, B → H. Compute the attribute closure (AG)⁺ and show that AG is a candidate key of r₁.

Show worked answer

(AG)⁺: start with {A, G}. A → B adds B. A → C adds C. CG → H adds H (C, G present). CG → I adds I. B → H adds nothing new. Result: (AG)⁺ = {A, B, C, G, H, I}, every attribute of r₁, so AG is a superkey.

Minimal? Check the subsets with one attribute removed: A⁺ = {A, B, C, H} (A → B, A → C, B → H) misses G and I. G⁺ = {G} (no FD has left side G alone). Neither is a superkey, so AG is a candidate key. (In fact it is the only one: A and G never appear on a right side, so every key contains both.)

Summary: X⁺ is the set of attributes X determines. Compute it by starting with X and repeatedly firing any FD whose whole left side is already in the set, adding its right side, until nothing changes. X → Y follows from S exactly when Y ⊆ X⁺, and X is a superkey exactly when X⁺ is all of R.
