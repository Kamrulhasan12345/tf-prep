Dependency Preservation, and Where BCNF Falls Short

A BCNF decomposition never loses tuples, but it can lose the ability to check an FD without joining tables. This chapter shows the problem on the slides' R(A, B, C) and Bookings examples, gives a test for dependency preservation with a tool, and explains why this motivates 3NF.

1. Three things we want from a decomposition

The textbook lists three properties:

  1. Elimination of anomalies (Chapter 9): the pieces are in a normal form such as BCNF.
  2. Recoverability of information (Chapter 12): the join is lossless.
  3. Preservation of dependencies: if each piece satisfies its own projected FDs, then the join is sure to satisfy all the original FDs. Every FD can be enforced by checking the pieces separately, with no join.

The BCNF algorithm guarantees 1 and 2 but not 3. The 3NF algorithm (Chapter 14) guarantees 2 and 3 but not quite 1. No method can guarantee all three for every relation.

Dependency-preserving decomposition
Let S₁, …, Sₖ be the FD sets projected onto the pieces R₁, …, Rₖ. The decomposition preserves dependencies if every FD X → Y of the original set S can be logically inferred from S₁ ∪ S₂ ∪ … ∪ Sₖ.

2. BCNF does not preserve dependency (slide 53)

Back to R(A, B, C) with AB → C and C → A (Chapter 12). BCNF splits it into R₁ = {A, C} and R₂ = {B, C}. Neither piece contains all of A, B, C, so AB → C cannot be checked on either piece alone. Projected FDs: S₁ = {C → A}, S₂ = ∅ (nothing nontrivial on B, C). Under S₁ ∪ S₂, (AB)⁺ = {A, B}, which lacks C: AB → C is not implied. Here is the damage in data:

3. Bookings (slides 54–55, book Example 3.25)

Bookings(title, theatre, city): movie title is being shown at theatre in city. FDs:

  • theatre → city: a theatre is in one city.
  • title city → theatre: a movie is not shown in two theatres of the same city (assumed for the example).

Keys (slide 54). No single attribute is a key: a title plays in several theatres, a theatre plays several movies (multiscreen), a city has several theatres. {title, city} is a key (it determines theatre by the second FD). {title, theatre} is a key (theatre gives city). {theatre, city} is not ({theatre, city}⁺ = {theatre, city}). So the keys are {title, city} and {title, theatre}.

BCNF violation (slide 55): theatre → city, since theatre is not a superkey. Decomposing gives {theatre, city} and {theatre, title}. The FD title city → theatre now spans both pieces:

Each piece is legal on its own: {theatre, city} satisfies theatre → city, and {theatre, title} has no nontrivial FD to violate. But the join holds two tuples with the same (title, city) = (Antz, Menlo Park) and different theatres, so title city → theatre is violated, and no check on the pieces could have caught it.

4. How to test dependency preservation

Slide 53's method: project S onto each piece (Chapter 10), take the union of the projections, and for each original FD X → Y compute X⁺ under that union. If some FD is not implied, the decomposition does not preserve dependencies.

A faster equivalent test (Silberschatz) avoids computing projections, which is exponential. For each FD X → Y in S:

result := X
repeat until result stops changing:
    for each piece Rᵢ:
        result := result ∪ ((result ∩ Rᵢ)⁺ ∩ Rᵢ)      -- closure under the original S
X → Y is preserved  ⇔  Y ⊆ result

Each pass asks “what can piece Rᵢ alone conclude from what we know so far?”. If the pieces together can reach Y, the FD is enforced by the pieces.

5. What to do about it (slide 56)

We want a decomposition that has (1) a lossless join and (2) the dependency-preservation property. BCNF cannot always give both: for Bookings, every BCNF decomposition must split the three attributes (the relation itself is not in BCNF), and any split loses title city → theatre. The solution is a slightly weaker normal form, third normal form (3NF), which allows Bookings to stay as it is. That is Chapter 14.

For a relation schema R(A, B, C, D, E), consider the following set of functional dependencies: ABE → C, BC → D, BD → E, DE → A. Decompose the relation into BCNF. Show the final schemas and the projected functional dependencies for each schema after decomposition. Is your final decomposition dependency-preserving? Justify your answer.

Show worked answer

Keys. B appears on no right side, so it is in every key. B⁺ = {B}. BC⁺: BC → D, BD → E, DE → A gives ABCDE. BD⁺: BD → E, DE → A, ABE → C gives ABCDE. BE⁺ = {B, E}, AB⁺ = {A, B}. ABE⁺: ABE → C, BC → D gives ABCDE, and AB, AE, BE are not superkeys, so ABE is a key. Keys: BC, BD, ABE.

BCNF check. ABE → C: ABE is a key ✓. BC → D: BC key ✓. BD → E: BD key ✓. DE → A: DE⁺ = {A, D, E}, not a superkey ✗. One violation.

Split on DE → A. DE⁺ = {A, D, E}. R₁ = ADE, R₂ = DE ∪ (R − ADE) = BCDE.

  • R₁(A, D, E): projected FDs: DE → A (A⁺ = A, D⁺ = D, E⁺ = E, AD⁺ = AD, AE⁺ = AE give nothing). Key DE. BCNF.
  • R₂(B, C, D, E): closing its subsets with the original FDs: BC⁺ ⊇ BCDE gives BC → D, BC → E; BD⁺ ⊇ BCDE gives BD → C, BD → E; no other subset gives anything inside BCDE (e.g. DE⁺ = ADE, CE⁺ = CE, BE⁺ = BE). Minimal basis: BC → D, BD → C, BD → E (BC → E follows from BC → D and BD → E). Keys BC, BD. Every left side is a key: BCNF.

Final schemas: R₁(A, D, E) with {DE → A}; R₂(B, C, D, E) with {BC → D, BD → C, BD → E}.

Dependency preserving? No. BC → D, BD → E and DE → A are each inside one piece. Test ABE → C with the union S₁ ∪ S₂ = {DE → A, BC → D, BD → C, BD → E}: (ABE)⁺ = {A, B, E}; no FD fires (each needs C, D or both D and E). C is not reached, so ABE → C is lost: to enforce it we would have to join R₁ and R₂. (The only BCNF violations of R are DE → A and its augmentation CDE → A. Splitting on either separates A from B, so no piece can hold A, B, E and C together: every BCNF decomposition of R loses ABE → C.)

Summary: a decomposition preserves dependencies if the FDs projected onto the pieces imply every original FD, so each FD can be enforced without a join. BCNF decompositions are lossless but may lose FDs: R(A, B, C) with AB → C, C → A, and Bookings with title city → theatre, cannot be decomposed into BCNF without losing an FD. Test preservation by closing each left side through the pieces; the fix is 3NF.
