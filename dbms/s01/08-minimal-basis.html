Minimal Basis (Canonical Cover)

A set of FDs can be written in many equivalent ways. A minimal basis is a cleaned-up version with no redundant FD and no unnecessary attribute on any left side. The 3NF algorithm (Chapter 14) starts from one. This chapter explains the algorithm, runs the slide's example, and gives a tool that shows every check.

1. Basis and minimal basis (slide 34)

Basis
Given a set S of FDs that hold on R, any set of FDs equivalent to S (Chapter 7) is a basis for S.
Minimal basis
A basis B that satisfies:
Condition 1, singleton right sides: every FD in B has one attribute on the right.
Condition 2, no redundant FD: if any FD is removed from B, the result is no longer a basis (no longer equivalent to S).
Condition 3, no extraneous left-side attribute: if one or more attributes are removed from the left side of any FD in B, the result is no longer a basis.
Canonical cover
Another name for a minimal basis (Korth). Korth's version also merges FDs with equal left sides, as step 2 of 3NF synthesis does.

No trivial FD can be in a minimal basis: a trivial FD follows from nothing, so removing it never changes the meaning, which violates condition 2.

2. The algorithm (slide 35)

minimal_basis(S):
  Step 1. T := S.
  Step 2. Split every FD of T so its right side is one attribute.
  Step 3. Remove redundant FDs: for an FD X → Y in T, compute X⁺ using
          T − {X → Y}.  If X⁺ contains Y, X → Y is redundant: delete it.
  Step 4. Remove extraneous attributes: for an FD Y → B in T with at least
          two attributes in Y, write Y = ZA (A one attribute). Compute Z⁺
          using T (all of it). If Z⁺ contains B, A is extraneous:
          replace Y → B by Z → B.
  Step 5. Repeat steps 3 and 4 until nothing changes.

Two details trip students up:

  • In step 3 the FD being tested is removed before computing the closure. Otherwise it would always prove itself.
  • In step 4 the closure uses all of T, including Y → B itself. We are asking whether the weaker-looking FD Z → B already follows; if it does, swapping it in changes nothing.

Small example of step 4

T = {A → B, AB → C}. Is A extraneous in AB → C? Z = B, B⁺ = {B}: no C, so A is needed. Is B extraneous? Z = A, A⁺ = {A, B, C} (A → B, then AB → C): contains C, so B is extraneous and AB → C becomes A → C. Minimal basis: {A → B, A → C}.

3. Slide 36's example

Find a minimal basis for A → B, A → C, B → A, B → C, C → A, C → B, AB → C, AC → B, BC → A. Here each of A, B, C determines the other two.

  • All right sides are already single attributes.
  • First remove AB → C, AC → B and BC → A: each follows from the single-attribute FDs (e.g. A → C alone gives AB → C by left augmentation).
  • Then remove A → C (it follows from A → B and B → C), B → A (from B → C and C → A), and C → B (from C → A and A → B).
  • Result: A → B, B → C, C → A. No left side has two attributes, so step 4 has nothing to do.

The answer depends on the order in which FDs are tried, and the slide notes that “other sets are also possible”. The textbook (Example 3.11) gives two minimal bases for this same relation: {A → B, B → A, B → C, C → B} and {A → B, B → C, C → A}. Both are correct: they are equivalent to S and satisfy the three conditions. A minimal basis is minimal in the sense of “nothing can be removed”, not “fewest FDs”.

BUET QBank · CSE 303 | L-3/T-1 | 2016–17 · 9 marks

Given a set F of functional dependencies on R(A, B, C): A → BC, B → C, A → B, AB → C. (a) Compute the canonical cover for F. (b) Decompose R into R₁ and R₂ such that the decomposition is lossless. What are the normal forms of the decomposed relations?

Show worked answer

(a) Step 2, split: A → B, A → C, B → C, A → B, AB → C. The two copies of A → B are the same FD; keep one. T = {A → B, A → C, B → C, AB → C}.

Step 3, redundant FDs (each tested without itself):

  • A → B: A⁺ under {A → C, B → C, AB → C} = {A, C}. No B: keep.
  • A → C: A⁺ under {A → B, B → C, AB → C} = {A, B, C}. Contains C: remove.
  • B → C: B⁺ under {A → B, AB → C} = {B}. Keep.
  • AB → C: (AB)⁺ under {A → B, B → C} = {A, B, C}. Contains C: remove.

Step 4: no left side has two attributes. Another pass changes nothing. Canonical cover F_c = {A → B, B → C}.

(b) The key of R is A (A⁺ = ABC). B → C violates BCNF (B⁺ = {B, C}, not a superkey). Decompose on it: R₁(B, C) with B → C, and R₂(A, B) with A → B. Lossless: R₁ ∩ R₂ = {B} and B → C, so the common attribute is a key of R₁ (Chapter 12's test). Dependencies are preserved too: A → B lives in R₂ and B → C in R₁. Normal forms: each is a two-attribute relation whose only FD has a key on the left, so both are in BCNF (hence also 3NF, 2NF and 1NF). The original R was only in 2NF (B → C is a transitive dependency).

Summary: a minimal basis is an equivalent FD set with single right sides, no redundant FD and no extraneous left-side attribute. Build it by splitting, then repeatedly deleting any FD X → A that follows from the others (X⁺ without it still has A) and shrinking any left side when the smaller left side still determines the right side (closure using all FDs). Different orders can give different, equally valid, minimal bases.
