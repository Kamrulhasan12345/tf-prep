Closures, Superkeys and Finding All Keys

Slide 28 links closures to keys: X is a superkey exactly when X⁺ is every attribute. This chapter turns that into a systematic method for finding all keys, all superkeys and all FDs that follow, which is how most exam questions on this topic are phrased.

1. Closure and superkey (slide 28)

  • If {A₁, …, Aₙ}⁺ contains all attributes of R, then {A₁, …, Aₙ} is a superkey: it determines everything.
  • If, in addition, no proper subset of {A₁, …, Aₙ} is a superkey, then {A₁, …, Aₙ} is a key (candidate key in Korth's terms).
  • So keys can be tested by computing closures.

The textbook adds a saving: to check minimality you only need the subsets formed by removing one attribute. If none of those is a superkey, no smaller subset can be (a smaller set has a smaller or equal closure).

2. A method for finding every key

Trying all 2ⁿ subsets works but is slow by hand. Sort the attributes first, looking only at nontrivial FDs (split to single right sides):

  1. Never on a right side (including attributes in no FD at all): nothing can derive them, so they are in every key. Call this set the core.
  2. Only on right sides, never on a left side: they are always derived and never help derive anything else, so they are in no key.
  3. On both sides: may or may not be needed.

Then compute core⁺. If it is everything, the core is the only key. Otherwise add “both-sides” attributes to the core, first one at a time, then two at a time, and so on, computing closures. A set whose closure is everything and which does not contain an already-found key is a new key; a set that contains a found key is skipped (it is a superkey, but not minimal).

Worked example: Movies1

FD: title year → length genre studioName. title, year and starName never appear on a right side, so all three are in every key; length, genre, studioName are only on the right, so they are in no key. Closure of the core {title, year, starName} is everything. So {title, year, starName} is the only key, exactly what slides 16–17 proved by hand.

3. Listing every FD that follows

A common exam request: “What are all the nontrivial FDs that follow from the given FDs? Restrict yourself to FDs with single attributes on the right.” The reliable method:

  1. For every nonempty subset X of R (2ⁿ − 1 of them), compute X⁺.
  2. For every attribute A in X⁺ − X, write X → A.

Because the closure finds everything X determines, this list is complete. Two shortcuts: the full set R gives nothing (X⁺ − X is empty), and any superset of a superkey has closure R without any work (but it still contributes FDs such as ABC → D, so do not skip it). The same table also answers “what are the keys” (minimal sets marked superkey) and “which superkeys are not keys”. DB QB · 24-25 1b · 10 marks  |  BUET QBank · CSE 215 | L-2/T-1 | 2024–25 · 10 marks

Consider a relation with schema R(A, B, C, D, E) and functional dependencies (FDs): A → C, BE → D, CD → A, BC → E and AD → B. Answer the following questions: (i) Determine whether the following functional dependencies follow from the given functional dependencies: BC → AD, AC → BD. (ii) Determine whether the following are keys of the given relation: {A, B}, {A, E}.

Show worked answer

(i) BC → AD. (BC)⁺: start {B, C}. BC → E adds E. BE → D adds D. CD → A adds A. (BC)⁺ = {A, B, C, D, E} ⊇ {A, D}, so BC → AD follows.

AC → BD. (AC)⁺: start {A, C}. A → C adds nothing. BE → D needs B, E; CD → A needs D; BC → E needs B; AD → B needs D. Nothing fires. (AC)⁺ = {A, C}, which lacks B and D, so AC → BD does not follow.

(ii) {A, B}. (AB)⁺: A → C adds C; BC → E adds E; BE → D adds D. (AB)⁺ = {A, B, C, D, E}: a superkey. Subsets: A⁺ = {A, C}, B⁺ = {B}; neither is a superkey. So {A, B} is a key.

{A, E}. (AE)⁺: A → C adds C; then no FD fires (BE, CD, BC, AD each need B or D). (AE)⁺ = {A, C, E} ≠ R, so {A, E} is not even a superkey: not a key.

(For reference, the keys of R are AB, BC, AD and CD.)

Show worked answer

BUET QBank · CSE 303 | L-3/T-1 | 2015–16 · 12 marks

Consider a relation R(A, B, C, D) and FDs: AB → C, BC → D, CD → A, and AD → B. (a) What are all nontrivial FDs that follow from the given FDs? (Restrict yourself to FDs with single attributes on the right side.) (b) What are all the keys of R? (c) What are all the superkeys for R that are not keys?

Show worked answer

(a) No single attribute determines anything (each appears on a left side only together with another). The 12 FDs: AB → C, AB → D, BC → A, BC → D, AD → B, AD → C, CD → A, CD → B, ABC → D, ABD → C, ACD → B, BCD → A.

(b) Pairs with full closure: AB, BC, AD, CD (AC⁺ = AC, BD⁺ = BD). Single attributes are not superkeys. Keys: AB, BC, AD, CD.

(c) Every set of 3 or 4 attributes contains one of these pairs: ABC, ABD, ACD, BCD, ABCD.

BUET QBank · CSE 303 | L-3/T-1 | 2011–12 · 10 marks

Consider a relation with schema R(A, B, C, D) and FDs: AB → C, AD → B, B → D. Find all non-trivial FDs that follow from the given FDs.

Show worked answer

Reading off the table, the nontrivial FDs with one attribute on the right are the 9: B → D, AB → C, AB → D, BC → D, AD → B, AD → C, ABC → D, ABD → C, ACD → B. Combining right sides gives more, e.g. AB → CD and AD → BC. (Keys: AB and AD.)

Summary: X is a superkey iff X⁺ = R, and a key iff, in addition, removing any one attribute breaks that. To find all keys: attributes on no right side are in every key, attributes only on right sides are in none, and the rest are tried in growing combinations. To list every FD that follows, close every subset X and write X → A for each A ∈ X⁺ − X.
