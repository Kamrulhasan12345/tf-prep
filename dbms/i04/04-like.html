Pattern Matching with LIKE

How s LIKE p decides whether a string fits a pattern built from % and _; how to search for the special characters themselves (apostrophe, %, _) with doubling and ESCAPE; why LIKE does not ignore trailing blanks the way = does; and NOT LIKE. An interactive matcher animates any pattern on any string.

1. The LIKE operator (slide 26)

s LIKE p
A condition that is TRUE when the string s matches the pattern p. Every ordinary character in p must match itself exactly (upper and lower case are different in Oracle), and two characters are wildcards:
% (percent)
matches any sequence of characters, of any length, including zero.
_ (underscore)
matches exactly one character, whatever it is.

The pattern must cover the whole string, from the first character to the last. That is why "contains mo" is written '%mo%': the first % absorbs whatever comes before mo, the second whatever comes after.

(Slides 27–29 and 35 write FROM Products; the table is called Product. With the extra s, Oracle would report ORA-00942: table or view does not exist.)

Show all products' info that has 'mo' as a substring of the product name (slide 27):

SELECT * FROM Product WHERE pname LIKE '%mo%';        -- Gizmo, Powergizmo

Show all products' info where the product name ends with 'Touch' (slide 28):

SELECT * FROM Product WHERE pname LIKE '%Touch';      -- SingleTouch, MultiTouch

Slide 29 matches the manufacturer with one-character wildcards. 'G_z_oWorks' has 10 characters, so it only matches 10-character strings; GizmoWorks fits (G, i, z, m, o, W…), so both GizmoWorks products are returned:

SELECT * FROM Product WHERE manufacturer LIKE 'G_z_oWorks';   -- Gizmo, Powergizmo

4. Searching for the special characters (slides 30–33)

Three characters have special meaning inside a pattern string: the apostrophe ' (it ends the string), % and _ (they are wildcards). Each needs a way to be searched for literally.

The apostrophe: write it twice (slide 31)

Inside a string constant, two apostrophes in a row stand for one apostrophe character. This is a rule of string constants in general, not of LIKE: 'Baby''s World' is the 13-character string Baby's World.

-- company names containing 's (apostrophe s)
SELECT * FROM Company WHERE cname LIKE '%''s%';

% and _: the ESCAPE clause (slides 32–33)

ESCAPE 'c'
Declares a character c that, inside this pattern, makes the character right after it ordinary. \% then matches a real percent sign and \_ a real underscore. Any character can be chosen as the escape character; \ and ! are common choices because they rarely occur in the data.
-- interest rates that end with a percent sign (slide 32)
SELECT * FROM Bank WHERE interestRates LIKE '%\%' ESCAPE '\';

-- country names that contain an underscore (slide 33)
SELECT * FROM Company WHERE country LIKE '%\_%' ESCAPE '\';

Read '%\%' as two tokens: a wildcard % (anything) followed by an escaped, literal % (the last character must be a percent sign). Without ESCAPE, '%%' would be two wildcards and would match every string, and '%_%' would match every string of at least one character.

5. LIKE does not pad with blanks (slide 34)

WHERE category = 'Household'        -- blank-padded comparison for CHAR
WHERE category LIKE 'Household'     -- pattern match: NOT equivalent

Chapter 3 showed that = between CHAR values ignores trailing blanks. LIKE does not: it matches the pattern against the value exactly as stored. If category is CHAR(15), the stored value is 'Household␣␣␣␣␣␣', and the pattern 'Household' has no wildcard to absorb the six blanks, so LIKE 'Household' is FALSE while = 'Household' is TRUE. For a VARCHAR2 column the two conditions give the same answer. A pattern that works for CHAR columns is 'Household%'.

6. NOT LIKE (slide 35)

s NOT LIKE p is TRUE exactly when s LIKE p is FALSE.

SELECT * FROM Product WHERE manufacturer NOT LIKE '%mo%';   -- SingleTouch, MultiTouch

GizmoWorks contains mo, so both GizmoWorks products are excluded; Canon and Hitachi do not, so their products are returned.

Because LIKE is case-sensitive in Oracle, a case-insensitive search converts the column first: WHERE UPPER(pname) LIKE '%GIZ%' finds both Gizmo and Powergizmo. (UPPER is one of the single-row functions in Lec 05 Chapter 4.)

BUET QBank · CSE 215 | L-2/T-1 | 2024–25 · 12 marks

Consider the following relational database schema:

Planet(planet_id, name, type, distance_sun_au), planet_id is the primary key.
Moon(moon_id, name, planet_id, diameter_km), moon_id is the primary key, and planet_id is a foreign key referencing Planet(planet_id).

(a) Write an SQL function total_moons() that returns a single integer representing the total number of moons possessed by all planets. Then write the SQL statement to call the function.
(b) Find the names of all planets whose name contains a substring that starts with "Ma", then has exactly two unknown characters, and ends with "s".

Show worked answer

(b) The substring is: the two letters Ma, then exactly two unknown characters (__), then s. It may appear anywhere in the name, so put % on both sides:

SELECT name
FROM   Planet
WHERE  name LIKE '%Ma__s%';

Check on example names: Malys matches (Ma, ly, s); Neo Mares matches (Ma, re, s inside the name); Mars does not (only one character, r, between Ma and s); Magnus does not (after Ma + gn comes u, not s); Tamaras does not, because its "ma" has a lower-case m and Oracle's LIKE is case-sensitive. The real planets Mercury … Neptune give no match at all.

(a) In Oracle, a stored function is written in PL/SQL. It counts the rows of Moon (each row is one moon):

CREATE OR REPLACE FUNCTION total_moons
RETURN NUMBER
IS
  v_total NUMBER;
BEGIN
  SELECT COUNT(*) INTO v_total FROM Moon;
  RETURN v_total;
END;
/

SELECT total_moons() FROM dual;     -- call it in a query

COUNT(*) counts the rows of Moon (aggregate functions are taught in Lecture 10); SELECT … INTO stores the single result in the variable; the / line tells SQL*Plus to compile the block. Because every moon row has a planet_id referencing a planet, counting Moon counts exactly the moons possessed by planets. (If planet_id could be NULL, use COUNT(planet_id) to count only moons that belong to a planet.) The function can also be called from PL/SQL: DBMS_OUTPUT.PUT_LINE(total_moons);.

Note: the question bank's answer for (a) is written in PostgreSQL's PL/pgSQL (RETURNS INTEGER … $$ … LANGUAGE plpgsql), which does not run on Oracle; in this course write the Oracle version above. Its answer for (b) is correct, but it contains a stray space ('% Ma__s % ') that would change the pattern.

The exercise below lets you test (b) on a small invented Planet table, and the query part of (a) as SELECT COUNT(*) FROM Moon.

Summary: s LIKE p matches the whole string against the pattern: % = any sequence (even empty), _ = exactly one character, everything else literal and case-sensitive. Write an apostrophe as ''; search for a literal % or _ with an escape character declared by ESCAPE. LIKE does not ignore trailing blanks (= on CHAR does). NOT LIKE negates the match.
