Comparisons, BETWEEN and String Equality

Range conditions on numbers, strings and dates: the six comparison operators, BETWEEN … AND … and NOT BETWEEN (both inclusive), and how Oracle compares strings, including the blank-padding rule for CHAR columns that slides 24–25 point out.

1. A range condition (slide 19)

Show all products' info that will cost more than 100 dollars.

SELECT *
FROM   Product
WHERE  price > 100;

The slide shows the result next to the loop of slide 17: each row is tested; SingleTouch (149.99) and MultiTouch (203.99) pass.

The operators work on numbers, strings and dates. Numbers compare by value and dates by time (earlier is smaller). Strings compare in lexicographic order, character by character, like words in a dictionary; Oracle's default compares the characters' codes, so all upper-case letters come before all lower-case ones ('Zebra' < 'apple'), and a string that is a prefix of another is smaller ('P' < 'Photography').

3. BETWEEN … AND … (slides 21–22)

SELECT <attributes>
FROM   <table>
WHERE  attribute BETWEEN value1 AND value2
BETWEEN
x BETWEEN a AND b means exactly x >= a AND x <= b. It is inclusive: both end values qualify. It works on numbers, texts and dates. The smaller value must come first: BETWEEN 200 AND 100 is never true.

Show all products' info in the price range $100 to $200 (inclusive).

SELECT *
FROM   Product
WHERE  price BETWEEN 100 AND 200;      -- SingleTouch only

4. NOT BETWEEN (slide 23)

Show all products' info not in the price range $10 to $200 (inclusive).

SELECT *
FROM   Product
WHERE  price NOT BETWEEN 10 AND 200;   -- MultiTouch only

x NOT BETWEEN a AND b means x < a OR x > b. The slide says "NOT BETWEEN-AND is also inclusive": the range being excluded, [10, 200], includes its end points, so a price of exactly 10 or 200 would not be returned. Gizmo (19.99) lies inside [10, 200], so it is excluded too; only MultiTouch is left.

5. String equality and CHAR padding (slides 24–25)

Show all household products' info.

SELECT pname, price, manufacturer
FROM   Product
WHERE  category = 'Household';

Slides 24 and 25 make a point about the column's type. Suppose category were declared CHAR(15). Then the stored value is 'Household' followed by 6 blanks. Does it still equal the 9-character constant 'Household'? In Oracle, yes, because of this rule:

Blank-padded comparison
When Oracle compares two values that are both of a fixed-length type (CHAR columns and string constants count as CHAR), it first pads the shorter one with blanks to the same length, then compares. Trailing blanks therefore never matter.
Non-padded comparison
When either value is a VARCHAR2, Oracle compares the strings exactly as they are; trailing blanks count, and a string with an extra blank is different (and greater).

Summary: the comparison operators are = < > <= >= and two forms of not-equal, <> and !=. They work on numbers, strings (lexicographic, case-sensitive) and dates. x BETWEEN a AND b = a <= x AND x <= b, inclusive, smaller value first; NOT BETWEEN excludes the same closed range. Oracle compares two CHAR values after padding with blanks, so trailing blanks do not matter; with VARCHAR2 they do.
