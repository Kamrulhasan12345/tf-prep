NULL in Conditions: Three-Valued Logic

Lecture 3 introduced NULL as a missing value. This chapter, which follows the textbook, explains what happens when a WHERE condition meets a NULL: comparisons give a third truth value, UNKNOWN; AND, OR and NOT follow three-valued truth tables; and WHERE keeps only rows whose condition is TRUE. It ends with IS NULL, NVL, and the surprising query that does not return every row.

1. Arithmetic and comparisons with NULL (textbook §6.1.6)

NULL means "no value is known here". The textbook draws two rules from that:

  1. Arithmetic: if either operand of + − × / is NULL, the result is NULL. If commission is unknown, so is salary * commission_pct.
  2. Comparison: if either side of = <> < > <= >= is NULL, the result is the truth value UNKNOWN. The unknown value might make the comparison true or false; SQL does not guess.

So NULL = NULL is UNKNOWN, not TRUE (two unknown values need not be equal), and commission_pct > 0.2 is UNKNOWN for an employee without a commission. NULL itself is not a value, so writing WHERE commission_pct = NULL is never TRUE for any row.

IS NULL / IS NOT NULL
The only correct tests for NULL. x IS NULL is TRUE when x is NULL and FALSE otherwise; it never gives UNKNOWN.

2. The three truth values (textbook §6.1.7)

With UNKNOWN in play, AND, OR and NOT need extended truth tables. A simple way to remember them, from the textbook: think of TRUE as 1, FALSE as 0 and UNKNOWN as ½. Then

A AND B = min(A, B)     A OR B = max(A, B)     NOT A = 1 − A

The WHERE rule: a row is returned only when its whole condition is TRUE. Rows whose condition is FALSE or UNKNOWN are dropped. (UNKNOWN is not FALSE, but WHERE treats both as "not proven true".)

4. The query that does not return every row

The textbook's best illustration (its Example 6.10) is a condition that looks like it is always true:

SELECT last_name
FROM   Employees
WHERE  commission_pct <= 0.2 OR commission_pct > 0.2;

For any real number, one of the two comparisons is true. But for the 13 employees whose commission is NULL, both comparisons are UNKNOWN, and UNKNOWN OR UNKNOWN is UNKNOWN. The query returns only the 4 employees who have a commission. To include everyone, say so: … OR commission_pct IS NULL.

5. Replacing NULL: NVL

NVL(x, y)
Oracle function that returns x if x is not NULL, and y otherwise. NVL(commission_pct, 0) treats a missing commission as 0. (NVL2(x, y, z) returns y if x is not NULL and z if it is.)
SELECT last_name, salary * (1 + NVL(commission_pct, 0)) AS total_pay
FROM   Employees;

Without NVL, salary * (1 + commission_pct) would be NULL for 13 of the 17 employees. Use NVL only when the replacement makes sense: a missing commission really is "no commission", so 0 is right; a missing date of birth is not 1 January 1900.

Summary: arithmetic with NULL gives NULL; comparisons with NULL give UNKNOWN. With TRUE = 1, UNKNOWN = ½, FALSE = 0: AND = min, OR = max, NOT = 1 − x. WHERE returns only TRUE rows, so UNKNOWN rows disappear, even from conditions like x <= 0.2 OR x > 0.2. Test NULL with IS NULL / IS NOT NULL, and substitute a value with NVL.
