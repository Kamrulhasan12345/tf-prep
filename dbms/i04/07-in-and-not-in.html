Membership Tests: IN and NOT IN

IN tests whether a value belongs to a list; NOT IN tests that it does not. Each is shorthand for a chain of = joined by OR, or <> joined by AND, as slides 44–45 show side by side. The chapter ends with the one trap of NOT IN: a NULL in the list.

1. IN (slide 44)

x IN (v1, v2, …, vn)
TRUE when x equals at least one of the listed values. It means exactly x = v1 OR x = v2 OR … OR x = vn. The values can be numbers, strings or dates. (In Lecture 11 the list can also be a subquery, as in Lecture 5's DELETE examples.)

The slides use a small table of CDs:

Find all albums launched in 1984 or 1996. The two queries below are equivalent:

SELECT album
FROM   CDCollection
WHERE  year IN (1984, 1996);
SELECT album
FROM   CDCollection
WHERE  year = 1984
OR     year = 1996;

IN is shorter, easier to read and easier to extend: adding 1991 means adding one value to the list instead of one more OR year = 1991.

2. NOT IN (slide 45)

x NOT IN (v1, …, vn)
TRUE when x differs from every listed value: x <> v1 AND x <> v2 AND … AND x <> vn. It is the same as NOT (x IN (v1, …, vn)).
SELECT *
FROM   CDCollection
WHERE  year NOT IN (1984, 1996);
SELECT *
FROM   CDCollection
WHERE  year <> 1984
AND    year <> 1996;

Both return Rattle and Hum (1988) and Achtung Boys (1991). Notice the switch from OR to AND: by De Morgan's law, NOT (A OR B) = (NOT A) AND (NOT B). Writing year <> 1984 OR year <> 1996 is a common mistake: every year differs from at least one of the two, so it returns every row.

3. The NULL trap in NOT IN

Expand year NOT IN (1984, NULL) with the rule above: year <> 1984 AND year <> NULL. Any comparison with NULL is UNKNOWN (Chapter 8), so the second half is never TRUE, and the whole condition is never TRUE: a NOT IN list that contains a NULL returns no rows at all. IN does not have this problem: year IN (1984, NULL) still finds 1984, because TRUE OR UNKNOWN is TRUE.

The same happens when the tested value itself is NULL: an employee whose department_id is NULL satisfies neither department_id IN (50, 60) nor department_id NOT IN (50, 60). You will meet this again with subqueries (NOT IN (SELECT …)), where a single NULL returned by the subquery empties the answer.

Summary: x IN (v1, …, vn) = x = v1 OR … OR x = vn; x NOT IN (…) = x <> v1 AND … AND x <> vn (OR becomes AND, by De Morgan). A NULL in a NOT IN list makes the condition never TRUE, and a NULL x satisfies neither IN nor NOT IN.
