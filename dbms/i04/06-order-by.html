Sorting the Result with ORDER BY

How ORDER BY sorts the output, ascending by default or descending with DESC, how a second and third sort key break ties, how each key gets its own direction, and where NULLs go (with a correction to slide 43 for Oracle's DESC order).

1. ORDER BY (slide 41)

ORDER BY
The last clause of a query. It lists one or more sort keys (columns or expressions), each optionally followed by ASC (ascending, the default) or DESC (descending). It is evaluated last, after SELECT and DISTINCT, and only reorders the output rows: it never adds or removes rows.
SELECT   pname, price, category, manufacturer
FROM     Product
WHERE    price > 50
ORDER BY pname;          -- MultiTouch, SingleTouch

The two products above $50 are sorted by name: M comes before S. Without ORDER BY the order is not defined (Lec 03, Chapter 2), so ORDER BY is the only way to get a guaranteed order.

2. Several sort keys: breaking ties (slide 42)

SELECT   pname, price, manufacturer
FROM     Product
WHERE    category = 'Gadgets' AND price > 10
ORDER BY price, pname;

The rows are sorted by the first key, price. Only rows that are equal on price (a tie) are then put in order by the second key, pname; rows still tied are ordered by the third key, and so on. The second key never overrides the first. On the slide data the two gadgets have different prices (19.99, 29.99), so the second key has no effect there.

3. A direction for each key (slide 43)

SELECT   pname, price, manufacturer
FROM     Product
WHERE    category = 'Gadgets' AND price > 10
ORDER BY price ASC, pname DESC;

ASC or DESC applies only to the key it follows. Here price is ascending and, among equal prices, names are descending. Writing ORDER BY price, pname DESC means the same thing: price is ASC by default.

4. Where do NULLs go? (slide 43)

Slide 43 says "NULL values always come last". In Oracle that is true for ascending keys only. Oracle sorts NULL as if it were larger than every value, so:

  • ORDER BY x or ORDER BY x ASC: NULLs come last (default NULLS LAST);
  • ORDER BY x DESC: NULLs come first (default NULLS FIRST).

Either default can be overridden per key, as the slide shows: ORDER BY price ASC NULLS FIRST or ORDER BY price DESC NULLS LAST.

Other systems differ: SQLite and MySQL treat NULL as the smallest value (first in ASC). The playground runs on SQLite, so in the boxes below write NULLS LAST / NULLS FIRST explicitly to get Oracle's order.

5. Two more facts worth knowing

  • You may sort by a column you do not select: SELECT pname FROM Product ORDER BY price is legal, since ORDER BY can see the rows' other columns. The exception is SELECT DISTINCT: after duplicate removal there is no single price for a row, so Oracle then requires the sort keys to be in the SELECT list (ORA-01791).
  • You may sort by position or by alias: ORDER BY 2 sorts by the second selected column; SELECT price * 1.15 AS with_vat … ORDER BY with_vat uses an alias (aliases: Lec 05, Chapter 4).

Summary: ORDER BY is evaluated last and only reorders rows. Each key is ASC by default or DESC; the second key only orders rows tied on the first, and so on. In Oracle NULL sorts as the largest value: last for ASC, first for DESC (slide 43's "always last" holds only for ASC); NULLS FIRST / NULLS LAST override this per key. Without ORDER BY, row order is not guaranteed.
