5. Formula sheet

B = blocks, T = tuples, M = memory buffers, V(R, a) = distinct values of a. Cost = disk I/Os; writing the final result is not counted unless asked.

Disks
capacity = platters × 2 surfaces × Σ(tracks × sectors/track) × bytes/sector
access time = seek + rotational latency; one block = seek + latency + transfer
avg rotational latency = ½ × (60,000 ÷ rpm) ms · transfer = block size ÷ transfer rate
RAID 5: usable = n − 1 disks · parity on disk k mod n · new P = old P ⊕ old B ⊕ new B
RAID 6: usable = n − 2 · survives 2 failures · RAID 1: half the space, 2 writes per block

Records
record i starts at byte n(i − 1) · records/block = ⌊block ÷ record⌋ · block of record i (0-based) = ⌊i ÷ records/block⌋

Indexing
B+ node: n pointers, n − 1 keys; height ≤ ⌈log⌈n/2⌉(K)⌉ · leaf min ⌈(n−1)/2⌉ keys, internal min ⌈n/2⌉ pointers
leaf split: first ⌈n/2⌉ stay, new leaf's first key is copied up · internal split: middle key pushed up
search unindexed index file ≈ log₂(b) reads · multilevel: one read per level
secondary-index range: (hi + n)(tS + tT) · primary B+ equality: (hi + 1)(tT + tS) · range: hi(tT + tS) + tS + b·tT
static hashing buckets nB = (nr ÷ fr)(1 + d) · linear hashing: bucket = m if m < n, else m − 2i−1

Query execution
one-pass binary: B(R) + B(S), needs min(B(R), B(S)) ≤ M − 1
block nested loop: B(S) + ⌈B(S)/(M − 1)⌉·B(R) ≈ B(R)B(S)/M (S = smaller, outer)
TPMMS: 3B (4B if result stored), needs B ≤ M(M − 1) ≈ M² ⇒ M ≥ √B
more passes: B(2⌈logM−1(B/M)⌉ + 1)
sort-based δ, γ: 3B, M ≥ √B · sort-based ∪ ∩ −: 3(B(R) + B(S)), M ≥ √(B(R) + B(S))
simple sort-join: 5(B(R) + B(S)), M ≥ √max(B(R), B(S))
sort-merge-join: 3(B(R) + B(S)), M ≥ √(B(R) + B(S))
hash join: 3(B(R) + B(S)), M ≥ √min(B(R), B(S)) · hybrid hash ≈ (3 − 2M/B(S))(B(R) + B(S))
T(R ⋈ S) ≈ T(R)T(S) ÷ max(V(R, Y), V(S, Y)) · T(σA=cR) ≈ T(R) ÷ V(R, A)

Algebra and SQL
R ∩ S = R − (R − S) · R ÷ S = πA(R) − πA((πA(R) × S) − R)
|R × S| = |R|·|S| · bag ∪ adds counts, ∩ = min, − = max(0, a − b)
3-valued logic: T = 1, U = ½, F = 0; AND = min, OR = max, NOT = 1 − x
SQL evaluation order: FROM → WHERE → GROUP BY → HAVING → SELECT → DISTINCT → ORDER BY
superkeys with one k-attribute key in n attributes: 2n−k

6. Procedures to run in your head

Attribute closure X⁺
Start with X; fire any FD whose whole left side is inside; repeat until nothing changes. X is a superkey iff X⁺ = R.
All keys
Attributes on no right side are in every key; attributes only on right sides are in none; try the rest in growing combinations, keeping only minimal ones.
Minimal basis
Split right sides → drop any FD implied by the others → shrink left sides whose smaller version still determines the right side.
BCNF decomposition
Find violation X → Y (X not a superkey); split into X⁺ and X ∪ (R − X⁺); project FDs; repeat. Lossless, may lose FDs.
3NF synthesis
Minimal basis → one relation per left side → add a key relation if no relation contains a key → drop subsets. Lossless and dependency-preserving.
Lossless two-way split
(R₁ ∩ R₂) → R₁ or (R₁ ∩ R₂) → R₂. More pieces: the chase.
Precedence graph
Element by element: arc Ti → Tj for each pair on the same element, different transactions, at least one write, Ti first. Cycle = not conflict-serializable; otherwise any topological order is the serial order. Two reads never make an arc.
Wait-die / wound-wait
T requests a lock U holds. Wait-die: older T waits, younger T dies. Wound-wait: older T wounds (rolls back) U, younger T waits. Restarted transactions keep their timestamp.
Undo recovery
Scan backward; undo (write old value) every transaction without COMMIT; log ABORT. Disk order: log records → data → COMMIT.
Redo recovery
Find committed transactions; scan forward rewriting their new values. Disk order: log records → COMMIT → data.
Undo/redo recovery
Redo committed forward, then undo incomplete backward. Only rule: write-ahead logging.
Checkpoint stop point
Undo log: meet END CKPT first → stop at its START CKPT; meet START CKPT first → go back to the earliest START of the listed transactions. Redo: use the last completed checkpoint.
ER → tables
Entity → table on its key; composite → flatten; multivalued → own table (owner key + value); weak → owner key in its PK; many-to-one → FK on the many side (NOT NULL if total); one-to-one → UNIQUE FK; many-to-many and multi-way → own table.
isA conversion
E/R style: table per entity set with key + own attributes. OO style: table per possible combination. Null style: one table with NULLs.
RA query recipe
“but not” → −; “both” on different tuples → ∩; “pairs” → ρ and self-product with ≠ or <; “highest” → all minus those smaller than something; “every” → ÷.
