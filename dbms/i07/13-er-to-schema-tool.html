Exam questions

DB QB · 20-21 6b · 20 marks  ·  BUET QBank · CSE 215 | L-2/T-2 | 2020–21 · 20 marks

You are running a startup company allowing users to post blogs, and to comment on other user's blogs. (i) Design the E/R diagram for your company's data. Your database should store information about users, bloggers, and blogs, and encode the following information: Every user has a user ID and a name. Every blog has a blog ID, a text content and one author, who is a blogger. Every blogger is a user. Every blogger also has a rating attribute. Users may comment on blogs. Every comment has an optional text content, and/or an optional rating. (ii) Write a sequence of SQL queries that create the tables for this E/R diagram; uid, bid, and rating are integers, all other attributes are text. You should turn in several CREATE TABLE statements, which include key, foreign key, and not null declarations.

Show worked answer

(i) ERD. User(uid, name). Blogger isA User with its own attribute rating ("every blogger is a user"). Blog(bid, text). writes: Blog → Blogger, many-to-one, total on Blog ("one author, who is a blogger"); it is attached to Blogger, not User, so only bloggers can author. comments: User – Blog, many-to-many, with attributes text and rating (both optional). Assumption: a user comments on a given blog at most once; if repeated comments must be kept, make Comment an entity set with its own cid (Chapter 5, section 6).

(ii) Tables (E/R style for the isA, Chapter 12; rule 6 for writes; rule 8 for comments). In Oracle "text" is VARCHAR2 (or CLOB for long blog bodies) and "integer" is NUMBER(10):

CREATE TABLE Users (
  user_id    NUMBER(10)    PRIMARY KEY,
  name   VARCHAR2(100) NOT NULL
);
CREATE TABLE Bloggers (
  user_id    NUMBER(10) PRIMARY KEY REFERENCES Users(user_id),
  rating NUMBER(10)
);
CREATE TABLE Blogs (
  bid       NUMBER(10)     PRIMARY KEY,
  text      VARCHAR2(4000) NOT NULL,
  author    NUMBER(10)     NOT NULL REFERENCES Bloggers(user_id)
);
CREATE TABLE Comments (
  user_id    NUMBER(10) REFERENCES Users(user_id),
  bid    NUMBER(10) REFERENCES Blogs(bid),
  text   VARCHAR2(1000),
  rating NUMBER(10),
  PRIMARY KEY (user_id, bid),
  CHECK (text IS NOT NULL OR rating IS NOT NULL)   -- "text and/or rating"
);

author is NOT NULL and references Bloggers (every blog has exactly one blogger author). The CHECK enforces "and/or": a comment has at least one of the two. (USER and UID are Oracle reserved words, so the table is named Users and the column user_id; the question's uid is the same attribute.) The question bank's version uses a surrogate comment_id, which allows several comments per user and blog; both are acceptable if the assumption is stated, but its TEXT data type is not Oracle.

Summary: the converter applies Chapter 11's rules in a fixed order: strong entities, weak entities, hierarchies, multivalued attributes, then relationships (many-to-one and one-to-one as foreign keys, many-to-many and multi-way as tables). Use it to check a hand conversion: if your table count or keys differ, find the rule you applied differently.
