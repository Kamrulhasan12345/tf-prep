EXISTS and NOT EXISTS

EXISTS asks a yes/no question about a subquery: does it return any row at all? Correlated with the outer row, it expresses "has some …" and NOT EXISTS expresses "has no …". This chapter covers slides 13–16, compares IN and EXISTS, shows how "for all" questions (relational division) are written with NOT EXISTS, and works exam questions that use subqueries inside INSERT and DELETE.

1. EXISTS (slide 13)

SELECT <attributes>
FROM   <one or more relations>
WHERE  EXISTS (sub-query)
EXISTS (subquery)
TRUE if the subquery returns at least one row, FALSE if it returns none (slide 13: empty → FALSE, not empty → TRUE). It never yields UNKNOWN, and it does not care what the rows contain, so the subquery is conventionally written SELECT * or SELECT 1.
NOT EXISTS (subquery)
TRUE if the subquery returns no row.

EXISTS is almost always used with a correlated subquery (Chapter 2): the subquery mentions the outer row, so it asks a different question for every outer row.

2. Makers of both, and makers of PCs only (slides 14–15)

With PC(model, maker) and Laptop(model, maker) of Lecture 09:

-- slide 14: makers of both PCs and laptops
SELECT DISTINCT maker
FROM   PC
WHERE  EXISTS (SELECT *
               FROM   Laptop
               WHERE  PC.maker = Laptop.maker);        -- A, B

-- slide 15: makers of PCs but not laptops
SELECT DISTINCT maker
FROM   PC
WHERE  NOT EXISTS (SELECT *
                   FROM   Laptop
                   WHERE  PC.maker = Laptop.maker);    -- C

For each PC row, the subquery looks for laptops with the same maker. For 1001 (A) it finds 2001, so EXISTS is TRUE; for 1003 (C) it finds nothing, so EXISTS is FALSE and NOT EXISTS is TRUE. Inside the subquery, the unqualified maker would mean Laptop.maker, so the outer column is written PC.maker.

So the four maker questions of Lecture 09 now have three solutions each: set operators (Lecture 08), outer joins (Lecture 09) and subqueries (here). NOT EXISTS is the most robust form of "but not": unlike NOT IN, it is not broken by NULLs, and unlike MINUS, it can return columns other than the ones compared.

3. Maximum without aggregates, revisited (slide 16)

Find the PC model with maximum processing speed, using and without using an aggregate function. Slide 16 shows the PC table of the textbook (13 PCs) and two solutions:

SELECT model FROM PC
WHERE  speed = (SELECT MAX(speed) FROM PC);       -- with an aggregate

SELECT model FROM PC
WHERE  speed >= ALL (SELECT speed FROM PC);       -- without

Both return 1005 and 1006, the two PCs at 3.2 GHz (a tie, which is why questions say "model(s)"). A third version uses NOT EXISTS: a PC is fastest if no PC is faster.

SELECT model FROM PC p1
WHERE  NOT EXISTS (SELECT * FROM PC p2 WHERE p2.speed > p1.speed);

4. "For all" questions: relational division

Many exam questions say "… who have taken all courses …" or "… who sell every type …". SQL has no "for all" quantifier, so we use a double negative: x qualifies if there is no required item that x lacks.

Relational division
R ÷ S: the values of R's other attributes that are paired in R with every tuple of S. "Students who took all level-3 courses" = takes(student, course) ÷ (level-3 courses).

Two standard SQL forms, both valid in Oracle:

-- (1) NOT EXISTS ( required MINUS what x has )
SELECT s.student_id FROM student s
WHERE NOT EXISTS (
        SELECT c.course_number FROM course c WHERE c.lvl = 3 AND c.term = 1
        MINUS
        SELECT t.course_number FROM takes t WHERE t.student_id = s.student_id);

-- (2) double NOT EXISTS: no required course without a matching takes row
SELECT s.student_id FROM student s
WHERE NOT EXISTS (
        SELECT * FROM course c
        WHERE  c.lvl = 3 AND c.term = 1
        AND    NOT EXISTS (SELECT * FROM takes t
                           WHERE t.student_id = s.student_id
                           AND   t.course_number = c.course_number));

A third form counts: a student qualifies if the number of distinct required courses he took equals the number of required courses (GROUP BY … HAVING COUNT(DISTINCT …) = (SELECT COUNT(*) …)). Watch the empty case: if there are no required courses at all, forms (1) and (2) return every student (vacuous truth), while a join-based count returns nobody.

BUET QBank · CSE 303 | L-3/T-1 | 2016–17 · 15 marks

Given the relation schema of CSE department course database: course(course_number, title, credit_hour, level, term, pre_req_course_number), takes(course_number, student_id), student(student_id, name, CGPA). Write SQL statements to: (a) Find the list of only those students who have taken all the courses of level 3 and term 1. (b) Find the list of courses that are not taken by any student. (c) Find the student id and the number of courses taken for those students with CGPA higher than 3.5.

Show worked answer

Oracle note: LEVEL is a reserved word in Oracle (it is the pseudo-column of hierarchical queries), so a real Oracle table could not have a column called level unless it is quoted ("LEVEL") everywhere. The answers below call it lvl; with the question's name, write "LEVEL".

(a) Division (section 4): students for whom no level-3 term-1 course is missing.

SELECT s.student_id, s.name
FROM   student s
WHERE  NOT EXISTS (
         SELECT c.course_number FROM course c WHERE c.lvl = 3 AND c.term = 1
         MINUS
         SELECT t.course_number FROM takes t WHERE t.student_id = s.student_id);

(b) Courses with no takes row (an anti-join):

SELECT c.course_number, c.title
FROM   course c
WHERE  NOT EXISTS (SELECT * FROM takes t WHERE t.course_number = c.course_number);

(c) Count each good student's courses; the left join keeps a good student who has taken no course, with 0:

SELECT   s.student_id, COUNT(t.course_number) AS num_courses
FROM     student s LEFT JOIN takes t ON t.student_id = s.student_id
WHERE    s.CGPA > 3.5
GROUP BY s.student_id;

The question bank's answers are correct (it uses EXCEPT in (a) and notes that Oracle needs MINUS). Invented data for the checks: 5 students, 6 courses (three of them level 3 term 1: CSE 301, CSE 303, CSE 307); student 1805003 has a CGPA of 3.80 but has taken nothing.

DB QB · 21-22 1b · 10 marks  |  BUET QBank · CSE 215 | L-2/T-2 | 2021–22 · 10 marks

Consider the following relational database schema: Product(maker, model, type), PC(model, speed, ram, hd, price), Laptop(model, speed, ram, hd, screen, price). Write SQL queries as part of DML to update the above tables to reflect the following facts:

(i) Insert the fact that for every PC there is a laptop with the same manufacturer, speed, ram, and hard disk, a 17-inch screen, a model number 1100 greater and a price $400 more with respect to the PC.
(ii) Delete all laptops made by manufacturer that does not make PCs.

Show worked answer

(i) An INSERT can take its rows from a query (INSERT INTO table (columns) SELECT …). Two inserts are needed: the manufacturer belongs in Product, the specification in Laptop. Product goes first, because Laptop.model is a foreign key to Product.model.

INSERT INTO Product (maker, model, type)
SELECT maker, model + 1100, 'laptop'
FROM   Product
WHERE  type = 'pc';

INSERT INTO Laptop (model, speed, ram, hd, screen, price)
SELECT model + 1100, speed, ram, hd, 17, price + 400
FROM   PC;

With the textbook data this adds 13 laptops, models 2101–2113 (PC 1001 becomes laptop 2101 at 2114 + 400 = 2514), none of which collides with the existing laptops 2001–2010.

(ii) The makers that make PCs are SELECT maker FROM Product WHERE type = 'pc'. Delete the laptops whose model belongs to any other maker:

DELETE FROM Laptop
WHERE  model IN (SELECT model FROM Product
                 WHERE  maker NOT IN (SELECT maker FROM Product
                                      WHERE  type = 'pc'));

On the textbook data, F and G make laptops but no PCs, so laptops 2008, 2009 and 2010 are deleted. Their Product rows still say type 'laptop'; to keep the database consistent you would also run DELETE FROM Product WHERE type = 'laptop' AND maker NOT IN (SELECT maker FROM Product WHERE type = 'pc') afterwards (Laptop first, since it references Product). (maker is never NULL here, so NOT IN is safe; NOT EXISTS works too.) The question bank's answer is correct.

BUET QBank · CSE 303 | L-3/T-1 | 2011–12 · 5 + 5 marks

A database schema consists of four relations: Product(maker, model, type), PC(model, speed, ram, hd, price), Laptop(model, speed, ram, hd, screen, price), Printer(model, color, type, price). (a) Delete all laptops made by a manufacturer that does not make printers. (b) Assume that manufacturer A bought manufacturer B. Change all products made by B so that they are now made by A.

Show worked answer
-- (a)
DELETE FROM Laptop
WHERE  model IN (SELECT model FROM Product
                 WHERE  type = 'laptop'
                 AND    maker NOT IN (SELECT maker FROM Product WHERE type = 'printer'));

-- (b)
UPDATE Product SET maker = 'A' WHERE maker = 'B';

(a) Printer makers are D, E and H, so the laptops of A, B, F and G are deleted and only E's laptops 2001–2003 remain. Written with NOT EXISTS: DELETE FROM Laptop l WHERE NOT EXISTS (SELECT * FROM Product p1, Product p2 WHERE p1.model = l.model AND p2.maker = p1.maker AND p2.type = 'printer'). (b) The maker is stored only in Product, so one UPDATE changes the maker of all of B's PCs, laptops and printers at once. The question bank's answers are correct.

Summary: EXISTS (subquery) is TRUE when the subquery returns at least one row; NOT EXISTS when it returns none. Correlated with the outer row, they express "has some …" and "has no …" (slides 14–15), and NOT EXISTS is the NULL-safe way to write "but not". The maximum can be found with MAX, with >= ALL, or with NOT EXISTS of something larger. "For all" questions are division: NOT EXISTS (required MINUS owned), or a double NOT EXISTS. Subqueries also drive INSERT … SELECT and DELETE … WHERE … IN.
