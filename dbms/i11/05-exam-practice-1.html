Exam Practice I: Multi-Table Queries

Most exam questions on Lectures 08–11 give a new schema and ask for five queries that mix joins, grouping and subqueries. This chapter first gives a short method for attacking such questions, then works four of them from the question banks in full (toys, books, research projects, conference reviews), each with runnable checks on invented data.

1. A method for "write SQL for the following"

  1. Draw the schema's links. For every foreign key, note which columns join (Request.toy_id = Toys.id). Most mistakes are missing or wrong join conditions.
  2. Classify the question by its keywords.
    • "… and …", "with their …": a join (Lecture 08).
    • "for each …", "number of …", "total …": GROUP BY with an aggregate (Lecture 10).
    • "… that have at least / more than k …": HAVING COUNT.
    • "more than the average / maximum …": a scalar subquery; "… of the same …" makes it correlated (Lecture 11).
    • "… who do not / never …", "… without any …": anti-join: NOT EXISTS, NOT IN (beware NULLs), MINUS, or LEFT JOIN … IS NULL.
    • "the most / the highest (with ties)": HAVING COUNT(*) >= ALL (…) or = (SELECT MAX …).
    • "… all …": division with NOT EXISTS (… MINUS …).
    • "include those with none / zero": LEFT JOIN and COUNT(column).
  3. Decide the output and its duplicates. If the answer is a set of names, use DISTINCT or a subquery so a person is not repeated once per matching row; group by the key, not only the name.
  4. Check edge cases: ties, NULLs, empty groups, case of string literals, Oracle syntax (no AS for table aliases, MINUS, NVL).

Exam questions

DB QB · 21-22 1a · 25 marks  |  BUET QBank · CSE 215 | L-2/T-2 | 2021–22 · 25 marks

Consider the Toys database of a retail store. It has the following database schema: Toys (id, name, color, min_age, weight, number_available), Client (id, name, age, address, city), Request (client id, toy id). Toys records information about all of the toys in the store. Each toy has a unique integer id. Attributes name and color are strings that describe the toy; min_age, weight and number_available are integers giving the minimum age a child should be to use the toy, the weight of the toy in pounds, and how many are currently available in the store. Client stores information about each of the clients: a unique integer id, strings with the client's name, address and city, and an integer age. Request has a pair of integers indicating that a particular client has requested a particular toy. You should assume that all entries in all of the tables are not null. Answer the following:

i. Give the name of the clients who do not have any request at the moment for any toys.
ii. List the name of the toys that have weight more than the average weight of the toys with the same color.
iii. List the name of the requesting clients who have to wait because the toys are currently unavailable at the store.
iv. List all of the requests where age of the client is less than the min_age listed for the toy. The answer should include the client id, client name, and the toy id. The results should be sorted by client name.
v. Give the id and name of the "most popular" toy. The most popular toy is the one that has more requests than all others. If there is a tie so there is more than one toy with the maximum number of requests, give the ids and names of all of these toys.

Show worked answer

Links: Request.client_id = Client.id, Request.toy_id = Toys.id (the attribute names "client id" and "toy id" are written with underscores, since SQL identifiers cannot contain spaces).

i. Anti-join. Every value is NOT NULL, so NOT IN is safe:

SELECT name FROM Client
WHERE  id NOT IN (SELECT client_id FROM Request);

ii. Correlated subquery: compare each toy with the average of its own colour.

SELECT t1.name FROM Toys t1
WHERE  t1.weight > (SELECT AVG(t2.weight) FROM Toys t2 WHERE t2.color = t1.color);

iii. A client waits if he requested a toy with nothing in stock. DISTINCT, because a client may wait for several toys:

SELECT DISTINCT c.name
FROM   Client c, Request r, Toys t
WHERE  c.id = r.client_id AND r.toy_id = t.id
AND    t.number_available = 0;

iv.

SELECT c.id, c.name, r.toy_id
FROM   Client c, Request r, Toys t
WHERE  c.id = r.client_id AND r.toy_id = t.id
AND    c.age < t.min_age
ORDER BY c.name;

v. Count requests per toy and keep the toys whose count is at least every toy's count (ties included):

SELECT   t.id, t.name
FROM     Toys t, Request r
WHERE    t.id = r.toy_id
GROUP BY t.id, t.name
HAVING   COUNT(*) >= ALL (SELECT COUNT(*) FROM Request GROUP BY toy_id);

The question bank's answers are correct. Invented data for the checks: 8 toys, 6 clients; Lego and Doll House are tied as most popular with 3 requests each.

DB QB · 17-18 6a · 25 marks  |  BUET QBank · CSE 215 | L-2/T-2 | 2017–18 · 25 marks

Consider the following schemas: Books(isbn, title, publisher_id, publish_year, price_per_copy, copies_sold), Author(author_id, name, contact), Publisher(publisher_id, name, address), AuthorOfBook(book_id, author_id). Now answer the following queries.

(i) Find all the books authored by "Ernest Hemingway".
(ii) Find the revenue earned by each publisher between 1980 and 1990 by selling books.
(iii) Find the name of the authors who have published at least 5 books since 1995.
(iv) Find the publisher which published books of most of the authors.
(v) Find the name of all the books which are sold more copies than any other books published before 1990 by the same publisher.

Show worked answer

Links: AuthorOfBook.book_id = Books.isbn, AuthorOfBook.author_id = Author.author_id, Books.publisher_id = Publisher.publisher_id.

(i)

SELECT b.title
FROM   Books b, AuthorOfBook ab, Author a
WHERE  b.isbn = ab.book_id AND ab.author_id = a.author_id
AND    a.name = 'Ernest Hemingway';

(ii) Revenue of a book = price_per_copy × copies_sold; sum per publisher over the books published 1980–1990:

SELECT   p.publisher_id, p.name, SUM(b.price_per_copy * b.copies_sold) AS revenue
FROM     Publisher p, Books b
WHERE    p.publisher_id = b.publisher_id
AND      b.publish_year BETWEEN 1980 AND 1990
GROUP BY p.publisher_id, p.name;

(The schema has no sale dates, so "between 1980 and 1990" can only refer to the publication year.)

(iii) Group by the author's key; COUNT(DISTINCT) in case of duplicate rows:

SELECT   a.name
FROM     Author a, AuthorOfBook ab, Books b
WHERE    a.author_id = ab.author_id AND ab.book_id = b.isbn
AND      b.publish_year >= 1995
GROUP BY a.author_id, a.name
HAVING   COUNT(DISTINCT b.isbn) >= 5;

(iv) "Published books of most of the authors": count the distinct authors per publisher and take the maximum (ties included), without a WITH clause:

SELECT   p.name
FROM     Publisher p, Books b, AuthorOfBook ab
WHERE    p.publisher_id = b.publisher_id AND b.isbn = ab.book_id
GROUP BY p.publisher_id, p.name
HAVING   COUNT(DISTINCT ab.author_id) >= ALL
         (SELECT COUNT(DISTINCT ab2.author_id)
          FROM   Books b2, AuthorOfBook ab2
          WHERE  b2.isbn = ab2.book_id
          GROUP BY b2.publisher_id);

(v) "More copies than any other book published before 1990 by the same publisher" means more than every such book (in English "more than any other" means "more than all others"), so > ALL with a correlated subquery; the book itself is excluded from the comparison:

SELECT b1.title
FROM   Books b1
WHERE  b1.copies_sold > ALL (SELECT b2.copies_sold
                             FROM   Books b2
                             WHERE  b2.publisher_id = b1.publisher_id
                             AND    b2.publish_year < 1990
                             AND    b2.isbn <> b1.isbn);

A publisher with no other pre-1990 book makes the subquery empty and > ALL TRUE, so its books qualify vacuously; if you read the question as requiring at least one such book, use > (SELECT MAX(…)) instead and say so. The question bank's answers are correct (its (iv) uses a WITH clause, which Oracle accepts, but the version above shows it is not needed).

DB QB · 21 CT1 2 · 10 marks

The below figure contains some tables in the University Research Management schema. Here '...' represents other (unshown) attributes. Now, write an SQL code that prints the number of research projects a student is (or was) involved in who hasn't published any paper for those projects.

Show worked answer

Read the question as: for each student, count the projects he is (or was) involved in (rows of STUDENT_PROJECT) for which he has no paper (no STUDENT_PAPER row of his whose PAPER belongs to that project).

SELECT   sp.student_id, COUNT(*) AS projects_without_paper
FROM     STUDENT_PROJECT sp
WHERE    NOT EXISTS (SELECT *
                     FROM   STUDENT_PAPER x, PAPER p
                     WHERE  x.paper_id = p.id
                     AND    x.student_id = sp.student_id
                     AND    p.project_id = sp.project_id)
GROUP BY sp.student_id;

The correlated NOT EXISTS looks, for each (student, project) involvement, for a paper of that student under that project; involvements with none survive and are counted per student. A student who published in every project he joined (or joined none) does not appear; to list him with 0, start from STUDENT with a left join that carries the NOT EXISTS in its ON clause:

SELECT   s.id, COUNT(sp.project_id) AS projects_without_paper
FROM     STUDENT s LEFT JOIN STUDENT_PROJECT sp
         ON  sp.student_id = s.id
         AND NOT EXISTS (SELECT * FROM STUDENT_PAPER x, PAPER p
                         WHERE  x.paper_id = p.id AND x.student_id = s.id
                         AND    p.project_id = sp.project_id)
GROUP BY s.id;

Invented data for the check: 4 students, 3 projects, 4 papers (one standalone, with no project).

DB QB · 20-21 5b · 15 marks  |  BUET QBank · CSE 215 | L-2/T-2 | 2020–21 · 15 marks

You are in charge of managing the program committee for an important conference. The conference database stores information about papers submitted to the conference (table Paper), reviewers on the program committee (table Reviewer), and the assignment of reviewers to papers (table Reviews). Each reviewer will have to review a set of papers. Each paper will be reviewed by a subset of reviewers. Paper(pid, title), Reviewer(rid, name), Reviews(rid, pid).

i. Declare the conference database using CREATE TABLE. Include the declaration of the keys and maintain the referential integrities as needed: pid is a unique paper identifier and the primary key of Paper; rid is a unique reviewer identifier and the primary key of Reviewer; rid in Reviews must be someone mentioned in Reviewer, and modifications to Reviewer that violate this constraint result in the rid in Reviews being set to NULL upon deletion, and update of the rid in Reviews; pid in Reviews must be a paper mentioned in Paper, and modifications to Paper that violate this constraint are rejected. A reviewer is assigned zero or more papers; a paper is assigned zero or more reviewers.
ii. Write a SQL query that finds all papers with fewer than three reviewers assigned to them. The output should be a list of paper titles, and it should include papers without any reviewers assigned to them.
iii. Write a SQL query that finds the reviewers with the most papers assigned to them. There can be more than one such reviewer. The output should be a list of reviewer names. A reviewer should be listed if no other reviewer has strictly more papers to review.

Show worked answer

i. Because a deleted reviewer's rid must become NULL, rid in Reviews must be nullable, so (rid, pid) cannot be the primary key (key columns are never NULL). Use a UNIQUE constraint, which allows NULLs, to stop the same reviewer being assigned twice to a paper.

CREATE TABLE Paper (
  pid   NUMBER PRIMARY KEY,
  title VARCHAR2(200) NOT NULL
);
CREATE TABLE Reviewer (
  rid  NUMBER PRIMARY KEY,
  name VARCHAR2(100) NOT NULL
);
CREATE TABLE Reviews (
  rid NUMBER,
  pid NUMBER NOT NULL,
  CONSTRAINT reviews_rid_fk FOREIGN KEY (rid) REFERENCES Reviewer(rid) ON DELETE SET NULL,
  CONSTRAINT reviews_pid_fk FOREIGN KEY (pid) REFERENCES Paper(pid),   -- default: reject
  CONSTRAINT reviews_uq UNIQUE (rid, pid)
);

Oracle specifics. (1) "Rejected" is Oracle's default behaviour (NO ACTION) when no ON DELETE clause is given; Oracle has no RESTRICT keyword. (2) Oracle has no ON UPDATE clause at all: a foreign key cannot cascade updates of the parent key. In standard SQL the rid constraint would read REFERENCES Reviewer(rid) ON DELETE SET NULL ON UPDATE CASCADE. In Oracle, the cascading update must be programmed, for example with an AFTER UPDATE OF rid trigger on Reviewer that updates Reviews, together with a deferrable constraint (or the application updates the child rows itself). The question bank's answer writes ON DELETE RESTRICT ON UPDATE CASCADE, which is correct standard SQL but is rejected by Oracle; it also adds a surrogate key review_id, which is fine.

ii. The left join keeps papers with no reviews; COUNT(r.rid) counts only real reviewers (0 for none, and a reviewer whose rid was set to NULL no longer counts):

SELECT   p.title
FROM     Paper p LEFT JOIN Reviews r ON p.pid = r.pid
GROUP BY p.pid, p.title
HAVING   COUNT(r.rid) < 3;

iii.

SELECT   rv.name
FROM     Reviewer rv, Reviews r
WHERE    rv.rid = r.rid
GROUP BY rv.rid, rv.name
HAVING   COUNT(*) >= ALL (SELECT COUNT(*) FROM Reviews
                          WHERE rid IS NOT NULL GROUP BY rid);

(If no reviewer had any paper at all, every reviewer would tie at 0; a left join from Reviewer with COUNT(r.pid) handles that corner case.) Invented data for the checks: 5 papers, 4 reviewers; Karim and Lima tie with 3 papers each.

More practice

Six more exercises on the same four databases, from easy to exam level.

Summary: attack a multi-part query question by drawing the join links, classifying each part by its keywords (join, group, compare with an aggregate, anti-join, maximum with ties, division), choosing the output's duplicates, and checking edge cases. Most questions reduce to a handful of patterns: correlated comparison with AVG, NOT IN / NOT EXISTS, GROUP BY with HAVING COUNT(…) >= ALL (…), LEFT JOIN with COUNT(column). Know Oracle's limits too: no ON UPDATE CASCADE, no RESTRICT, no AS for table aliases.
