B+ Tree Structure

The anatomy of a B+ tree: its nodes, what the keys and pointers in each node mean, the rules for leaves and non-leaves, and how full each node is allowed to be (with the answer for n = 99).

1. The big picture (slide 26)

A B+ tree is an index organised as a tree of nodes. Each node is one disk block. The slides' example indexes the instructor relation on name:

Root node
The single node at the top, [Mozart]. Every search starts here.
Internal (non-leaf) nodes
Nodes between the root and the leaves, here [Einstein, Gold] and [Srinivasan]. They contain only keys and pointers to other nodes, which guide the search downward.
Leaf nodes
The bottom level. Together the leaves contain every search-key value in the file, in sorted order, each with a pointer to its record. (Lines from the leaves to the records are left out of Figure 1 to keep it readable; Section 3 shows them for one leaf.)

All paths from root to leaf are the same length

This property is what the “B” stands for: balanced. Every leaf is at the same depth, so every search reads the same number of nodes. A tree can never become lopsided, with some keys hidden at the end of a long chain, which is exactly the overflow-chain problem from Chapter 7. Step through all five paths:

2. Inside a node (slide 28)

  • The Ki are search-key values. Inside a node they are kept sorted: K₁ < K₂ < K₃ < … < Kn−1.
  • The Pi are pointers. In a non-leaf node they point to child nodes. In a leaf they point to records (or to buckets of records, if the key is not unique).
  • n is the maximum number of pointers in a node, called the fan-out. It is chosen so that one node fills one disk block. The figures here use n = 4 to stay small. Real B+ trees have n around 100 or more (Chapter 9).

3. Leaf nodes (slide 29)

The slide lists three properties of a leaf node:

  1. For i = 1, 2, …, n−1, pointer Pi points to a file record with search-key value Ki.
  2. Leaves are in order: if Li and Lj are leaves and i < j (Li is to the left), every key in Li is ≤ every key in Lj.
  3. Pn points to the next leaf in search-key order. This last pointer slot is not used for a record.

The next-leaf pointers chain all the leaves into one sorted list. That makes range queries efficient: for WHERE name BETWEEN 'Crick' AND 'Katz', search down to Crick once, then walk right along the leaves (Crick, Einstein, El Said, Gold, Katz) without going back up the tree.

4. Non-leaf nodes (slide 30)

For a non-leaf node with m pointers, the keys split the key space into ranges, one per pointer:

  • All search keys in the subtree that P₁ points to are less than K₁.
  • For 2 ≤ i ≤ m − 1, all search keys in the subtree that Pi points to are ≥ Ki−1 and < Ki.
  • All search keys in the subtree that Pm points to are ≥ Km−1.

The slide writes the middle rule as “for 2 ≤ i ≤ n − 1” and the last one with Pn and Kn−1, which describes a full node. For a node that uses only m of its n pointers, read n as m, as in the list above.

In short: the pointer to the left of a key leads to smaller values, and the pointer to its right leads to values greater than or equal to it.

Non-leaf nodes form a multilevel sparse index on the leaf nodes. Explain!

Look at the internal node [Einstein, Gold] and its three leaves. Its keys Einstein and Gold are exactly the first keys of its second and third leaves. That is a sparse index (Chapter 2): one entry per block (leaf), holding the block's smallest key. The first leaf needs no key, since everything smaller than Einstein goes there. The root [Mozart] does the same one level up: Mozart is the smallest key under its right child. So the non-leaf levels are a sparse index on the leaves, plus a sparse index on that sparse index, which is precisely the multilevel index from Chapter 4. The difference is that B+ tree nodes may be partly empty and are split or merged locally, so the structure never needs reorganizing.

5. How full must a node be?

To keep the tree shallow, nodes may not become too empty. Each node (except the root) must be at least about half full. With fan-out n:

Node typePointers (children)Search keys
Root, when it is not a leaf2 to n1 to n − 1
Root, when it is the only node (a leaf)—0 to n − 1
Internal (non-leaf, non-root)⌈n/2⌉ to n⌈n/2⌉ − 1 to n − 1
Leaf—⌈(n−1)/2⌉ to n − 1

Check against Figure 1 (n = 4): leaves hold 2 or 3 keys (⌈3/2⌉ = 2 to 3), internal nodes have 2 to 4 children ([Srinivasan] has 2, [Einstein, Gold] has 3), and the root has 2 children.

Question (worked answer): minimum and maximum keys for n = 99

Find the minimum and maximum number of search keys in the root, leaf and non-leaf nodes of a B+ tree with n = 99.

A node holds at most n = 99 pointers, so at most n − 1 = 98 keys, whatever its type. The minimums differ:

NodeMinimum keysMaximum keysWhy
Root (non-leaf)198A non-leaf root needs at least 2 children, so at least 1 key to separate them.
Root (if it is the only node)098An empty tree is allowed.
Non-leaf (internal)4998At least ⌈99/2⌉ = 50 children, and 50 children need 49 keys.
Leaf4998At least ⌈(99−1)/2⌉ = ⌈49⌉ = 49 keys.

BUET QBank · CSE 303 | L-3/T-1 | 2017–18, 2016–17, 2011–12 · 8 marks

Write down the key properties of a B+ tree.

Show worked answer

For a B+ tree with fan-out n (at most n pointers per node):

  1. Balanced: every path from the root to a leaf has the same length.
  2. Node format: a node holds up to n pointers P₁…Pn and n − 1 keys K₁ < K₂ < … < Kn−1, kept sorted. A node normally fills one disk block.
  3. Leaves hold all keys: every search-key value of the file appears in some leaf, with Pi pointing to the record (or bucket) for Ki.
  4. Leaves are ordered and chained: all keys in a leaf to the left are ≤ all keys in a leaf to the right, and Pn of each leaf points to the next leaf, which makes range scans cheap.
  5. Non-leaf nodes route the search: with m pointers, the subtree of P₁ has keys < K₁, the subtree of Pi has keys ≥ Ki−1 and < Ki, and the subtree of Pm has keys ≥ Km−1. The non-leaf levels form a multilevel sparse index on the leaves.
  6. Occupancy: a non-leaf node other than the root has between ⌈n/2⌉ and n children; a leaf has between ⌈(n−1)/2⌉ and n − 1 keys; a non-leaf root has at least 2 children; a root that is a leaf may hold 0 to n − 1 keys.
  7. Height: with K keys the height is at most ⌈log⌈n/2⌉(K)⌉, so a lookup reads very few nodes.
  8. Self-maintaining: inserts split full nodes and deletes merge or redistribute underfull ones, locally, so the file never needs a full reorganization (Chapter 7).

Note: the question bank gives the leaf minimum as ⌈m/2⌉ − 1 keys. That equals the textbook's ⌈(n−1)/2⌉ only when n is odd; for n = 4 the correct minimum is ⌈3/2⌉ = 2, not 1.

BUET QBank · CSE 303 | L-3/T-1 | 2014–15 · 10 marks

Discuss the basic principles of B+ tree index structure.

Show worked answer

What it is. A B+ tree is a balanced, multilevel ordered index whose nodes are disk blocks. Its leaves contain every search key with a pointer to the record, linked left to right in key order. The levels above form a sparse index on the leaves (Section 4).

Principle 1, large fan-out. A node holds about n ≈ 100 or more pointers, so each level multiplies the reach by at least ⌈n/2⌉. A million keys need at most 4 levels (Chapter 9), so a lookup costs about 4 block reads.

Principle 2, balance. All leaves are at the same depth, so every lookup costs the same: the height of the tree.

Principle 3, routing by key ranges. In a non-leaf node, the pointer left of Ki leads to keys < Ki and the pointer right of it to keys ≥ Ki. The search follows one pointer per level (find(v), Chapter 9).

Principle 4, nodes stay at least half full. Every node except the root keeps between about n/2 and n pointers. This guarantees the height bound and limits wasted space to at most half a node.

Principle 5, local reorganization. Insertion puts the key in its leaf; a full leaf splits into two half-full leaves and one new key goes into the parent, which may split in turn, and a root split adds a level. Deletion removes the key; an underfull node borrows from a sibling or merges with it, and a root left with one child is removed. Only nodes on one root-to-leaf path change, so the tree never needs the periodic full reorganization an indexed-sequential file needs. (Insertion and deletion are taught in detail in B+ tree insertion and B+ tree deletion.)

Principle 6, sequential access. The leaf chain gives the keys in sorted order, so a range query does one descent and then walks along the leaves.

BUET QBank · CSE 303 | L-3/T-1 | 2011–12 · 12 marks (similar: CSE 215 | L-3/T-1 | 2012–13)

Suppose in a B+ tree, pointers are 4 bytes long and keys are 12 bytes long. How many keys and pointers will a block of 16,384 bytes have? For a one million record table, what would be the expected length of the index?

Show worked answer

Keys and pointers per block. A node with n pointers has n − 1 keys and must fit in the block:

4n + 12(n − 1) ≤ 16,384 ⇒ 16n ≤ 16,396 ⇒ n ≤ 1024.75

So a node holds n = 1024 pointers and 1023 keys (1024 × 4 + 1023 × 12 = 16,372 bytes). A leaf uses the same layout: 1023 (key, record-pointer) pairs plus the next-leaf pointer.

Length of the index for 1,000,000 keys. “Length” is read here as the number of levels (the length of a root-to-leaf path); the total size in blocks follows from the same count.

AssumptionKeys per leafLeavesLevels aboveLevelsBlocks
Completely full nodes (best case)1023⌈10⁶/1023⌉ = 978978 ≤ 1024 → 1 root2979 (≈ 16.0 MB)
Typical fill, about 69% (706 keys and 706 children per node)706⌈10⁶/706⌉ = 1417⌈1417/706⌉ = 3, then 1 root31421 (≈ 23.3 MB)
Half-full nodes (worst case)512⌈10⁶/512⌉ = 1954⌈1954/512⌉ = 4, then 1 root31959 (≈ 32.1 MB)

So the index has 3 levels in the expected case (2 if every node is packed full), and the slide formula agrees: ⌈log⌈1024/2⌉(10⁶)⌉ = ⌈log₅₁₂ 10⁶⌉ = ⌈2.21⌉ = 3. In bytes, the expected index is about 1421 × 16,384 = 23,281,664 bytes ≈ 23.3 MB. A lookup reads 3 nodes plus the data block.

Summary: a B+ tree is a balanced tree of block-sized nodes: a root, internal nodes and leaves, with every root-to-leaf path the same length. Each node holds up to n pointers and n − 1 sorted keys. Leaves hold every key with a pointer to its record, plus a pointer to the next leaf. Non-leaf nodes route the search by key ranges and act as a multilevel sparse index on the leaves. Every node except the root stays at least half full.
