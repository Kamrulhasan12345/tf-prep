Grouping Examples on the Computer Database

Slide 28 lists seven questions on the Product/PC/Laptop database and slides 29–37 solve them. This chapter works each one on the textbook's sample data, explains why each clause is there, corrects slide 31 (its self-join answers a different question), and finishes with a seven-part exam question on the same schema.

Schema (Lecture 08, Chapter 5): Product(maker, model, type), PC(model, speed, ram, hd, price), Laptop(model, speed, ram, hd, screen, price), plus Printer(model, color, type, price). The playgrounds use the full textbook data: makers A to H, 13 PCs, 10 laptops, 7 printers.

1. Makers of at least three different PC models (slides 29–31)

SELECT   maker
FROM     Product
WHERE    type = 'pc'
GROUP BY maker
HAVING   COUNT(model) >= 3;

WHERE keeps only PC rows; GROUP BY makes one group per PC maker; HAVING keeps the groups with at least 3 models. Since model is the key of Product, the models in a group are automatically different, so COUNT(model) counts different models (COUNT(DISTINCT model) would say so explicitly). On the sample data: A has 3 PCs, B 3, C 1, D 3, E 3, so the answer is A, B, D, E.

Slide 31 offers a second solution without aggregation, using a three-way self-join:

SELECT DISTINCT p1.maker
FROM   Product p1, Product p2, Product p3
WHERE  p1.type <> p2.type
AND    p1.type <> p3.type
AND    p2.type <> p3.type
AND    p1.maker = p2.maker
AND    p1.maker = p3.maker;

Question (worked answer): is slide 31's query correct?

No: it answers a different question. It looks for three products of the same maker with three pairwise different types. That is "makers that produce all three types of product" (slide 32's question), and on the sample data it returns only E, while the right answer to "at least three different PC models" is A, B, D, E. To ask for three different PC models, require the three rows to be PCs and to have different models:

SELECT DISTINCT p1.maker
FROM   Product p1, Product p2, Product p3
WHERE  p1.type = 'pc' AND p2.type = 'pc' AND p3.type = 'pc'
AND    p1.maker = p2.maker AND p1.maker = p3.maker
AND    p1.model < p2.model AND p2.model < p3.model;

Using < instead of <> makes each set of three models appear once (Lecture 08, Chapter 4). The self-join idea works for "at least 3" but becomes clumsy for "at least 10" (ten copies of Product); GROUP BY with HAVING COUNT is the general tool.

2. Makers of all three types (slide 32)

SELECT   maker
FROM     Product
GROUP BY maker
HAVING   COUNT(DISTINCT type) = 3;

Each maker's group contains one row per product; the number of different types in the group must be 3 (pc, laptop, printer). DISTINCT is essential: maker A has 6 products but only 2 types. Answer: E, the only maker with PCs, laptops and printers.

3. Only one product type, more than one model (slide 33)

SELECT   maker
FROM     Product
GROUP BY maker
HAVING   COUNT(DISTINCT type) = 1
AND      COUNT(model) > 1;

HAVING may combine several conditions with AND/OR. Answer: F (two laptops) and H (two printers). C and G also make one type, but only one model each.

4. Averages (slides 34–36)

Average speed of PCs (slide 34): no grouping, one number over all 13 PCs.

SELECT AVG(speed) FROM PC;            -- 2.4846… GHz

Average price of PCs made by manufacturer 'A' (slide 35): the maker is in Product, the price in PC, so join first, then aggregate the joined rows.

SELECT AVG(price)
FROM   Product, PC
WHERE  Product.model = PC.model
AND    maker = 'A';                   -- (2114 + 995 + 478) / 3 = 1195.67

For each speed of PC above 2.0, the average price (slide 36): group by speed, after WHERE has removed the slow PCs. Note "above 2.0" means > 2.0, so the 2.00 GHz PC (1009) is excluded.

SELECT   speed, AVG(price)
FROM     PC
WHERE    speed > 2.0
GROUP BY speed;

5. Maximum PC price per maker (slide 37)

SELECT   maker, MAX(price)
FROM     PC, Product
WHERE    PC.model = Product.model
GROUP BY maker;

The join attaches the maker to each PC; GROUP BY maker gathers each maker's PCs; MAX gives the most expensive. Only makers who sell PCs appear, because the join with PC drops everyone else (exactly what "for each manufacturer who sells PCs" asks). A: 2114, B: 1049, C: 510, D: 770, E: 959.

Question (worked answer): how do you also get the model of the most expensive PC of each maker?

Not by adding model to the SELECT list: it is not a grouping attribute (Chapter 3, slide 26). You need the maximum first and then the rows that reach it, which is a subquery, the topic of Lecture 11:

SELECT maker, PC.model, price
FROM   Product, PC
WHERE  Product.model = PC.model
AND    (maker, price) IN (SELECT maker, MAX(price)
                          FROM   Product, PC
                          WHERE  Product.model = PC.model
                          GROUP BY maker);

BUET QBank · CSE 303 | L-3/T-1 | 2015–16 · 28 marks

Consider the following relational database schema: Product(maker, model, type), PC(model, speed, ram, hd, price), Laptop(model, speed, ram, hd, screen, price), Printer(model, color, type, price). The Product relation gives the manufacturer, model number and type (PC, laptop, or printer) of various products. We assume for convenience that model numbers are unique over all manufacturers and product types. The PC relation gives for each model number that is a PC the speed (of the processor, in gigahertz), the amount of RAM (in megabytes), the size of the hard disk (in gigabytes), and the price. The Laptop relation is similar, except that the screen size (in inches) is also included. The Printer relation records for each printer model whether the printer produces color output ('T', if so; 'F' otherwise), the process type (laser or ink-jet, typically), and the price. Write the following SQL queries:

(a) Find those manufacturers that sell Laptops, but not PCs or Printers.
(b) Find those hard disk sizes that occur in two or more PCs.
(c) Find those pairs of PC models that have both the same speed and RAM. A pair should be listed only once.
(d) Find the manufacturers of PCs with at least three different speeds.
(e) Find the makers who produce only one type of product.
(f) Find the maker(s) of the cheapest color printer(s).
(g) Find the PC model with maximum processing speed without using any aggregate function.

Show worked answer

Results are given for the textbook's sample data (the same data as the playgrounds), where type values are stored in lower case ('pc', 'laptop', 'printer').

(a) Set difference (Lecture 08):

SELECT maker FROM Product WHERE type = 'laptop'
MINUS
SELECT maker FROM Product WHERE type IN ('pc', 'printer');      -- F, G

(b) Group the PCs by disk size and keep groups of 2 or more:

SELECT hd FROM PC GROUP BY hd HAVING COUNT(*) >= 2;          -- 80, 160, 250

(c) Self-join; < lists each pair once and excludes a PC paired with itself:

SELECT p1.model, p2.model
FROM   PC p1, PC p2
WHERE  p1.speed = p2.speed AND p1.ram = p2.ram
AND    p1.model < p2.model;                                      -- (1004, 1012)

(d) Join to get the maker, group by maker, count distinct speeds (B has 3 PCs but only 2 speeds, 2.80 and 3.20):

SELECT   maker
FROM     Product, PC
WHERE    Product.model = PC.model
GROUP BY maker
HAVING   COUNT(DISTINCT speed) >= 3;                            -- A, D, E

(e)

SELECT maker FROM Product GROUP BY maker HAVING COUNT(DISTINCT type) = 1;   -- C, F, G, H

(f) The cheapest price among colour printers is a single value, found by a subquery; then the makers of colour printers with that price (ties included):

SELECT maker
FROM   Product, Printer
WHERE  Product.model = Printer.model
AND    color = 'T'
AND    price = (SELECT MIN(price) FROM Printer WHERE color = 'T');   -- E (model 3001, 99)

Both color = 'T' conditions are needed: without the outer one, a black-and-white printer that happened to cost the same minimum would be listed.

(g) Without aggregates: a PC has maximum speed if its speed is ≥ every PC's speed, or equivalently if no PC is faster (Lecture 11, slide 16):

SELECT model FROM PC WHERE speed >= ALL (SELECT speed FROM PC);   -- 1005, 1006
-- or
SELECT model FROM PC p1
WHERE NOT EXISTS (SELECT * FROM PC p2 WHERE p2.speed > p1.speed);

Note: the question bank's answer to (a) writes type IN ('PC', 'printer'). Oracle compares strings case-sensitively, so with the data stored as 'pc' the PC makers would not be subtracted and the answer would wrongly include A and B (E is still removed, because it makes printers). Use the stored spelling. The bank also writes EXCEPT, which Oracle accepts only from version 21c; MINUS is the Oracle operator taught in Lecture 08. The bank's other parts are correct.

Summary: "makers with at least k models / types / speeds" is GROUP BY maker HAVING COUNT(…) ≥ k, with DISTINCT whenever repeated values must count once. When the attribute you aggregate lives in another table, join first and group the joined rows. HAVING can combine conditions. Slide 31's self-join compares types and therefore answers slide 32's question; the corrected version compares models of PC rows.
