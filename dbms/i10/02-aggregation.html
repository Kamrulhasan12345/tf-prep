Aggregate Functions

An aggregate function turns a whole column of values into one value: a sum, a count, an average, a minimum or a maximum. This chapter defines the five aggregates, explains exactly how they treat NULLs (the difference between COUNT(*) and COUNT(column) is animated), shows COUNT(DISTINCT …), and points out two slips on slides 16 and 18.

1. The five aggregates (slide 13)

Aggregate function
A function that takes a bag of values (one per row) and returns a single value. SQL has SUM, AVG, MIN, MAX and COUNT. Without GROUP BY, the aggregate is computed over all rows that pass the WHERE clause, and the query returns exactly one row.
FunctionReturnsWorks on
SUM(x)total of the non-NULL valuesnumbers
AVG(x)SUM(x) / COUNT(x), the mean of the non-NULL valuesnumbers
MIN(x), MAX(x)smallest / largest non-NULL valuenumbers, strings, dates
COUNT(x)number of rows where x is not NULLany type
COUNT(*)number of rows, whatever they containwhole rows

The slide's two examples use a car-style Product table (with columns maker and year, different from the computer database):

SELECT AVG(price) FROM Product WHERE maker = 'Toyota';
SELECT COUNT(*)   FROM Product WHERE year > 1995;

The WHERE clause runs first (it filters rows), then the aggregate summarises what is left. Slide 13 states two rules:

  1. An aggregate applies to a single attribute, but that attribute may be a formula over several columns (e.g. SUM(price*quantity)). COUNT(*) is the exception: it counts rows, not values.
  2. NULL values are ignored, again except by COUNT(*).

2. COUNT(*) versus COUNT(column) (slides 14–15)

With the Marks table of Chapter 1 (one mark is NULL):

SELECT COUNT(*)    FROM Marks;     -- 4: there are 4 rows
SELECT COUNT(mark) FROM Marks;     -- 3: only 3 rows have a mark

Slide 15 adds a fifth row in which both columns are NULL. COUNT(*) becomes 5, because a row of NULLs is still a row. COUNT(mark) stays 3. (The slides repeat Chapter 1's sentence "any NULL in a formula will cause a NULL result" at the top of these slides; it is about formulas, not about aggregates, which skip NULLs instead of turning NULL.)

The same rule affects AVG: it divides by the number of non-NULL values. AVG(mark) = (43 + 57 + 72) / 3 = 57.33, not 172 / 4 = 43. If you want missing marks counted as 0, write AVG(NVL(mark, 0)), which gives 43. Two edge cases: over zero rows (or only NULLs) COUNT returns 0 while SUM, AVG, MIN and MAX return NULL.

3. COUNT and duplicates: COUNT(DISTINCT …) (slide 16)

COUNT counts values with duplicates, unless told otherwise:

SELECT COUNT(category) FROM Product WHERE year > 1995;            -- counts rows with a category
SELECT COUNT(DISTINCT category) FROM Product WHERE year > 1995;   -- counts different categories

If the question is "how many categories?", the first query is wrong: three sedans count as three. COUNT(DISTINCT x) removes duplicates (and NULLs) first. DISTINCT also works inside SUM and AVG, though that is rarely what you want.

Slide 16 says COUNT(category) is "same as COUNT(*)". That is true only when category is never NULL. In our sample data the Mitsubishi Lancer has no category, so for year > 1995 COUNT(*) = 7 but COUNT(category) = 6, and COUNT(DISTINCT category) = 3 (sedan, SUV, hybrid).

4. Totals from the Purchase table (slides 17–18)

Find total sales. An aggregate over a formula (slide 17):

SELECT SUM(price * quantity)
FROM   Purchase;                     -- 20 + 5 + 10 + 30 = 65

The formula is evaluated for each row, then summed. Find total sales of product Bagel (slide 18):

SELECT SUM(price * quantity)
FROM   Purchase
WHERE  product = 'Bagel';            -- 20 + 30 = 50

The slide writes product = 'bagel' with a lower-case b. In Oracle, string comparison is case-sensitive, so 'bagel' does not equal 'Bagel', no row qualifies, and SUM over no rows returns NULL, not 50. Write the literal exactly as stored, or compare UPPER(product) = 'BAGEL'.

Two rules you will need in Chapter 3

  • No plain columns next to aggregates (without GROUP BY). SELECT product, SUM(quantity) FROM Purchase is an error in Oracle (ORA-00937: not a single-group group function): SUM produces one row for the whole table, and there is no single product to print beside it. GROUP BY (next chapter) is the fix.
  • No aggregates in WHERE. WHERE tests one row at a time, before any aggregate has been computed, so WHERE SUM(quantity) > 30 is an error (ORA-00934: group function is not allowed here). Conditions on aggregates go in HAVING, or in a subquery (Lecture 11).

(The playground's SQLite is more lenient about the first rule and returns an arbitrary product; Oracle is not, so always write it the Oracle way.)

Summary: SUM, AVG, MIN, MAX and COUNT reduce a column (or a formula) to one value; without GROUP BY a query with aggregates returns one row. All aggregates ignore NULLs except COUNT(*), which counts rows: COUNT(*) ≥ COUNT(col), and AVG divides by the number of non-NULL values. COUNT(DISTINCT col) counts different values. Plain columns cannot sit beside aggregates without GROUP BY, and aggregates cannot appear in WHERE. Oracle compares strings case-sensitively, so slide 18's 'bagel' matches nothing.
