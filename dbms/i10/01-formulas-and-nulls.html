Formulas, NULLs and Three-Valued Logic

Before aggregating, we need two tools: arithmetic formulas inside queries, and a precise understanding of NULL. This chapter covers slides 3–12: computing values in SELECT, what NULL means, why any formula with NULL gives NULL, and the three-valued logic (TRUE, UNKNOWN, FALSE) that decides which rows a WHERE clause keeps. A small tool evaluates slide 9's condition for values you choose.

Slide 2 outlines the lecture: mathematical operators and functions (this chapter), aggregation (Chapter 2; the slide cites textbook sections 6.4.3–6.4.6), the HAVING clause (Chapter 3), and many examples (Chapter 4).

1. Formulas in SQL (slides 3–4)

So far every query returned stored values. SQL also lets you compute: a formula may appear wherever a column or literal may appear, in SELECT, WHERE, the SET of an UPDATE, the VALUES of an INSERT, and HAVING. The infix operators are +, -, * and / (slide 3), with the usual precedence (* and / before + and −) and parentheses to override it.

Find the day-wise sale of each product (slide 4). The sale amount is price × quantity:

SELECT product, day, price*quantity AS Sales
FROM   Purchase;
Column alias
A name given to an output column with AS name (the AS is optional in Oracle for column aliases, and forbidden for table aliases). Without it, the column would be titled PRICE*QUANTITY. Put the alias in double quotes to keep spaces or lower case: AS "Total Sales".

The slides print dates as MM/DD/YYYY (10/21/2005). The table stores them as Oracle DATE values; how a date is displayed depends on the session's date format (Oracle's default is DD-MON-RR, e.g. 21-OCT-05), and the playground shows them as 2005-10-21.

2. NULL (slides 5–6)

NULL
A special marker meaning "no value here". It is not zero and not the empty string. Slide 5 lists what it can mean: the value does not exist (a person with no middle name), the value exists but is unknown (a student whose mark is not yet entered), or the value is not applicable (the commission of an employee who is not in sales).
Nullable attribute
A column allowed to contain NULL. The schema decides for each column: mark NUMBER is nullable, mark NUMBER NOT NULL is not; primary-key columns are never nullable.

Rule 1: any NULL in a formula makes the whole formula NULL (slide 6, "not a value of 0"). If a mark is unknown, mark/3 is unknown too; treating it as 0 would invent a mark of 0. So for the Marks table:

SELECT student, mark, mark/3
FROM   Marks;

gives 43 → 14.3333333, 57 → 19, 72 → 24 and Pinder Surree's NULL → NULL. (Slide 6 prints Helen Treacy's mark as 32 in the input table and as 72 in the output. 72 is the right value for mark/3 = 24; the 32 is a typo. Our sample data uses 72.)

If you really want a NULL treated as some value, say so explicitly with Oracle's NVL(mark, 0), which returns 0 when mark is NULL. That is a decision about meaning, not something SQL does on its own.

3. Comparisons with NULL: three-valued logic (slides 7–10)

What is x = 'Joe' when x is NULL? We cannot say it is true (x might not be Joe) or false (x might be Joe). SQL answers UNKNOWN. So conditions in SQL have three truth values, and slide 7 gives them numbers that make the rules easy:

Every comparison (=, <, >, <>, …) with a NULL operand is UNKNOWN, even NULL = NULL. The min/max rules then give the full truth tables:

Rule 2: the WHERE clause keeps a row only if its condition is TRUE. Slide 8 recalls the order in which a query is evaluated: (1) FROM, (2) WHERE, (3) SELECT. Only rows whose WHERE condition evaluates to TRUE are passed on to SELECT. UNKNOWN is treated like FALSE: the row is dropped.

Question (worked answer): slide 9, "Will it be in the result?" (age = 20, height = NULL, weight = 200)

SELECT * FROM Person
WHERE (age < 25) AND (height > 6 OR weight > 190)

age < 25 → 20 < 25 = TRUE (1). height > 6 → NULL > 6 = UNKNOWN (0.5). weight > 190 → 200 > 190 = TRUE (1).
OR: max(0.5, 1) = 1 (TRUE). AND: min(1, 1) = 1 (TRUE). Yes, the row is in the result. The unknown height does not matter, because the weight alone makes the OR true.

Question (worked answer): slide 10 (age = NULL, height = 5, weight = 200)

age < 25 → UNKNOWN (0.5). height > 6 → 5 > 6 = FALSE (0). weight > 190 → TRUE (1).
OR: max(0, 1) = 1. AND: min(0.5, 1) = 0.5 = UNKNOWN. Only TRUE passes, so no, the row is not in the result.

4. Unexpected behaviour, and IS NULL (slides 11–12)

SELECT * FROM Person
WHERE  age < 25 OR age >= 25;

In ordinary logic this condition is always true, so it should return every person. Slide 11 warns that some persons are not included: for a person whose age is NULL both comparisons are UNKNOWN, max(0.5, 0.5) = 0.5, and the row is dropped. In our sample data Babu and Era have no age, so 3 of the 5 persons are returned.

To test for NULL you need special predicates, because age = NULL is itself always UNKNOWN (slide 12):

x IS NULL / x IS NOT NULL
TRUE or FALSE (never UNKNOWN) depending on whether x is NULL. These are the only correct ways to look for NULLs.
SELECT * FROM Person
WHERE  age < 25 OR age >= 25 OR age IS NULL;     -- now all persons

Question (worked answer): which of these return the person with age NULL?

(a) WHERE NOT (age < 25): NOT UNKNOWN = 1 − 0.5 = UNKNOWN, so no. (b) WHERE age <> 30: UNKNOWN, no. (c) WHERE NVL(age, 0) < 25: NVL makes it 0, 0 < 25 is TRUE, yes. (d) WHERE age IS NULL OR age > 100: TRUE OR UNKNOWN = TRUE, yes. The lesson: a negated or "not equal" condition does not pick up NULLs; you must ask for them with IS NULL.

Summary: formulas with + − * / can appear in SELECT, WHERE, SET, VALUES and HAVING, and AS names the output column. NULL means "no value" (missing, unknown or not applicable); any formula with a NULL operand is NULL, and any comparison with NULL is UNKNOWN. SQL logic has three values (F = 0, U = 0.5, T = 1) with AND = min, OR = max, NOT = 1 − x, and WHERE keeps only rows that evaluate to TRUE. Therefore "x < 25 OR x >= 25" misses NULLs; test for them with IS NULL / IS NOT NULL.
