Two-Pass Algorithms Based on Hashing

Hashing reaches the same goal as sorting by a different road: split the data into M − 1 buckets so that everything that must be compared ends up in the same bucket, then run a one-pass algorithm on each bucket. This chapter gives hash partitioning, hash-based δ, γ, ∪, ∩, −, and the hash join, with costs, memory rules, two slide corrections and a worked exam question.

1. Partitioning a relation by hashing (slides 29–30)

Hash partitioning
Splitting R into M − 1 buckets of roughly equal size with a hash function h: tuple t goes to bucket h(t). Each bucket is written to disk as its own set of blocks.

Memory: one buffer per bucket (M − 1) plus one buffer to read R. The algorithm (textbook Fig. 15.12):

initialize M-1 buckets using M-1 empty buffers;
FOR each block b of relation R DO BEGIN
    read block b into the Mth buffer;
    FOR each tuple t in b DO BEGIN
        IF the buffer for bucket h(t) has no room for t THEN BEGIN
            copy the buffer to disk;
            initialize a new empty block in that buffer;
        END;
        copy t to the buffer for bucket h(t);
    END;
END;
FOR each bucket DO
    IF the buffer for this bucket is not empty THEN
        write the buffer to disk;

Cost of partitioning: read R once (B(R)) and write every bucket block once (about B(R)): ≈ 2B(R). (Each bucket's last block may be partly empty, so the writes can exceed B(R) by up to M − 1 blocks; we ignore that.) The key idea: two tuples that are equal on the hash key always go to the same bucket.

Try it: tuples are numbers, h(t) = t mod (M − 1).

2. Duplicate elimination δ(R) using hashing (slide 31)

  • Phase 1: hash R into M − 1 buckets (h on the whole tuple). Identical tuples hash to the same bucket.
  • Phase 2: read one bucket at a time into main memory and run the one-pass duplicate-elimination algorithm (Lec 07, Ch. 6) on it. The union of the per-bucket results is δ(R), because no duplicate pair is ever split across buckets.

Memory: each bucket is about B(R)/(M − 1) blocks, and for phase 2 a bucket must fit in memory: B(R)/(M − 1) ≤ M ⟹ B(R) ≤ M(M − 1) ⟹ B(R) ≤ M² (simplified). (Strictly only the distinct tuples of a bucket must fit.)

I/O: phase 1 partitioning 2B(R) + phase 2 reading each bucket B(R) = 3B(R).

3. Grouping and aggregation γL(R) using hashing (textbook §15.5.3)

The slides list γ in their summary table; the algorithm is the same as for δ with one change: hash only on the grouping attributes of L, so that all tuples of a group land in the same bucket. Then run the one-pass γ (one entry per group) on each bucket. Cost 3B(R); memory B(R) ≤ M² is a safe estimate (a bucket can be larger than M as long as its group entries fit).

4. Union, intersection and difference using hashing (slides 32–33)

  • Phase 1: hash R and S with the same hash function into buckets R1, …, RM−1 and S1, …, SM−1. A tuple t that is in both R and S lands in Ri and Si for the same i.
  • Phase 2: for each i, run the one-pass algorithm on Ri and Si. For union (slide 32): read Si into M − 1 buffers with a main-memory search structure; copy all tuples of Si to the output; read Ri a block at a time, and for each tuple, copy it to the output if it does not appear in Si, otherwise discard it. Intersection and difference use their one-pass rules (Lec 07, Ch. 7) in the same way.

I/O: 2(B(R) + B(S)) to hash + (B(R) + B(S)) for phase 2 = 3(B(R) + B(S))

Memory: the smaller of Ri, Si must fit in M − 1 buffers ⟹ min(B(R), B(S)) ≤ M² ⟹ M ≥ √min(B(R), B(S))

(Bucket sizes are about B(R)/(M − 1) and B(S)/(M − 1); slide 33 writes B(R)/M, which is the same approximation.)

5. Hash join (slide 34)

To compute R(X, Y) ⋈ S(Y, Z): the same as the set operations, except the hash key is just the join attributes Y. Then if r ∈ R and s ∈ S join, they agree on Y, so they land in corresponding buckets Ri and Si.

  • Phase 1: hash R and S on Y with the same hash function into M − 1 buckets each.
  • Phase 2: for each pair (Ri, Si), use the one-pass join: read the smaller bucket into memory with a search structure on Y, stream the other.

Hash join: 3(B(R) + B(S)) disk I/Os · Memory: min(B(R), B(S)) ≤ M² ⟹ M ≥ √min(B(R), B(S))

Slide correction: slide 34 gives the I/O cost as "3B(R) [same as before for set union, intersection, etc.]". As its own bracket says, it is the same as for the set operations: 3(B(R) + B(S)); both relations are hashed and written, and both are read again.

Example (textbook Example 15.8): B(R) = 1000, B(S) = 500, M = 101. Hash each into 100 buckets: on average 10 blocks per R bucket and 5 per S bucket, far below the 100 buffers available, so each pair joins easily in one pass. I/Os: 1500 to read R and S while hashing, 1500 to write the buckets, 1500 to read them again: 4500, the same as the efficient sort-merge-join.

For binary operations, S is the smaller relation. Compare the sort-based table (Chapter 4): the costs are the same, but the hash-based memory requirement depends only on the smaller argument, while sort-based ∪, ∩, − and sort-merge-join need √(B(R) + B(S)).

Sorting or hashing? (textbook §15.5.7)

  • Memory: hash-based binary operations need √min(B(R), B(S)); sort-based ones need √(B(R) + B(S)). Hashing wins when one relation is much smaller.
  • Sorted output: sort-based algorithms produce their result in sorted order, which a later operator (ORDER BY, another sort-based operator, a merge join) can use for free.
  • Skew: hash algorithms depend on buckets of equal size. With few distinct key values, or a skewed hash, some buckets overflow memory, so buckets must be planned somewhat smaller than M blocks.
  • Disk layout: sorted sublists can be written to consecutive blocks and read several blocks at a time, saving seeks; hash buckets can get the same benefit only if fewer than M buckets are used so each has several output buffers.

DB QB · 22-23 2b · 10 marks  |  BUET QBank · CSE 215 | L-2/T-1 | 2022–23 · 10 marks

Give a two-pass hash-based algorithm for computing the set difference R − S. Analyze the memory and disk I/O requirements of your algorithm.

Show worked answer

Algorithm.

  1. Phase 1 (partition). With M buffers (M − 1 bucket buffers + 1 input buffer), hash every tuple of R with a hash function h on the whole tuple into buckets R1, …, RM−1, writing them to disk. Do the same for S with the same h, giving S1, …, SM−1.
  2. Phase 2 (one-pass difference per bucket). For i = 1 to M − 1:
    • If Si is the smaller bucket: read Si into M − 1 buffers and build an in-memory hash table on the whole tuple (with a different hash function from h). Read Ri one block at a time; output each tuple t of Ri that is not in the table; discard the others.
    • If Ri is the smaller bucket: read Ri into memory; read Si block by block and delete from memory every tuple that occurs in Si; then output the tuples of Ri that remain.

Correctness. A tuple t of R must be excluded exactly when t is also in S. Equal tuples hash to the same bucket index, so if t ∈ Ri is in S at all, it is in Si. Hence checking only the matching bucket is enough, and R − S = ⋃i(Ri − Si).

Disk I/O. Phase 1 reads R and S and writes their buckets: 2(B(R) + B(S)). Phase 2 reads every bucket once: B(R) + B(S). Total 3(B(R) + B(S)) (plus the output write if stored).

Memory. Buckets are about B(R)/(M − 1) and B(S)/(M − 1) blocks. In phase 2 the smaller bucket of each pair must fit in M − 1 buffers: min(B(R), B(S))/(M − 1) ≤ M − 1, i.e. approximately min(B(R), B(S)) ≤ M², or M ≥ √min(B(R), B(S)). Example: B(R) = 10,000, B(S) = 2,500 needs M ≈ 50 and costs 37,500 I/Os.

Summary: hash-based two-pass algorithms partition R (and S) into M − 1 buckets with one hash function, so all tuples that must meet share a bucket index, then run a one-pass algorithm per bucket (pair). δ and γ: 3B, M ≥ √B (γ hashes on the grouping attributes). ∪, ∩, − and ⋈ (hash on Y): 3(B(R) + B(S)), M ≥ √min(B(R), B(S)). Slide 34's "3B(R)" for hash join should read 3(B(R) + B(S)).
