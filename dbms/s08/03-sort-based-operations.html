Two-Pass Sort-Based Duplicate Elimination, Grouping and Set Operations

Every two-pass sort-based algorithm is TPMMS with a different phase 2. Phase 1 always writes sorted sublists; phase 2 merges them and, instead of just outputting tuples in order, handles all copies of the smallest value together. This chapter does that for δ, γ, ∪, ∩ and −, gives the cost 3B and the memory √B rules, and works three exam questions.

1. The common pattern

All the algorithms in this chapter:

  1. Phase 1: read the argument(s) M blocks at a time, sort, and write sorted sublists (exactly TPMMS phase 1, "do not merge").
  2. Phase 2: bring one block of each sublist into its own buffer, plus one output buffer. Repeatedly find the smallest value among the fronts of all the buffers, deal with all tuples having that value at once (they are all at the fronts, since every sublist is sorted), output what the operation calls for, and manage empty input buffers and a full output buffer as in TPMMS.

Cost: each block is read in phase 1, written in phase 1, and read in phase 2: 3 I/Os per block. Memory: the total number of sublists must not exceed M − 1, which gives roughly B ≤ M².

2. Duplicate elimination δ(R) (slides 14–15)

  • Phase 1: sort the tuples of R into sublists as in TPMMS (do not merge).
  • Phase 2: one memory block per sublist and one for output; bring one block from each sublist into memory. Repeatedly: find the smallest tuple t among all the sublists, together with all other tuples equal to t; send one copy of t to the output and discard the other copies. When the output block is full, write it to disk.

The output comes out sorted, with each tuple exactly once.

Disk I/O: 3B(R) (ignoring the output write)  ·  Memory: B(R) ≤ M² ⟹ M ≥ √B(R)

Compare the one-pass algorithm (Lec 07, Ch. 6): B(R) I/Os, but M ≥ B(R).

So two passes trade 2B(R) extra I/Os for an enormous saving in memory: √B(R) blocks instead of B(R). Animate it with your own tuples (the tool is the TPMMS animator with "discard if equal to the last tuple output"):

3. Grouping and aggregation γL(R) (slides 16–17)

  • Phase 1: sort the tuples of R into sublists, using the grouping attributes of L as the sort key.
  • Phase 2: one buffer per sublist and one for output; load the first block of each sublist. Repeatedly:
    1. Find the smallest value v of the sort key among the fronts. v is the next group. Prepare its aggregate accumulators (MIN, MAX, SUM, COUNT; for AVG, SUM and COUNT).
    2. Examine all tuples with sort key v and update the accumulators.
    3. If an input buffer becomes empty, replace it with the next block from the same sublist (there may be more v's there).
    4. When no tuples with key v remain, output one tuple: the grouping attributes L = v and the aggregate values.

Disk I/O: 3B(R), ignoring the output write. Memory: B(R) ≤ M² ⟹ M ≥ √B(R), against M ≥ B(R) for the one-pass algorithm. Unlike one-pass γ, the output is produced group by group during phase 2, in sorted order of the grouping attributes.

Example. R(dept, salary) = (CSE 50), (EEE 40), (CSE 70), (ME 30), (EEE 60), (CSE 20), 1 tuple per block, M = 3. Phase 1 makes sublists [CSE 50, CSE 70, EEE 40] and [CSE 20, EEE 60, ME 30]. Phase 2: the smallest key is CSE: CSE 50 and CSE 70 from sublist 1, CSE 20 from sublist 2: output (CSE, SUM 140, COUNT 3, AVG 46.67). Next EEE: 40 and 60: (EEE, 100, 2, 50). Then ME: (ME, 30, 1, 30).

4. Set union, intersection and difference (slides 18–21)

For a binary operation, phase 1 creates sorted sublists for both R and S (on the whole tuple), and phase 2 uses one buffer for each sublist of R and of S, plus one output buffer. Then, repeatedly, take the smallest tuple t among all buffers and:

OperationOutput for the current smallest tThen
R ∪ S (slide 18)one copy of tfind all other copies of t (in R's and S's sublists) and discard them
R ∩ S (slide 20)t, if it appears in both some sublist of R and some sublist of Sremove and discard all copies of t from R's and S's sublists
R − S (slide 21)t, if it appears in some sublist of R but in no sublist of Sremove and discard all copies of t (from R's and S's sublists)

Wording fixes: slide 20's "present in at least one sub list of R and S" means present in at least one sublist of R and in at least one sublist of S. Slide 21 says "find all tuples of R that are same as t"; the copies of t in S's sublists must be removed too, or they would be met again.

Disk I/O: 3(B(R) + B(S))  ·  Memory: B(R)/M + B(S)/M ≤ M ⟹ B(R) + B(S) ≤ M² ⟹ M ≥ √(B(R) + B(S))

(slide 19: "M − 1 to be more correct"; compare one-pass: M ≥ min(B(R), B(S)), which the slide writes as B(R) + B(S))

Why the cost is 3(B(R) + B(S)) (slide 19): R and S are read and written once while the sorted sublists are created, and read a second time in phase 2 while outputs are generated. Note that the memory now depends on the sum of the sizes, because all sublists of both relations are open at once. (Slide 19's comparison line "one pass: M ≥ B(R) + B(S)" is stricter than needed: a one-pass set operation only needs the smaller relation in memory, min(B(R), B(S)) < M.)

DB QB · 23-24 6a · 14 marks  |  BUET QBank · CSE 215 | L-2/T-1 | 2023–24 · 14 marks

Describe the two-pass algorithm for grouping and aggregation using sorting. Suppose the number of blocks in relation R is 50,000 and in relation S is 20,000. Compute the memory and I/O cost for the sort-based union operation R ∪ S.

Show worked answer

Two-pass γL(R) using sorting (Section 3):

  1. Phase 1: read R M blocks at a time, sort each load on the grouping attributes of L, write it as a sorted sublist.
  2. Phase 2: one buffer per sublist (first block loaded) plus an output buffer. Repeatedly take the least sort-key value v among the buffer fronts as the next group; initialize its accumulators (MIN, MAX, SUM, COUNT, or SUM and COUNT for AVG); consume every tuple with key v from all buffers, refilling an empty buffer from its sublist; when no v-tuples remain, output (v, aggregates).
  3. Cost 3B(R); needs B(R) ≤ M² (M ≥ √B(R)).

Sort-based R ∪ S with B(R) = 50,000, B(S) = 20,000.

  • Memory: all sublists of R and S must be merged at once: B(R)/M + B(S)/M ≤ M, so M² ≥ B(R) + B(S) = 70,000, M ≥ √70,000 ≈ 264.6, so M = 265 blocks. Being exact (sublists of M blocks, one output buffer: ⌈50,000/M⌉ + ⌈20,000/M⌉ ≤ M − 1), M = 265 gives 189 + 76 = 265 sublists, one too many, and M = 266 gives 188 + 76 = 264 ≤ 265: so 266 buffers are needed strictly.
  • I/O: phase 1 reads and writes both relations: 2 × 70,000 = 140,000; phase 2 reads them once more: 70,000. Total 3(B(R) + B(S)) = 210,000 disk I/Os (plus the output write if the union is stored).
BUET QBank · CSE 303 | L-3/T-1 | 2013–14 · 15 marks

Show the steps of duplicate elimination using a two-pass algorithm. Derive the relationship between number of records and memory size in this algorithm.

Show worked answer

Steps (sort-based δ, Section 2):

  1. Phase 1: repeatedly read M blocks of R, sort the tuples in memory (on the whole tuple), and write them as a sorted sublist. (Duplicates inside one load may already be dropped here.)
  2. Phase 2: allocate one buffer per sublist and one output buffer; load each sublist's first block.
  3. Repeatedly find the smallest tuple t among the buffer fronts; output one copy of t; remove every copy of t from the fronts of all buffers, loading the next block of a sublist whenever its buffer empties (a run of t's may continue into it).
  4. Write the output buffer whenever it fills. Stop when all sublists are exhausted. The output is δ(R), in sorted order.

Relationship. Let N = number of records, b = records per block, so B(R) = N/b blocks. Phase 1 makes B(R)/M sublists; phase 2 needs one buffer for each plus one output buffer:

B(R)/M ≤ M − 1 ⟹ N/b ≤ M(M − 1) ⟹ N ≤ b·M(M − 1) ≈ b·M²

So the number of records that can be de-duplicated in two passes grows with the square of the memory size: M ≥ √(N/b) blocks suffice. Example: b = 100 records per block, M = 1000 buffers: up to 100 × 1000 × 999 ≈ 108 records. The cost is 3B(R) = 3N/b I/Os.

BUET QBank · CSE 303 | L-3/T-1 | 2016–17 · 12 marks

Write down the pseudocode for a sort-based union algorithm that computes R ∪ S. Also mention its runtime and constraints in terms of B(R), B(S) and M, where B(R) and B(S) are the number of blocks in R and S, and M is the number of blocks of each sublist to be sorted.

Show worked answer
SortUnion(R, S, M):
  -- Phase 1: sorted sublists of M blocks each
  for each relation X in {R, S}:
      repeat until X is exhausted:
          read the next M blocks of X into memory; sort them on the whole tuple;
          write them out as a sorted sublist
  -- Phase 2: merge all sublists of R and S together
  give each sublist one buffer and load its first block; one buffer is the output
  while some buffer is non-empty:
      t := smallest tuple at the front of all buffers
      append t to the output buffer; if it is full, write it to disk
      for each buffer: while its front tuple = t:
          remove it; if the buffer is empty, load the next block of its sublist (if any)

Runtime: phase 1 reads and writes every block (2(B(R) + B(S))), phase 2 reads every block once (B(R) + B(S)): 3(B(R) + B(S)) disk I/Os, plus the output write if the result is stored.

Constraint: phase 2 holds one buffer per sublist and one output buffer, and there are ⌈B(R)/M⌉ + ⌈B(S)/M⌉ sublists: ⌈B(R)/M⌉ + ⌈B(S)/M⌉ + 1 ≤ M, i.e. approximately B(R) + B(S) ≤ M².

Alternative: fully sort R and S separately with TPMMS (4B each, results stored) and then merge the two sorted files with 3 buffers: 5(B(R) + B(S)) I/Os, needing only B(R) ≤ M² and B(S) ≤ M² separately. The question bank lists this as the "unoptimized" version; the merged-phase version above is the slides' algorithm.

Summary: sort-based two-pass algorithms = TPMMS phase 1 + a modified merge. δ: output one copy of the smallest tuple, drop the rest. γ: the smallest grouping value is the next group; aggregate all its tuples, then output it. ∪ / ∩ / −: sublists of both relations merged together; output t once, only if in both, or only if in R and not S; then drop all copies. Costs 3B(R) or 3(B(R) + B(S)); memory √B(R) or √(B(R) + B(S)).
