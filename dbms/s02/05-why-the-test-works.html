Why the Precedence-Graph Test Works

The test has two halves: a cycle rules out every serial order, and no cycle guarantees one. This chapter proves both, as the slides do, and animates the induction that peels one transaction at a time off the front of the schedule. The same induction reappears in the proof that two-phase locking works.

Let P be “the precedence graph of S has a cycle” and Q be “S is not conflict-serializable”. The test claims P ⇔ Q. Slide 26 proves P ⇒ Q; slides 27–29 prove the other direction in the equivalent form ¬P ⇒ ¬Q (no cycle ⇒ conflict-serializable). (The slides call the second statement the “inverse”; together with P ⇒ Q it gives the full equivalence.)

1. A cycle means not conflict-serializable (slide 26)

Claim. If the precedence graph of S has a cycle, then S is not conflict-serializable.

Proof (by contradiction). Suppose the graph has a cycle T₁ → T₂ → ⋯ → Tn → T₁, and suppose some serial schedule S′ is conflict-equivalent to S. Each arc Tk → Tk+1 comes from a conflicting pair whose order no legal swap can change, so in S′ all of Tk's actions precede all of Tk+1's (Chapter 4, slide 22). Following the arcs T₁ → T₂ → ⋯ → Tn, the actions of T₁ precede those of Tn in S′. But the arc Tn → T₁ says the actions of Tn precede those of T₁. Both cannot hold in a serial schedule, a contradiction. So no such S′ exists. ∎

2. No cycle means conflict-serializable (slides 27–29)

Claim. If the precedence graph of S is acyclic, then S can be turned into a serial schedule by swaps of adjacent non-conflicting actions.

Proof by induction on n, the number of transactions in S.

Basis, n = 1. A schedule of one transaction is already serial. (Slide 27: “trivial”.)

Induction step. Assume the claim for every schedule of n − 1 transactions, and let Sn have n transactions and an acyclic graph.

  1. There is a node with no incoming arcs. In a finite acyclic graph, start anywhere and keep walking backwards along incoming arcs; without a cycle you can never revisit a node, so the walk must stop, at a node with no incoming arc. Call it node i, transaction Ti.
  2. No action of another transaction that conflicts with an action of Ti comes before it. If some action aj of Tj conflicted with an action ai of Ti and came ahead of it in Sn, then Tj <S Ti, and there would be an arc j → i. There is none.
  3. So Ti's actions can be moved to the front, keeping their own order. Move the first action of Ti forward by adjacent swaps: everything it passes belongs to another transaction and, by step 2, does not conflict with it. Then the second action, up to just behind the first, and so on. The schedule becomes
    (actions of Ti) (actions of the other n − 1 transactions)
  4. The tail is handled by the induction hypothesis. The tail is a schedule of n − 1 transactions whose actions keep their original relative order. Its precedence graph is acyclic (see the question below), so by hypothesis it can be swapped into a serial schedule. Putting Ti first and the serial tail after it gives a serial schedule conflict-equivalent to Sn. ∎

Slide 29 question: why is the precedence graph of the tail acyclic?

The tail contains exactly the actions of the other n − 1 transactions, in the same relative order as in S. So two of its actions conflict, and come in a given order, exactly when they did in S. Its precedence graph is therefore the original graph with node i and node i's arcs removed. Deleting nodes and arcs can never create a cycle: any cycle in the smaller graph would already be a cycle in the original one. Since the original is acyclic, so is the tail's graph.

Each round finds a transaction with no incoming arcs (yellow), moves all its actions to the front (they never pass a conflicting action), and then treats the rest as a smaller schedule. 3. What the proof gives us

  • The test is exact for conflict-serializability: cycle ⇔ not conflict-serializable.
  • Any topological order works. The proof may pick any node without incoming arcs at each step, so every topological order is reachable.
  • The proof is a recipe. Repeatedly moving a source transaction to the front is exactly how to answer “transform the schedule into an equivalent serial schedule by swapping”.

BUET QBank · CSE 303 | L-3/T-1 | 2012–13 · 4 marks

Give a counter-example for: P(S₁) = P(S₂) ⇒ S₁, S₂ conflict equivalent. (P(S) is the precedence graph of S.)

Show worked answer

The precedence graph records only whether some conflict points from Ti to Tj, not which pairs. Conflict-equivalence needs every conflicting pair in the same order. Take T₁: r₁(A); w₁(B) and T₂: w₂(A); r₂(B).

S₁: r₁(A); w₂(A); r₂(B); w₁(B)
S₂: w₂(A); r₁(A); w₁(B); r₂(B)
  • S₁: on A, r₁(A) before w₂(A): 1 → 2. On B, r₂(B) before w₁(B): 2 → 1.
  • S₂: on A, w₂(A) before r₁(A): 2 → 1. On B, w₁(B) before r₂(B): 1 → 2.

So P(S₁) = P(S₂) = {1 → 2, 2 → 1}. But the conflicting pair r₁(A), w₂(A) is in opposite orders in S₁ and S₂, and no legal swap can reverse it, so S₁ and S₂ are not conflict-equivalent. (In S₁, T₁ reads the old A; in S₂ it reads T₂'s A, so they can produce different results.)

Note that any counter-example must have a cyclic graph: if P(S₁) = P(S₂) is acyclic, both schedules are conflict-equivalent to the same serial schedule (any topological order), and hence to each other.

Summary: a cycle T₁ → ⋯ → Tₙ → T₁ would force each transaction before itself in any serial order, so a cyclic schedule is not conflict-serializable. If the graph is acyclic, some transaction has no incoming arc; no conflicting action precedes any of its actions, so it can be swapped to the front, and the remaining schedule has an acyclic graph and is handled by induction. The order of removal is a topological order.
