2024–25 · Q1(a) · 12 marks

Prove that \(P = NP \Rightarrow NP = \text{co-NP}\).

Show answer

Chapter: P, NP, co-NP, NP-complete.

  1. Assume \(P = NP\).
  2. P is closed under complement: if a poly-time machine decides \(L\), swap its accept and reject answers to decide \(\bar L\). So \(L \in P \Rightarrow \bar L \in P\).
  3. NP ⊆ co-NP. Take \(L \in NP\). Then \(L \in P\) (assumption). So \(\bar L \in P = NP\). By definition of co-NP (\(L \in\) co-NP iff \(\bar L \in NP\)), \(L \in\) co-NP.
  4. co-NP ⊆ NP. Take \(L \in\) co-NP. Then \(\bar L \in NP = P\). So \(L \in P\) (closure, step 2). Hence \(L \in P = NP\).
  5. Steps 3 and 4 give \(NP = \text{co-NP}\). ∎

Say this too: the converse is not known. Nobody has proved that \(NP = \text{co-NP}\) forces \(P = NP\) (see Q2(c)).

2024–25 · Q1(b) · 8 marks

Prove or disprove that \(P = NP \cap \text{co-NP}\).

Show answer

Chapter: P, NP, co-NP, NP-complete.

Neither can be done today. The honest answer earns the marks: prove the easy half, state that the other half is an open problem, and say what it would imply.

  1. \(P \subseteq NP \cap \text{co-NP}\) (provable). \(P \subseteq NP\) because a poly-time decider is a verifier that ignores the certificate. \(L \in P \Rightarrow \bar L \in P \subseteq NP\), so \(L \in\) co-NP.
  2. \(NP \cap \text{co-NP} \subseteq P\) (open). No proof and no counterexample is known. Both are open problems. If \(P = NP\), the equality holds (Q1(a): everything collapses into P). If \(P \ne NP\), the equality can still go either way.
  3. Evidence that people suspect it is false: factoring (the decision version) and, before AKS in 2002, PRIMES were in \(NP \cap \text{co-NP}\) with no poly algorithm known. PRIMES then moved into P; factoring has not.

Where marks go

  • Writing "true" or "false" with a fake proof. Write: "inclusion one way is proved, the other way is open".
2024–25 · Q1(c) · 15 marks

Independent set: \(I \subseteq V\) with no edge between any two vertices of \(I\). Clique: \(C \subseteq V\) where every two distinct vertices are adjacent. INDEPENDENT SET (is there an independent set of size at least \(K\)?) is NP-complete. CLIQUE asks whether \(G\) has a clique of size at least \(K\). Prove that the clique problem is as hard as the independent set problem.

Show answer

Chapter: Reductions, with proof templates. "As hard as" means we must show IS \(\le_p\) CLIQUE, so CLIQUE is NP-hard.

  1. Direction. Reduce the known hard problem (IS) to the new one (CLIQUE). Never the other way.
  2. Map. Given an IS instance \((G=(V,E), K)\), build \(\bar G = (V, \bar E)\) where \(\bar E = \{\{u,v\} : u \ne v,\ \{u,v\} \notin E\}\). Output the CLIQUE instance \((\bar G, K)\).
  3. Poly time. Checking all \(\binom{|V|}{2}\) pairs takes \(O(|V|^2)\).
  4. Correctness, forward. If \(I\) is independent in \(G\) with \(|I| \ge K\): for any two distinct \(u,v \in I\), \(\{u,v\} \notin E\), so \(\{u,v\} \in \bar E\). So \(I\) is a clique of size at least \(K\) in \(\bar G\).
  5. Correctness, backward. If \(C\) is a clique in \(\bar G\) with \(|C| \ge K\): any two distinct \(u,v \in C\) have \(\{u,v\} \in \bar E\), so \(\{u,v\} \notin E\). So \(C\) is independent in \(G\).
  6. Steps 4 and 5: \((G,K) \in\) IS iff \((\bar G,K) \in\) CLIQUE. The map is poly-time, so IS \(\le_p\) CLIQUE. IS is NP-hard, so CLIQUE is NP-hard. ∎
  7. To call CLIQUE NP-complete also add: it is in NP (certificate = the \(K\) vertices, check all pairs in \(O(K^2)\)). The question only asks "as hard as", so this line is a bonus.

On paper: draw a small \(G\) (a path A-B-C), then \(\bar G\) next to it (only A-C), and mark \(\{A,C\}\) as independent in \(G\) and a clique in \(\bar G\).

2024–25 · Q2(a) · 15 marks

Give an approximation algorithm for the vertex cover problem. Analyze the approximation ratio of your algorithm.

Show answer

Chapter: Approximation algorithms. Syllabus note: Bayzid sir's notes say vertex cover is "not in syllabus", but it was asked here and in 2022–23 (15 marks each). Learn it.

APPROX-VERTEX-COVER(G)
  C = empty set
  E' = G.E
  while E' is not empty
     pick any edge (u, v) in E'
     C = C + {u, v}
     remove from E' every edge incident on u or v
  return C

Claim: \(C\) is a vertex cover and \(|C| \le 2\,|OPT|\). Time \(O(V+E)\) with adjacency lists.

  1. Let \(A\) be the set of edges picked in the loop. Each pick removes all edges at \(u\) and \(v\), so no later pick shares an endpoint with an earlier one. \(A\) is a matching.
  2. Valid cover. The loop ends only when \(E'\) is empty. Every edge was either picked (both ends in \(C\)) or removed because it touched a picked vertex. So every edge has an endpoint in \(C\).
  3. Size. Each pick adds exactly 2 new vertices (they are new because earlier picks removed their edges). So \(|C| = 2|A|\).
  4. Lower bound on OPT. Any vertex cover must contain an endpoint of every edge of \(A\). The edges of \(A\) share no endpoints, so these endpoints are all different. So \(|OPT| \ge |A|\).
  5. Combine: \(|C| = 2|A| \le 2|OPT|\). The ratio is at most 2. ∎

Tight example. Path A-B-C-D-E, picking A-B and C-D gives \(C=\{A,B,C,D\}\), size 4. The optimum is \(\{B,D\}\), size 2. Ratio exactly 2.

On paper: draw the 5-vertex path, circle the two picked edges (the matching), colour their four endpoints, then circle B and D in a different colour as the optimum.

2024–25 · Q2(b) · 12 marks

Analyze the running time of the randomized quick sort algorithm.

Show answer

Chapter: Randomized quicksort, Monte Carlo, Karger. Result: expected \(O(n\log n)\) for every input; worst case \(O(n^2)\).

  1. Setup. Let \(z_1 < z_2 < \dots < z_n\) be the keys in sorted order. The pivot is chosen uniformly at random. Running time is dominated by the number of comparisons \(X\) (each partition step compares each element with the pivot once).
  2. Each pair is compared at most once. Two keys are compared only when one of them is the pivot, and the pivot is then removed from all later calls.
  3. When are \(z_i\) and \(z_j\) (\(i Let \(Z_{ij} = \{z_i,\dots,z_j\}\). While no element of \(Z_{ij}\) has been picked as pivot, they stay together in one sublist. The first pivot picked from \(Z_{ij}\) decides: if it is \(z_i\) or \(z_j\), they are compared. If it is strictly between, they are split apart and never compared.
  4. All \(j-i+1\) elements of \(Z_{ij}\) are equally likely to be the first pivot from \(Z_{ij}\). So \(\Pr[z_i, z_j \text{ compared}] = \dfrac{2}{j-i+1}\).
  5. Expectation (linearity). \[E[X] = \sum_{i=1}^{n-1}\sum_{j=i+1}^{n} \frac{2}{j-i+1} = \sum_{i=1}^{n-1}\sum_{k=2}^{n-i+1}\frac{2}{k} < 2\sum_{i=1}^{n-1} H_n \le 2n H_n = O(n\log n).\]
  6. Worst case. Pivot is always the smallest or largest: \(T(n) = T(n-1) + \Theta(n) = \Theta(n^2)\). Randomization makes this happen with very small probability on any fixed input, so no input is bad. ∎
2024–25 · Q2(c) · 8 marks

"It is possible that \(P \ne NP\), yet \(NP = \text{co-NP}\)." Do you agree with this statement? Justify your answer.

Show answer

Chapter: P, NP, co-NP, NP-complete.

  1. Agree. It is consistent with everything known: no theorem links the two statements in that direction.
  2. What is proved is Q1(a): \(P = NP \Rightarrow NP = \text{co-NP}\). Its contrapositive is \(NP \ne \text{co-NP} \Rightarrow P \ne NP\). So if someone proves \(NP \ne \text{co-NP}\), then \(P\ne NP\) follows.
  3. The statement in the question is the converse direction: \(P \ne NP\) together with \(NP = \text{co-NP}\). An implication does not give its converse for free. To rule the case out one would have to prove \(NP = \text{co-NP} \Rightarrow P = NP\), and nobody has.
  4. So the case "\(P \ne NP\) but \(NP = \text{co-NP}\)" cannot be excluded. Most researchers believe \(NP \ne \text{co-NP}\), but that is a belief, not a proof.

Suppose you have designed a Monte Carlo algorithm for a given problem which succeeds with probability \(\ge 1/n^2\) (as read from the scan). Your boss has asked you to achieve at least \(1 - 1/n\) success probability. Explain how you can achieve this.

Show answer

Chapter: Randomized quicksort, Monte Carlo, Karger. Idea: repeat with fresh random bits and keep the best verified answer.

  1. Assumption (state it). A returned answer can be recognised as correct (one-sided error, or the answer can be checked). Then the repeated run can keep any correct answer it sees.
  2. Run the algorithm \(t\) times, each time with independent random choices.
  3. All \(t\) runs fail with probability at most \(\left(1-\frac1{n^2}\right)^t\).
  4. Use \(1 - x \le e^{-x}\): \(\left(1-\frac1{n^2}\right)^t \le e^{-t/n^2}\).
  5. Choose \(t = n^2\ln n\). Then the failure probability is at most \(e^{-\ln n} = 1/n\).
  6. So the success probability is at least \(1 - 1/n\). The cost is \(n^2 \ln n\) times the cost of one run, i.e. \(O(n^2\log n)\cdot T(n)\). (The handwritten "\(n^2\log n\)" in the margin of the scan agrees.) ∎

2024–25 · Q4(a) · 8 marks

Prove that there are \(\binom{k}{i}\) nodes at depth \(i\) in a binomial heap \(B_k\) of order \(k\).

Show answer

Chapter: Binomial trees and their proofs.

  1. Definition used. \(B_0\) is one node. \(B_k\) is two copies of \(B_{k-1}\), where the root of one becomes the leftmost child of the root of the other.
  2. Induction on \(k\). Claim: \(B_k\) has \(\binom{k}{i}\) nodes at depth \(i\) for \(0\le i\le k\).
  3. Base \(k=0\). One node at depth 0. \(\binom00=1\). ✓
  4. Step. Assume the claim for \(B_{k-1}\). In \(B_k\), a node at depth \(i\) is either in the copy that kept its root (same depth \(i\) as inside \(B_{k-1}\)): \(\binom{k-1}{i}\) of them, or in the copy that was attached below the root (depth shifts by +1, so depth \(i-1\) inside \(B_{k-1}\)): \(\binom{k-1}{i-1}\) of them.
  5. Total: \(\binom{k-1}{i}+\binom{k-1}{i-1}=\binom{k}{i}\) by Pascal's rule. ∎

This is why the name is "binomial": row \(k\) of Pascal's triangle is the number of nodes per level. Check \(B_3\): levels 1, 3, 3, 1.

2024–25 · Q4(c) · 7 marks

Let \(H_1\) and \(H_2\) be binomial heaps. Suppose the highest order tree in \(H_1\) is of order \(m\), and the highest order tree in \(H_2\) has degree \(m+1\). Prove or disprove: "\(H_2\) must have more nodes than \(H_1\), regardless of how many trees are present in \(H_1\) and \(H_2\)."

Show answer

Chapter: Binomial trees and their proofs. The statement is true.

  1. A binomial heap has at most one tree of each order (it mirrors the binary form of \(n\)). \(B_j\) has \(2^j\) nodes.
  2. Most nodes \(H_1\) can have. One tree of each order \(0,\dots,m\): \(\sum_{j=0}^{m}2^j = 2^{m+1}-1\).
  3. Fewest nodes \(H_2\) can have. It contains \(B_{m+1}\), which alone has \(2^{m+1}\) nodes. Any other trees only add nodes.
  4. So \(|H_2| \ge 2^{m+1} > 2^{m+1}-1 \ge |H_1|\). ∎

Short form: the number of nodes has top bit \(m\) in \(H_1\), and \(H_2\) has a top bit \(m+1\), so \(n_2 \ge 2^{m+1} > n_1\).

Directed weighted graph on {A, B, C, D}, edges: A→B (3), B→C (2), C→D (2), D→B (−8), A→D (10), B→D (5). Determine whether it contains a negative weight cycle by applying the Floyd-Warshall algorithm. If so, identify the vertices involved.

Show answer

Chapter: Matrix squaring, Floyd-Warshall, closure. Rule: after the algorithm, if any diagonal entry \(d[i][i]<0\), a negative cycle goes through \(i\).

  1. \(D^{(0)}\): diagonal 0, edge weights where edges exist, \(\infty\) otherwise.
  2. \(k=A\): nothing enters A, no improvement.
  3. \(k=B\): \(d[A,C]=3+2=5\), \(d[A,D]=3+5=8\), \(d[D,C]=-8+2=-6\), and \(d[D,D]=-8+5=-3\). The diagonal at D is already negative: the cycle D→B→D has weight \(-8+5=-3\).
  4. \(k=C\) and \(k=D\): the diagonal entries get more negative at B, C and D.
  5. Answer. Yes, there is a negative cycle. The simple cycles are D→B→D (\(-3\)) and B→C→D→B (\(2+2-8=-4\)). The vertices on negative cycles are B, C and D. A is not on any cycle (no edge enters A); it only reaches the cycle.

Because of the cycle, shortest-path distances through B, C, D are not defined (they go to \(-\infty\)); the final matrix values are not real distances.
