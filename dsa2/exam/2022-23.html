2022–23 · Q1(a) · 12 marks

Analyze the complexity of Johnson's algorithm for the all-pair shortest paths problem.

Show answer

Chapter: Johnson's algorithm.

  1. Step 1: add a source \(s\) with a 0-weight edge to every vertex. Cost \(O(V)\).
  2. Step 2: Bellman-Ford from \(s\). Gives \(h(v)=\delta(s,v)\) or reports a negative cycle (then stop). Cost \(O(VE)\) on the \(V+1\) vertices and \(E+V\) edges.
  3. Step 3: reweight \(w'(u,v)=w(u,v)+h(u)-h(v)\). By the triangle inequality \(h(v)\le h(u)+w(u,v)\), so \(w'\ge0\). Every path from \(u\) to \(v\) changes by the same amount \(h(u)-h(v)\), so shortest paths do not change. Cost \(O(E)\).
  4. Step 4: Dijkstra from every vertex on the non-negative graph. One run: \(O(V\log V+E)\) with a Fibonacci heap, \(O((V+E)\log V)\) with a binary heap. \(V\) runs: \(O(V^2\log V+VE)\) or \(O(VE\log V)\).
  5. Step 5: undo the reweighting: \(d(u,v)=d'(u,v)-h(u)+h(v)\). Cost \(O(V^2)\).
  6. Total. \(O(VE)+O(E)+O(V^2\log V+VE)+O(V^2)=\mathbf{O(V^2\log V+VE)}\) (Fibonacci heap), or \(O(VE\log V)\) with binary heaps. Space \(O(V^2)\) for the answer.
  7. Compare: sparse graph (\(E=O(V)\)): \(O(V^2\log V)\), better than Floyd-Warshall \(O(V^3)\). Dense graph: \(O(V^3)\), the same.

A city with N towns and M bidirectional roads of three types. Men may use roads of types 1 and 3; women may use roads of types 2 and 3. The Mayor wants to renovate (close) as many roads as possible while the city stays connected for both men and women. (i) Formulate the problem as a graph problem. (ii) Develop the solution using a well-known graph algorithm. (iii) Write the pseudo-code.

Show answer

Chapters: MST and union-find, Modelling. Pattern: "keep the fewest edges so that a connectivity condition holds" is a spanning-tree problem; the algorithm is union-find (Kruskal with no weights).

(i) Formulation.

  1. Graph \(G=(V,E)\): town = vertex, road = undirected edge labelled 1, 2 or 3. \(|V|=N,\ |E|=M\).
  2. Men's graph \(G_m\): edges of types 1 and 3. Women's graph \(G_w\): types 2 and 3.
  3. Find a smallest set \(K\subseteq E\) of roads to keep such that \(K\cap(\text{types }1,3)\) connects all \(N\) towns and \(K\cap(\text{types }2,3)\) connects all \(N\) towns. The answer is \(M-|K|\). If one of \(G_m\), \(G_w\) is not connected to begin with, the answer is \(-1\) (impossible).

(ii) Key idea: type-3 roads first.

  1. Men need a spanning tree of \(G_m\): \(N-1\) edges. Women need a spanning tree of \(G_w\): \(N-1\) edges. A type-3 road counts for both, types 1 and 2 count for one.
  2. If \(k_3\) type-3 roads are kept, the men still need \(N-1-k_3\) type-1 roads and the women \(N-1-k_3\) type-2 roads. So \(|K|=k_3+2(N-1-k_3)=2(N-1)-k_3\). Maximise \(k_3\).
  3. The most type-3 roads that can be kept without a cycle is a spanning forest of the type-3 graph. Take it greedily with union-find: \(k_3\) = number of type-3 edges that join two different components.
  4. Why greedy is right (exchange argument). Any optimal solution uses a set of type-3 roads that is acyclic. If it used fewer than a maximal forest, a type-3 road in the forest could replace a type-1 and a type-2 road it makes redundant, reducing \(|K|\). So a maximum acyclic set of type-3 roads is optimal, and the remaining roads are then chosen by the same union-find rule separately for men and women.

(iii) Pseudo-code (union-find with path compression and union by size, nearly \(O(1)\) per operation).

MAX-RENOVATED(N, edges)
  DSU_both = new DSU(N);  k3 = 0
  for each edge (u, v, type 3)
     if UNION(DSU_both, u, v) then k3 = k3 + 1
  DSU_m = copy of DSU_both;  DSU_w = copy of DSU_both
  km = 0;  kw = 0
  for each edge (u, v, type 1): if UNION(DSU_m, u, v) then km++
  for each edge (u, v, type 2): if UNION(DSU_w, u, v) then kw++
  if components(DSU_m) != 1 or components(DSU_w) != 1 then return -1
  return M - (k3 + km + kw)

Time \(O(M\,\alpha(N))\), \(\alpha\) the inverse Ackermann function. Space \(O(N)\). Check: \(k_3+k_m=N-1\) and \(k_3+k_w=N-1\), so the kept count is \(2(N-1)-k_3\).

On paper: draw a small example (4 towns, a few roads of each type), circle the type-3 spanning forest first, then add type-1 edges in one colour and type-2 in another, and count the unused roads.

Question 2 (35)

2022–23 · Q2(a)(b)(c) · 8 + 12 + 15 marks

(a) Develop an algorithm for finding the shortest path in a graph where all edge weights are equal. (8)
(b) Devise an efficient algorithm for the same problem where edge weights are non-equal but positive. (12)
(c) Develop an efficient algorithm when edge weights can be negative and the graph can have negative-weight cycles. (15)

Show answer

Chapters: Bellman-Ford, Dijkstra.

(a) Equal weights: BFS. If every edge has weight \(c\), the shortest path is the one with the fewest edges, so the distance is \(c\times\)(number of edges) and BFS finds it.

BFS(G, s)
  for each v: d[v] = INF, parent[v] = NIL
  d[s] = 0; enqueue s
  while queue not empty
     u = dequeue
     for each v in Adj[u] with d[v] == INF
         d[v] = d[u] + 1; parent[v] = u; enqueue v
  // distance = c * d[v]; path from the parent pointers

Time \(O(V+E)\). BFS is correct because it visits vertices in order of increasing edge count.

(b) Positive weights: Dijkstra.

DIJKSTRA(G, w, s)
  INITIALIZE-SINGLE-SOURCE(G, s)      // d[s]=0, others INF
  S = empty;  Q = all vertices keyed by d
  while Q not empty
     u = EXTRACT-MIN(Q);  S = S + {u}
     for each v in Adj[u]
         if d[v] > d[u] + w(u,v)       // relax
             d[v] = d[u] + w(u,v); parent[v] = u; DECREASE-KEY(Q, v, d[v])

Time \(O((V+E)\log V)\) with a binary heap, \(O(V\log V+E)\) with a Fibonacci heap. Correctness: see the proof in the chapter (greedy, needs non-negative weights).

(c) Negative weights and possible negative cycles: Bellman-Ford with cycle handling.

BELLMAN-FORD(G, w, s)
  INITIALIZE-SINGLE-SOURCE(G, s)
  repeat |V|-1 times
     for each edge (u, v): RELAX(u, v, w)
  for each edge (u, v)                  // one more round
     if d[v] > d[u] + w(u,v) then mark v      // v is on or reachable from a negative cycle
  every vertex reachable from a marked vertex has distance -INF
  other vertices: d[v] is the true shortest distance
  1. After round \(i\), every vertex whose shortest path has at most \(i\) edges is correct. A shortest path without a cycle has at most \(V-1\) edges, so \(V-1\) rounds are enough when no negative cycle is reachable.
  2. If after \(V-1\) rounds some edge still relaxes, there is a negative cycle reachable from \(s\). For those vertices no shortest path exists (the distance is \(-\infty\)). A search from the marked vertices finds all of them.

Time \(O(VE)\). A DAG would give \(O(V+E)\), but the question allows cycles.

2022–23 · Q3(a) · 8 marks

How is the concept of a potential function used to design a splay tree? Explain.

Show answer

Chapter: Splay trees. Low priority: splay trees are not in the available notes or slides; this was asked in older papers, not in 2024-25.

  1. Problem. A splay tree does not store balance information. A single operation can cost \(O(n)\) (a long chain). We want to show that a sequence of \(m\) operations costs \(O(m\log n)\): each operation has amortized cost \(O(\log n)\).
  2. Potential. \(s(x)\) = number of nodes in the subtree of \(x\). \(r(x)=\log_2 s(x)\) (the rank). \(\Phi(T)=\sum_x r(x)\). A balanced tree has a low potential and a chain has a high one.
  3. Amortized cost of an operation = actual cost + \(\Phi_{\text{after}}-\Phi_{\text{before}}\). A cheap operation that leaves the tree more unbalanced pays for it by raising \(\Phi\); an expensive splay of a deep node lowers \(\Phi\) a lot and its actual cost is paid by that fall.
  4. Splay-step bound (access lemma). For a node \(x\) with ranks \(r\) before and \(r'\) after one step: zig costs at most \(1+3(r'(x)-r(x))\); zig-zig and zig-zag each cost at most \(3(r'(x)-r(x))\) in amortized terms (cost counted as 2 rotations, proved with \(\log a+\log b\le 2\log(a+b)-2\)).
  5. Telescoping. Summing over all steps of one splay, the differences telescope: amortized cost \(\le 3(r(\text{root})-r(x))+1\le 3\log_2 n+1=O(\log n)\).
  6. Over \(m\) operations from an empty tree, total actual cost \(\le\) total amortized cost \(+\Phi_{\text{start}}-\Phi_{\text{end}}=O(m\log n)\) since \(\Phi\le n\log n\).
2022–23 · Q3(b) · 6 + 6 marks

Formulate the problem of maximum bipartite matching. Give two examples of real-life problems that can be solved using it.

Show answer

Chapter: Bipartite matching and modelling.

  1. Input. A bipartite graph \(G=(L\cup R,E)\): every edge joins a vertex of \(L\) to one of \(R\).
  2. Matching. \(M\subseteq E\) in which no two edges share an endpoint (every vertex is in at most one edge of \(M\)).
  3. Problem. Find a matching of maximum size \(|M|\).

Examples.

  • Job assignment: \(L\) = workers, \(R\) = jobs, edge = "worker is qualified for the job". The maximum matching is the most jobs that can be filled with one job per worker.
  • Course or room allocation / car-parking: \(L\) = students (or cars), \(R\) = seats (or parking slots), edge = allowed or reachable. Maximum matching = most students seated.
2022–23 · Q3(c) · 10 + 5 marks

Develop a solution for the maximum bipartite matching problem. What is the Edmonds-Karp optimization for the Ford-Fulkerson algorithm?

Show answer

Chapters: Flow networks, Ford-Fulkerson, Edmonds-Karp, Matching.

Reduction to max flow.

  1. Add a source \(s\) and sink \(t\). Edges \(s\to u\) for all \(u\in L\), edges \(u\to v\) for every \((u,v)\in E\) with \(u\in L\), edges \(v\to t\) for all \(v\in R\). Every capacity is 1.
  2. Find a max flow with Ford-Fulkerson. By the integrality theorem it is integral, so every edge carries 0 or 1.
  3. The edges \(L\to R\) with flow 1 form a matching: flow into \(u\in L\) is at most 1 so \(u\) uses at most one edge, same for \(v\in R\). Its size is \(|f|\).
  4. Conversely a matching of size \(k\) gives a flow of value \(k\). So max flow = max matching.
  5. Time: \(|f|\le\min(|L|,|R|)\le V\), each augmentation \(O(E)\), so \(O(VE)\).

Example: \(L=\{a,b,c\}\), \(R=\{x,y,z\}\), edges a-x, a-y, b-x, c-y, c-z.

Edmonds-Karp optimization. Ford-Fulkerson does not say how to choose the augmenting path, so with large capacities it can take \(|f^*|\) steps (and with irrational capacities it may not stop). Edmonds-Karp chooses the augmenting path with the fewest edges, found by BFS in the residual network. Then the shortest-path distance of every vertex from \(s\) in the residual graph never decreases, each edge becomes critical (the bottleneck) at most \(V/2\) times, there are \(O(VE)\) augmentations of cost \(O(E)\): total \(O(VE^2)\), independent of the capacities.

2022–23 · Q4(a) · 8 marks

Prove the max-flow min-cut theorem.

Show answer

Chapter: Max-flow min-cut, Edmonds-Karp. The full numbered proof is written out in the 2023–24 solution, Q11(c); short form here.

  1. Lemma. For every flow \(f\) and every cut \((S,T)\): \(|f|=f(S,T)-f(T,S)\le c(S,T)\). So max flow \(\le\) min cut.
  2. No augmenting path \(\Rightarrow\) equality. If \(G_f\) has no \(s\leadsto t\) path, let \(S\) = vertices reachable from \(s\) in \(G_f\), \(T\) = the rest (\(t\in T\)). Every edge \(S\to T\) is saturated (else the residual edge would reach \(T\)); every edge \(T\to S\) carries 0 flow. So \(|f|=c(S,T)\).
  3. By step 1 this flow is maximum and this cut is minimum. So max flow = min cut. A flow is maximum iff there is no augmenting path. ∎
2022–23 · Q4(b) · 12 marks

Write down the properties of an AVL tree and prove that it is a balanced binary search tree.

Show answer

Chapter: Rotations and AVL trees.

Properties.

  1. It is a binary search tree (left keys smaller, right keys larger).
  2. At every node the heights of the left and right subtrees differ by at most 1 (balance factor \(\in\{-1,0,+1\}\)).
  3. After an insert or delete, rotations (single or double) restore property 2; the height is stored or recomputed at each node.

Proof: height is \(O(\log n)\). (leaf height 0)

  1. Let \(N(h)\) = fewest nodes in an AVL tree of height \(h\). The root has subtrees of height \(h-1\) and, at least, \(h-2\).
  2. \(N(h)=N(h-1)+N(h-2)+1\), \(N(0)=1,\ N(1)=2\). So 1, 2, 4, 7, 12, 20, ...
  3. \(N(h)>2N(h-2)\), so \(N(h)\ge 2^{\lfloor h/2\rfloor}\).
  4. Any AVL tree of height \(h\) with \(n\) nodes has \(n\ge N(h)\ge2^{(h-1)/2}\), so \(h\le 2\log_2n+1\).
  5. So height is \(O(\log n)\): search, insert and delete cost \(O(\log n)\). ∎ (The sharper bound is \(1.44\log_2n\).)

2022–23 · Q5(b) · 17 marks

A team of employees, each with tasks. Some tasks cannot be worked on simultaneously due to dependencies or resource constraints. The goal is to maximize productivity by scheduling as many tasks as possible, with no two conflicting tasks assigned to the same team member simultaneously. A friend says: "The problem can be mapped to a popular NP-complete problem and proved NP-hard by reduction." Justify the comment by mapping the problem to an NP-complete problem and reducing it to another known NP-complete problem.

Show answer

Chapter: Reductions, with proof templates. The question is loose, so state your model first; the marks are for a clean mapping and a correct reduction.

Part 1: map to INDEPENDENT SET.

  1. Model: a task is a vertex; two tasks that conflict (cannot run at the same time for the same member) are joined by an edge. Choosing the tasks to run simultaneously means choosing a set with no conflicting pair, i.e. an independent set.
  2. Decision version SCHEDULE: given tasks, conflicts and \(k\), can \(k\) tasks be chosen with no two in conflict? This is exactly INDEPENDENT SET on the conflict graph with the same \(k\).
  3. INDEPENDENT SET is a popular NP-complete problem. Maximising the number of scheduled tasks is its optimization version, so it is NP-hard.

Part 2: prove INDEPENDENT SET NP-hard by VERTEX COVER \(\le_p\) INDEPENDENT SET (vertex cover is the known NP-complete problem).

  1. Given \((G=(V,E),k)\) for VERTEX COVER, output \((G,\ n-k)\) for INDEPENDENT SET, where \(n=|V|\). Poly time.
  2. Key fact: \(S\) is a vertex cover iff \(V\setminus S\) is independent. (\(S\) covers every edge \(\iff\) no edge has both endpoints outside \(S\).)
  3. Forward. If \(G\) has a vertex cover of size \(\le k\), its complement is independent with size \(\ge n-k\).
  4. Backward. If \(G\) has an independent set of size \(\ge n-k\), its complement is a vertex cover of size \(\le k\).
  5. So VC \(\le_p\) IS and IS is NP-hard. With membership in NP (certificate: the \(k\) tasks, check all pairs), IS is NP-complete. Hence SCHEDULE is NP-hard. ∎

Where marks go

  • Reduce from the known problem to the new one. Writing it backwards (IS to VC) proves nothing about IS.
  • Write the construction, the polynomial time, and both directions of the iff.

2022–23 · Q5(c) · 12 marks

Recall the deletion operation of the Fibonacci heap. Professor Rahsut proposes RAHSUT-DELETE(H, x): if x == H.min, FIB-HEAP-EXTRACT-MIN(H); else y = x.p; if y != NIL, CUT(H, x, y) and CASCADING-CUT(H, y); add x's children to the root list of H; remove x from the root list of H. (i) Construct a good upper bound on the actual time of RAHSUT-DELETE when x is not H.min, in terms of x.degree and the number c of calls to CASCADING-CUT. (ii) Let H' be the heap that results, with x not a root. Find the potential of H' in terms of x.degree, c, t(H) and m(H).

Show answer

Chapters: Fibonacci heap, Potential method. Potential \(\Phi(H)=t(H)+2m(H)\): \(t\) = number of trees (roots), \(m\) = number of marked nodes. \(c\) counts calls to CASCADING-CUT (the last call ends the cascade).

(i) Actual time.

  1. CUT: \(O(1)\).
  2. CASCADING-CUT: \(c\) calls, each \(O(1)\) (a cut and a mark test): \(O(c)\).
  3. Adding \(x\)'s children to the root list, one by one: \(O(x.\text{degree})\). Removing \(x\) from the root list: \(O(1)\).
  4. Total: \(\mathbf{O(x.\text{degree}+c)}\).

(ii) Potential of \(H'\).

  1. Roots. \(x\) is cut (+1 root) and then removed (−1): net 0. The \(x.\text{degree}\) children become roots: \(+x.\text{degree}\). Each of the \(c-1\) cascading cuts that actually cut a node adds a root: \(+(c-1)\). So \(t(H')=t(H)+x.\text{degree}+c-1\).
  2. Marks. Each of the \(c-1\) cuts clears a mark: \(-(c-1)\). The last call may mark one node: at most \(+1\). \(x\) itself, if it was marked, disappears (only lowers \(m\)). So \(m(H')\le m(H)-(c-1)+1=m(H)-c+2\).
  3. Potential: \[\Phi(H')\le t(H)+x.\text{degree}+c-1+2\bigl(m(H)-c+2\bigr)=t(H)+2m(H)+x.\text{degree}-c+3.\]
  4. So \(\Phi(H')-\Phi(H)\le x.\text{degree}-c+3\).

Amortized cost (not asked, but marks for it if time): actual \(O(x.\text{degree}+c)\) plus \(\Delta\Phi\le x.\text{degree}-c+3\). Scaling the potential units, the \(c\) terms cancel, but the \(x.\text{degree}\) term stays, so the amortized cost is \(O(x.\text{degree})=O(\log n)\). This matches the original FIB-HEAP-DELETE; it is not \(O(1)\) as the professor might hope.

Where marks go

  • The count of new roots is \(c-1\) (not \(c\)) because the last CASCADING-CUT call does not cut. State what \(c\) counts.
  • Children moved to the root list keep their marks in this variant, so \(m\) does not drop for them.

Question 6 (35)

2022–23 · Q6(a) · 15 + 5 marks

You use hash function h1 into a table of size 16; your friend uses h2 into size 17. h1 hashes the keys 100, 130, 110, 150, 160, 200, 700, 800, 300 into 0, 3, 2, 0, 3, 1, 2, 5, 8. h2 hashes them into 1, 4, 7, 10, 13, 4, 7, 10, 13. You use quadratic probing \(f(i)=2i^2+3\); your friend uses double hashing with the second hash \(h_2'(x)=19-(x\%17)\). Insert in the given order, then delete 100 and search 150: your table says "key 150 not found". (i) Compare the two by the total unsuccessful probes during insertion. (15) (ii) Identify the possible core reason for not finding 150 and give a solution. (5)

Show answer

Chapter: Chaining and open addressing. Probe \(i\) goes to \((h(k)+f(i))\bmod m\), \(i=0,1,\dots\) (see the note at the top).

Your table: quadratic probing, size 16, \(f(i)=2i^2+3\)

Final: slot 3=100, 4=200, 5=110, 6=130, 7=700, 8=160, 10=800, 11=150, 13=300; the rest are empty. Unsuccessful probes: 150: 2, 160: 1, 700: 1, 800: 1, 300: 1. Total 6.

Friend's table: double hashing, size 17, step \(19-(x\%17)\)

Steps: 100→4, 130→8, 110→11, 150→5, 160→12, 200→6, 700→16, 800→18, 300→8. Final: slot 1=100, 4=130, 6=700, 7=110, 10=150, 11=800, 12=300, 13=160, 16=200; the rest are empty. Unsuccessful probes: 200: 2, 700: 1, 800: 1, 300: 2. Total 6.

(i) Comparison. Both need 6 unsuccessful probes, so on this input neither wins. In general double hashing is better: the step depends on the key, so keys that start at the same slot follow different paths (no clustering), and the prime size 17 makes every step coprime with the size, so every slot is reachable. Quadratic probing with \(2i^2+3\) in a table of size 16 reaches only a few slots (the offsets \(2i^2\bmod16\) take only the values 0, 2, 8), so insertion can fail with a table that is not full.

(ii) Why 150 is not found, and the fix.

  1. 150 has home slot 0, so its first probe is slot \((0+3)\bmod16=3\). That slot held 100 when 150 was inserted, so 150 went on and sat in slot 11 (probes 3, 5, 11).
  2. Deleting 100 simply emptied slot 3. Search for 150 now probes slot 3, finds it empty and stops, concluding "not found", although 150 is in slot 11.
  3. Core reason: deleting by emptying a slot breaks the probe chain of every key that was pushed past it.
  4. Fix: lazy deletion. Mark the slot as DELETED (a tombstone). Search continues past DELETED slots and stops only at a truly empty one. Insert may reuse a DELETED slot. If many tombstones accumulate, rehash the table.
2022–23 · Q6(b) · 15 marks

Give a 2-approximation algorithm for the vertex cover problem and prove that the algorithm computes a vertex cover at most twice the size of the optimal vertex cover.

Show answer

Chapter: Approximation algorithms. Syllabus note: Bayzid sir's notes say vertex cover is "not in syllabus", but it was asked here and again in 2024–25 (15 marks each). Learn it.

APPROX-VERTEX-COVER(G)
  C = empty set;  E' = G.E
  while E' is not empty
     pick any edge (u, v) in E'
     C = C + {u, v}
     remove from E' every edge incident on u or v
  return C
  1. Let \(A\) be the edges picked. After a pick all edges at \(u\) and \(v\) are removed, so no later pick touches them: \(A\) is a matching.
  2. Cover. The loop stops when \(E'\) is empty. Every edge was picked (both ends in \(C\)) or removed because it touched a picked vertex. So \(C\) is a vertex cover.
  3. Size. Each pick adds 2 new vertices: \(|C|=2|A|\).
  4. Lower bound. A cover has to contain an endpoint of each edge of \(A\), and those edges share no endpoint, so \(|OPT|\ge|A|\).
  5. \(|C|=2|A|\le2|OPT|\). Time \(O(V+E)\). ∎ Tight on a path of 4 edges A-B-C-D-E (picks A-B, C-D: size 4; optimum \(\{B,D\}\): size 2).

Held-Karp. Fix city 1 as the start. \(C(S,j)\) = cheapest path that starts at 1, visits exactly the cities of \(S\) (\(S\subseteq\{2..n\}\)) and ends at \(j\in S\).

  1. \(C(\{j\},j)=d(1,j)\).

2022–23 · Q8(b) · 12 marks

Prove that in a binomial heap, the amortized cost of INSERT is \(O(1)\) and the worst-case cost of EXTRACT-MIN and DECREASE-KEY is \(O(\log n)\).

Show answer

Chapters: Binomial trees, Binomial heap operations, Potential method.

  1. Facts. A binomial heap with \(n\) keys has one tree \(B_i\) for each 1-bit of \(n\). So it has at most \(\lfloor\log_2n\rfloor+1\) trees, every tree has height at most \(\log_2n\), every degree at most \(\log_2 n\).
  2. INSERT, amortized. Potential \(\Phi(H)=t(H)\), the number of trees. Insert makes a one-node heap and unions it in, like adding 1 to a binary counter. If \(k\) links happen, the actual cost is \(O(1+k)\).
  3. Each link reduces the number of trees by 1, and the new node adds 1: \(\Delta\Phi=1-k\).
  4. Amortized cost \(=(1+k)+(1-k)=2=O(1)\). ∎ (Starting from an empty heap, \(\Phi\ge0\), so the total actual cost of \(m\) inserts is at most \(2m\).)
  5. EXTRACT-MIN, worst case. Finding the minimum root scans at most \(\log n+1\) roots: \(O(\log n)\). The min root has at most \(\log n\) children; reversing them and uniting the two heaps (each with \(O(\log n)\) trees) costs \(O(\log n)\), because UNION walks the two root lists once. Total \(O(\log n)\). ∎
  6. DECREASE-KEY, worst case. Lower the key and exchange it with its parent while the parent is larger. A node is at depth at most the tree height, \(\le\log n\), and each exchange is \(O(1)\). So \(O(\log n)\). ∎
