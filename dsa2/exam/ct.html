CT-1 (AMR) Q1 · 6 marks

Run the Floyd-Warshall algorithm on the weighted, directed graph given below and show the distance matrices of all steps.

Graph read from scan: 1→2 (5), 2→3 (1), 3→4 (3), 4→1 (2), 3→1 (8).

Show answer

\(D^{(k)}[i][j]=\min\big(D^{(k-1)}[i][j],\ D^{(k-1)}[i][k]+D^{(k-1)}[k][j]\big)\). Row and column \(k\) do not change in round \(k\). Draw four matrices \(D^{(1)}..D^{(4)}\) after \(D^{(0)}\).

  1. \(D^{(0)}\): the weight matrix (diagonal 0, \(\infty\) for no edge).
  2. \(k=1\): through vertex 1: \(d[3,2]=8+5=13\), \(d[4,2]=2+5=7\).
  3. \(k=2\): through 2: \(d[1,3]=5+1=6\), \(d[4,3]=7+1=8\).
  4. \(k=3\): through 3: \(d[1,4]=6+3=9\), \(d[2,1]=1+8=9\), \(d[2,4]=1+3=4\).
  5. \(k=4\): through 4: \(d[2,1]=4+2=6\), \(d[3,1]=3+2=5\), \(d[3,2]=3+7=10\).

Final matrix (rows = from, columns = to, order 1..4): row 1: 0, 5, 6, 9. Row 2: 6, 0, 1, 4. Row 3: 5, 10, 0, 3. Row 4: 2, 7, 8, 0. No diagonal entry is negative, so there is no negative cycle.

CT-1 (AMR) Q2 · 4 marks

Analyze and compare the time complexity of Dijkstra's algorithm when implemented using a binary heap versus a simple array.

Show answer

Dijkstra does \(V\) extract-mins and up to \(E\) decrease-keys.

QueueExtract-minDecrease-keyTotal
Simple array (scan for min)\(O(V)\)\(O(1)\)\(O(V^2+E)=O(V^2)\)
Binary heap\(O(\log V)\)\(O(\log V)\)\(O((V+E)\log V)\)
  1. Sparse graph (\(E=O(V)\)): heap gives \(O(V\log V)\), much better than \(O(V^2)\).
  2. Dense graph (\(E\approx V^2\)): array gives \(O(V^2)\); heap gives \(O(V^2\log V)\), which is worse. So the simple array wins on dense graphs.

CT-1 (AMR) Q3 · 4 marks

"Dijkstra's algorithm is very centralized but Bellman-Ford algorithm can be used in a distributed fashion" - explain the significance of this statement in no more than 25 words.

Show answer
Dijkstra needs a global view to choose the minimum vertex; Bellman-Ford only needs neighbours' estimates, so each node can run it locally (distance-vector routing).

24 words. Real use: RIP routers run Bellman-Ford, each exchanging distance tables with neighbours only; OSPF routers flood the whole map and run Dijkstra.

Chapter: Relaxation, Bellman-Ford, DAG.

CT-1 (AMR) Q4 · 4 marks

You are given a weighted graph, but it only contains edge weights 1, 2 and 3. Of course, you can use Dijkstra's algorithm to find shortest paths but can you do faster than that? Just outline the solution and complexity.

Show answer
  1. Subdivide. Replace each edge of weight \(w\in\{1,2,3\}\) by a chain of \(w\) unit edges (add \(w-1\) dummy vertices). At most \(2E\) dummy vertices and \(3E\) edges.
  2. Run BFS from the source. BFS distance on the new graph = weighted distance on the old one.
  3. Time \(O(V+E)\) (more exactly \(O(V+3E)\)), faster than Dijkstra's \(O(E\log V)\).
  4. Same idea without dummy vertices: keep 4 circular buckets for distances \(d,d+1,d+2,d+3\) (a bucket queue). Every relaxation lands within 3 of the current distance. Also \(O(V+E)\).

CT1 bank · tag 18 CT1(B) 3

Show how to find the maximum spanning tree of a graph, that is, the spanning tree of largest total weight.

Show answer
  1. Kruskal with the order reversed: sort edges by weight decreasing, then run the same union-find loop. Or Prim with a max-heap (take the largest key each step).
  2. By negation: replace every weight \(w\) by \(-w\) (or by \(W_{max}-w\), non-negative), run any MST algorithm, and keep the chosen edges. A spanning tree has exactly \(V-1\) edges, so it minimises \(\sum(-w)\) iff it maximises \(\sum w\). Negative weights are fine for Kruskal and Prim.
  3. Correctness: the cut property flips: the heaviest edge crossing any cut is in some maximum spanning tree.

Chapter: Cut property, Kruskal, Prim, uniqueness.

CT1 bank · tag 18 CT1(A) 2

The following statements may or may not be correct. In each case, either prove it (if it is correct) or give a counterexample (if it isn't correct). Always assume that the graph G = (V, E) is undirected. Do not assume that edge weights are distinct unless this is specifically stated.

If graph G has more than |V| − 1 edges, and there is a unique heaviest edge, then this edge cannot be part of a minimum spanning tree.

Show answer

False. A unique heaviest edge can be a bridge, and a bridge is in every spanning tree.

Counterexample: triangle x, y, z with all three edges of weight 1, plus a pendant edge z–w of weight 9. \(|E|=4>|V|-1=3\), and z–w is the unique heaviest edge. But w has only that edge, so every spanning tree (hence every MST) contains it.

What is true: a unique heaviest edge is in no MST if it lies on a cycle (cycle property).

CT1 bank · tag 18 CT1(B) 2

(Same instructions as above.) For any r > 0, define an r-path to be a path whose edges all have weight < r. If G contains an r-path from node s to t, then every MST of G must also contain an r-path from node s to node t.

Show answer

True.

  1. Let \(T\) be an MST and \(Q\) an r-path from \(s\) to \(t\) in \(G\). Suppose \(T\) has no r-path from \(s\) to \(t\).
  2. The \(s\)–\(t\) path in \(T\) then has an edge \(e\) with \(w(e)\ge r\).
  3. Remove \(e\) from \(T\). It splits into two components, with \(s\) and \(t\) on different sides.
  4. \(Q\) joins \(s\) to \(t\), so it has an edge \(f\) crossing between the two components. \(f\) is on an r-path, so \(w(f)
  5. \(T-e+f\) is a spanning tree with weight \(w(T)-w(e)+w(f)
  6. So \(T\) contains an r-path from \(s\) to \(t\). \(\blacksquare\)

CT1 bank · tag 18 CT1(C) 2

(Same instructions.) Prim's algorithm works correctly when there are negative edges.

Show answer

True.

  1. Prim's correctness rests on the cut property: the lightest edge crossing a cut is in some MST. The proof compares weights of edges only (exchange argument); it never uses the sign of a weight.
  2. Another way: add a constant \(c\) large enough to make every weight non-negative. Every spanning tree has exactly \(V-1\) edges, so every tree's weight rises by the same \((V-1)c\). The ranking of trees does not change, so the MST is the same. Prim only compares weights, so it behaves identically on the shifted graph.
  3. Contrast: Dijkstra fails with negative edges, because a path's total length matters and extending a path can lower it.

Chapter: Cut property, Kruskal, Prim, uniqueness.

CT1 bank · tag 18 CT1(D) 2

(Same instructions.) The shortest path between two nodes is necessarily part of some MST.

Show answer

False. Counterexample: triangle a, b, c with a–b = 2, b–c = 2, a–c = 3.

  • The shortest path from a to c is the direct edge a–c (length 3), because the path a–b–c has length 4.
  • The only MST is {a–b, b–c} (weight 4). The edge a–c is not in it (a–c is the unique heaviest edge on the cycle).
  • So this shortest path is in no MST. MST minimises total weight; shortest path minimises the length of one path.

Chapter: Cut property, Kruskal, Prim, uniqueness.

CT1 bank · tag 18 CT2(B) 1

Both in Dijkstra and in Prim we have a set of nodes S (that initially contains only s), and we add one additional node in each iteration. Prove or disprove that in both algorithms the nodes are added to S in the same order.

Show answer

Disprove. Prim picks the vertex joined by the lightest single edge; Dijkstra picks the vertex with the smallest total path length from \(s\).

Counterexample: s–a 3, s–c 4, a–b 2, all distinct.

  • Prim from s: keys a = 3, c = 4: take a. Then b = 2 (edge a–b), c = 4: take b. Then c. Order: s, a, b, c.
  • Dijkstra from s: d[a] = 3, d[c] = 4: take a. Then d[b] = 3+2 = 5, d[c] = 4: take c. Then b. Order: s, a, c, b.

The orders differ (b and c swapped). The two algorithms look alike but use different keys. They agree only on the first step (and on some graphs).

CT1 bank · tag 18 CT1(A) 3

Suppose you are given a weighted graph G = (V, E) with a distinguished vertex s and where all edge weights are positive and distinct. Is it possible for a tree of shortest paths from s and a minimum spanning tree in G to not share any edges? If so, give an example. If not, give a reason.

Show answer

Not possible: they always share at least one edge. The shared edge is the lightest edge at \(s\).

  1. Let \(e=(s,u)\) be the lightest edge incident to \(s\). Weights are distinct, so \(e\) is the unique lightest.
  2. \(e\in\) MST. Apply the cut property to the cut \((\{s\},V\setminus\{s\})\): the lightest crossing edge is \(e\), and with distinct weights it is in the (unique) MST.
  3. \(e\in\) shortest-path tree. Any path from \(s\) to \(u\) other than \(e\) starts with an edge \((s,x)\), \(x\ne u\), of weight \(>w(e)\), and then has more positive edges. So its length \(>w(e)\). Hence \(e\) is the unique shortest path to \(u\), and the shortest-path tree contains it.
  4. So both trees contain \(e\). \(\blacksquare\)

Chapter: Cut property, Kruskal, Prim, uniqueness.

CT1 bank · tag 22 CT1 1 · 6 marks

For the following scenarios, which algorithm should you use in order to minimize the runtime? What will be the runtime in each scenario?

(a) Finding shortest pairwise distance between all vertices in an unweighted graph
(b) Finding shortest distance from one source to all vertices in an undirected graph with negative edges
(c) Finding shortest distance between all vertices in a directed sparse graph

Show answer
  1. (a) BFS from every vertex: \(V\) runs of \(O(V+E)\): \(O(V(V+E))\) (\(O(VE)\) for connected graphs). Faster than Floyd-Warshall's \(O(V^3)\) on sparse graphs.
  2. (b) Bellman-Ford from the source: \(O(VE)\). Note: in an undirected graph a negative edge \(\{u,v\}\) is itself a negative cycle (walk \(u\to v\to u\)), so if such an edge is reachable the shortest distances are not defined, and Bellman-Ford reports a negative cycle. If the answer is wanted for "negative edges allowed" in the directed sense, Bellman-Ford is the algorithm and \(O(VE)\) the time.
  3. (c) Johnson's algorithm (works with negative edges, no negative cycle): \(O(V^2\log V+VE)\) with Fibonacci heaps, \(O(VE\log V)\) with binary heaps. For a sparse graph \(E=O(V)\) this is \(O(V^2\log V)\), better than Floyd-Warshall's \(O(V^3)\). If all weights are non-negative, run Dijkstra from every vertex: same bound.

CT1 bank · tag 18 CT2(A) 2

Consider a directed graph with positive weights. Give an algorithm that receives a node s and prints the shortest cycle that contains s.

Show answer
SHORTEST-CYCLE-THROUGH(G, s)
 run DIJKSTRA(G, s)                      // d[v], pi[v] from s
 best = INF;  last = NIL
 for each edge (v, s) entering s          // the cycle must come back to s
    if d[v] + w(v,s) < best
        best = d[v] + w(v,s);  last = v
 if best == INF: print "no cycle through s"
 else: print the path s ... last using pi, then s again
  1. A cycle through \(s\) is a path \(s\leadsto v\) plus an edge \((v,s)\). The best choice for a fixed \(v\) is the shortest path \(s\leadsto v\), \(d[v]\).
  2. Take the minimum over all in-neighbours \(v\) of \(s\). Weights are positive so Dijkstra is valid.
  3. Time \(O(E\log V)\).

CT1 bank · tag 22 CT1 3 · 9 marks

Modify the weights of the following graph so that no negative weights remain and shortest paths between any two vertices are preserved. You must use an algorithm that works on any such graphs.

The graph is not in the sources.

Show answer

This is Johnson's reweighting. The figure is not available, so here is the method with a worked small example.

  1. Add a new vertex \(q\) with 0-weight edges to every vertex.
  2. Run Bellman-Ford from \(q\); \(h(v)=\delta(q,v)\). (If it reports a negative cycle, stop: shortest paths are undefined.)
  3. New weight \(\hat w(u,v)=w(u,v)+h(u)-h(v)\ge0\) for every edge.
  4. Every path from \(a\) to \(b\) changes by the same constant \(h(a)-h(b)\), so shortest paths stay shortest.

Example: A→B 2, B→C −3, C→A 4, A→C 5. \(h(A)=0,h(B)=0,h(C)=-3\). New weights: A→B 2, B→C 0, C→A 1, A→C 8.

CT2 Q2 · 10 marks

You know how to convert a flow network with multiple sources and sinks into a single-source, single-sink network by adding edges with infinite capacity. Can you replace this infinite capacities by finite values if the edges of the original network with multiple sources and sinks have finite capacity? Justify your solution. Also prove that any flow in the resulting network has a finite flow value even if the additional edges have infinite capacities, provided the edges of the original network with multiple sources and sinks have finite capacity.

Show answer

Setup. Sources \(s_1..s_p\), sinks \(t_1..t_q\). Add a super-source \(s^*\) with edges \(s^*\to s_i\) and a super-sink \(t^*\) with edges \(t_j\to t^*\).

(1) Yes, finite capacities work.

  1. Set \(c(s^*,s_i)=\sum_{(s_i,v)\in E}c(s_i,v)\) (the total capacity of the edges leaving \(s_i\)).
  2. Set \(c(t_j,t^*)=\sum_{(u,t_j)\in E}c(u,t_j)\) (the total capacity entering \(t_j\)).
  3. These are finite because the original capacities are finite (and the graph has finitely many edges).
  4. Why nothing is lost. Any flow in the original network sends out of \(s_i\) at most \(\sum c(s_i,v)\), so the new capacity on \(s^*\to s_i\) never limits any flow that the original network could carry. The same holds on the sink side. So the max-flow values of the infinite-capacity and finite-capacity versions are equal.

(2) Every flow in the infinite network has finite value.

  1. The value of a flow is \(|f|=\sum_if(s^*,s_i)\), the flow leaving \(s^*\).
  2. Conservation at \(s_i\) (it is an ordinary vertex now): \(f(s^*,s_i)+\text{inflow from original edges}=\text{outflow on original edges}\). So \(f(s^*,s_i)\le\text{outflow}(s_i)\le\sum_{(s_i,v)\in E}c(s_i,v)<\infty\).
  3. Sum over the finitely many sources: \(|f|\le\sum_i\sum_{(s_i,v)}c(s_i,v)<\infty\).
  4. So every flow value is finite, whatever capacity the added edges have. (A flow value is at most the capacity of any cut, and the cut that isolates the original sources has a finite capacity.) \(\blacksquare\)

CT-4 (MSB) Q2 · 10 marks

Let H1 have a binomial tree of maximum order m and H2 have a binomial tree of max degree m+1. Prove or disprove the statement that H2 must have more nodes than H1, regardless of the fact of the count of trees in those heaps.

Show answer

True (prove).

  1. A binomial tree \(B_k\) has exactly \(2^k\) nodes.
  2. A binomial heap has at most one tree of each order. If its largest tree has order \(m\), its trees are among \(B_0,\dots,B_m\), so \(|H_1|\le\sum_{k=0}^{m}2^k=2^{m+1}-1\).
  3. \(H_2\) contains a \(B_{m+1}\) (maximum order \(m+1\)), which alone has \(2^{m+1}\) nodes. So \(|H_2|\ge2^{m+1}\).
  4. \(|H_2|\ge2^{m+1}>2^{m+1}-1\ge|H_1|\). \(\blacksquare\)

The number of trees does not matter: even if \(H_1\) has every possible tree and \(H_2\) only the one tree \(B_{m+1}\), \(H_2\) still has one more node.

CT4 bank · tag 18 CT4 6c · 4 marks

Point out and briefly discuss the fallacy in the following "proof" that P ≠ NP: "To see if a 3-SAT formula is satisfiable, we need to look at 2n possible truth assignments. This takes exponential time, so 3-SAT is not in P. But it is in NP, so P ≠ NP."

Show answer
  1. The fallacy: "this algorithm takes exponential time, so 3-SAT is not in P". Brute force is one algorithm. A problem is in P if some polynomial algorithm exists. The existence of a slow algorithm says nothing about the existence of a fast one.
  2. To show 3-SAT is not in P you must prove a lower bound for every possible algorithm: none runs in polynomial time. Nobody knows how.
  3. The last step is fine: if 3-SAT were in NP but not in P, then P ≠ NP. The error is the unproved middle step.

CT4 bank · tag 22 CT3 2 · 10 marks

The Set Partition Problem takes as input a multiset S of numbers. The question is whether the numbers can be partitioned into two subsets A and A′ = S − A such that Σx∈A x = Σx∈A′ x. Show that the Set Partition Problem is NP-complete. Hint: The Subset Sum Problem takes as input a multiset S of numbers and a target sum T. The question is to decide whether there exists a subset S′ ⊆ S whose elements sum to T. The Subset Sum Problem is known to be NP-complete.

Show answer

Method (two parts: in NP, and NP-hard by reduction)

  1. In NP. Certificate: the subset \(A\). The verifier adds up both sides and compares: polynomial time.
  2. NP-hard: Subset Sum \(\le_p\) Set Partition. Instance \((S,T)\) of subset sum. Let \(\sigma=\sum_{x\in S}x\). If \(T>\sigma\), output a fixed no-instance (for example \(\{1\}\)). Otherwise build \(S'=S\cup\{u,v\}\) with \(u=2\sigma-T\) and \(v=\sigma+T\).
  3. Total of \(S'\): \(\sigma+(2\sigma-T)+(\sigma+T)=4\sigma\). Each side must sum to \(2\sigma\).
  4. (⇒) If some \(X\subseteq S\) sums to \(T\): side A = \(X\cup\{u\}\) has \(T+2\sigma-T=2\sigma\); side B = \((S\setminus X)\cup\{v\}\) has \((\sigma-T)+(\sigma+T)=2\sigma\). A valid partition.
  5. (⇐) Suppose a partition into two sides of sum \(2\sigma\) exists. \(u+v=3\sigma>2\sigma\), so \(u\) and \(v\) are on different sides. The side containing \(u\) is \(\{u\}\cup X\) for some \(X\subseteq S\), with sum \(2\sigma-T+\sum X=2\sigma\), so \(\sum X=T\). The subset \(X\) solves subset sum.
  6. The construction takes linear time. So Set Partition is NP-hard, and in NP, so NP-complete. \(\blacksquare\)
