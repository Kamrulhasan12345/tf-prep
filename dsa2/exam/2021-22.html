2021–22 · Q1(a) · 8 marks

Define and distinguish the two basic properties of the greedy algorithm.

Show answer

Chapter: Cut property, Kruskal, Prim, uniqueness.

  1. Greedy-choice property. A globally optimal solution can be built by making the locally best choice at each step. After the first greedy choice, some optimal solution still contains it. (Example: the lightest edge across a cut is in some MST.)
  2. Optimal substructure. An optimal solution to the problem contains optimal solutions to its sub-problems. (Example: remove an edge from an MST, each of the two parts is an MST of its vertex set; or contract the chosen edge, the rest is an MST of the smaller graph.)
  3. Difference. Greedy-choice says which first step is safe. Optimal substructure says what is left after the step is again the same kind of problem solved optimally. Dynamic programming needs substructure but tries every choice; greedy needs both and tries one.
2021–22 · Q1(b) · 12 marks

Prove (i) the optimal sub-structure property and (ii) the greedy choice property of the Minimum Spanning Tree (MST) problem.

Show answer

Chapter: Cut property, Kruskal, Prim, uniqueness.

(i) Optimal substructure.

  1. Let \(T\) be an MST of \(G=(V,E)\) and \(e=(u,v)\in T\). Removing \(e\) splits \(T\) into two trees \(T_1\) on vertex set \(V_1\) and \(T_2\) on \(V_2\).
  2. Claim: \(T_1\) is an MST of \(G[V_1]\) (the subgraph induced by \(V_1\)), and likewise \(T_2\) of \(G[V_2]\).
  3. Suppose not: some spanning tree \(T_1'\) of \(G[V_1]\) has \(w(T_1')

(ii) Greedy-choice property (cut property). Claim: let \((S,V\setminus S)\) be any cut and \(e\) a minimum-weight edge crossing it. Then some MST contains \(e\).

  1. Let \(T\) be an MST. If \(e\in T\), done.
  2. Otherwise \(T+e\) has exactly one cycle. The cycle crosses the cut at \(e\), so it must cross back at another edge \(f\in T\) crossing the cut.
  3. \(w(e)\le w(f)\) since \(e\) is a lightest crossing edge.
  4. \(T'=T-f+e\) is a spanning tree (the cycle is broken) with \(w(T')=w(T)-w(f)+w(e)\le w(T)\). So \(T'\) is also an MST and contains \(e\). ∎
  5. Kruskal and Prim are this property applied repeatedly: the edge chosen is the lightest across a cut that respects the edges chosen so far.
2021–22 · Q1(c) · 15 marks

Develop a solution of the MST problem using the disjoint set / union-find data structure. Use the array implementation to maintain union-find.

Show answer

Chapter: Cut property, Kruskal, Prim, uniqueness. This is Kruskal's algorithm; the union-find answers "do \(u\) and \(v\) lie in the same tree?" in nearly \(O(1)\).

Array implementation. Three arrays over the vertices \(1..n\): set[v] = label of the set containing \(v\); size[label]; and a member list per label (a linked list or array).

MAKE-SET(v):  set[v] = v;  size[v] = 1;  members[v] = [v]
FIND(v):      return set[v]                        // O(1)
UNION(a, b):  // a, b are labels, a != b
   if size[a] < size[b] then swap(a, b)
   for each v in members[b]                         // relabel the SMALLER set
        set[v] = a
   members[a] = members[a] + members[b];  size[a] += size[b]

KRUSKAL(G, w)
   A = empty;  for each v: MAKE-SET(v)
   sort the edges by weight increasing
   for each edge (u, v) in order
       if FIND(u) != FIND(v)
           A = A + {(u, v)};  UNION(FIND(u), FIND(v))
   return A
  1. Correctness. Each accepted edge is the lightest edge leaving the tree that contains \(u\), among edges not yet considered: it is a light edge across a cut respecting \(A\), so it is safe (cut property). A rejected edge would close a cycle.
  2. Cost of unions. A vertex is relabelled only when its set is the smaller one, so its set size at least doubles each time. A vertex is relabelled at most \(\log_2n\) times, so all unions cost \(O(n\log n)\) in total.
  3. Total. Sorting \(O(E\log E)=O(E\log V)\); \(2E\) FIND calls \(O(E)\); unions \(O(V\log V)\). Total \(O(E\log V)\).

The tree-of-parents array (parent[v]) with union by rank and path compression gives \(O(E\alpha(V))\) after sorting, but the label-array version above is what "array implementation" asks for. You can run Kruskal on any graph in the chapter's tracer to see the sets merge.

What are the splay-step operations to make a binary search tree a balanced one?

Show answer

Chapter: Splay trees. Low priority: splay trees are not in the available notes or slides. When a node \(x\) is accessed, it is moved to the root by repeating one of three steps, with \(p\) its parent and \(g\) its grandparent:

  1. Zig: \(p\) is the root. One rotation at \(p\) (right if \(x\) is a left child, left otherwise). Used only as the last step.
  2. Zig-zig: \(x\) and \(p\) are both left children (or both right). Rotate at \(g\) first, then at \(p\).
  3. Zig-zag: \(x\) is a left child and \(p\) a right child (or the opposite). Rotate at \(p\), then at \(g\) (the double rotation of AVL).

Splaying also roughly halves the depth of every node on the access path, which is why a bad tree gets balanced after a few accesses. Example run (insert 5, 4, 3, 2, 1, each splayed to the root, then access 1):

Suppose you are inserting a node in an AVL tree, and x is the lowest node violating AVL and x is left-heavy. Demonstrate the balancing procedure using figures.

Show answer

Chapter: Rotations and AVL trees. Balance factor = height(left) minus height(right). \(x\) is left-heavy, so \(bf(x)=+2\). Look at \(x\)'s left child \(y\). There are exactly two cases.

  1. \(bf(y)=+1\): Left-Left (LL). The new key went into \(y\)'s left subtree. One right rotation at \(x\). \(y\) becomes the subtree root, \(x\) its right child, \(y\)'s old right subtree becomes \(x\)'s left subtree. Both balance factors become 0.
  2. \(bf(y)=-1\): Left-Right (LR). The new key went into \(y\)'s right subtree. Let \(z\) be \(y\)'s right child. Left rotation at \(y\), then right rotation at \(x\). \(z\) becomes the root of the subtree with \(y\) on the left and \(x\) on the right. \(z\) gets balance 0.

After insertion \(bf(y)\) cannot be 0 (that happens only in deletion). After the rotation the subtree height returns to what it was before the insert, so no ancestor changes: one rebalancing per insertion.

2021–22 · Q2(c) · 15 marks

What are the properties of a red-black tree? Derive that if a tree with \(n\) keys follows the red-black properties, its height \(h\) can be bounded as \(h\le2\lg(n+1)\).

Show answer

Chapter: Red-black trees from zero.

Properties.

  1. Every node is red or black.
  2. The root is black.
  3. Every leaf (NIL) is black.
  4. A red node has only black children (no two reds in a row).
  5. All paths from a node down to its NIL leaves contain the same number of black nodes (black height).

Derivation. \(bh(x)\) = number of black nodes on a path from \(x\) down to a leaf, not counting \(x\).

  1. Claim. The subtree rooted at \(x\) has at least \(2^{bh(x)}-1\) internal nodes.
  2. Induction on the height of \(x\). If \(x\) is a NIL leaf: \(bh=0\), \(2^0-1=0\) nodes. ✓
  3. Otherwise \(x\) has two children, each with black height \(bh(x)\) (red child) or \(bh(x)-1\) (black child), so at least \(bh(x)-1\). By induction each child's subtree has at least \(2^{bh(x)-1}-1\) internal nodes. So \(x\)'s subtree has at least \(2(2^{bh(x)-1}-1)+1=2^{bh(x)}-1\). ✓
  4. Let \(h\) be the height of the tree. By property 4, at least half the nodes on any root-to-leaf path are black, so \(bh(\text{root})\ge h/2\).
  5. Then \(n\ge2^{h/2}-1\), so \(n+1\ge2^{h/2}\), and taking \(\lg\): \(h\le2\lg(n+1)\). ∎

Question 3 (35)

2021–22 · Q3 · 8 + 12 + 15 marks

Dhaka traffic: the map is an undirected graph, nodes are stations (2-D points), the cost of a road is proportional to the Euclidean distance. Temporarily build one new road between two chosen nodes. Whether to build \(u\)-\(v\) is decided by \(C_{uv}=\sum(\text{PreCost}_{ij}-\text{CurCost}_{ij})\), where CurCost is the shortest path cost from \(i\) to \(j\) if the road \(u\)-\(v\) is built and PreCost is the shortest path cost before. The pair with the highest \(C_{uv}\) is chosen. (a) Define the input and output of the program. (8) (b) Sketch the pseudo-code of the solution. (12) (c) Develop the most efficient solution of the underlying algorithm that serves as the backbone of the solution. (15)

Show answer

Chapters: Floyd-Warshall, Johnson, Dijkstra.

(a) Input and output.

  • Input: \(n\) stations with coordinates \((x_k,y_k)\); \(m\) existing roads \((a,b)\), each with cost \(c(a,b)=\kappa\cdot\sqrt{(x_a-x_b)^2+(y_a-y_b)^2}\) (\(\kappa\) the constant of proportionality). Any pair of stations may be linked by a new road, with its cost from the same formula.
  • Output: the pair \((u,v)\) with the largest \(C_{uv}\) and that value.

(b) Pseudo-code. Adding one edge \(u\)-\(v\) of cost \(c\) changes a shortest path only if it uses the new edge once, so

\[ D'[i][j]=\min\bigl(D[i][j],\ D[i][u]+c+D[v][j],\ D[i][v]+c+D[u][j]\bigr) \]

BEST-ROAD(V, E)
  D = ALL-PAIRS-SHORTEST-PATHS(V, E)        // backbone, part (c)
  best = -INF
  for each pair u < v                          // O(n^2) candidates
     c = euclid(u, v)
     gain = 0
     for each pair i < j                       // O(n^2) per candidate
        new = min(D[i][j], D[i][u] + c + D[v][j], D[i][v] + c + D[u][j])
        gain = gain + (D[i][j] - new)
     if gain > best then best = gain; (bu, bv) = (u, v)
  return (bu, bv), best

Time: APSP \(+\;O(n^2)\cdot O(n^2)=O(n^4)\) for the search. Memory \(O(n^2)\). (This avoids re-running APSP \(n^2\) times, which would cost \(O(n^5)\).)

(c) The backbone: all-pairs shortest paths. Weights are positive (distances), so there are no negative edges and no reweighting is needed.

  1. Dense case, Floyd-Warshall: \(d^{(k)}_{ij}=\min(d^{(k-1)}_{ij},d^{(k-1)}_{ik}+d^{(k-1)}_{kj})\), three nested loops, \(\Theta(n^3)\) time, \(\Theta(n^2)\) space. Simple, with a tiny constant.
  2. Sparse case (road maps are sparse, \(m=O(n)\)): run Dijkstra from every station: \(n\) runs of \(O(m+n\log n)\) with a Fibonacci heap (or \(O((m+n)\log n)\) with a binary heap), total \(O(nm+n^2\log n)\), which for \(m=O(n)\) is \(O(n^2\log n)\), better than \(n^3\). This is Johnson's algorithm minus the reweighting step.
  3. So the most efficient backbone for a road network is \(n\) Dijkstra runs; for a dense graph, Floyd-Warshall. The overall running time is then dominated by the \(O(n^4)\) candidate search, not by the APSP.

Question 4 (35)

2021–22 · Q4(a) · 8 marks

Define the max-flow problem.

Show answer

Chapter: Flow networks, residuals, Ford-Fulkerson.

  1. Flow network: directed graph \(G=(V,E)\), a source \(s\), a sink \(t\), a capacity \(c(u,v)\ge0\) on every edge.
  2. Flow: \(f:V\times V\to\mathbb R\) with (a) capacity constraint \(0\le f(u,v)\le c(u,v)\); (b) flow conservation: for every \(v\ne s,t\), flow in equals flow out.
  3. Value \(|f|=\)(flow out of \(s\)) \(-\) (flow into \(s\)).
  4. Max-flow problem: find a flow of maximum value. Solved by Ford-Fulkerson / Edmonds-Karp; its value equals the capacity of a minimum \(s\)-\(t\) cut.
2021–22 · Q4(b) · 12 + 15 marks

Car parking: match each car with a parking spot. Cars \(A\) and parking slots \(B\) are located around the city and reachable through a road network graph \(G\). The cost for \(a\in A\) to reach \(b\in B\) is the shortest distance between them in \(G\) (infinite if unreachable). (i) Formulate the problem using max-flow/min-cut. (12) (ii) Develop an efficient solution that matches every car so that the overall cost is minimized. (15)

Show answer

Chapters: Bipartite matching and modelling, Flow, Dijkstra.

(i) Formulation.

  1. Costs first: run Dijkstra from every car on \(G\) (or from every slot, whichever set is smaller) to get \(d(a,b)\) for all \(a\in A,b\in B\).
  2. Build a flow network: source \(s\), sink \(t\), a vertex for each car and each slot. Edges \(s\to a\) (capacity 1, cost 0), \(a\to b\) when \(d(a,b)<\infty\) (capacity 1, cost \(d(a,b)\)), \(b\to t\) (capacity 1, cost 0).
  3. A flow of value \(k\) is a set of \(k\) car-slot pairs, no car and no slot used twice (integrality theorem). The maximum flow is the largest number of cars that can be parked.
  4. Can every car be matched? Yes iff \(\max\text{ flow}=|A|\). By max-flow min-cut, the matching is incomplete iff some cut has capacity below \(|A|\); this is Hall's condition (some set of cars has fewer reachable slots than cars).
  5. Honest point: plain max-flow ignores the cost. It tells you whether a full matching exists and gives some matching; it does not minimise the total distance. That is the next part.

(ii) Minimum-cost matching = min-cost max-flow.

  1. Use the same network and find a maximum flow of minimum total cost \(\sum f(u,v)\,\text{cost}(u,v)\).
  2. Successive shortest paths. Start with zero flow. Repeat: in the residual network (a backward edge of an edge with cost \(c\) has cost \(-c\)) find a cheapest \(s\to t\) path, with Bellman-Ford (negative residual costs), and push 1 unit along it. Stop when no path exists.
  3. Why it is optimal: the flow after each step is a min-cost flow for its value, because the residual network never contains a negative cycle (a negative cycle would let us reduce the cost). So after \(|A|\) pushes the flow is a minimum-cost matching of all cars.
  4. Time. \(|A|\) augmentations, each Bellman-Ford \(O(VE)\) with \(V=|A|+|B|+2\) and \(E\le|A||B|+|A|+|B|\): \(O(|A|\,VE)\). With Dijkstra and potentials (Johnson's reweighting) each augmentation is \(O(E+V\log V)\). The Hungarian algorithm solves the same assignment problem in \(O(n^3)\) for \(|A|=|B|=n\).
  5. If a car has no reachable slot (all costs infinite), no full matching exists: report the maximum number that can be parked and the cheapest way to do it.

Chapters: Binomial heap operations, Potential method.

(a) Algorithm and analysis

The heap order of a min-heap does not fit a max-heap, so the trees cannot be reused. Rebuild by inserting every key into a new max-heap.

MIN-TO-MAX(H)                       // H: binomial min-heap with n keys
   H' = new empty binomial max-heap
   for each tree T in the root list of H
       traverse T (preorder, DFS)
          for each node x visited: BINOMIAL-INSERT(H', x.key)   // max-heap insert
   return H'
  1. Traversal: each of the \(n\) nodes is visited once: \(O(n)\) actual cost, and the unlinking of the old structure is free (the old heap is discarded).
  2. Potential: \(\Phi(H')=t(H')\), the number of trees of \(H'\). \(\Phi(\text{empty})=0\) and \(\Phi\ge0\).
  3. One insert: actual cost \(1+k\), where \(k\) is the number of links (like carries in a binary counter). Each link removes one tree, the new node adds one: \(\Delta\Phi=1-k\). Amortized cost \(=(1+k)+(1-k)=2=O(1)\).
  4. Total: traversal \(O(n)\) plus \(n\) inserts at amortized \(2\) each, \(2n\): \(\mathbf{O(n)}\) amortized. (The actual cost of \(n\) inserts is also \(\le2n\), since the final potential is non-negative.) ∎

2021–22 · Q6(b) · 10 marks

Analyze the running time of a chaining hash table in both successful and unsuccessful search cases.

Show answer

Chapter: Chaining and open addressing. Assumption: simple uniform hashing. \(n\) keys, \(m\) slots, \(\alpha=n/m\).

  1. Unsuccessful search. The key hashes to a uniformly random slot. The whole chain there is scanned. Expected chain length \(=\alpha\). Cost \(\Theta(1+\alpha)\): \(O(1)\) to compute the hash, \(\alpha\) to scan.
  2. Successful search. The searched key is one of the \(n\) keys, each with probability \(1/n\). For the \(i\)-th inserted key (tail insertion), the search scans \(1+\) the number of earlier keys in the same chain. Expected \(1+(i-1)/m\).
  3. Average over \(i\): \[\frac1n\sum_{i=1}^n\Bigl(1+\frac{i-1}{m}\Bigr)=1+\frac{n-1}{2m}=1+\frac{\alpha}2-\frac{\alpha}{2n}.\] So \(\Theta(1+\alpha)\).
  4. If \(m=\Theta(n)\) (so \(\alpha=O(1)\)) both cases are \(O(1)\) on average. Worst case, all keys in one chain: \(\Theta(n)\).

Question 7 (35)

2021–22 · Q7(a) · 5 + 10 marks

A social media platform wants an admin feature: find the minimal subset of users who can reach out to all other users through their connections. A colleague says the problem maps to a popular NP-complete problem. (i) Map the problem to the NP-complete problem your colleague suggested. (5) (ii) Prove that the problem is NP-complete, using 3-SAT in the proof. (10)

Show answer

Chapters: Reductions, with proof templates, NP classes.

(i) Mapping: DOMINATING SET. Users are vertices; a connection is an undirected edge. A chosen subset reaches everyone through its connections if every user is in the subset or is adjacent to a member (the subset dominates the graph). The platform's problem is the minimum dominating set. Decision version DS: given \(G\) and \(k\), is there a dominating set of size \(\le k\)?

(ii) DS is NP-complete.

  1. In NP. Certificate: the set \(D\). Check \(|D|\le k\) and that every vertex is in \(D\) or has a neighbour in \(D\): \(O(V+E)\).
  2. NP-hard: 3-SAT \(\le_p\) DS. Given a formula \(\varphi\) with variables \(x_1..x_n\) and clauses \(c_1..c_m\), each with 3 literals.
  3. Variable gadget. For each variable \(x_i\): a triangle on three vertices \(x_i\), \(\bar x_i\), \(v_i\).
  4. Clause gadget. For each clause \(c_j\): one vertex \(c_j\), joined to the three literal vertices that appear in the clause.
  5. Set \(k=n\). The graph has \(3n+m\) vertices; built in polynomial time.
  6. Forward. A satisfying assignment: put \(x_i\) in \(D\) if \(x_i\) is true, else \(\bar x_i\). So \(|D|=n\). Each triangle is dominated (the chosen vertex is adjacent to the other two). Each clause vertex has at least one true literal, hence a neighbour in \(D\). So \(D\) dominates.
  7. Backward. Let \(D\) be a dominating set with \(|D|\le n\). Each \(v_i\) is adjacent only to \(x_i,\bar x_i\), so \(D\) must contain one of \(\{v_i,x_i,\bar x_i\}\) for every \(i\). These \(n\) triangles are disjoint, so \(D\) contains exactly one vertex from each and no clause vertex. If it chose \(v_i\), swap it for \(x_i\): the triangle is still dominated and no vertex loses its dominator (\(v_i\) dominated nobody outside its triangle). Now \(D\) has exactly one literal per variable: set that literal true. Every clause vertex is outside \(D\), so it has a neighbour in \(D\): a true literal in the clause. Every clause is satisfied.
  8. So \(\varphi\) is satisfiable iff \(G\) has a dominating set of size \(n\). 3-SAT is NP-hard, hence DS is NP-hard, and with step 1 NP-complete. ∎

Where marks go

  • The question names 3-SAT, so VERTEX COVER \(\to\) DS is not what is asked, even though it also works.
  • The step that most students miss is "one vertex per triangle exactly, so no clause vertex is in \(D\)" and the swap of \(v_i\) for a literal.

On paper: draw the gadget for \((x_1\vee\bar x_2\vee x_3)\): three triangles and the clause vertex joined to \(x_1\), \(\bar x_2\) and \(x_3\).

2021–22 · Q8 · 5 + 15 + 15 marks

Luggage capacity 600 kg. Items (value, weight): 1 (1200, 150), 2 (1100, 100), 3 (950, 250), 4 (1350, 350), 5 (800, 200), 6 (1500, 300). Use the approximation algorithm that scales values down by \(\varepsilon V_{\max}/2n\) and uses dynamic programming with sub-problem \(OPT(i,v)\) (the minimum weight needed to reach value at least \(v\) using items \(1..i\)) instead of \(OPT(i,w)\). (a) Why does the algorithm use \(OPT(i,v)\) rather than \(OPT(i,w)\)? (5) (b) Apply the algorithm with \(\varepsilon=0.1\). (15) (c) Prove that for any \(\varepsilon>0\) the algorithm computes a feasible solution within a \((1+\varepsilon)\) factor of the optimum in \(O(n^3/\varepsilon)\). (15)

Show answer

Chapter: Approximation algorithms.

(a) Why \(OPT(i,v)\).

  1. The DP over weights, \(OPT(i,w)\), has \(n\times W\) entries: pseudo-polynomial. \(W\) is a number given in binary, so \(W\) can be exponential in the input size.
  2. We cannot shrink weights: rounding a weight can make a set that fits look like it does not fit, or the reverse, so the answer may be infeasible.
  3. We can shrink values: rounding values only makes the value slightly wrong, never infeasible. So the table is indexed by (scaled) value. After scaling each value is at most \(2n/\varepsilon\), so the table has polynomially many entries.

(b) The algorithm with \(\varepsilon=0.1\).

  1. \(V_{\max}=1500\), \(n=6\). Scale factor \(\theta=\dfrac{\varepsilon V_{\max}}{2n}=\dfrac{0.1\times1500}{12}=12.5\).
  2. Scaled values \(\bar v_i=\lfloor v_i/\theta\rfloor\): item 1: 96, item 2: 88, item 3: 76, item 4: 108, item 5: 64, item 6: 120. Sum 552.
  3. \(OPT(i,v)\) = least weight of a subset of items \(1..i\) with scaled value \(\ge v\): \(OPT(0,0)=0\), \(OPT(0,v>0)=\infty\), and \(OPT(i,v)=\min\bigl(OPT(i-1,v),\ w_i+OPT(i-1,\max(0,v-\bar v_i))\bigr)\).
  4. Answer = the largest \(v\) with \(OPT(n,v)\le600\). Computed: \(v=304\), with \(OPT(6,304)=550\). For \(v=304\) the column reads \(OPT(i,304)\): \(\infty,\infty,\infty,\infty\) for \(i=0..3\), then 850 (\(i=4\)), 700 (\(i=5\)), 550 (\(i=6\)). Larger \(v\) needs more than 600 kg.
  5. Recover the set by walking back: items 1, 2, 6. Scaled value \(96+88+120=304\). Real value \(1200+1100+1500=\mathbf{3800}\). Weight \(150+100+300=550\le600\).
  6. Check against brute force over all 64 subsets: the true optimum is also 3800 with items 1, 2, 6, so here the approximation is exact. The guarantee only promises \(\ge3800/1.1\approx3455\).

On paper: write \(\theta\), the six scaled values, and a table whose rows are items 1..6 and columns are the values reachable (only the interesting ones, such as 96, 88, 64, 120, 184, 304). Underline the final cell and trace back.

(c) Proof of the \((1+\varepsilon)\) guarantee and the running time. Take \(0<\varepsilon\le1\). Assume every item fits alone (weight \(\le W\)), so \(\text{OPT}\ge V_{\max}\). Let \(S^*\) be an optimal set and \(S\) the set the algorithm returns.

  1. Feasible. The DP only accepts sets with total weight \(\le W\) (the real weights, unchanged). So \(S\) is feasible.
  2. Rounding error per item. \(\bar v_i=\lfloor v_i/\theta\rfloor\) gives \(\theta\bar v_i\le v_i<\theta\bar v_i+\theta\), so \(v_i-\theta\bar v_i<\theta\).
  3. Chain. \(S\) is optimal for the scaled values, and \(S^*\) is feasible, so \(\sum_{S}\bar v_i\ge\sum_{S^*}\bar v_i\). Then \[\sum_{i\in S}v_i\ \ge\ \theta\sum_{S}\bar v_i\ \ge\ \theta\sum_{S^*}\bar v_i\ \ge\ \sum_{S^*}(v_i-\theta)\ \ge\ \text{OPT}-n\theta.\]
  4. \(n\theta=\varepsilon V_{\max}/2\le\varepsilon\,\text{OPT}/2\). So \(\text{value}(S)\ge(1-\varepsilon/2)\,\text{OPT}\).
  5. \(\dfrac{1}{1-\varepsilon/2}\le1+\varepsilon\) for \(0<\varepsilon\le1\) because \((1+\varepsilon)(1-\varepsilon/2)=1+\tfrac{\varepsilon}{2}-\tfrac{\varepsilon^2}{2}\ge1\). So \(\text{OPT}\le(1+\varepsilon)\,\text{value}(S)\). ∎
  6. Running time. The largest scaled value is \(\lfloor V_{\max}/\theta\rfloor=2n/\varepsilon\). The total of scaled values is at most \(n\cdot2n/\varepsilon=2n^2/\varepsilon\). The table has \(n\) rows and \(2n^2/\varepsilon\) columns, each cell in \(O(1)\): \(O(n\cdot n^2/\varepsilon)=\mathbf{O(n^3/\varepsilon)}\). That is polynomial in \(n\) and \(1/\varepsilon\): a fully polynomial-time approximation scheme (FPTAS).
