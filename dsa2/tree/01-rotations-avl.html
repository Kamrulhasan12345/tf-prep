Rotations and AVL Trees

AVL is asked almost every year. 2024–25: Q5(b), 10 marks (name the imbalance, show before and after), Q6(b), 10 marks (smallest AVL tree of height 5). 2023–24: Q12(a) height O(log n), 10; Q12(c) insert and delete sequence, 15. 2022–23: Q4(b) properties and balance proof, 12. 2021–22: Q2(b) left-heavy fix with figures, 12. 2020–21: Q7(a) two insertions, 5+5. 2019–20: Q4(b) prove or disprove, 12. 2018–19: Q3(a) rotations, 15. 2017–18: Q5(a) height proof, 12; Q5(d), 4.

1. The problem: a BST can be a stick

Search, insert and delete in a binary search tree cost O(h), where h is the height. If you insert 1, 2, 3, 4, 5 in order, every key goes to the right of the last one. The tree is a chain and h = n − 1, so every operation costs O(n).

A balanced tree keeps h about lg n. The notes list four tools: rotations, AVL trees, red-black trees, splay trees. Rotations are the basic move that the other three all use.

Height convention (your teacher's): a leaf has height 0. An empty child has height −1. So h(node) = 1 + max(h(left), h(right)). All numbers in this chapter use it.

2. Rotation: change the shape, keep the order

A rotation moves one node up and its parent down, in O(1), and the in-order sequence stays sorted. Greek letters below are whole subtrees. Their order is always α < x < β < y < γ.

Read the picture left to right for right rotate at y (y is the node that goes down, to the right). Read it right to left for left rotate at x. The name always says which node goes down and in which direction.

Method · right rotate at y (y has a left child x)

  1. x becomes the root of this piece. y becomes x's right child.
  2. The subtree β (x's old right child) must move: it becomes y's left child. This is the only subtree that changes parent. The slides call it "transplant x.right into y.left".
  3. α stays under x, γ stays under y. The link above the piece now points to x instead of y.

Left rotate at x is the mirror: y = x.right moves up, x becomes y's left child, β (y's old left child) becomes x's right child.

LEFT-ROTATE(T, x)
 y = x.right
 x.right = y.left                  // beta moves over
 if y.left != NIL: y.left.p = x
 y.p = x.p                         // y takes x's place under the parent
 if x.p == NIL: T.root = y
 elif x == x.p.left: x.p.left = y
 else: x.p.right = y
 y.left = x; x.p = y

Rotation changes depths. In the right rotation, α goes up one level, γ goes down one level, β stays at the same depth. That is why a rotation can fix a tree that is too heavy on one side.

3. What an AVL tree is

An AVL tree is a BST in which for every node, the heights of its left and right subtrees differ by at most 1. The slides phrase it as: both subtrees are AVL trees, and the sibling height difference is at most 1.

Balance factor (the sign convention used in the papers): bf(v) = h(left) − h(right). A node is fine if bf ∈ {−1, 0, +1}. bf = +2 means too heavy on the left. bf = −2 means too heavy on the right.

AVL: every bf is -1, 0 or +1
Not AVL: root is 0 but node 30 has +2

Where marks go

  • Checking only the root. The rule is for every node. The right-hand tree has bf 0 at the root and is still not AVL.
  • Mixing the sign. Say once at the top of your answer: "bf = height(left) − height(right)".
  • Counting a leaf as height 1 and an empty tree as 0. The numbers (N(5) = 20 and so on) assume leaf = 0.

4. The four imbalance cases

After an insert or delete, one node can reach bf = ±2. Call the lowest such node A. Call its taller child B. If needed, call B's taller child C. The case name is the path A → B → C: first letter A→B, second letter B→C.

Method · pick the rotation from two numbers

  1. Find the lowest node A with bf = +2 or −2.
  2. Look at B, the child on the heavy side, and its bf.
  3. bf(A) = +2, bf(B) = +1 or 0 → LL: one right rotate at A.
  4. bf(A) = +2, bf(B) = −1 → LR: left rotate at B, then right rotate at A.
  5. bf(A) = −2, bf(B) = −1 or 0 → RR: one left rotate at A.
  6. bf(A) = −2, bf(B) = +1 → RL: right rotate at B, then left rotate at A.

Same sign (or B is 0): the heavy side is a straight line, one rotation. Opposite signs: the heavy side bends like a zig-zag, two rotations. The slides say it as: "rotate once if left-left or right-right, twice if left-right or right-left", and "move to the right, then to the left: two steps down to the heavier subtree".

Heights in the figures: for an insertion, one subtree has just grown, so it is h+1 while its neighbours are h. The small label under each triangle shows this. Blue numbers beside a node are bf.

LL: A is +2, B is +1

RR: A is −2, B is −1 (mirror of LL)

LR: A is +2, B is −1

RL: A is −2, B is +1 (mirror of LR)

After deletion, B can have bf = 0 (both its subtrees are h+1). That still counts as LL or RR and one rotation fixes A, but the result is B = −1, A = +1 for LL (or B = +1, A = −1 for RR), not 0, 0. The whole subtree keeps its height this time, so the walk up the tree continues only if the height dropped.

5. 2024–25 Q5(b), the exact answer

"After inserting a key into an AVL tree, a node A becomes unbalanced such that its balance factor becomes +2, while its left child B has a balance factor of −1. Determine the exact type of imbalance, describe the rotations, show the subtree before and after, with the final balance factors of all nodes involved." (10 marks)

Method · model answer, in the order a marker ticks it

  1. Type. bf(A) = +2 means the left side is too tall. bf(B) = −1 means B's right side is the taller one. So the new key went into the right subtree of A's left child: a Left-Right (LR) imbalance. A single right rotation at A would not work, because the heavy part (C) would just move to the other side.
  2. Heights. Let δ (A's right subtree) have height h. Then B has height h+2, so α (B's left) has height h and C (B's right) has height h+1. C's children β and γ have heights h and h, or h and h−1, or h−1 and h. (If C is the new leaf, β and γ are empty and the formulas still work with h = −1.)
  3. Rotation 1: left rotate at B. C moves up, B becomes C's left child, β moves to B's right. Now A, C, B form a straight left line (LL shape).
  4. Rotation 2: right rotate at A. C moves up again. A becomes C's right child, γ moves to A's left.
  5. Result. C is the root of the subtree, B is its left child with α and β, A is its right child with γ and δ.
  6. Final balance factors. bf(C) = 0 always. B and A depend on C's old bf, see the table.
  7. Order and height. The in-order sequence α B β C γ A δ is unchanged. The subtree has height h+2 again, the same as before the insertion, so no ancestor above A is affected.

6. Insertion and deletion

Method · AVL insertion

  1. Insert as in a normal BST. The new node is a leaf, bf = 0.
  2. Walk up from the new node, updating heights and bf.
  3. At the first (lowest) node with bf = ±2, apply the case from section 4.
  4. Stop. After the rotation the subtree is as tall as before the insert, so no other node can be unbalanced. Insertion needs at most one rotation (single or double).

Method · AVL deletion

  1. Delete as in an ordinary BST. If the node z has two children, find x, the in-order successor (smallest key in the right subtree), copy the key of x into z, then delete x (x has at most one child). The slides draw it as "z: to be deleted, copy key of x to z, then delete x". Using the predecessor instead is also correct, but say which one you use.
  2. Walk from the place where a node was removed up to the root, updating heights and bf.
  3. At every node with bf = ±2, rotate as in section 4. If the heavy child has bf = 0, use the single rotation.
  4. Do not stop at the first rotation. A rotation can shorten the subtree, which can unbalance a node higher up. Deletion may need O(log n) rotations.
AVL-INSERT(T, k)
 BST-insert k as a leaf; z = new node
 for each ancestor v of z, from the bottom up
   update h(v)
   if |bf(v)| == 2
     rebalance(v)          // LL, LR, RR or RL
     break                 // one fix is enough for insert

AVL-DELETE(T, k)
 z = node with key k
 if z has two children: x = successor(z); z.key = x.key; z = x
 splice out z (it has at most one child)
 for each ancestor v of z, from the bottom up to the root
   update h(v)
   if |bf(v)| == 2: rebalance(v)    // no break: keep going

8. Height is O(log n): the proof

Asked in 2023–24 Q12(a), 2022–23 Q4(b), 2017–18 Q5(a). Idea: find the fewest nodes an AVL tree of height h can have. If that grows exponentially in h, then h is logarithmic in n.

Method · exam-ready proof

  1. Let N(h) be the minimum number of nodes in an AVL tree of height h. Leaf height is 0, so N(0) = 1 and N(1) = 2.
  2. Take a tree of height h with the fewest nodes. Its root has two subtrees. One has height h−1 (to make the tree height h). The other must have height at least h−2 (AVL rule). To use as few nodes as possible, both subtrees are themselves minimal, so \[ N(h) = N(h-1) + N(h-2) + 1. \]
  3. Since N(h−1) > N(h−2), we get \( N(h) > 2N(h-2) \). Repeating: \( N(h) \ge 2^{\lfloor h/2 \rfloor} \), so \( N(h) \ge 2^{(h-1)/2} \).
  4. A tree with n nodes and height h has \( n \ge N(h) \ge 2^{(h-1)/2} \). Take logs: \( h \le 2\lg n + 1 \).
  5. Therefore \( h = O(\log n) \). Also h ≥ lg n for any binary tree, so h = Θ(log n).

Sharper bound (optional, impresses): the recurrence says \( N(h)+1 = (N(h-1)+1) + (N(h-2)+1) \), the Fibonacci rule, so \( N(h) + 1 = F_{h+3} \) (with F₁ = F₂ = 1). Since \( F_k \approx \varphi^k/\sqrt5 \), \( h \lesssim 1.44\lg n \). Table: h = 0, 1, 2, 3, 4, 5 gives N = 1, 2, 4, 7, 12, 20.

2018–19 Q3(a)(iii): maximum height with 10 nodes. We need the largest h with N(h) ≤ 10. N(3) = 7 ≤ 10 but N(4) = 12 > 10, so the maximum height is 3.

2017–18 Q5(d): i-th and (i+2)-th Fibonacci numbers are x and y, what is the minimum number of nodes with height i−1? From N(h) + 1 = F_{h+3}: N(i−1) = F_{i+2} − 1 = y − 1 (with F₁ = F₂ = 1, leaf height 0). The source does not give a key, so state your Fibonacci indexing and your leaf-height convention in the answer.

Where marks go

  • Writing the recurrence without saying why the other subtree has height h−2 (the AVL rule allows h−1 or h−2, the minimum uses h−2).
  • Jumping from N(h) to "so h is log n" without the inequality \( n \ge N(h) \) and the step that turns it into a bound on h.
  • Using "=" where it should be "≥" in step 3.

9. Smallest AVL tree of height 5 (2024–25 Q6(b), 10 marks; 2019–20 Q4(b))

Build it from the recurrence: T(h) = a root with T(h−1) on one side and T(h−2) on the other. T(0) is a single node. T(1) is a root with one child. Count: 1, 2, 4, 7, 12, 20.

Method · construct on paper

  1. Draw T(3) (7 nodes) and T(4) (12 nodes) first. They are the parts.
  2. T(4) = root with T(3) on the left and T(2) on the right: 12 = 7 + 4 + 1. Check the count.
  3. T(5) = root with T(4) left and T(3) right: 20 = 12 + 7 + 1.
  4. Number the nodes 1 to 20 by in-order position (left to right) so it is a valid BST. Write bf beside each node (the figure below shows them).

This tree also settles 2019–20 Q4(b).

(i) "The difference between the shortest and the longest root-to-leaf paths is at most one": FALSE. In the tree above the path 13 → 8 → 11 → 12 has 3 edges and the path 13 → 8 → 5 → 3 → 2 → 1 has 5 edges. AVL balances the heights of siblings at every node, not the lengths of all paths. (ii) "The minimum number of nodes with height 5 is 20": TRUE, by N(5) = N(4) + N(3) + 1 = 12 + 7 + 1 = 20 (leaf height 0). If a paper used leaf = 1, the same tree has height 6 and the answer shifts, so state your convention.

On paper: draw the full 20-node tree, number it, and write the count next to each subtree (7, 12, 20). That is the proof that 20 is the minimum: shrinking any subtree breaks the AVL rule at its parent.
