Red-Black Trees from Zero

Start here if you have never studied red-black trees. Asked: 2021–22 Q2(c), 15 marks (properties and the height bound h ≤ 2 lg(n+1)); 2018–19 Q4(a), 15 (why red, insert then delete, longest to shortest ratio); 2022–23 Q4(c), 15 (pseudocode and RB versus AVL); 2020–21 Q7(d), 5 (Mr X black insertion); 2017–18 Q5(c), 4 (one advantage each, AVL versus RB).

1. What a red-black tree is for

A red-black tree is a binary search tree where every node also has a colour, red or black. The colours are not decoration. They are a cheap bookkeeping trick: if the colours follow five rules, the tree can never become a long stick. The tree stays balanced without storing any heights.

You will do three things with it: check that a tree is valid, insert (chapter 3), and delete (chapter 4). All of them are "keep the five rules true".

2. The five properties

  1. Every node is red or black.
  2. The root is black.
  3. Every leaf (NIL) is black.
  4. A red node has two black children. Equivalent: there are never two red nodes in a row on a path.
  5. Black height rule. For each node, every path from that node down to a leaf has the same number of black nodes.

Only rules 4 and 5 do real work. Rule 4 limits red, rule 5 forces equal black counts. Together they stop any path from being much longer than another.

NIL: the invisible leaves

Every missing child is a NIL leaf, and a NIL is black. In textbook figures the NILs are drawn as small black squares. In the exam you may draw them or leave them out, but you must count them as black when you check rule 5 and when you ask "is the uncle red or black?". A node with only one real child has one NIL child. In the trace tool, a NIL carrying an extra black is drawn as a box with a double ring.

From the lecture (notes p.46, slides 22–23): all NIL leaves are drawn as one shared node T.nil, "like the common ground in an electrical circuit". It is black, and the root is connected to it too. The notes also list where black is forced: the root, every leaf (NIL), and the children of a red node. A red node can be anywhere else, but never two in a row.

Black height

The black height bh(x) of a node x is the number of black nodes on a path from x down to a leaf, not counting x itself (CLRS and the notes), counting the final NIL. Rule 5 says this number is the same for every downward path, so bh(x) is well defined.

Fast rule: bh(x) = bh(child) if the child is red, and bh(child) + 1 if the child is black. A NIL has bh = 0.

3. Valid and invalid trees

Learn to check a tree in this order: root colour, then red-red pairs, then count black nodes on every path to a NIL (include the NIL, include the root, be consistent).

Valid. Every path to NIL: 20, X, NIL = 3 blacks
Valid. Two reds under black root
Valid. Root-to-NIL has 3 blacks everywhere

Check the first one: path 20 → 10 → 5 → NIL has blacks 20, 5, NIL = 3. Path 20 → 10 → 15 → NIL: 20, 15, NIL = 3. Path 20 → 30 → NIL: 20, 30, NIL = 3. Red 10 contributes nothing. All equal, so valid.

Invalid: root is red (rule 2)
Invalid: 5 is red under red 10 (rule 4)
Invalid: all black, black counts differ (rule 5)
  • Red root. 10 is red. Fix: colour it black. That never breaks anything else, it adds one black to every path.
  • Red under red. Node 10 and its child 5 are both red. Paths are fine on black count (every path to NIL has 20 plus NIL, 2 blacks), but rule 4 is broken.
  • Black counts differ. No red at all, root black, but path 20 → 10 → NIL has 3 blacks and path 20 → 30 → 25 → NIL has 4. Rule 5 fails. A tree with only black nodes is valid only if it is perfectly balanced (all NIL at the same depth).

Where marks go

  • Forgetting that NIL is black and counts toward the black height. Be consistent: count NIL on every path, or on none.
  • Checking rule 5 on one path only. It must hold for every node, not just the root.
  • Saying "red-black means half red". No. A tree of only black nodes is possible if it is perfectly balanced.

4. Path lengths: longest at most twice the shortest

Asked as 2018–19 Q4(a)(iii): "What is the ratio between the lengths of the longest and shortest path in a red-black tree?" Answer: at most 2 (so the longest path is never more than twice the shortest, from the root to a leaf).

Method · why at most 2

  1. Every path from the root to a leaf has the same number of black nodes, say b (rule 5).
  2. The shortest path can be all black: it has at least b nodes.
  3. The longest path can alternate black, red, black, red. Reds cannot be adjacent (rule 4) and the path ends at a black NIL, so each red is followed by a black and different reds by different blacks: at most one red per black, so it has at most 2b nodes.
  4. So longest / shortest ≤ 2b / b = 2.

The same argument works from any node, not just the root: from any node x, no downward path to a leaf is more than twice as long as another one.

5. Height proof: h ≤ 2 lg(n+1)

Asked in full in 2021–22 Q2(c) (properties, then derive the bound), 15 marks. Here n is the number of internal nodes (real keys), NIL leaves are not counted. h is the height of the tree.

Method · exam-ready proof in two steps

  1. Claim. The subtree rooted at any node x has at least \( 2^{bh(x)} - 1 \) internal nodes.
  2. Proof by induction on the height of x. Base: x is a NIL. bh(x) = 0 and the subtree has 0 internal nodes, and \( 2^0 - 1 = 0 \). True.
  3. Step. x is an internal node with two children. Each child has black height bh(x) (if the child is red) or bh(x) − 1 (if the child is black). In both cases at least bh(x) − 1. By the hypothesis, each child's subtree has at least \( 2^{bh(x)-1} - 1 \) internal nodes.
  4. So the subtree of x has at least \[ 2\left(2^{bh(x)-1} - 1\right) + 1 = 2^{bh(x)} - 1 \] internal nodes (the +1 is x itself). The claim holds.
  5. From the claim to the height. Let h be the tree height and take a longest root-to-leaf path: it has h nodes below the root, ending at a black NIL. By rule 4 each red node on it is followed by a black node (its child), so pair each red with the black just below it: different reds get different blacks, hence at least half of these h nodes are black. By rule 5 every root-to-leaf path has bh(root) blacks below the root, so \( bh(root) \ge h/2 \).
  6. Apply the claim to the root: \[ n \ge 2^{bh(root)} - 1 \ge 2^{h/2} - 1. \]
  7. Rearrange: \( n + 1 \ge 2^{h/2} \). Take log base 2: \( \lg(n+1) \ge h/2 \). Hence \[ h \le 2\lg(n+1). \]

So search, insert and delete, which cost O(h), are all O(log n).

On paper: list the five properties numbered, say what NIL is, define bh(x) in one line, then write the claim and the two induction parts with the formula in a box. Examiners tick: claim, base case, step with the 2·(…)+1 count, "at least half black" for bh ≥ h/2, final inequality.

Two-line answer for the 4-mark question. AVL advantage: stricter balance gives a shorter tree, so lookups are faster. Red-black advantage: updates are cheaper, fewer rotations (deletion needs at most 3 rotations, AVL deletion may need O(log n)).

7. "Why insert red, not black?" (2018–19 Q4(a)(i))

The full answer is in the insertion chapter. Short version: a new red leaf adds no black to any path, so rule 5 stays true. It can only break rule 4 (red under red) and that is a local problem near the new node. A new black leaf adds one black to every path through it, breaking rule 5 for the whole tree.

8. Mr X: "colour the new node black by default" (2020–21 Q7(d), 5 marks)

Discuss advantages and disadvantages against the normal red insertion.

Valid tree
After inserting 3 as BLACK

Path 10 → 5 → 3 → NIL has 4 blacks, path 10 → 15 → NIL has 3. Rule 5 is broken.

Method · what to write

  1. Advantage. A black node can never create a red-red conflict (rule 4), and the root rule (2) is also safe if it is the first node. The red-red fix-up cases 1, 2, 3 would not be needed. The code to detect the problem is trivial.
  2. Disadvantage 1. A black insert always breaks rule 5 (except into an empty tree): every path through the new node has one more black than the paths that avoid it. Red insert breaks something only when the parent is red.
  3. Disadvantage 2. The repair is global. A single extra black cannot be removed locally. You need the same machinery as deletion (push the extra black up, recolour, rotate), possibly up to the root, so more recolouring and more rotations on average. Red insertion needs at most 2 rotations.
  4. Conclusion. Worse on every insertion, so the standard algorithm colours new nodes red.

9. Insert then immediately delete the same node (2018–19 Q4(a)(ii))

"Would inserting a new node and then immediately deleting it change the tree?" Answer: it can. If the new red leaf had a black parent (no fix-up), the tree is always restored. If the fix-up ran, the tree usually changes, as the two examples below show. It is not always different: in 10B(5R,), inserting 7 needs cases 2 and 3 and gives 7B(5R,10R), and deleting 7 (successor 10) gives back 10B(5R,).
