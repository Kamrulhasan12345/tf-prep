RB Insertion: the 3 Cases

Asked in 2024–25 (compulsory, 25 marks with deletion), 2022–23 (15), and earlier as "insert 11 into this tree" (15). You get marks for showing every tree with every colour, so the skill here is doing it by hand without errors.

1. The idea in one paragraph

Insert the new key as in any BST and colour it red. A red node adds no black to any path, so black-height stays correct. The only rule it can break is "a red node has no red child". The fix looks at the new node's uncle, the other child of the grandparent.

Why red and not black? A black node adds 1 to the black-height of every path through it and breaks the black-height rule everywhere above. A red node can only cause one local red-red conflict, and that is cheap to repair. This exact question was asked in earlier papers.

2. Name the four nodes first

Every step, before anything else, name z (the red node with the problem), p (its parent, also red), g (grandparent, always black, because p is red and the tree was valid) and u (uncle). NIL counts as black.

Method · while z's parent is red

  1. Uncle red → Case 1. Colour p and u black, g red. Set z = g and repeat from there. No rotation.
  2. Uncle black, z is an inner child (g–p–z bends) → Case 2. Rotate at p, away from z's side, so the bend becomes a straight line. The old p is now the lower node: call it z. Go straight to case 3.
  3. Uncle black, z is an outer child (g–p–z straight) → Case 3. Colour p black, g red, rotate at g in the opposite direction. Finished: no further loop.
  4. When the loop ends, colour the root black.

From the lecture (deck 19 slides 30–31, notes p.47)

After inserting a red node: property 1 (colours) and property 3 (NIL black) and property 5 (black height) cannot break. Property 4 (no red-red) may break. Property 2 (root black) may break, and the last step repairs it. If the parent is black, nothing is needed. If the parent is red, the grandparent must be black, because the tree was valid before. The slides count "six possibilities: 3 + 3 symmetric cases", so learn the left versions and mirror them.

Slides 19 use the same numbering: case 1 "uncle red", case 2 "uncle not red and path to g not straight", case 3 "uncle not red and path straight".

RB-INSERT-FIXUP(T, z)
 while z.p.color == RED
   if z.p == z.p.p.left
     y = z.p.p.right              // uncle
     if y.color == RED            // case 1
       z.p.color = BLACK; y.color = BLACK
       z.p.p.color = RED; z = z.p.p
     else
       if z == z.p.right          // case 2
         z = z.p; LEFT-ROTATE(T, z)
       z.p.color = BLACK          // case 3
       z.p.p.color = RED
       RIGHT-ROTATE(T, z.p.p)
   else (same with left and right exchanged)
 T.root.color = BLACK

Why the fix-up is correct, terminates, and rotates at most twice

  1. Invariant at the top of each loop: only one rule can be broken: rule 4 between \(z\) and \(z.p\) (both red), or rule 2 if \(z\) is a red root. Rule 5 holds everywhere. True at the start: a red leaf adds no black to any path.
  2. g exists and is black: \(p\) is red and the root is black, so \(p\) is not the root; the tree was valid apart from \(z\), so the red \(p\) has a black parent \(g\).
  3. Case 1 keeps rule 5: \(g\) black, \(p,u\) red becomes \(g\) red, \(p,u\) black. Every path through \(g\) passes through exactly one of \(p,u\), so it loses one black (at \(g\)) and gains one (at \(p\) or \(u\)): counts unchanged. The only possible new violation is \(g\) red under a red parent, which is the invariant with \(z=g\).
  4. Case 3 keeps rule 5 and ends the loop: after recolouring and rotating at \(g\), the subtree root is \(p\) (black) with red children \(z\) and \(g\). Each of the subtrees under them (black-rooted, since \(u\) is black and the children of red \(p\), \(z\) were black) has the same black height as before, and every path from the top of the piece still meets exactly one black (now \(p\), before \(g\)) above them. No red-red pair is left, and the subtree root is black, so z.p.color == RED is false and the loop stops.
  5. Case 2 is one rotation between two red nodes (\(z\) and \(p\)), so no black count changes; it turns the bend into case 3, which then stops.
  6. Termination: case 1 moves \(z\) up two levels; cases 2 and 3 end the loop. The loop also ends when \(z\) is the root (its parent T.nil is black). So there are at most \(h/2=O(\log n)\) iterations, each \(O(1)\).
  7. Rotations: case 1 does none, and a rotation happens only in case 2 (one) followed by case 3 (one), after which the loop ends. So at most 2 rotations per insert. Finally the root is coloured black, fixing rule 2 without changing any relative black count. \(\blacksquare\)

5. Traps

Where marks go

  • Checking the uncle's colour when the uncle is NIL: NIL is black.
  • Case 2 alone does not finish. It always runs straight into case 3.
  • Case 1 moves z up by two levels, and you must re-check from the new z.
  • Forgetting to blacken the root after case 1 reaches it.
  • Rotating at the wrong node: case 2 rotates at p, case 3 rotates at g.
