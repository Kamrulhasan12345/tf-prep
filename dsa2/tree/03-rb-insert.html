RB Insertion: the 3 Cases

Asked in 2024–25 (compulsory, 25 marks with deletion), 2022–23 (15), and earlier as "insert 11 into this tree" (15). You get marks for showing every tree with every colour, so the skill here is doing it by hand without errors.

1. The idea in one paragraph

Insert the new key as in any BST and colour it red. A red node adds no black to any path, so black-height stays correct. The only rule it can break is "a red node has no red child". The fix looks at the new node's uncle, the other child of the grandparent.

Why red and not black? A black node adds 1 to the black-height of every path through it and breaks the black-height rule everywhere above. A red node can only cause one local red-red conflict, and that is cheap to repair. This exact question was asked in earlier papers.

2. Name the four nodes first

Every step, before anything else, name z (the red node with the problem), p (its parent, also red), g (grandparent, always black, because p is red and the tree was valid) and u (uncle). NIL counts as black.

Method · while z's parent is red

  1. Uncle red → Case 1. Colour p and u black, g red. Set z = g and repeat from there. No rotation.
  2. Uncle black, z is an inner child (g–p–z bends) → Case 2. Rotate at p, away from z's side, so the bend becomes a straight line. The old p is now the lower node: call it z. Go straight to case 3.
  3. Uncle black, z is an outer child (g–p–z straight) → Case 3. Colour p black, g red, rotate at g in the opposite direction. Finished: no further loop.
  4. When the loop ends, colour the root black.

Slides 19 use the same numbering: case 1 "uncle red", case 2 "uncle not red and path to g not straight", case 3 "uncle not red and path straight".

RB-INSERT-FIXUP(T, z)
 while z.p.color == RED
   if z.p == z.p.p.left
     y = z.p.p.right              // uncle
     if y.color == RED            // case 1
       z.p.color = BLACK; y.color = BLACK
       z.p.p.color = RED; z = z.p.p
     else
       if z == z.p.right          // case 2
         z = z.p; LEFT-ROTATE(T, z)
       z.p.color = BLACK          // case 3
       z.p.p.color = RED
       RIGHT-ROTATE(T, z.p.p)
   else (same with left and right exchanged)
 T.root.color = BLACK

3. Watch the 2024–25 question

Keys 41, 38, 31, 12, 19, 8, 25, 32. Press Next and say the case aloud before reading the caption. You can type your own keys too.

On paper: draw a fresh tree after every insert. Write red nodes as a circle with an R beside the key (or use a red pen and still write R). Next to each fix write the case number and the rotation, for example "Case 3: recolour 38, 41; right-rotate at 41". The last tree of each insert is the one the examiner marks.

4. Insert into a given tree

The older form of the question gives you a tree. Same steps. This is the 11-into-this-tree question: cases 1, 2 and 3 all appear, in that order.

5. Traps

Where marks go

  • Checking the uncle's colour when the uncle is NIL: NIL is black.
  • Case 2 alone does not finish. It always runs straight into case 3.
  • Case 1 moves z up by two levels, and you must re-check from the new z.
  • Forgetting to blacken the root after case 1 reaches it.
  • Rotating at the wrong node: case 2 rotates at p, case 3 rotates at g.

6. Mandatory practice

Do these with pen and paper. The next chapter opens once they are done.

If you got one wrong: open the steps and find the first frame where your tree differs. That frame names the case you misapplied.
