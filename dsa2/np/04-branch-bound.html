Branch and Bound, and TSP

Knapsack branch and bound is asked almost every year with a tree: 2024–25 Q3(b) (15), 2022–23 Q7(b) (15), 2019–20 Q3(c) (15), 2017–18 Q3(b) (10), and "explain branch and bound with an example" in 2023–24 Q6 (15). 1. The idea

Branch and bound is backtracking for optimization. We build a tree of partial solutions. At every node we compute a bound: a number that no solution below this node can beat.

  • Maximisation (knapsack): the bound is an upper bound on the best value reachable from the node.
  • Minimisation (TSP): the bound is a lower bound on the cost reachable from the node.

Keep the best complete solution found so far. Prune a node when its bound cannot beat the best (upper bound ≤ best for maximisation, lower bound ≥ best for minimisation). Explore the most promising node first (largest upper bound or smallest lower bound), so a good solution is found early and more nodes are pruned.

2. 0/1 knapsack with the fractional bound

Items have weight w and value v. Capacity W. Take each item whole or not at all, maximise the total value.

Fractional knapsack lets you take part of an item, and a greedy algorithm solves it (sort by v/w, take whole items in that order, then a fraction of the next). It always gives at least as much as 0/1 knapsack, because 0/1 is a special case. So the fractional value is a valid upper bound on any 0/1 completion of a node.

Method · knapsack branch and bound (Bayzid sir)

  1. Sort items by value/weight, largest first. Number them 1..n in this order. Level i of the tree decides item i.
  2. Root: weight W = 0, value V = 0. Its upper bound is the fractional knapsack value of the whole instance.
  3. Each node has two children: take item i (weight and value increase) and skip item i. If taking breaks capacity, the child is infeasible: cross it out.
  4. Bound of a child = value so far + fractional knapsack value of the remaining items in the remaining capacity.
  5. Always expand the open node with the largest upper bound. Each time a feasible child has a value above the best, record it as the new best.
  6. Prune every node whose upper bound is ≤ the best value. Stop when no open node can beat the best.
BNB-KNAPSACK(items sorted by v/w, W)
  best = 0;  open = { root(i=0, w=0, v=0) }
  while open not empty
    n = node in open with largest upper bound
    if n.ub <= best: prune n; continue
    for choice in { take item n.i+1, skip item n.i+1 }
       c = child(n, choice)
       if c.w > W: mark infeasible; continue
       c.ub = c.v + FRACTIONAL(items n.i+2..m, W - c.w)
       if c.v > best: best = c.v
       if c.ub > best and c is not a leaf: add c to open
  return best

What goes in each node of your drawing: the weight so far, the value so far, and the upper bound. Write the item and "take" or "skip" on the edge. Mark pruned nodes with a cross and the reason ("ub 135 ≤ best 135"). Mark the best leaf. This is what the examiner marks.

3. 2024–25 Q3(b): capacity 10, items (weight, value) = (4, 40), (3, 50), (5, 70), (3, 45)

Sort by value/weight: item 2 (16.67), item 4 (15), item 3 (14), item 1 (10). The root bound is 50 + 45 + (4/5) of item 3 = 151. Step through. The best value found is 135 with items 1, 2, 4 (weight 4 + 3 + 3 = 10), the same 135 written in the margin of the paper.

On paper: a tree four levels deep in the sorted order (2, 4, 3, 1). In the tree above, after item 2 and item 4 are taken (W = 6, V = 95), taking item 3 makes W = 11, which is infeasible. Then "skip item 3" has bound 135 and taking item 1 gives W = 10, V = 135, the new best. After that every open node has bound ≤ 135 and is pruned. Write the answer: "maximum value 135, items 1, 2 and 4".

4. 2022–23 Q7(b): capacity 60, (value, weight) = (120,15), (110,10), (95,25), (135,35), (80,20), (150,30)

Ratios: item 2 (11), item 1 (8), item 6 (5), item 5 (4), item 4 (3.86), item 3 (3.8). Root bound 400 = 110 + 120 + 150 + (5/20) of item 5 (80). Best is 380 with items 1, 2, 6 (weight 55).

Note that the "skip" chain after the best is found still has bounds 399.286 and 399, which are above 380, so you must walk it down to a leaf with bound 380. Only then is the node pruned or closed. Do not stop early because 380 "looks optimal".

6. 2023–24 Q6: "explain branch and bound with an illustrative example"

An easy illustration that fits in half a page: capacity 10, items A (weight 5, value 25), B (weight 4, value 40), C (weight 3, value 60). Ratios: C 20, B 10, A 5. Root bound: C and B fit whole (weight 7, value 100), and 3 units of room remain, which is 3/5 of A: 60 + 40 + 15 = 115.

The one student solution for this question writes the bound for "pick A" as 95. It should be 105 (25 for A, 60 for C, and 2 units of B at 10 each = 20). The final answer 100 (items B and C) is still right. In your explanation say: bound, prune, best-first, and give this tree.

Where marks go

  • Computing the bound from the unsorted items. The fractional bound only makes sense in ratio order.
  • Forgetting the remaining capacity: the bound of a child counts only the remaining items in the leftover capacity.
  • Pruning when the bound is greater than the best. Prune when the bound is ≤ the best.
  • Calling a node infeasible when the weight is exactly W. W = capacity is feasible.
  • Not writing the final answer (value and chosen items).

7. TSP by dynamic programming: Held-Karp (2022–23 Q7(a))

TSP: given cities and a cost matrix \(c[i][j]\) (may be asymmetric), find the cheapest tour that visits every city once and returns to the start. Trying every order costs \((n-1)!\). Held-Karp does it in \(O(n^2 2^n)\).

g(i, S)
the cheapest cost to start at city i, visit every city in S exactly once, and finish at city 1 (the start). S never contains 1 or i.
g(i, ∅) = c[i][1] · g(i, S) = min over j ∈ S of ( c[i][j] + g(j, S − {j}) )

The answer is \(g(1, \{2,\dots,n\})\). To recover the tour, remember which j gave each minimum and follow them from the full set.

Method · Held-Karp by hand

  1. Fill g(i, ∅) for every i ≠ 1: the cost of going straight back to 1.
  2. Fill all sets S of size 1, then size 2, ..., up to size n − 2. For every i not in S (and i ≠ 1) write g(i, S) as a min over j ∈ S, showing every candidate sum.
  3. Finally compute g(1, all others) the same way. That is the optimal cost.
  4. Trace the argmins to read off the tour.
HELD-KARP(c, n)
  for i = 2..n:  g[i][{}] = c[i][1]
  for size = 1..n-2:
    for each subset S of {2..n} with |S| = size:
      for each i in {2..n} not in S:
        g[i][S] = min over j in S of  c[i][j] + g[j][S - {j}]
  return min over j in {2..n} of  c[1][j] + g[j][{2..n} - {j}]

Time. There are \(n \cdot 2^{n-1}\) states (g(i, S)), and each takes a min over at most n choices, so \(O(n^2 2^n)\). Memory \(O(n 2^n)\). It is still exponential, but much better than \(n!\).

2022–23 Q7(a) matrix (rows = from, columns = to): row 1: 0 10 15 20; row 2: 5 0 12 18; row 3: 8 9 0 17; row 4: 11 14 16 0. The table is below; the answer is 50, tour 1 → 2 → 3 → 4 → 1. The tour 1 → 4 → 3 → 2 → 1 also costs 50, so a tie.

On paper: three columns (state, candidates, value) or, more neatly, one table per subset size. Show the candidate sums inside every min, e.g. g(4,{2,3}) = min(14 + 20, 16 + 14) = 30. Circle the minimum in each. End with the tour and its cost.

8. TSP by branch and bound (2021–22 Q7(b), 20 marks)

The bound is a lower bound on the cost of any tour that extends a partial tour. The classical choice is the reduced cost matrix.

Method · reduced cost matrix

  1. Write the cost matrix with the diagonal as ∞.
  2. Row reduction: subtract each row's minimum from that row. Add all these minima. Column reduction: then subtract each column's minimum from that column, and add them. The total is the lower bound of the root (every tour leaves each city once and enters each city once, so it pays at least these amounts).
  3. To extend a partial tour by the edge i → j: bound of child = bound of parent + (reduced cost of i → j) + the new reduction cost after you set row i and column j to ∞ and set the entry j → 1 (the edge that would close the tour early) to ∞ and reduce again.
  4. Expand the node with the smallest lower bound first. The first complete tour you finish gives the first upper bound (best). Prune every node whose lower bound is ≥ best.
  5. Stop when all open nodes are pruned. The best tour is optimal.

9. 2020–21 Q5(d): is the MST bound correct?

"In one approach, the lower bound for completing a partial tour is the cost of the minimum spanning tree of the remaining nodes. Will this bound give a correct answer all the time? Is there a better bound?"

Answer

  1. Let the partial tour end at u, start at s, with remaining cities R. A completion is a path u → r₁ → ... → rk → s through every city of R.
  2. Delete the first and last edge of that path. What is left is a path through all of R, which is a spanning tree of R, so its cost is at least MST(R). So completion cost ≥ MST(R).
  3. So the bound never overestimates (for symmetric costs, or after taking the cheaper direction of each pair). Pruning with it never throws away an optimal tour: it is correct, but weak.
  4. Better: add the cheapest edge from u into R and the cheapest edge from R back to s: MST(R) + min c(u, R) + min c(R, s), which is still a valid lower bound. The reduced-cost-matrix bound of section 8 is the other standard improvement.
