Randomized Quicksort, Monte Carlo, Karger

Asked: 2024–25 Q2(b) analyse the running time of randomized quicksort (12); 2018–19 Q8(b) the same (10); 2024–25 Q3(a) a Monte Carlo algorithm succeeds with probability at least 1/n², boost it to 1 − 1/n (10). Karger's min-cut is in Bayzid sir's notes (lectures 15–16) and Q3(a) is exactly its amplification step. No paper in these sources asks Karger's proof directly, but it is the one place where the n² comes from, so know it.

1. Las Vegas versus Monte Carlo

A randomized algorithm makes random choices, so the same input can give different runs. Two kinds, defined by what is allowed to go wrong:

Las VegasMonte Carlo
Answeralways correctmay be wrong, with a bounded probability
Running timerandom (we bound the expectation)fixed or bounded
"Gambles on"running timeaccuracy
Examplerandomized quicksortKarger's min-cut

A Monte Carlo algorithm can be repeated to make its error as small as you like. That is section 6.

2. Randomized quicksort

Ordinary quicksort takes the last element as the pivot. On an already sorted array the pivot is always the largest, one side is empty, and \(T(n) = T(n-1) + O(n) = O(n^2)\). A sorted array is an adversarial input: someone can design inputs that are always bad. The best case is a perfect split, \(T(n) = 2T(n/2) + O(n) = O(n \log n)\). Even a lopsided but fixed ratio split such as \(T(n) = T(n/10) + T(9n/10) + O(n)\) is \(O(n \log n)\).

Randomized quicksort changes one line: instead of pivot = A[n−1], use pivot = A[random index]. Now no input is bad on purpose. Quicksort becomes Las Vegas: always sorted correctly, and the expected time is \(O(n \log n)\) for every input. The worst case is still \(O(n^2)\), but its probability is tiny.

RANDOMIZED-QUICKSORT(A, p, r)
  if p < r
    i = RANDOM(p, r);  swap A[i] with A[r]     // random pivot
    q = PARTITION(A, p, r)                      // O(r - p) comparisons with the pivot
    RANDOMIZED-QUICKSORT(A, p, q - 1)
    RANDOMIZED-QUICKSORT(A, q + 1, r)

3. Proof: expected running time is O(n log n) (2024–25 Q2(b); 2018–19 Q8(b))

Write this as numbered steps. Every step below is worth marks.

Proof · expected number of comparisons

  1. Cost is comparisons. Partition compares each element with the pivot, so the work in a call is proportional to the comparisons it makes. Every call removes its pivot from further calls, so there are at most n calls and the other work is O(n). Total time = O(n + X), where X is the total number of comparisons.
  2. Name the elements by rank. Let \(z_1 < z_2 < \dots < z_n\) be the array in sorted order. (Initial positions do not matter.)
  3. Indicator variables. For \(i < j\) let \(X_{ij} = 1\) if \(z_i\) and \(z_j\) are ever compared, and 0 otherwise. Then \(X = \sum_{i=1}^{n-1} \sum_{j=i+1}^{n} X_{ij}\).
  4. Linearity of expectation. \(E[X] = \sum_{i \lt j} E[X_{ij}] = \sum_{i \lt j} \Pr[z_i \text{ and } z_j \text{ are compared}]\), because \(E[X_{ij}] = 1 \cdot \Pr[X_{ij}=1] + 0 \cdot \Pr[X_{ij}=0] = \Pr[X_{ij}=1]\).
  5. Two facts. Elements are compared only with a pivot. Two elements in different partitions are never compared. After \(z_i, z_j\) are compared once, one of them was the pivot and is now gone, so they are never compared twice.
  6. The key probability. Look at the set \(Z_{ij} = \{z_i, z_{i+1}, \dots, z_j\}\), which has \(j - i + 1\) elements. As long as no element of \(Z_{ij}\) has been a pivot, all of them stay together in the same sub-array (a pivot outside the range sends them all the same way). So the first pivot chosen from \(Z_{ij}\) decides:
    • it is \(z_i\) or \(z_j\): then \(z_i\) and \(z_j\) are compared.
    • it is strictly between them: they go to different sides and are never compared.
    The pivot is uniformly random, so each of the \(j-i+1\) elements of \(Z_{ij}\) is equally likely to be the first one picked. Hence \(\Pr[z_i, z_j \text{ compared}] = \dfrac{2}{j-i+1}\).
  7. Sum. Put \(k = j - i + 1\), which runs from 2 to \(n-i+1\): \[ E[X] = \sum_{i=1}^{n-1} \sum_{j=i+1}^{n} \frac{2}{j-i+1} = \sum_{i=1}^{n-1} \sum_{k=2}^{n-i+1} \frac{2}{k} \le \sum_{i=1}^{n-1} 2\ln n < 2n \ln n . \] The inner sum is a harmonic sum: \(\sum_{k=2}^{m} 1/k \le \int_1^m dx/x = \ln m\).
  8. Conclusion. \(E[X] = O(n \log n)\), so the expected running time is \(O(n + n\log n) = O(n \log n)\) for every input. (\(2n\ln n \approx 1.39\, n \log_2 n\).) ∎

Where marks go

  • Writing "the average case is n log n" without the indicator-variable argument. The question says "analyse", so give the proof.
  • The probability 2/(j − i + 1) is the heart. Explain why it is the first pivot in the range \(Z_{ij}\) that matters.
  • Say that the expectation is over the algorithm's random choices, not over random inputs. That is why the bound holds for every input.
  • Do not forget to mention the worst case is still \(O(n^2)\).
On paper: one small picture helps the key step: draw the sorted line \(z_1 \dots z_n\), bracket \(Z_{ij}\), and mark "pivot hits an end: compared" versus "pivot hits the middle: split apart".

4. Karger's contraction algorithm (Monte Carlo)

A cut is a set of edges whose removal splits the graph into two parts. The minimum cut is the smallest such set. The algorithm:

Method · Karger's min-cut

  1. Pick an edge uniformly at random.
  2. Contract it: merge its endpoints u, v into one supernode. Edges from u or v to other vertices now go to the supernode. Keep parallel edges. Delete self-loops (an edge between the two merged vertices).
  3. Repeat until two supernodes remain (that is n − 2 contractions).
  4. The edges between the two supernodes are the output cut.

Bayzid sir's example graph has vertices a, b, c, d, p, q, r and edges a–b, a–c, b–d, c–p, d–p, p–q, p–r, q–r. Contractions end with supernodes {a, b, d} and {c, p, q, r}, and the cut is the two edges {a–c, d–p}. In his example this is a minimum cut (size 2). The exact order of his drawn contractions is partly unreadable in the scan, so I do not repeat it.

The output is not always a minimum cut: if we contract an edge that belongs to every minimum cut we can never get one. That is the Monte Carlo risk. So we compute how likely success is.

5. Proof: Karger succeeds with probability at least 2/(n(n−1)) ≥ 2/n²

Proof

  1. Fix a minimum cut C with k edges. The algorithm outputs C exactly when it never contracts an edge of C. Contracting only edges outside C keeps both sides of C intact.
  2. Suppose there are m supernodes left and no edge of C has been contracted. The minimum cut is still k: any cut of a contracted graph is also a cut of the original graph.
  3. So every supernode has degree at least k (the edges at a supernode form a cut). Hence the number of edges is at least \(mk/2\).
  4. The probability that the next random edge lies in C is at most \(\dfrac{k}{mk/2} = \dfrac{2}{m}\). So with probability at least \(1 - \dfrac{2}{m}\) the step is safe.
  5. The contractions go from \(m = n\) down to \(m = 3\) (n − 2 contractions). Multiply the survival probabilities: \[ \Pr[\text{success}] \ge \prod_{m=3}^{n}\Bigl(1 - \frac{2}{m}\Bigr) = \frac{n-2}{n}\cdot\frac{n-3}{n-1}\cdot\frac{n-4}{n-2}\cdots\frac{2}{4}\cdot\frac{1}{3} = \frac{2}{n(n-1)} \ge \frac{2}{n^2}. \]
  6. The product telescopes: numerators \(1\cdot 2 \cdots (n-2)\), denominators \(3 \cdot 4 \cdots n\), leaving \(2/(n(n-1))\). ∎

So one run succeeds with probability at least \(2/n^2\), which is tiny but not zero. Repeating many times makes failure as small as we like. That is the next section.

6. Boosting the success probability (2024–25 Q3(a), 10 marks)

Question. A Monte Carlo algorithm succeeds with probability at least \(1/n^2\). The boss wants success probability at least \(1 - 1/n\). How?

Answer: run it independently about \(n^2 \ln n\) times and keep the best answer. Working:

Working · amplification

  1. Run the algorithm t times with fresh, independent random bits each time.
  2. One run fails with probability at most \(1 - \dfrac{1}{n^2}\).
  3. All t runs fail with probability at most \(\Bigl(1 - \dfrac{1}{n^2}\Bigr)^t\), because the runs are independent.
  4. Use \(1 - x \le e^{-x}\) for all x: \(\Bigl(1 - \dfrac{1}{n^2}\Bigr)^t \le e^{-t/n^2}\).
  5. We want the failure probability to be at most \(1/n\): \(e^{-t/n^2} \le \dfrac{1}{n}\). Take natural logs: \(-\dfrac{t}{n^2} \le -\ln n\), i.e. \(t \ge n^2 \ln n\).
  6. Choose \(t = \lceil n^2 \ln n \rceil\). Then the failure probability is at most \(1/n\), so the success probability is at least \(1 - \dfrac{1}{n}\).
  7. Running time: t times the time of one run, so \(O(n^2 \log n)\) runs.

The handwritten note in the paper margin reads "n² log n", which matches. General formula (Bayzid sir, p.53): with one-run success probability P and target failure probability δ, \(t \ge \dfrac{1}{P}\ln\dfrac{1}{\delta}\). Here \(P = 1/n^2\) and \(\delta = 1/n\).

Where marks go

  • Independence. Say it. Fresh random bits for each run, otherwise the product formula is wrong.
  • How do you pick the answer? The question does not say, so state your assumption: the correct answer can be recognised, or the outputs can be compared. For Karger, keep the smallest cut over the runs; the run is wrong only if it finds a larger cut. For a decision problem with one-sided error, accept if any run says YES. Majority voting does not work here, because the success probability is far below 1/2.
  • Do not stop at "repeat many times". Derive t, with \(1-x \le e^{-x}\).
  • \(t = n^2 \ln n\) uses the natural log. Using \(\log_2\) changes only a constant, but write \(\ln\) when you use \(e^{-x}\).
