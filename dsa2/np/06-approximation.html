1. What an approximation algorithm promises

A heuristic returns a good-enough answer with no promise. An approximation algorithm is a polynomial-time heuristic with a proven bound on how far from optimal it can be. Example promise: "the output is at most 1.5 times the optimum."

Problem typeGuaranteeRatio
MinimisationALG ≤ ρ · OPTρ = ALG / OPT ≥ 1
MaximisationALG ≥ OPT / ρ (equivalently ρ = OPT / ALG ≥ 1)Bayzid sir writes the max version as ALG ≥ α · OPT with α ≤ 1

The closer the ratio is to 1, the better. Ratio 1 means optimal. State which convention you use and keep to it. A 2-approximation for a minimisation problem never returns more than twice the optimum.

The pattern behind every proof here. You cannot compare to OPT directly because OPT is NP-hard to compute. So (1) find something easy to compute that is a lower bound on OPT (for minimisation), (2) show your algorithm's cost is at most a constant times that lower bound. Chain: ALG ≤ c · lower bound ≤ c · OPT.

2. Vertex cover: 2-approximation by maximal matching (2024–25 Q2(a), 2022–23 Q6(b), 2018–19 Q8(a))

Pick any uncovered edge, take both endpoints, and remove every edge those endpoints touch. Repeat.

APPROX-VERTEX-COVER(G = (V, E))
  C = {}
  E' = E
  while E' is not empty
     pick any edge (u, v) in E'
     C = C ∪ {u, v}                      // both endpoints
     remove from E' every edge incident to u or to v
  return C

Runs in \(O(V + E)\) with adjacency lists.

Proof · cover, matching, ratio 2

  1. C is a vertex cover. The loop ends only when E′ is empty. Every edge left E′ either because it was picked (both its endpoints entered C) or because it touched a vertex that entered C. So every edge has an endpoint in C.
  2. The picked edges form a matching M (no two share an endpoint). After picking (u, v) every edge touching u or v is deleted, so no later edge can touch them.
  3. |C| = 2|M|, since each picked edge adds two new vertices (their endpoints are not in C yet, otherwise the edge would have been deleted).
  4. OPT ≥ |M|. Any vertex cover must contain at least one endpoint of every edge of M. The edges of M share no endpoints, so these endpoints are all different vertices. So any cover, in particular an optimal cover \(C^*\), has at least |M| vertices.
  5. Therefore \(|C| = 2|M| \le 2\,|C^*|\). The algorithm is a 2-approximation. ∎

The lower bound \(|M| \le OPT\) is the whole trick, and it is the sentence graders look for.

Checked example

Path-like graph with edges a–b, b–c, c–d, d–e, e–f, b–e (processed in this order). The algorithm picks a–b, then c–d, then e–f, so C = {a, b, c, d, e, f}, size 6. A brute-force search gives the optimal cover {a, c, e}, size 3. The ratio is exactly 2, so the bound is tight on this graph. (Another tight family: the complete bipartite graph \(K_{n,n}\), where the matching has n edges, ALG = 2n, OPT = n.)

On paper: the small graph, the picked edges (matching) in a heavy line, the vertices of C circled, and the optimal cover marked with a different symbol. Next to it write "|C| = 2|M| and OPT ≥ |M|".

Where marks go

  • Picking only one endpoint is not the algorithm and does not give ratio 2. Take both.
  • The proof needs OPT ≥ |M| because M is a matching. Without the "disjoint edges" argument you lose most of the marks.
  • Forgetting to prove that C is a vertex cover at all.

3. Set cover: greedy, ratio \(H_n \le \ln n + 1\) (2017–18 Q4(c))

Universe U of n elements, subsets \(S_1..S_m\). Choose the fewest subsets covering U. Greedy: repeatedly pick the subset that covers the most still-uncovered elements, until all are covered.

GREEDY-SET-COVER(U, S)
  C = {};  R = U                          // R = uncovered elements
  while R is not empty
     pick S_i in S maximising |S_i ∩ R|
     C = C ∪ {S_i};  R = R − S_i
  return C

Proof · charging argument

  1. When greedy picks a set that covers r new elements, give each of those elements a price 1/r. Then the number of sets chosen equals the sum of the prices of all n elements.
  2. Number the elements \(e_1, e_2, \dots, e_n\) in the order greedy covers them.
  3. Just before \(e_k\) is covered, at least \(n - k + 1\) elements are uncovered (\(e_k, \dots, e_n\)).
  4. An optimal cover with OPT sets covers all of them, so some set in it covers at least \((n-k+1)/\text{OPT}\) of them (pigeonhole).
  5. Greedy chose the set with the most new elements, so it covers at least that many: \(r \ge (n-k+1)/\text{OPT}\). Hence \(\text{price}(e_k) \le \dfrac{\text{OPT}}{n-k+1}\).
  6. Sum: \(|C| = \sum_{k=1}^n \text{price}(e_k) \le \text{OPT} \sum_{k=1}^{n} \dfrac{1}{n-k+1} = \text{OPT}\cdot H_n \le \text{OPT}(\ln n + 1)\), using \(H_n = 1 + \sum_{k=2}^{n} \frac1k \le 1 + \int_1^n \frac{dx}{x}\).
  7. Polynomial time. Each iteration covers at least one new element, so there are at most n iterations, each scanning the m sets in \(O(mn)\): \(O(mn^2)\) in total. ∎

So greedy is an \(H_n\)-approximation. The ratio grows with n, unlike vertex cover's constant 2.

4. TSP

4.1 General TSP cannot be approximated (2017–18 Q3(d), the "discuss" part)

Claim. If P ≠ NP, then for no constant ρ ≥ 1 (and no polynomial-time computable ρ(n)) is there a polynomial-time ρ-approximation for general TSP.

Proof · from Hamiltonian cycle

  1. Suppose such an algorithm A exists. We use it to decide Hamiltonian cycle (an NP-complete problem).
  2. Given G = (V, E), build a complete graph G′ on V. Edge cost 1 if the edge is in E, and cost \(\rho |V| + 1\) otherwise. This takes \(O(|V|^2)\) time, and the costs have polynomially many bits.
  3. If G has a Hamiltonian cycle, it is a tour of G′ of cost |V|. Every tour has |V| edges of cost ≥ 1, so the optimum is exactly |V|, and A returns a tour of cost ≤ ρ·OPT = ρ|V|.
  4. If G has no Hamiltonian cycle, every tour in G′ uses at least one non-edge, so it costs at least \((|V|-1) + \rho|V| + 1 > \rho|V|\).
  5. So A's tour has cost ≤ ρ|V| exactly when G is Hamiltonian. Build G′, run A, and answer YES iff the returned cost is ≤ ρ|V|: that decides Hamiltonian cycle in polynomial time. Hamiltonian cycle is NP-complete, so P = NP (chapter 1, section 10), contradicting P ≠ NP. ∎

4.2 Metric (Euclidean) TSP: 2-approximation by MST (2019–20 Q8(a); 2017–18 Q3(d))

Condition: costs satisfy the triangle inequality (\(c(a,c) \le c(a,b) + c(b,c)\)); Euclidean distances do.

Method · MST double walk

  1. Build a minimum spanning tree T of the cities (Prim or Kruskal).
  2. Walk around T (a depth-first traversal that returns along each edge). That walk uses every tree edge twice.
  3. List the cities in preorder (the order of first visit) and return to the start. Skipping a city already visited is a shortcut. The result is the tour H.

Proof · cost at most 2 · OPT

  1. c(T) ≤ OPT. Delete any one edge from an optimal tour \(H^*\). Costs are non-negative, so what remains costs at most OPT, and it is a spanning path, which is a spanning tree. The MST is no more expensive, so \(c(T) \le c(H^*) = \text{OPT}\).
  2. The full walk uses each tree edge twice, so its cost is \(2c(T)\).
  3. Shortcuts do not increase cost. H visits the cities in the order of the walk, skipping repeats, so it lists every city exactly once: it is a tour. Each stretch of the walk \(a \to b_1 \to \dots \to b_j \to c\) that H skips is replaced by the edge \(a \to c\). Applying the triangle inequality j times, \(c(a,c) \le c(a,b_1) + c(b_1,b_2) + \dots + c(b_j,c)\). So \(c(H) \le c(\text{walk}) = 2c(T)\).
  4. Therefore \(c(H) \le 2c(T) \le 2\,\text{OPT}\). Every step (MST, DFS, shortcutting) is polynomial, so this is a 2-approximation. ∎
On paper: the MST in heavy lines, preorder numbers beside the cities, the final tour in a different style, and a line stating "c(T) ≤ OPT, walk = 2c(T), shortcuts ≤ walk". The figure for 2019–20 Q8(a) is not readable in the scan, so use these steps on whatever graph is given.

Note: the triangle inequality is essential. Without it, section 4.1 shows no constant ratio is possible.

5. 0/1 knapsack FPTAS (2021–22 Q8: parts a, b, c)

The exact DP \(OPT(i, w)\) (best value from items 1..i with weight limit w) takes \(O(nW)\) time. That is polynomial in the number W, not in the number of bits of W, so it is not polynomial time. The approximation scheme rounds the values and does the DP over values.

Method · the scheme in the question

  1. Let \(V_{\max}\) be the largest value. Set the scaling unit \(\theta = \dfrac{\epsilon V_{\max}}{2n}\).
  2. Scaled values \(\hat v_i = \lceil v_i / \theta \rceil\) (integers). Use \(\bar v_i = \hat v_i\,\theta\) for the rounded value.
  3. \(OPT(i, v)\) = the minimum weight of a subset of items 1..i whose scaled value is at least v. \(OPT(0, 0) = 0\), \(OPT(0, v > 0) = \infty\), and \(OPT(i, v) = \min\{OPT(i-1, v),\ w_i + OPT(i-1, \max(0, v - \hat v_i))\}\).
  4. Answer: the largest v with \(OPT(n, v) \le W\). The items behind it are the output set S.

(a) Why OPT(i, v) and not OPT(i, w)?

The table over weights has W columns. W can be exponentially large in its bit length, so the DP is only pseudo-polynomial. And you cannot round the weights: rounding could make a set look feasible when it is not (or the reverse), breaking the capacity constraint. Values can be rounded safely, since rounding only changes the objective by a bounded amount, and after rounding the total value is at most about \(n \cdot 2n/\epsilon\), a polynomial. So a table indexed by value has polynomial size.

(b) The luggage instance, ε = 0.1

Capacity 600. Values 1200, 1100, 950, 1350, 800, 1500; weights 150, 100, 250, 350, 200, 300. n = 6, \(V_{\max} = 1500\). Unit \(\theta = 0.1 \times 1500 / 12 = 12.5\). Scaled values (value / 12.5): 96, 88, 76, 108, 64, 120. All six are exact integers, so rounding changes nothing here. (A computer run of the DP, checked against trying all 64 subsets:) the largest scaled value reachable within weight 600 is 304, with minimum weight 550, using items 1, 2 and 6. True value 1200 + 1100 + 1500 = 3800, weight 150 + 100 + 300 = 550. The true optimum is also 3800, so the ratio is 1 on this instance. The DP table has \(6 \times 553\) entries (maximum total scaled value is 552).

(c) Proof: value within a (1 + ε) factor, time \(O(n^3/\epsilon)\)

Proof

  1. Let \(S^*\) be an optimal set (true values) and S the set returned. Assume every single item fits in the bag, so \(V_{\max} \le \text{OPT}\).
  2. Rounding up gives \(v_i \le \bar v_i \le v_i + \theta\) for every item.
  3. S has the largest scaled value among all sets of weight ≤ W, and \(S^*\) is such a set, so \(\sum_{S} \hat v_i \ge \sum_{S^*} \hat v_i\); multiplying by θ, \(\sum_{S} \bar v_i \ge \sum_{S^*} \bar v_i\).
  4. Chain (S has at most n items, each losing at most θ): \(\sum_{S} v_i \ \ge\ \sum_{S} \bar v_i - n\theta \ \ge\ \sum_{S^*} \bar v_i - n\theta \ \ge\ \sum_{S^*} v_i - n\theta = \text{OPT} - n\theta\).
  5. \(n\theta = \epsilon V_{\max}/2 \le \epsilon\,\text{OPT}/2\). So \(\sum_S v_i \ge (1 - \epsilon/2)\,\text{OPT}\).
  6. For \(0 < \epsilon \le 1\): \((1+\epsilon)(1 - \epsilon/2) = 1 + \tfrac{\epsilon}{2}(1 - \epsilon) \ge 1\). So \((1+\epsilon) \sum_S v_i \ge \text{OPT}\): the value is within a \(1+\epsilon\) factor of optimal.
  7. Time. Each \(\hat v_i \le \lceil V_{\max}/\theta \rceil = \lceil 2n/\epsilon \rceil\). The largest total scaled value is \(O(n \cdot n/\epsilon)\). The table has n rows and \(O(n^2/\epsilon)\) columns, and each entry costs O(1). Total \(O(n^3/\epsilon)\). ∎

Where marks go

  • Scaling by the wrong amount. It is \(\epsilon V_{\max}/(2n)\), as the question says.
  • In (c) say "S is optimal for the rounded problem" and that rounding loses at most θ per item, n items, so at most nθ.
  • The condition \(V_{\max} \le \text{OPT}\) (every item fits alone) is what turns nθ into \(\epsilon\,\text{OPT}/2\).

6. Sorting by reversals (2023–24 Q5) · low priority

A reversal (i, j) reverses the segment between positions i and j. The goal is the fewest reversals that turn a permutation into 1 2 ... n. Add \(\pi_0 = 0\) and \(\pi_{n+1} = n+1\) at the ends. A breakpoint lies between neighbours that are not consecutive numbers (they differ by anything other than 1, in either order). The question's example: [4 1 2 3] becomes [0 4 1 2 3 5], with 3 breakpoints (0|4, 4|1, 3|5).

(i) Lower bound

  1. A reversal cuts the sequence at only two places, so it can change at most 2 adjacencies and remove at most 2 breakpoints.
  2. The identity has 0 breakpoints. So a permutation with b breakpoints needs at least \(\lceil b/2 \rceil\) reversals: \(\text{OPT} \ge b/2\).
  3. On [4 1 2 3]: b = 3, so OPT ≥ 2, and the question shows 2 reversals suffice.

(ii) Approximation with ratio at most 4

  1. A strip is a maximal run with no breakpoint inside. Strips are increasing or decreasing.
  2. Known lemma (Kececioglu and Sankoff): if some decreasing strip exists, there is a reversal that removes at least one breakpoint. Idea: take the smallest element k in a decreasing strip. The element k − 1 lies in an increasing strip. Reverse the segment that places k − 1 next to k. This creates a new adjacency and cuts only at breakpoints.
  3. If there is no decreasing strip, reverse any increasing strip (not a single element, and not one made of 0 or n + 1). That makes a decreasing strip and does not add breakpoints.
  4. So every breakpoint removed costs at most 2 reversals: total ≤ 2b.
  5. With OPT ≥ b/2: \(2b \le 4\,\text{OPT}\). Ratio at most 4. ∎

Flag: the lemma in step 2 is only sketched here. One student solution for 2023–24 Q5 gives the example "5 1 2 3 4 8 6 7" with b = 3. With 0 and 9 added there are 5 breakpoints (0|5, 5|1, 4|8, 8|6, 7|9), so the lower bound is 3. Count breakpoints on the extended permutation, always.
