Fibonacci Heap

Asked in 2024–25 Q4(d) (delete the min, 12 marks), 2023–24 Q2 (extract-min, 15), 2022–23 Q5(c) (RAHSUT-DELETE, 12; chapter 5), 2019–20 Q2(c) and Q4(a) (damaged tree f6, 8; running times, 8), 2018–19 Q6(b)(c) (delete min, 15; running times, 5), 2017–18 Q6(b)(c) and Q7(a) (running times and the "all O(1)" claim, 6+6; extract-min algorithm, 8; damaged tree of order 5, 4+6). Extract-min with consolidation is the one to master.

1. The idea

A Fibonacci heap is a binomial heap with lazy union. Binomial heaps keep a strict shape, and that costs O(log n) on every insert and union. A Fibonacci heap keeps no shape. It does nothing until the next extract-min, and then does all the tidying at once.

  • A collection of min-heap-ordered trees, any shapes, any number of trees.
  • The roots are in a circular doubly linked root list. A pointer min points to the smallest root.
  • Each node stores its key, degree (number of children), parent, one child pointer, and a mark bit. A node is marked if it has lost one child since it last became a child of another node. Roots are never marked.

It was invented to speed up Dijkstra: V extract-mins at O(log V) and E decrease-keys at O(1) give \(O(E + V\log V)\) instead of \(O(E\log V)\) for a binary heap.

2. The cheap operations

Union H1, H2Splice the two circular root lists together. min = the smaller of the two mins.O(1)

Insert does not look at degrees at all: that is the "lazy" part, and it is what the binomial heap structure gives up.

3. Extract-min and consolidate

This is the main operation. The root list can be long, so after removing the min you consolidate: link roots of equal degree until all roots have distinct degrees. An array A indexed by degree remembers one root per degree.

Method · extract-min

  1. Remove the min root z. Its children go into the root list, in z's place (they become roots; this book clears their marks. CLRS's pseudocode leaves the bit alone, but a mark on a root has no effect, because cascading cut stops at roots. Write "roots unmarked" and the tree shape is the same either way).
  2. Make an empty array A[0 .. D(n)]. Go through the root list once, starting at the root just right of where z was and wrapping around to the end. (Children inserted for z come at the end of that walk.)
  3. For each root w, with degree d: while A[d] holds some root y, link the two: the one with the larger key goes under the smaller. The winner has degree d+1 now. Clear A[d] and set d = d+1. When A[d] is empty, store the winner in A[d].
  4. Rebuild the root list from the array and find the new min by scanning it.

Order convention. Bayzid sir's notes do not say where consolidation starts, but the slide's simulation starts to the right of the removed min, with the children in the min's place. The traces in this book do the same. The final set of trees can differ slightly if you start somewhere else, so write your convention down.

FIB-HEAP-EXTRACT-MIN(H)
  z = H.min
  if z != NIL
    for each child x of z: add x to the root list of H; x.p = NIL
    remove z from the root list of H
    if z == z.right: H.min = NIL
    else H.min = z.right; CONSOLIDATE(H)
    H.n = H.n - 1
  return z

CONSOLIDATE(H)
  let A[0 .. D(H.n)] be a new array, all NIL
  for each node w in the root list of H
    x = w; d = x.degree
    while A[d] != NIL
      y = A[d]
      if x.key > y.key: exchange x and y
      FIB-HEAP-LINK(H, y, x)      // remove y from root list, make y a child of x, x.degree++, y.mark = FALSE
      A[d] = NIL; d = d + 1
    A[d] = x
  H.min = NIL
  for i = 0 to D(H.n)
    if A[i] != NIL: add A[i] to the root list (rebuilt); update H.min if A[i].key < H.min.key

4. Decrease-key, cut, cascading cut

Decrease-key must be O(1). Bubbling up (as in a binary heap) is O(log n), so instead we cut the node out and make it a root.

Method · decrease-key(x, k)

  1. Set x.key = k. Let y = x.parent. If x is a root, or y.key ≤ k, heap order still holds: only update min if needed. Stop.
  2. Otherwise CUT(x, y): remove x from y's child list, y.degree decreases, x goes to the root list, x.mark = false.
  3. CASCADING-CUT(y): if y is a root, stop. If y is unmarked, mark it and stop (y has now lost its first child). If y is marked (it is now losing its second child), cut y from its parent too, then repeat the check at y's old parent.
  4. If k < H.min.key, update min to x.
FIB-HEAP-DECREASE-KEY(H, x, k)
  x.key = k; y = x.p
  if y != NIL and x.key < y.key
    CUT(H, x, y); CASCADING-CUT(H, y)
  if x.key < H.min.key: H.min = x

CUT(H, x, y)                  // remove x from child list of y, add x to root list
  y.degree--; x.p = NIL; x.mark = FALSE

CASCADING-CUT(H, y)
  z = y.p
  if z != NIL
    if y.mark == FALSE: y.mark = TRUE
    else CUT(H, y, z); CASCADING-CUT(H, z)

Why marks. If a node could lose many children, a tree with many nodes could shrink to a very thin tree with a large degree, and the root list could grow like n. The mark rule says: a node may lose at most one child; losing a second one means cut the node itself. The shape then stays "fat enough" (chapter 5 proves the Fibonacci-number bound).

An example of my own with a chain of marked nodes (nodes 18 and 21 are marked, shown by the star; the "*" is a mark). Decrease 30 to 2. Press Next: 2 is cut from 21, 21 is marked so it is cut from 18, 18 is marked so it is cut from 7, and 7 is a root so the cascade stops. Min becomes 2.

On paper: draw the heap before. Draw one picture per cut, marking which nodes are marked (an M or a filled node) and which are unmarked after the cut. Write "cascading cut" at each extra cut, and "stop: root" or "stop: now marked" at the end. Say the new min.

5. Delete

Delete x: decrease its key to \(-\infty\) (it is cut to the root list and becomes the min), then extract-min. Cost = decrease-key + extract-min = O(log n) amortized. The trace below deletes 21 from the same heap and shows both phases.

6. Running times and the "all O(1)" claim

OperationBinary heapBinomial heapFibonacci heap (amortized)
InsertO(log n)O(log n) worst, O(1) amortizedO(1)
Find-minO(1)O(log n) (O(1) with a min pointer)O(1)
UnionO(n)O(log n)O(1)
Extract-minO(log n)O(log n)O(log n)
Decrease-keyO(log n)O(log n)O(1)
DeleteO(log n)O(log n)O(log n)

Why extract-min is amortized O(log n) but worst case O(n) (slides 35 to 37, notes p.20). A run of inserts with no extract-min does no consolidation, so the root list grows to length n. One extract-min then consolidates it. The slides state that a sequence of c inserts and d extract-mins takes O(c + d log n), and, with decrease-keys, that a inserts, b extract-mins and c decrease-keys take O(a + c + b log n) (slide 51). Slide 19 adds the reason for the mark rule: without it, repeated cuts can build a node of degree O(n), and decrease-key and delete would rise from O(log n) to O(n).

The Fibonacci figures are amortized: an individual extract-min can take O(n) when the root list is long, but a sequence of m operations is cheap in total. Chapter 5 proves the table.

2017–18 Q6(b): "A friend says he has a mergeable heap with O(1) for insert, find-min, extract-min, union and decrease-key. Would you believe it?"

  1. No. Suppose insert and extract-min both took O(1) amortized. The heap is comparison-based: it learns about keys only by comparing them (true of binary, binomial and Fibonacci heaps).
  2. Then you could sort n numbers by n inserts followed by n extract-mins, which gives the numbers in sorted order. Starting from the empty heap (potential 0, and potential is never negative), the actual total is at most the amortized total, so the 2n operations take O(n) time and O(n) comparisons.
  3. But every comparison-based sorting algorithm needs \(\Omega(n\log n)\) comparisons in the worst case. Contradiction.
  4. So at least one of insert and extract-min is \(\Omega(\log n)\). The best known (the Fibonacci heap) makes insert, find-min, union and decrease-key O(1) amortized and pays O(log n) amortized for extract-min.

Where marks go

  • Linking the wrong way: the larger key goes under the smaller.
  • Stopping consolidation too early. Repeat until all root degrees are different. After linking, the new root has degree d+1 and may collide again with A[d+1].
  • Leaving the min's children out of the root list, or forgetting that they lose their marks.
  • Marking roots. Roots are never marked; cascading cut stops at a root.
  • Cascading cut: a marked parent gets cut; an unmarked parent gets marked and the cascade stops. Do not swap these.
  • Writing "amortized O(log n)" and "worst case O(n)" for extract-min as if they were the same claim. They are not; say both.
  • Not showing array A. The marker wants to see each consolidation step.
