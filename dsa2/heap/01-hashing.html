Hashing: Chaining and Open Addressing

Asked in 2024–25 Q6(a) (25 marks, four strategies on one table), 2023–24 Q1 (8+7, chaining proof and double hashing), 2022–23 Q6(a) (15+5, probe counts and "why search fails"), 2021–22 Q6(a)(b) (15+5+5 and 10), 2019–20 Q1 (10+10+15), 2018–19 Q5 (12+6+12) and 2017–18 Q7(c)(d). The table questions are pure drawing and counting, so they are safe marks if you do not slip.

1. The setup

A hash table has m slots numbered 0 to m−1. A hash function h maps a key to a slot. Two different keys with the same slot are a collision. The load factor is \(\alpha = n/m\), where n is the number of stored keys.

There are two ways to handle a collision.

  • Chaining: each slot holds a linked list of all keys that hash there. \(\alpha\) can be above 1.
  • Open addressing: every key lives in the array itself. On a collision you try another slot, following a probe sequence \(h(k,0), h(k,1), h(k,2), \dots\) until you find a free slot. Needs \(n \le m\), so \(\alpha \le 1\).

Simple uniform hashing is the assumption behind every expected-time proof: each key is equally likely to go to any of the m slots, independently of the others. Write it in the first line of every proof.

2. Chaining and its analysis

Insert: compute h(k), add to the chain. Search: compute h(k), walk that chain. Cost is 1 for hashing plus the chain length walked.

Proof · unsuccessful search takes expected \(O(1+\alpha)\) (2018–19 Q5(a), 2019–20, 2023–24)

  1. Assume simple uniform hashing. The key being searched for is not in the table and goes to a random slot.
  2. Chain j holds \(n_j\) keys with \(\sum_j n_j = n\), so the average chain length is \(n/m = \alpha\).
  3. The search computes h(k) (cost 1) and walks the whole chain (expected length \(\alpha\)).
  4. Expected time \(= 1 + \alpha = O(1+\alpha)\).

Proof · successful search takes expected \(O(1+\alpha)\) (Bayzid sir's version)

  1. Searching for a key y that is in the table costs the same as the unsuccessful search for y just before y was inserted. At that moment the chain at h(y) held only the keys inserted earlier.
  2. When the i-th key is inserted (\(i = 0, 1, \dots, n-1\)), i keys are already in the table, so the expected chain length is \(i/m\). The search for that key costs \(1 + i/m\).
  3. Average over all n keys (each is equally likely to be the one searched): \[ \frac1n \sum_{i=0}^{n-1}\Bigl(1+\frac im\Bigr) = 1 + \frac{1}{nm}\cdot\frac{n(n-1)}{2} = 1 + \frac{n-1}{2m} \approx 1 + \frac{\alpha}{2}. \]
  4. So successful search is \(O(1+\alpha/2) = O(1+\alpha)\). Asymptotically it equals unsuccessful search; in practice it is slightly faster.

Other forms of the same question. 2017–18 7(c) asks for the expected number of items that collide with x. Let \(X_y = 1\) if key y shares x's slot. \(\Pr[X_y=1] = 1/m\). By linearity of expectation \(E[\sum_{y\ne x} X_y] = (n-1)/m \approx \alpha\). 2021–22 6(b) asks for both searches: write the two proofs above.

2019–20 Q1(b), "1 + log α" expected unsuccessful search. The notes do not cover this; this is my reading. Keep each chain in a balanced BST (or a sorted array) instead of a list. The average chain holds \(\alpha\) keys, so an unsuccessful search is 1 for hashing plus \(O(\log\alpha)\) for the BST search. The arrival times are distinct integers, so a sorted structure is natural.

3. Open addressing: three probe sequences

Insert walks the probe sequence for i = 0, 1, 2, ... and stores the key in the first free slot. Search follows the same sequence and stops at the key (found) or at an empty slot (not found). The exam asks for unsuccessful probes: the probes that landed on an occupied slot. If a key is placed on probe number i (counting from 0), it had exactly i unsuccessful probes.

MethodProbe iDistinct sequencesWeakness
Linear\((h(k)+c\,i) \bmod m\)mPrimary clustering: runs of full slots grow, and a long run catches more keys, so it grows faster
Quadratic\((h(k)+c_1 i + c_2 i^2) \bmod m\)mSame start gives the same path; does not reach every slot
Double\((h_1(k) + i\,h_2(k)) \bmod m\)\(m^2\)\(h_2(k)\) must never be 0 and should share no factor with m

Linear probing is "not uniform at all": two keys that hit the same start slot follow the same path, and only m different paths exist. A perfect uniform scheme would have m! paths, which is practically impossible (strong uniform hashing). Double hashing has m starts times m jump sizes.

Quadratic probing may miss slots (2018–19 Q5(b), 2017–18 Q7(d)(i))

The statement "quadratic probing does not necessarily probe all locations" is true. Agree and prove it.

Proof · for \(h(k,i) = (h(k)+i^2) \bmod m\)

  1. Take i and m−i. \((m-i)^2 = m^2 - 2mi + i^2 \equiv i^2 \pmod m\).
  2. So probes i and m−i land on the same slot. Among i = 0..m−1 at most \(\lfloor m/2\rfloor + 1\) slots are distinct.
  3. For m > 2 that is fewer than m, so some slots are never probed.
  4. Example from the notes: m = 7, h(k) = 0 gives the squares 0, 1, 4, 2, 2, 4, 1, 0, ... so slots 3, 5, 6 are never reached.

The notes also state, without proof, that if m is prime and at least half the table is empty, quadratic probing always finds a free slot. Short reason: for \(0 \le i < j < m/2\), \(i^2 \equiv j^2\) means \((j-i)(j+i) \equiv 0 \pmod m\). For prime m that needs m to divide j−i or j+i, and both are between 1 and m−1. So the first \(\lceil m/2\rceil\) probes are all different slots.

4. Deletion: why search fails (2022–23 Q6(a)(ii), 2021–22 Q6(a)(iii))

If you delete a key in open addressing by just emptying its slot, you cut the probe path of every key that was pushed past that slot. Search stops at the first empty slot, so it reports "not found" for a key that is still in the table.

Method · answer for "why not found and how to fix"

  1. Reason: deleting set the slot to EMPTY. The searched key was inserted later and collided with the deleted key, so its probe sequence passes through that slot. Search sees EMPTY there and stops early.
  2. Fix: do not empty the slot. Mark it isDeleted = true (a tombstone). Search treats a tombstone as occupied and keeps probing. Insert may reuse the tombstone.
  3. Cost: tombstones lengthen searches, so rebuild (rehash) the table when there are many. Chaining does not have this problem: unlink the node.

The paper instances are worked in the traces below. In both, the deleted key sat on the probe path of the searched key.

7. Load factor and table size

  • Chaining: expected search \(1+\alpha\). Keep \(\alpha\) constant (grow the table when it gets large) and you get O(1).
  • Open addressing: \(\alpha < 1\) always. The expected number of probes for an unsuccessful search is at most \(1/(1-\alpha)\) under uniform hashing (CLRS Theorem 11.6; Bayzid sir's notes do not derive it). At \(\alpha = 0.9\) that is 10 probes, so resize at about 0.5 to 0.7.
  • Table size: prime m helps quadratic probing (the half-empty guarantee) and double hashing (any \(h_2\) in 1..m−1 is coprime to m).
