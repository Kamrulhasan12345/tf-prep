1. What "amortized" means

The worst case of one extract-min in a Fibonacci heap is O(n), but it can only be that slow after many cheap operations built a long root list. Amortized cost is the average cost per operation over a worst-case sequence. It is a guarantee about whole sequences, not about luck. There are three standard methods.

MethodIdeaExample
AggregateBound the total cost T(n) of n operations, then divide: T(n)/n.n increments of a binary counter flip at most 2n bits, so 2 per increment.
AccountingCharge each operation a fixed price. Cheap operations are overcharged and the extra is stored as credit that pays for later expensive ones.Binary counter: charge 2 to set a bit to 1, 1 of it stays on the bit to pay for resetting it later.
PotentialDefine a potential \(\Phi\) of the data structure (stored "work"). Amortized cost = actual cost + \(\Phi(\text{after}) - \Phi(\text{before})\).Binomial heap insert: \(\Phi\) = number of trees.

Potential method in four lines. Choose \(\Phi \ge 0\) with \(\Phi(\text{start}) = 0\). For each operation write \(\hat c = c + \Delta\Phi\). Then \(\sum \hat c = \sum c + \Phi_{\text{end}} - \Phi_{\text{start}} \ge \sum c\), so the amortized total bounds the actual total. Pick \(\Phi\) so that expensive operations make \(\Delta\Phi\) very negative.

2. The Fibonacci heap potential

\(\Phi(H) = t(H) + 2\,m(H)\), where t is the number of trees in the root list and m is the number of marked nodes. Why these two? A long root list is the work that the next extract-min must do, so every root stores 1 unit of potential. A marked node is a node that may soon be cascaded, and each cascading cut will create a root and cost a unit, so a mark stores 2 units. When the cut happens it removes the mark (−2) and adds a root (+1), and the net −1 pays for the cut itself.

Let D(n) be the maximum degree of any node in an n-node heap. Section 3 shows \(D(n) \le \lfloor\log_\varphi n\rfloor = O(\log n)\).

OperationActual cost\(\Delta\Phi\)Amortized
Insert1+1 (one new tree)2 = O(1)
Union10 (\(\Phi(H) = \Phi(H_1)+\Phi(H_2)\))1 = O(1)
Extract-min\(O(D(n) + t(H))\)\(\le D(n) + 1 - t(H)\)O(D(n)) = O(log n)
Decrease-keyO(c)\(\le 4 - c\)O(1)
Deletedecrease-key + extract-minO(log n)

Proof · amortized costs (write one line per operation)

  1. Insert. The new node is a new root: t rises by 1, m unchanged. \(\hat c = 1 + 1 = 2\).
  2. Union. Splice the lists: cost 1. Trees and marks just add up, so \(\Delta\Phi = 0\) and \(\hat c = 1\).
  3. Extract-min. The min's at most D(n) children join the root list (cost O(D(n))). Consolidate then walks a root list of at most \(D(n) + t(H) - 1\) roots. Each root is stored in A once, and each link removes one root for good, so there are at most \(D(n)+t(H)-1\) links in total, O(1) each. Creating A and rebuilding the root list from it cost O(D(n)). Actual cost \(O(D(n) + t(H))\).
  4. After consolidation all root degrees differ and are at most D(n), so \(t(H') \le D(n)+1\). No mark is added (children lose their marks if anything), so \(m(H') \le m(H)\). Hence \(\Delta\Phi \le (D(n)+1) - t(H)\).
  5. \(\hat c = O(D(n)+t(H)) + D(n) + 1 - t(H)\). Scale the unit of potential up so that the \(-t(H)\) term cancels the \(O(t(H))\) in the actual cost. Then \(\hat c = O(D(n)) = O(\log n)\).
  6. Decrease-key. If x is a root or its parent's key is still \(\le\) the new key, nothing is cut: actual O(1), \(\Delta\Phi = 0\), \(\hat c = O(1)\). Otherwise let c be the number of calls to CASCADING-CUT (the first is the call after the first CUT). That is one CUT for x plus \(c-1\) cascading cuts: actual cost O(c).
  7. Trees: x and each of the \(c-1\) cut ancestors become roots, so \(t(H') = t(H) + c\). Marks: each of the \(c-1\) cascading cuts clears a mark, and the last call marks at most one node, so \(m(H') \le m(H) - (c-1) + 1 = m(H) - c + 2\).
  8. \(\Delta\Phi \le c + 2(2 - c) = 4 - c\). \(\hat c = O(c) + 4 - c = O(1)\) after scaling. ∎
  9. Delete is decrease-key to \(-\infty\) (O(1)) plus extract-min (O(log n)): O(log n).

After, 3 roots, \(\Phi = 3\). \(\Delta\Phi = -2\): 3 children were added (+3), the removed min took away 1, and 4 links removed 4. The decrease-key example (30 to 2, with 18 and 21 marked): before \(t = 3\), \(m = 2\), \(\Phi = 7\); after \(t = 6\), \(m = 0\), \(\Phi = 6\), with \(c = 3\) calls (cut 21, cut 18, stop at root 7). \(\Delta\Phi = -1 \le 4 - c = 1\). ✓

3. Why D(n) = O(log n): the Fibonacci numbers

Notation: \(F_0 = 0\), \(F_1 = 1\), \(F_{k+2} = F_{k+1} + F_k\). So 0, 1, 1, 2, 3, 5, 8, 13, 21, ... Lemma: any node x of degree k in a Fibonacci heap has at least \(F_{k+2}\) nodes in its subtree. Then \(n \ge F_{k+2} \ge \varphi^k\) gives \(k \le \log_\varphi n\).

Proof · size of a node of degree k

  1. Let \(y_1, \dots, y_k\) be the children of x in the order they were linked to x.
  2. When \(y_i\) was linked to x, x already had \(y_1..y_{i-1}\) as children (and possibly others, later cut), so \(\deg x\ge i-1\). Linking only joins roots of equal degree, so \(y_i\) had degree \(\deg x\ge i-1\) then.
  3. Linking clears \(y_i\)'s mark. Since then \(y_i\) has lost at most one child: the first loss marks it, and a second loss would have cut \(y_i\) away from x by cascading cut, but \(y_i\) is still a child of x. So \(\deg y_i \ge i-2\), for \(i \ge 2\); and \(\deg y_1 \ge 0\).
  4. Let \(s_k\) be the minimum size of a subtree whose root has degree k. Then \(s_0 = 1\), \(s_1 = 2\), and \[ s_k \ge 2 + \sum_{i=2}^{k} s_{i-2} \] (1 for x itself, 1 for \(y_1\), and at least \(s_{i-2}\) for each \(y_i\) with \(i\ge2\), since \(\deg y_i \ge i-2\) and \(s_k\) never decreases as k grows: deleting the subtree of the last-linked child \(y_{k+1}\) from a smallest degree-\((k+1)\) tree leaves a smaller tree with root degree k whose children still satisfy step 3, so \(s_k \le s_{k+1}\)).
  5. Claim \(s_k \ge F_{k+2}\), by strong induction. Base: \(s_0 = 1 = F_2\), \(s_1 = 2 = F_3\). Step: \[ s_k \ge 2 + \sum_{i=2}^{k} F_i = 1 + \sum_{i=0}^{k} F_i = F_{k+2}, \] where the hypothesis \(s_{j}\ge F_{j+2}\) for all \(j
  6. \(F_{k+2} \ge \varphi^k\) where \(\varphi = (1+\sqrt5)/2\) satisfies \(\varphi^2 = \varphi + 1\). Base: \(F_2 = 1 \ge \varphi^0\), \(F_3 = 2 \ge \varphi\). Step: \(F_{k+2} = F_{k+1} + F_k \ge \varphi^{k-1} + \varphi^{k-2} = \varphi^{k-2}(\varphi+1) = \varphi^k\).
  7. x's subtree is part of the heap, so \(n \ge s_k \ge F_{k+2} \ge \varphi^k\). Taking \(\log_\varphi\): \(k\le\log_\varphi n\), and k is an integer, so \(D(n) \le \lfloor\log_\varphi n\rfloor = O(\log n)\). ∎

4. The maximally damaged tree

Definition (2017–18 Q7(a), 4 marks). A maximally damaged tree of degree k is the smallest tree that a Fibonacci heap can contain with a root of degree k: start from a binomial tree Bk and cut off as many nodes as the mark rule allows, keeping the root's degree k. Every non-root node may have lost at most one child (a node that lost two would itself have been cut). Its size is \(F_{k+2}\), so it is the tree that makes the bound of section 3 tight.

Method · draw the maximally damaged tree from Bk (2024–25 Q4(b); 2019–20 Q2(c); 2017–18 Q7(a))

  1. Draw (or imagine) Bk. Its root has children B0, B1, ..., Bk−1. The root keeps all k children: otherwise its degree would drop.
  2. Each child Bj (j ≥ 1) may lose one child, and you remove its largest one, Bj−1. B0 has nothing to lose and stays.
  3. The children Bj had left, B0 ... Bj−2, are now damaged the same way, recursively (each loses its largest child, down to the leaves).
  4. Mark every non-root node that lost a child. Count the nodes: for degree k you must get \(F_{k+2}\).

In the same shape: the damaged tree Dk is a root with children D0, D0, D1, D2, ..., Dk−2. The same thing says Dk = Dk−1 with a Dk−2 hung from its root (Bayzid sir's "fk has subtrees fk−1 and fk−2"). Marked nodes carry a star. Sizes are 3, 5, 8, 13, 21.

Why it is the smallest (one line for the 6 marks). The i-th child of Dk has degree exactly \(\max(0, i-2)\), the least that step 3 of section 3 allows, and by induction \(|D_k| = 1 + |D_0| + \sum_{j=0}^{k-2}|D_j| = 2 + \sum_{i=2}^{k} F_i = F_{k+2}\). That equals the lower bound \(s_k \ge F_{k+2}\), so no tree with root degree k can be smaller.

5. 2022–23 Q5(c): RAHSUT-DELETE (12 marks)

Professor Rahsut proposes this variant of FIB-HEAP-DELETE:

RAHSUT-DELETE(H, x)
  if x == H.min
    FIB-HEAP-EXTRACT-MIN(H)
  else
    y = x.p
    if y != NIL
      CUT(H, x, y)               // cut x from its parent y, x becomes a root
      CASCADING-CUT(H, y)        // recursively mark and cut parents if needed
    add x's child list to the root list of H
    remove x from the root list of H

This is CLRS Problem 19-1. It avoids the full extract-min but the saving is not real. Let c be the number of calls to CASCADING-CUT.

(i) Upper bound on the actual time when x is not H.min

  1. CUT(x, y): O(1).
  2. CASCADING-CUT: c calls, each O(1) (a mark test and possibly a cut): O(c).
  3. Adding x's children to the root list, one at a time: O(x.degree).
  4. Removing x from the root list: O(1).
  5. Actual time \(= O(x.\text{degree} + c)\).

(ii) The potential of H' (x not a root)

  1. Trees: x and each of the \(c-1\) cascade-cut ancestors become roots, so \(t(H)+c\). x's children join the root list: \(+ x.\text{degree}\). x is removed: \(-1\). So \(t(H') = t(H) + c + x.\text{degree} - 1\).
  2. Marks: the \(c-1\) cascading cuts clear marks and the last call marks at most one node. So \(m(H') \le m(H) - (c-1) + 1 = m(H) - c + 2\). (If x itself was marked, removing it only lowers this.)
  3. \(\Phi(H') = t(H') + 2m(H') \le t(H) + c + x.\text{degree} - 1 + 2m(H) - 2c + 4\).
  4. \[ \Phi(H') \le t(H) + 2m(H) + x.\text{degree} - c + 3. \]

(iii) Amortized time: the professor's claim is wrong

  1. \(\hat c = \text{actual} + \Phi(H') - \Phi(H) \le O(x.\text{degree} + c) + x.\text{degree} - c + 3\).
  2. Scale the potential so that \(-c\) cancels the \(O(c)\). What is left is \(O(x.\text{degree})\).
  3. x.degree can be \(\Theta(\log n)\), for example x = a child of the root of a large binomial-like tree Bk (its child Bk−1 has degree k−1). Deleting it does \(\Theta(k)\) work and creates k−1 new roots, so \(\Phi\) rises by \(\Theta(k)\): amortized \(\Theta(\log n)\), not O(1).
  4. FIB-HEAP-DELETE is O(D(n)) = O(log n) amortized too. So RAHSUT-DELETE is asymptotically no better.

Where marks go

  • Not defining c. Say "c is the number of calls to CASCADING-CUT" before using it.
  • Forgetting that x's children enter the root list: they add x.degree to the actual cost and to t.
  • Writing the potential without \(t(H) + 2m(H)\) in it. The whole answer is in those two terms.
  • Concluding O(1). The result has an x.degree term, and x.degree is not constant.
  • Counting the trees as \(t(H) + c\) and forgetting that x is removed: that is \(-1\).
