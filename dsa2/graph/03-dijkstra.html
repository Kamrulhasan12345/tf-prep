Dijkstra's Algorithm

Asked in 2024–25 (Q7b, 15 marks: construct a graph that gives a distance table), 2023–24 (Q10c, 13: correctness proof), 2019–20 (Q6a, 15: maximum-bandwidth path), 2018–19 (Q1a, 15: line-by-line complexity with an array), 2017–18 (Q8c: algorithm 5, proof 5, time 7, Fibonacci heap 5), 2020–21 (Q1b, 12: minimum-sum descent by Dijkstra), 2022–23 (Q2b, 12: positive weights), and CT-1 (AMR) Q2 (4 marks: binary heap against array). Correctness proof plus complexity is almost a guaranteed question.

1. The idea

Dijkstra is BFS with a priority queue. Keep a set \(S\) of vertices whose distance is final. Repeatedly pick the vertex \(u\) outside \(S\) with the smallest estimate \(d[u]\), put it in \(S\), and relax all its outgoing edges. It is the same shape as Prim.

Condition: all edge weights must be non-negative. With a negative edge the proof breaks and the answer can be wrong (section 5).

DIJKSTRA(G, w, s)
  INITIALIZE-SINGLE-SOURCE(G, s)        // d[v] = ∞, π[v] = NIL, d[s] = 0
  S = {}
  Q = V                                 // priority queue keyed by d[]
  while Q is not empty
      u = EXTRACT-MIN(Q)
      S = S ∪ {u}
      for each v in Adj[u]
          RELAX(u, v, w)                // may DECREASE-KEY of v in Q

Method · Dijkstra by hand

  1. Table: one row per step, one column per vertex. Row 0: \(0\) for the source, \(\infty\) elsewhere.
  2. Pick the unfinished vertex with the smallest \(d\). Circle it: it is final. Write the order of extraction.
  3. Relax every outgoing edge of that vertex. Update \(d\) (and \(\pi\)) only if the new value is strictly smaller.
  4. Repeat until all vertices are circled. Draw the shortest-path tree from \(\pi\).
  5. Ties for the minimum: choose alphabetical order, and say so.

3. Correctness proof (2023–24 Q10c 13 marks, 2017–18 Q8c)

Claim. Dijkstra terminates with \(d[v]=\delta(s,v)\) for every \(v\in V\), when all weights are \(\ge0\).

Two facts from the relaxation properties of chapter 2 are used. Know both:

  • Upper bound: \(d[v]\ge\delta(s,v)\) at all times (proof by induction using the triangle inequality).
  • Convergence: if \(s\leadsto x\to y\) is a shortest path and \(d[x]=\delta(s,x)\) before \((x,y)\) is relaxed, then \(d[y]=\delta(s,y)\) afterwards.

Proof by loop invariant

  1. Invariant. At the start of every iteration of the while loop, \(d[v]=\delta(s,v)\) for every \(v\in S\).
  2. Initialisation. \(S=\varnothing\): true.
  3. Maintenance. Let \(u\) be the vertex extracted in this iteration. We show \(d[u]=\delta(s,u)\) when \(u\) is added. Suppose not, and let \(u\) be the first vertex for which it fails. Then \(u\ne s\), because \(s\) is extracted first with \(d[s]=0=\delta(s,s)\). So \(S\ne\varnothing\) just before \(u\) is added.
  4. There is a path from \(s\) to \(u\). Otherwise \(d[u]=\infty=\delta(s,u)\) by the no-path property, and we are done. Let \(p\) be a shortest path from \(s\) to \(u\).
  5. \(p\) starts in \(S\) (at \(s\)) and ends outside \(S\) (at \(u\)). Let \(y\) be the first vertex on \(p\) that is not in \(S\), and \(x\) its predecessor on \(p\), so \(x\in S\). (It can happen that \(y=u\).)
  6. \(x\in S\), and \(u\) is the first failure, so \(d[x]=\delta(s,x)\) from the moment \(x\) was added. Right after that, the edge \((x,y)\) was relaxed. \(s\leadsto x\to y\) is a prefix of the shortest path \(p\), so it is itself a shortest path (optimal substructure). By the convergence property \(d[y]=\delta(s,y)\) then, and by the upper bound it is still so now.
  7. \(y\) comes before or equals \(u\) on the shortest path \(p\), and all weights are non-negative, so \(\delta(s,y)\le\delta(s,u)\).
  8. Chain: \(d[y]=\delta(s,y)\le\delta(s,u)\le d[u]\), the last step by the upper bound.
  9. But \(u\) was chosen by EXTRACT-MIN while \(y\) was still in the queue, so \(d[u]\le d[y]\) (the minimum was chosen).
  10. Steps 8 and 9 give \(d[y]\le\delta(s,u)\le d[u]\le d[y]\). So all are equal and \(d[u]=\delta(s,u)\). This contradicts the choice of \(u\). The invariant is maintained.
  11. Termination. The loop ends when \(Q=\varnothing\), so \(S=V\). By the invariant \(d[v]=\delta(s,v)\) for all \(v\). \(\blacksquare\)

Where marks go

  • The two places where the hypotheses are used must be visible: non-negative weights in step 7, minimum chosen in step 9. The student solution "DSA 23-24 solve" (Q10c) has the right shape but never writes the inequality chain \(d[u]\le d[y]=\delta(s,y)\le\delta(s,u)\le d[u]\). Write it.
  • Define \(x\) and \(y\) before using them. Draw the picture: set \(S\) as a blob, \(p\) leaving it at \(x\to y\), then going on to \(u\).
  • Do not say "the path goes through a vertex outside \(S\) so it is longer" without the weight sign.

Corollary 24.7 (slides 08 p.41-42, CLRS p.661). If Dijkstra runs on a weighted directed graph with non-negative weights and source \(s\), then at termination the predecessor subgraph \(G_\pi\) is a shortest-paths tree rooted at \(s\). Reason: Theorem 24.6 gives \(v.d=\delta(s,v)\) for every vertex, and the predecessor-subgraph property says the \(\pi\) edges then form a shortest-paths tree. This is why the "draw the shortest-path tree from \(\pi\)" step in section 1 is allowed.

The teacher's short version of the correctness argument (notes Lec 8, p.16)

  1. Invariant: every vertex in \(S\) has \(v.d=\delta(s,v)\), and the queue holds exactly \(V-S\).
  2. To show: when \(u\) is extracted and added to \(S\), \(u.d=\delta(s,u)\).
  3. (i) \(u\) was extracted, so its \(u.d\) is the minimum over the queue. (ii) Every vertex already in \(S\) has relaxed its outgoing edges, so it has already influenced the vertices outside \(S\). (iii) So \(u.\pi\) lies inside \(S\).
  4. (iv) Suppose we reached \(u\) from \(s\) through a middleman \(x\) outside \(S\). With non-negative weights this can only increase \(u.d\) (or leave it the same). (v) So going straight through \(S\) is the best choice. (vi) Hence \(u\) is most relaxed when it enters \(S\).

This is the same idea as the CLRS proof: the first vertex \(y\) on a shortest path that is outside \(S\) has \(y.d\le u.d\) and the rest of the path adds a non-negative amount. Use the CLRS wording for full marks.

5. Why negative edges break it

Edges S→A 3, S→B 2, A→B −2. The true distance to B is \(3-2=1\) via A. Dijkstra extracts B first (\(d=2\), the smallest), marks it final, and never revisits it.

  1. Dijkstra finishes with \(d[B]=2\), but \(\delta(S,B)=1\). Wrong. (This uses the test "v in Q" of the section 4 code and the trace. The unguarded RELAX of section 1 lowers \(d[B]\) to 1 after B is final, so this small graph happens to end right; add B→C 1 and it still gives \(d[C]=3\) while \(\delta(S,C)=2\).)
  2. In the proof, step 7 fails: \(\delta(s,y)\le\delta(s,u)\) needs non-negative weights on the rest of the path. Here \(y=A\), \(u=B\): \(\delta(S,A)=3>\delta(S,B)=1\).
  3. Does it terminate with a negative cycle? (2012–13, 6 marks) Yes. Each iteration extracts one vertex from \(Q\) and no vertex is ever put back, so the while loop runs exactly \(|V|\) times whatever the weights. It stops, but the \(d\) values can be wrong (here \(\delta=-\infty\) for vertices reachable from the cycle), and it does not report the cycle.
  4. The "add a constant to every edge" fix does not work either, because paths with more edges are penalised more. Use Bellman-Ford (chapter 2) or Johnson (chapter 5).

7. The 2024–25 question: construct a graph (Q7b, 15 marks)

Given distances from S: S 0, A 2, B 4, C 5, D 7, E 8, F 9, G 11. Build a directed graph with non-negative integer weights so that Dijkstra gives exactly these distances, every vertex is reachable, at least two edges are on no shortest path, and every shortest path is unique.

Method · design, then justify

  1. Pick a tree first. Give every vertex except S exactly one "tight" incoming edge \((u,v)\) with \(d[u]+w=d[v]\), so \(w=d[v]-d[u]\). Choose parents in increasing distance order: S→A 2 (\(2-0\)), A→B 2, B→C 1, C→D 2, C→E 3, E→F 1, D→G 4. Weights \(2,2,1,2,3,1,4\) are positive integers, and every vertex is reachable.
  2. Add the extra edges so each is strictly slack: for an extra edge \((u,v)\) make \(d[u]+w>d[v]\). Then it is on no shortest path (condition 2) and cannot create a second shortest path (condition 3). Used: S→B 5 (\(0+5=5>4\)), A→C 4 (\(2+4=6>5\)), B→D 4 (\(4+4=8>7\)), F→G 3 (\(9+3=12>11\)). That is four extra edges, at least the two required.
  3. Final graph: S→A 2, A→B 2, B→C 1, C→D 2, C→E 3, E→F 1, D→G 4, S→B 5, A→C 4, B→D 4, F→G 3.
  4. Justify by running Dijkstra (trace below): extraction order S, A, B, C, D, E, F, G with the distances in the table. Every weight is non-negative, so the algorithm is correct and these are the true distances.
  5. Check uniqueness by tight edges: every vertex has exactly one incoming edge with \(d[u]+w=d[v]\): A from S; B from A; C from B; D from C; E from C; F from E; G from D. A vertex with one tight incoming edge has one shortest path (induction from S). The four slack edges have \(d[u]+w>d[v]\), so none lies on a shortest path.
On paper: draw the 8 vertices with the distance written inside each. Draw the seven tree edges thick and label each with its weight; draw the four extra edges dashed and write beside each \(d[u]+w\) against \(d[v]\) (for example "0+5=5 > 4"). Then the Dijkstra table. The marker looks for: all conditions listed and checked one by one.

8. Maximum-bandwidth path (2019–20 Q6a, 15 marks)

Each edge has a capacity (bandwidth). The bandwidth of a path is the minimum edge on it (the bottleneck). Find the path of maximum bandwidth from \(s\) to every vertex.

Method · modify Dijkstra in three places

  1. Store \(b[v]\) = best bottleneck known from \(s\) to \(v\). Initialise \(b[s]=\infty\), others \(0\) (or \(-\infty\)).
  2. Extract the unfinished vertex with the largest \(b\) (a max-priority queue).
  3. Relax with \(b[v]=\max\bigl(b[v],\ \min(b[u],\ w(u,v))\bigr)\). Keep \(\pi\) for the path.
  4. Time is the same as Dijkstra: \(O(E\log V)\) with a binary heap, \(O(E+V\log V)\) with a Fibonacci heap.

Justify (the question says "justify your answer")

  1. Extending a path by an edge never increases its bottleneck: \(\min(b,w)\le b\). This plays the role of "non-negative weights".
  2. Run the same invariant proof: when \(u\) (largest \(b\) outside \(S\)) is extracted, take a best path \(p\) to \(u\), the first vertex \(y\) off \(S\) and its predecessor \(x\in S\). The bottleneck of \(p\) up to \(y\) is at most \(\min(\beta(s,x),w(x,y))=\min(b[x],w(x,y))\le b[y]\), because \(x\in S\) is final and \((x,y)\) was relaxed (a prefix of a best path need not be best, so do not claim equality). The bottleneck of the whole of \(p\) is at most that of its prefix, so \(\beta(s,u)\le b[y]\le b[u]\) (largest chosen) \(\le\beta(s,u)\) (every estimate is a real path). All equal.
  3. Alternative answer: a path inside a maximum spanning tree is a maximum-bandwidth path between its ends (the MST bottleneck property, chapter 1), so build the maximum spanning tree and read the tree path.
  4. Small check (undirected S-A 4, S-B 7, A-B 3, A-T 6, B-T 5): extract S (\(\infty\)), then B (7), then T (\(\min(7,5)=5\)), then A. Best bandwidth to T is 5 via S, B, T.

All-pairs strongest path (2017–18 Q2d) is the same idea with Floyd-Warshall: replace \(+\) by \(\min\) and \(\min\) by \(\max\): \(d_{ij}=\max\bigl(d_{ij},\min(d_{ik},d_{kj})\bigr)\). See chapter 4.

9. Minimum-sum descent by Dijkstra (2020–21 Q1b, 12 marks)

Positive integers in a triangle with \(n\) numbers in the bottom row. From the apex, go down each step to one of the two numbers directly below (adjacent). Find the path with the smallest sum. The figure for \(n=4\) is not in the text scan; the method does not depend on the numbers.

Method

  1. Vertices: one per number of the triangle, \(1+2+\cdots+n=n(n+1)/2\) of them. Add a sink \(T\).
  2. Edges: from the number at row \(i\), position \(j\), to the two below it: row \(i+1\) at positions \(j\) and \(j+1\). Give each edge the weight equal to the number at the target vertex. Add a 0-weight edge from every bottom-row vertex to \(T\).
  3. Source: the apex, with \(d[\text{apex}]=\) the apex number (start there, since its number is part of the sum). Or add a source \(s\) with an edge of weight = the apex number.
  4. All weights are positive, so Dijkstra applies. The smallest descent sum is \(d[T]\); the path is read back with \(\pi\).
  5. Size: \(V=O(n^2)\), \(E=2\cdot n(n-1)/2+n=O(n^2)\). With a binary heap \(O(n^2\log n)\).
  6. Remark: the graph is a DAG, so the DAG algorithm of chapter 2 does it in \(O(n^2)\). The question just asks for the Dijkstra reduction.
