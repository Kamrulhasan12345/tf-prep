1. What a flow network is

Think of pipes. Each pipe has a maximum amount of water per second. Water enters at one place (the source s) and leaves at another (the sink t). Every other junction just passes water on: what comes in goes out. The question is how much water can reach t.

Flow network
A directed graph \(G=(V,E)\) with a capacity \(c(u,v)\ge 0\) on every edge, one source \(s\) and one sink \(t\). If \((u,v)\in E\) then \((v,u)\notin E\) (no anti-parallel edges). If there is no edge from u to v, then \(c(u,v)=0\). Every vertex lies on some path from s to t (so the graph is connected).
Flow
A function \(f(u,v)\) on the edges with two rules.
Capacity constraint: \(0\le f(u,v)\le c(u,v)\).
Conservation: for every \(u\in V-\{s,t\}\): \(\sum_{v} f(v,u)=\sum_{v} f(u,v)\) (flow in = flow out).
Value of a flow
\(|f|=\sum_v f(s,v)-\sum_v f(v,s)\), the net flow leaving s. With no edge entering s this is just the sum of flows on the edges out of s. It equals the net flow entering t.
Max-flow problem
Find a flow of maximum value \(|f|\). (This is the 8-mark definition from 2021–22 Q4a.)

Labels in this book are written flow/capacity, so an edge labelled 4/9 carries 4 and can take 9. The teacher's notes use the same format.

2. Making a problem fit: three standard fixes

The definitions above are strict. Real problems break them, so you patch the graph first. The notes (slide 14, p31) show all three.

2.1 Anti-parallel edges

The definition does not allow both u→v and v→u. If you have u→v (capacity 4) and v→u (capacity 10), keep the first and replace the second by a detour through a new vertex w: v→w (10) and w→u (10). The new vertex only passes flow on, so max-flow does not change.

Why bother? The residual network and the augmentation lemma below are cleaner when each pair of vertices has at most one edge. (The engine here copes without the fix, but write the fix on paper when the question has such edges.)

2.2 Many sources, many sinks

Add a super source \(s^*\) with an edge to every source, and a super sink \(t^*\) with an edge from every sink. Give these new edges infinite capacity (use 9999 in the engine). Then solve a normal single-source single-sink problem.

2.3 Can the infinite capacities be finite? (CT2 Q2)

Yes, when every original edge is finite. Set the capacity of \(s^*\to s_i\) to the sum of the capacities of the edges leaving \(s_i\), and the capacity of \(t_j\to t^*\) to the sum of the capacities of the edges entering \(t_j\). No flow could ever use more than that anyway, so the max-flow value does not change.

Why the value is finite even with infinite edges.

  1. The value of any flow is the net flow leaving \(s^*\), which is \(\sum_i f(s^*,s_i)\).
  2. At each source \(s_i\), conservation gives: flow in from \(s^*\) = flow out of \(s_i\) minus flow into \(s_i\) from other original vertices. So \(f(s^*,s_i)\le\) flow out of \(s_i\le\) (sum of capacities of original edges leaving \(s_i\)).
  3. That sum is finite, there are finitely many sources, so \(|f|\) is at most a finite number.

2.4 Limits on a vertex

If a vertex v can pass only k units, split it into \(v_{in}\to v_{out}\) with capacity k. All edges that entered v now enter \(v_{in}\), all edges that left v now leave \(v_{out}\). When the limit sits on a depot next to the source or a zone next to the sink, you can put it on the edge from s or to t instead (chapter 08 does this).

3. The residual network

The idea: given the current flow, the residual network \(G_f\) shows where you can still push more, and where you can take flow back. Taking flow back is what lets the algorithm fix an early bad choice.

Residual capacity
\(c_f(u,v)=c(u,v)-f(u,v)\) if \((u,v)\in E\) (room left);
\(c_f(u,v)=f(v,u)\) if \((v,u)\in E\) (flow that can be cancelled);
\(c_f(u,v)=0\) otherwise.
\(G_f\) has an edge wherever \(c_f>0\). The teacher calls it the "residue network".

Method · draw the residual network

  1. Take the network with current labels f/c.
  2. For every edge u→v with label f/c, draw u→v with value c − f if c − f > 0. This is the room left.
  3. For the same edge draw v→u with value f if f > 0. This is the flow you may cancel.
  4. Edges whose value would be 0 are not drawn.
  5. A saturated edge (f = c) shows only its backward edge. An empty edge (f = 0) shows only its forward edge.

Slide example: edge u→v labelled 4/9 becomes u→v with 5 and v→u with 4.

The residual network has at most 2|E| edges. Its edges are edges of G or their reversals, so some are not edges of G. An augmenting path may use a backward edge. That means "reduce the flow on the real edge in the opposite direction".

4. Augmenting paths and the augmentation lemma

Augmenting path
A simple path p from s to t in the residual network \(G_f\). Its residual capacity is \(c_f(p)=\min\{c_f(u,v):(u,v)\in p\}\), the bottleneck. Always \(c_f(p)>0\).

Pushing \(c_f(p)\) units along p is the same as adding a small flow \(f_p\) (value \(c_f(p)\) on the edges of p, 0 elsewhere) to f. Adding flows in a graph with backward edges needs a careful definition.

Augmentation
For \(f'\) a flow in \(G_f\): \((f\uparrow f')(u,v)=f(u,v)+f'(u,v)-f'(v,u)\) for \((u,v)\in E\), and 0 otherwise. In words: add what f' pushes forward, subtract what f' pushes back.

Lemma: \(f\uparrow f'\) is a flow in G and \(|f\uparrow f'|=|f|+|f'|\)

Proof. Take any edge \((u,v)\in E\). Then \((v,u)\notin E\) (no anti-parallel edges), so \(c_f(v,u)=f(u,v)\) and \(c_f(u,v)=c(u,v)-f(u,v)\).

  1. Lower bound. \(f'(v,u)\le c_f(v,u)=f(u,v)\). So \((f\uparrow f')(u,v)\ge f(u,v)+f'(u,v)-f(u,v)=f'(u,v)\ge0\).
  2. Upper bound. \((f\uparrow f')(u,v)\le f(u,v)+f'(u,v)\le f(u,v)+c_f(u,v)=c(u,v)\). So the capacity constraint holds.
  3. Conservation. Fix a vertex u. Every neighbour v of u has exactly one of the edges (u,v) or (v,u) in E. If \((u,v)\in E\), the edge adds \(f'(u,v)-f'(v,u)\) to the net outflow of u under \(f\uparrow f'\) (compared with f). If \((v,u)\in E\), the edge \((v,u)\) has value \(f(v,u)+f'(v,u)-f'(u,v)\); it enters u, so it adds \(-(f'(v,u)-f'(u,v))=f'(u,v)-f'(v,u)\) to the net outflow. In both cases the extra amount is \(f'(u,v)-f'(v,u)\), the net outflow of \(f'\) over that neighbour. Summing over all neighbours: \[\text{netout}_{f\uparrow f'}(u)=\text{netout}_f(u)+\text{netout}_{f'}(u).\]
  4. For \(u\ne s,t\) both terms on the right are 0, so conservation holds.
  5. For \(u=s\) the equation reads \(|f\uparrow f'|=|f|+|f'|\). \(\blacksquare\)

Since an augmenting path gives \(|f_p|=c_f(p)>0\), every augmentation strictly increases the flow value. This is why Ford-Fulkerson makes progress.

5. Ford-Fulkerson

Method · Ford-Fulkerson by hand (2018–19 (b), 2017–18 Q2(b))

  1. Start with flow 0 on every edge.
  2. Draw the residual network (rules in section 3).
  3. Find any path s to t in it. Write it down, with its bottleneck.
  4. Push the bottleneck. Along a forward residual edge, add to the real edge. Along a backward residual edge, subtract from the real edge in the opposite direction.
  5. Redraw the flow network with new labels and the residual network. Write the flow value.
  6. Stop when s cannot reach t in the residual network. The value is the max flow. (The set of vertices s can still reach gives the min cut: chapter 07.)
FORD-FULKERSON(G, s, t)
 for each edge (u,v) in E
   f(u,v) = 0
 while there is a path p from s to t in the residual network G_f
   c_f(p) = min { c_f(u,v) : (u,v) in p }
   for each edge (u,v) in p
     if (u,v) in E
       f(u,v) = f(u,v) + c_f(p)      // forward edge: push
     else
       f(v,u) = f(v,u) - c_f(p)      // backward edge: cancel
 return f

Ford-Fulkerson is a method, not one algorithm: it does not say which path to pick. Edmonds-Karp (next chapter) picks the shortest.

Watch it on the example network. Here the engine searches with DFS in alphabetical order. Look at the second picture in each step: it is the residual network. Notice the path that uses a backward edge.

On paper: for every iteration draw two pictures side by side. Left: the flow network with every edge labelled f/c and the augmenting path in a heavier line. Right: the residual network. Under them write "path s a c t, bottleneck 12, |f| = 12". Finish with a clean drawing of the final flow network with all labels and the value. This is how the 15-mark 2018–19 question is marked.

6. Runtime

  1. Termination. With integer capacities each augmentation adds at least 1 to the value. The value cannot exceed \(|f^*|\), the max flow. So there are at most \(|f^*|\) iterations.
  2. One iteration. Finding a path by BFS or DFS and updating costs \(O(V+E)=O(E)\), since the graph is connected (so \(E\ge V-1\)).
  3. Total: \(O(E\cdot|f^*|)\). With integer capacities the result is an integer flow on every edge.

Where marks go

  • This bound depends on the value of the flow, not on the size of the graph. Example: s→a, s→b, a→t, b→t with capacity 100 each and a→b with capacity 1. If you keep choosing s a b t, then s b a t (through the backward edge), each path pushes only 1, so 200 augmentations for a 5-edge graph. (DFS in alphabetical order does not walk into this, but the method allows it.)
  • With irrational capacities, an unlucky choice of paths may never terminate. That is why a rule for choosing paths (Edmonds-Karp) is needed.
  • Writing the runtime as \(O(VE^2)\) for plain Ford-Fulkerson. That is Edmonds-Karp. Plain FF is \(O(E|f^*|)\) (2023–24 Q11).
  • Forgetting backward edges in the residual network. Without them FF can get stuck below the max flow.
  • Drawing a residual edge with value 0, or forgetting that a partly used edge shows both a forward and a backward edge.
