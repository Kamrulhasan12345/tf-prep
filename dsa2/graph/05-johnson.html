Johnson's Algorithm

Asked in 2022–23 (Q1a, compulsory question, 12 marks: analyse the complexity), 2018–19 (Q2a, 15 marks: explain the clever idea), 2023–24 (Q9: "In what context is Johnson preferable to Floyd-Warshall", 5 of the 10+5 marks), and as a class-test question (modify the weights of a graph so that none is negative and shortest paths are preserved, 9 marks). Two different questions are asked about the same algorithm: the idea and the complexity. Learn both.

1. Why it exists

  • Floyd-Warshall costs \(\Theta(V^3)\) however few edges there are.
  • Dijkstra from every vertex costs \(V\cdot O(E+V\log V)=O(VE+V^2\log V)\), much better on a sparse graph. But Dijkstra needs non-negative weights.
  • Bellman-Ford from every vertex handles negative edges but costs \(O(V^2E)\), worse than Floyd-Warshall.

The clever idea (2018–19, 15 marks). Run Bellman-Ford once to compute a number \(h(v)\) for each vertex. Use these numbers to reweight every edge so that all weights become non-negative, without changing which paths are shortest. Then run Dijkstra from every vertex on the new weights, and convert the distances back. One slow run (\(O(VE)\)) buys the right to use the fast algorithm \(V\) times.

2. Reweighting: the two requirements

We want a new weight function \(\hat w\) with:

  1. For every pair \(u,v\): a path is shortest under \(w\) if and only if it is shortest under \(\hat w\).
  2. \(\hat w(u,v)\ge0\) for every edge.

Choose any function \(h\colon V\to\mathbb R\) and define \[\hat w(u,v)=w(u,v)+h(u)-h(v).\]

Proof of requirement 1 (shortest paths are preserved)

  1. Take any path \(p=\langle v_0,v_1,\dots,v_k\rangle\). Its new weight is \(\hat w(p)=\sum_{i=1}^{k}\bigl(w(v_{i-1},v_i)+h(v_{i-1})-h(v_i)\bigr)\).
  2. The \(h\) terms telescope: \(h(v_0)-h(v_1)+h(v_1)-h(v_2)+\cdots+h(v_{k-1})-h(v_k)=h(v_0)-h(v_k)\).
  3. So \(\hat w(p)=w(p)+h(v_0)-h(v_k)\).
  4. The correction \(h(v_0)-h(v_k)\) depends only on the two end vertices, not on the path. Every path from \(u\) to \(v\) shifts by the same amount \(h(u)-h(v)\). So the one that was lightest is still lightest: \(\hat\delta(u,v)=\delta(u,v)+h(u)-h(v)\).
  5. For a cycle \(v_0=v_k\), \(h(v_0)-h(v_k)=0\), so cycle weights do not change either. A negative cycle stays negative. \(\blacksquare\)

Proof of requirement 2 (choose \(h\) cleverly)

  1. Build \(G'\): add a new vertex \(q\) with an edge \(q\to v\) of weight 0 to every vertex \(v\).
  2. Run Bellman-Ford from \(q\) on \(G'\). Let \(h(v)=\delta(q,v)\). Every vertex is reachable from \(q\), so \(h\) is finite, and \(h(v)\le0\) (the direct edge costs 0).
  3. For every edge \((u,v)\) of \(G\), the triangle inequality gives \(h(v)=\delta(q,v)\le\delta(q,u)+w(u,v)=h(u)+w(u,v)\).
  4. Rearrange: \(\hat w(u,v)=w(u,v)+h(u)-h(v)\ge0\). \(\blacksquare\)

Why \(q\) with 0-weight edges: it makes every vertex reachable (so no \(\infty\)) and adds no edge into \(q\), so \(q\) lies on no cycle and no cycle weight changes. Why not "add a constant to every edge": paths with more edges would be penalised more, so the shortest path can change.

3. The algorithm

JOHNSON(G, w)
  1. Build G' = G + new vertex q + edges (q, v) of weight 0 for all v in V
  2. if BELLMAN-FORD(G', w, q) returns FALSE
         report "negative cycle" and stop
  3. for each vertex v:  h[v] = δ(q, v)                  // from step 2
  4. for each edge (u,v) in E:  ŵ(u,v) = w(u,v) + h[u] - h[v]    // all ≥ 0
  5. for each vertex u:
         run DIJKSTRA(G, ŵ, u)  to get δ̂(u, v) for all v
         for each vertex v:  d[u][v] = δ̂(u,v) - h[u] + h[v]     // undo
  6. return d

Method · Johnson by hand

  1. Draw \(q\) with 0 edges to all vertices.
  2. Compute \(h(v)\) by Bellman-Ford from \(q\). Write the \(h\) values next to the vertices. If Bellman-Ford finds a negative cycle, stop and say so.
  3. Write a table of the new weights: for each edge \((u,v)\), \(w+h(u)-h(v)\). Check every one is \(\ge0\). A negative result means an arithmetic slip.
  4. Run Dijkstra from each vertex on the new weights (write only the final distances if the question allows).
  5. Undo: \(d(u,v)=\hat d(u,v)-h(u)+h(v)\).

Trace: A→B 3, B→C −2, A→C 4, C→D 2, D→B 1

The only negative edge is B→C. \(h=(A\,0,\ B\,0,\ C\,{-2},\ D\,0)\). New weights: A→B 3, B→C 0, A→C 6, C→D 0, D→B 1. Then Dijkstra from every vertex. Final distances: A (0, 3, 1, 3), B (∞, 0, −2, 0), C (∞, 3, 0, 2), D (∞, 1, −1, 0). Check one: \(d(D,C)=\hat d(D,C)-h(D)+h(C)=1-0+(-2)=-1\), and indeed D→B→C costs \(1-2=-1\).

A→B 2, A→C 5, B→C −3, B→D 4, C→D 1, D→E −2, C→E 6. Three edges are negative. \(h=(0,0,-3,-2,-4)\). All reweighted edges are non-negative: A→B 2, A→C 8, B→C 0, B→D 6, C→D 0, D→E 0, C→E 7.

The 2024–25 Floyd-Warshall graph. Bellman-Ford from \(q\) still relaxes in pass \(V\), so Johnson stops.

4. Complexity analysis (2022–23 Q1a, 12 marks)

Go through the steps one at a time and cost each. Then add them. \(G\) has \(V\) vertices and \(E\) edges.

StepWorkCost
1. Build \(G'\)one new vertex, \(V\) new edges\(O(V+E)\) (or \(O(V)\) if you add in place)
2. Bellman-Ford on \(G'\)\(V+1\) vertices, \(E+V\) edges, \(V\) passes\(O((V+1)(E+V))=O(VE+V^2)=O(VE)\) for a connected graph (\(E\ge V-1\))
3. Read \(h\)copy \(V\) numbers\(O(V)\)
4. Reweightone addition pair per edge\(O(E)\)
5. Dijkstra from each of \(V\) sources\(V\) runsarray: \(V\cdot O(V^2)=O(V^3)\); binary heap: \(V\cdot O((V+E)\log V)=O(VE\log V)\); Fibonacci heap: \(V\cdot O(E+V\log V)=O(VE+V^2\log V)\)
5b. Undo for every pair\(V^2\) pairs, \(O(1)\) each\(O(V^2)\)

Method · the total

  1. Fibonacci heap: \(O(VE)+O(VE+V^2\log V)+O(V^2)=\boxed{O(V^2\log V+VE)}\).
  2. Binary heap: \(O(VE)+O(VE\log V)=O(VE\log V)\).
  3. Array (dense-friendly): \(O(V^3)\).
  4. Space: \(\Theta(V^2)\) for the answer matrix.
  5. Sparse graph \(E=O(V)\): \(O(V^2\log V)\). Dense graph \(E=\Theta(V^2)\): \(O(V^3)\) with Fibonacci heaps, \(O(V^3\log V)\) with binary heaps.

The slide writes it as \(O(V^2\lg V+VE)\), and the notes as "Bellman-Ford \(O(VE)\), Dijkstra \(O(V\lg V+E)\) each, total \(O(V^2\lg V+VE)\)". The same thing.

Where marks go

  • List every step with its cost. A single line "\(O(VE+V^2\log V)\)" without the breakdown loses most of the 12 marks.
  • Say which heap you assume. Without a Fibonacci heap the Dijkstra phase is \(O(VE\log V)\).
  • Do not forget that Bellman-Ford runs on \(G'\), which has one more vertex and \(V\) more edges (this does not change the order of growth).

5. Johnson against Floyd-Warshall (2023–24 Q9, the "5" of 10+5)

Floyd-WarshallJohnson
Time\(\Theta(V^3)\) always\(O(V^2\log V+VE)\)
Best ondense graphs, \(E\approx V^2\)sparse graphs, \(E\approx V\)
Negative edgesyesyes (through reweighting)
Negative cyclesdetects (negative diagonal)detects (Bellman-Ford step)
Codethree loops, very shortneeds Bellman-Ford, Dijkstra, a heap
Constantssmalllarger

Answer in two sentences. "Johnson is preferable on sparse graphs, where \(E\) is far below \(V^2\): with \(E=O(V)\) it runs in \(O(V^2\log V)\) against Floyd-Warshall's \(\Theta(V^3)\). On dense graphs, where \(E\approx V^2\), Johnson is no faster, and Floyd-Warshall's simplicity and small constant make it the better choice."

6. The class-test form: "modify the weights so none is negative"

The question (9 marks) gives a graph with some negative edges and asks to change the weights so that no negative weight remains and shortest paths between any two vertices are preserved, "using an algorithm that works on any such graph". The graph is not in the text scan. The answer is steps 1 to 4 of Johnson: add \(q\), Bellman-Ford for \(h\), \(\hat w=w+h(u)-h(v)\), and list the new weight of every edge. Do not just add the same number to all edges: that changes shortest paths (a path with more edges gains more).

7. Mandatory practice

Do these with pen and paper. Use the two trace graphs above as your practice instances: cover the widget, do the \(h\) values and the new weights by hand, then press Run.

If you got one wrong: check \(h\) first. Every wrong reweighting traces back to a wrong \(h\); a negative new weight is the alarm.
