What to write: answer templates

For every question type that appears in the papers: what goes on the script, in what order. Marks follow the steps: a correct circuit with no tables gets fewer marks than correct tables with a small slip in the circuit. Each template links to the chapter where it is worked in full.

Section A · combinational

1 · Minimise with a K-map (find PIs, EPIs, minimal SOP/POS) · 8–15 marks

  1. Write F = Σm(…) + d(…). If F is given as Π, list the 0s.
  2. Draw the map in Gray order (00 01 11 10), variables named on the corner, minterm numbers small in the cells. Fill in 1s and × for don't-cares (0s for POS).
  3. Circle every prime implicant and list them: "PIs: x'z' (0,2,8,10), …".
  4. List the essential PIs with their responsible minterm: "EPI x'z', because of m8".
  5. Write the minimal expression in a box. POS: group the 0s to get F', then F by De Morgan.
K-map chapter

2 · Tabulation (Quine-McCluskey) · 15–28 marks

  1. Column 1: minterms in binary, grouped by number of 1s.
  2. Columns 2, 3: merged pairs and quads with dashes, a ✓ on every term that merged.
  3. "Prime implicants = unticked terms: …".
  4. The PI chart (rows PIs, columns minterms, × marks); circle the single-× columns; name the EPIs.
  5. Cover what is left; final F in a box.
Tabulation chapter

3 · Implement with a MUX · 12–25 marks

  1. Σ list (convert from Π if needed). Say which variables go on the selects (and why, if you chose).
  2. The implementation table (slices by select value, the function of the remaining variables in each).
  3. The MUX block with every Ik labelled, S₁ = MSB written, enables drawn and tied to their active level, extra gates drawn.
  4. For large MUX from small: the enable table (which MUX is on for which value) and the OR of outputs.
MUX chapter

4 · Implement with a decoder · 10–15 marks

  1. Σ list for each output.
  2. State the decoder's output polarity and enables. Active-high outputs → OR the 1-minterms (or NOR the 0-minterms). Active-low → NAND the 1-minterms (or AND the 0-minterms).
  3. Draw the decoder with input order (MSB on the top input), every used output numbered, the gates, and the enable connections.
  4. Fewer inputs than variables (2-to-4 for a 4-variable function): table of the residue for each output, then F = Σ Di·gi.
Decoder chapter

5 · Priority encoder from a story · 13–15 marks

  1. Rename the story's items as inputs and write the priority order explicitly (highest first).
  2. Compressed truth table: one row per input as winner, × for all lower-priority inputs, 0 for higher ones; outputs = winner's code; a V (valid) column.
  3. Each output bit = OR of the "winner" terms whose code has a 1 there. Simplify, and write V = OR of all inputs.
  4. Draw the gates.

6 · PLA · 10–15 marks

  1. K-map each function and its complement. Choose T or C per output to share the most product terms.
  2. The programming table: numbered product terms, inputs 1/0/–, outputs 1/– with (T) or (C).
  3. The fuse map: input buffers, AND array with × at connections, OR array, XOR with 0 or 1.
  4. One line: "k distinct product terms".
PLA chapter

7 · Arithmetic circuits (adder-subtractor, BCD adder, CLA, multiplier) · 10–15 marks

  1. The block diagram with full-adder boxes chained, the carry/control lines labelled.
  2. The key equations: S = x⊕y⊕c, C = xy + c(x⊕y); for CLA Pi = Ai⊕Bi, Gi = AiBi, Ci+1 = Gi + PiCi, expanded to C₄; BCD correction when K + Z₈Z₄ + Z₈Z₂ = 1 (add 0110).
  3. One worked numeric example through your circuit if the question gives numbers (9+7, 3+4).
Arithmetic chapter

8 · Theory (universal gates, dual vs complement, canonical forms, PI vs EPI) · 5–14 marks

  1. Definition in one line.
  2. The proof or construction (NOT, AND, OR from NAND, drawn).
  3. A small example or truth table.
  4. One line on why it matters (cost, fault tolerance).
Universal gates · Boolean algebra

Section B · sequential (Adnan sir's step names)

9 · Synchronous design from words (detector, counter, vending, traffic) · 12–25 marks

His 8 steps, each as a heading on the script:

  1. State diagram (say Mealy or Moore, and overlapping or not; name the meaning of each state).
  2. State table (PS, NS and output per input).
  3. Number of FFs = ⌈log₂ states⌉ and the state assignment (A = 00 …).
  4. Transition table (binary y → Y).
  5. Excitation requirement of the FF used (Q→Q⁺ → inputs).
  6. Excitation table (FF inputs for every PS and input; unused states as ×).
  7. K-maps for every FF input and the output, with equations.
  8. Circuit diagram: FFs, gates, clock, input, output, all labelled.
Design chapter · Counters

10 · Analyse a given circuit · 12–25 marks

  1. Write the FF input equations and the output equation from the circuit.
  2. Transition table: for every PS and input, the FF inputs, then Q⁺ from the characteristic table.
  3. State table with names, then the state diagram.
  4. One line saying what it does (if recognisable).
Analysis chapter

11 · Flip-flop conversion · 5–11 marks

  1. Table: target inputs, Q, Q⁺ (from the target's characteristic table), source inputs (from the source's excitation table).
  2. K-map per source input → equation.
  3. Circuit: source FF plus gates, target inputs labelled. For "verify", one line per input combination showing Q⁺.
Conversion chapter

12 · Ripple counter (mod-N, up/down, BCD) · 5–12 marks

  1. Number of FFs, and which output clocks the next FF (Q or Q', for the edge type and direction; say it).
  2. The reset state and the NAND that detects it → CLEAR (or PRESET for down counters).
  3. The chain diagram and a short timing diagram or count sequence.
Ripple chapter

13 · Mealy vs Moore, conversion · 5–10 marks

  1. Both block diagrams; z = λ(S, x) vs z = λ(S).
  2. Difference table (at least 4 rows) and an example.
  3. Conversion: the incoming-output list, the split states, the new table with the Z column.
Mealy/Moore chapter

14 · State minimisation, completely specified · 8–12 marks

  1. P₀ = all states; P₁ by output rows; then P₂, P₃, … with a one-line reason for each split, until two are equal. (Or the implication table, passes marked.)
  2. "Equivalent: A ≡ F, …".
  3. The minimal state table with renamed states.
Chapter

15 · Incompletely specified (compatibles, bounds) · 15–25 marks

  1. Implication table with output conflicts crossed first, then the pass-by-pass crossings.
  2. The compatible pairs, and the merger graph (or table method) giving the maximal compatibles.
  3. The incompatible pairs → maximal incompatibles.
  4. Bounds: lower = largest maximal incompatible; upper = min(number of states, number of maximal compatibles).
  5. The closure table (each chosen compatible and its implied sets) proving the set is covering and closed.
  6. The minimal state table.
Chapter

16 · Pulse mode · 20–25 marks

  1. State the assumptions: inputs are pulses, never two at once, no clock.
  2. State diagram and state table with one column per pulse input (no x=0 column); Mealy or Moore by his rule.
  3. Assignment, transition table, excitation table for the latch type asked (SR/T/JK).
  4. K-maps one per input column; F = x₁f₁ + x₂f₂ + …; never group across columns.
  5. Circuit diagram; a trace of a few input pulses if asked.
Pulse mode

17 · Fundamental mode · 25 + 10 marks (he said it will come)

  1. Assumptions: one input change at a time, the circuit settles in between.
  2. Primitive flow table: one stable state per row (circled), every allowed single-input change, outputs by the "on quickly / off slowly" rule.
  3. Reduction: implication table or merger diagram on the rows → maximal compatibles → reduced flow table.
  4. Transition diagram of the reduced rows; any triangle (or diagonal) → add a spare row; race-free assignment written beside the table.
  5. Transition table, K-maps for each Y and z, the circuit (if asked).
Flow tables · Races

On every page

  • State every assumption in one line: enable polarity, MSB, initial state, overlapping or not, Mealy or Moore.
  • Box final answers. Label every wire.
  • If short of time: write the tables, skip the drawing, and say "circuit follows from these equations".
