Comparators, max/min, code converters and parity

Older: 2-bit magnitude comparator (2016–17, 10), negative-logic 4-bit parity checker/generator (2016–17, 6), BCD error detector, Binary-to-Excess-3 with control lines. A code-converter or comparator design question appears in about six of eight papers, 10–20 marks. The method is always the same: truth table with don't-cares, a K-map per output, gates.

1. Magnitude comparator

A comparator takes two n-bit numbers X and Y and gives three outputs: X > Y, X = Y, X < Y. Exactly one is 1.

  1. Bit i is equal when both bits match: ei = Xi ⊙ Yi = XiYi + Xi'Yi' (an XNOR gate).
  2. X = Y when every bit is equal: AND of all ei.
  3. X > Y: look from the MSB. X is bigger if the top bits differ with X2 = 1, Y2 = 0; or the top bits are equal and the next bits give X bigger; and so on. X2Y2' + e2X1Y1' + e2e1X0Y0'.
  4. X < Y: the same with the roles swapped: X2'Y2 + e2X1'Y1 + e2e1X0'Y0.

This is ma'am's method (her n = 4 version has one more term). A 6-input truth table has 64 rows, so never do it that way for 3 bits.

2024–25 Q6(b) · 14 marks · older: 2-bit comparator 2016–17 (10 marks)

Design a magnitude comparator for two 3-bit numbers X and Y.

Answer

Outputs: G (X > Y), E (X = Y), L (X < Y). Equal-bit signals e2, e1, e0 from XNOR gates.

G = X2 Y2' + e2 X1 Y1' + e2 e1 X0 Y0'
E = e2 e1 e0
L = X2' Y2 + e2 X1' Y1 + e2 e1 X0' Y0

(Shortcut: exactly one output is 1, so L = (G + E)' needs one NOR gate and saves the second set of AND gates. Either circuit is correct. The equations were checked for all 64 input pairs.)

What to write (comparator, 10–14 marks)

  1. "Three outputs G, E, L; exactly one is 1."
  2. ei = Xi ⊙ Yi (XNOR), with a line saying why.
  3. The three equations, written MSB first (G, E, L above).
  4. The circuit: 3 XNOR gates, AND gates for each term, an OR for G and L, an AND for E. Label X2 as MSB.
  5. One check: X = 101, Y = 011 gives e2 = 0, G = X2Y2' = 1.

2. Larger or smaller of two numbers (max / min)

This is a comparator followed by a multiplexer. The comparator output decides which number is passed to the output.

  1. Compare X and Y: get G = (X > Y).
  2. Maximum: Z = X if G = 1, otherwise Y. A 2×1 MUX on every bit: Zi = G·Xi + G'·Yi. (If X = Y it does not matter which one is chosen.)
  3. Minimum: Z = Y if G = 1, otherwise X. Swap the two MUX inputs: Zi = G'·Xi + G·Yi.
  4. Hardware: one comparator + a "quad 2×1" MUX (one 2×1 MUX per bit, one shared select).
2017–18 Q2(a) · 10 marks · 2018–19 Q2(a) · 12 marks · 2020–21 Q4(a) · 10 marks · older: 2-bit comparator in 2016–17

Design a circuit that outputs the larger of two 3-bit numbers X2X1X0 and Y2Y1Y0 (2017–18; 2020–21 adds "explain with 7 and 3"). Design a circuit that returns the smaller of two 4-bit numbers A and B; show it for A = 7, B = 9 (2018–19).

Answer

Design (3-bit max): comparator gives G; three 2×1 MUXes with S = G, I1 = Xi, I0 = Yi give Zi.

7 and 3 (max, 2020–21): X = 111, Y = 011. The top bits differ: X2 = 1, Y2 = 0, so G = X2Y2' = 1 straight away. The MUX selects X. Z = 111 = 7.

A = 7, B = 9 (min, 2018–19): A = 0111, B = 1001. Top bits: A3 = 0, B3 = 1, so L = A3'B3 = 1 (A < B), G = 0. For the minimum the MUX passes A. Z = 0111 = 7.

The bench above traces any two numbers bit by bit, the way you should on paper.

What to write (max/min, 10–12 marks)

  1. Block diagram: comparator, then MUX with the comparator output as select. Name G, and say which input is which.
  2. The comparator equations (section 1), or the block labelled "magnitude comparator" if the question lets you.
  3. Zi = G Xi + G' Yi for max, written per bit.
  4. The numeric trace, starting at the MSB, saying which equation fires.

3. Gray code and binary

In Gray code only one bit changes between neighbouring numbers. Binary → Gray: the top bit is copied, every other bit is XORed with the bit above it. Gray → binary: the top bit is copied, every other bit is the binary bit above it XOR the Gray bit.

Binary → Gray: g2 = b2, g1 = b2 ⊕ b1, g0 = b1 ⊕ b0
Gray → binary: b2 = g2, b1 = b2 ⊕ g1 = g2 ⊕ g1, b0 = b1 ⊕ g0 = g2 ⊕ g1 ⊕ g0

K-maps. B2 = Σ(4,5,6,7) = G2. B1 = Σ(2,3,4,5) = G2'G1 + G2G1' = G2 ⊕ G1. B0 = Σ(1,2,4,7): a checkerboard, no grouping possible, so as SOP it needs four 3-literal terms; it is G2 ⊕ G1 ⊕ G0.

What to write (code converter, 15–20 marks)

  1. The full truth table, every input row.
  2. A K-map for each output (3 variables, B0 is a checkerboard: say "no grouping, XOR").
  3. The simplified equations, then the XOR form that gives the minimum gates.
  4. The circuit with inputs G2 G1 G0 and outputs B2 B1 B0 labelled.

4. An arbitrary code to BCD ("random code")

A custom code converter is a standard 4-step design: (1) truth table with every input; (2) the unused input combinations become don't-cares; (3) one K-map per output; (4) minimise and draw. Use the don't-cares to get larger groups.

5. BCD ↔ Excess-3

6. Parity generator and checker

A parity bit is added to a word so that the total number of 1s is always even (even parity) or always odd (odd parity). The receiver recomputes parity and raises an error flag when it is wrong. It finds any single-bit error, but cannot say which bit.

The tool is the XOR gate. x ⊕ y ⊕ z is 1 exactly when an odd number of the inputs are 1. So a chain of XORs counts the 1s (mod 2).

generator (sender)checker (receiver)
inputsthe n data bitsthe n data bits + the received parity bit P (n + 1 bits)
outputthe parity bit Pan error flag E (1 = error)
even parity, n = 3P = x ⊕ y ⊕ zE = x ⊕ y ⊕ z ⊕ P
odd parity, n = 3P = (x ⊕ y ⊕ z)' (XNOR)E = (x ⊕ y ⊕ z ⊕ P)' (error when the count of 1s is even)
2018–19 Q4(a) · 8 marks · 2017–18 Q4(a) · 8 marks · 2020–21 Q2(c) · 5 marks · older 2016–17 (negative-logic 4-bit, 6 marks)

(2018–19) What are the differences between an odd parity checker and an odd parity generator? (2017–18) For a 3-bit Excess-3 code design an odd parity checker and an odd parity generator. (2020–21) Three-bit data is transmitted; an error is indicated if the parity is odd. Design the circuit.

Answer

Difference (2018–19): the generator is at the sender: it has n inputs (the data) and produces the parity bit that makes the total number of 1s odd. The checker is at the receiver: it has n + 1 inputs (data and the received parity bit) and produces an error flag that is 1 when the total number of 1s is even (a violation of odd parity). Both are XOR trees; the generator inverts once at the end, so does the checker.

Odd parity, 3 data bits (assumption: "3-bit" means three data bits x y z; for the 4-bit Excess-3 digit wxyz use the same circuit with one more XOR).

P = Σ(0,3,5,6) = (x ⊕ y ⊕ z)'. The checker is 1 for any received word with an even number of 1s, for example 0000 (no ones) or 0011 (two ones): E = (x ⊕ y ⊕ z ⊕ P)'.

2020–21 (error if the parity of the three bits is odd): E = x ⊕ y ⊕ z. E = 1 means an odd number of 1s was received, so report an error. (If the three bits are two data bits and an even parity bit, the circuit is the same.)

What to write (parity, 5–8 marks)

  1. Define the scheme: odd parity means an odd number of 1s in data + parity.
  2. Truth table (data, P) for the generator and the equation P = (x ⊕ y ⊕ z)'.
  3. The checker equation E = (x ⊕ y ⊕ z ⊕ P)' and what E = 1 means.
  4. Two small circuits made of XOR gates with every input labelled.
  5. For "differences": sender versus receiver, n versus n + 1 inputs, parity bit versus error flag.
Traps that cost marks
  • Comparator: forgetting the ei factors. X1Y1' alone is not enough: it must be ANDed with "the higher bits are equal".
  • Max versus min: swapping the MUX inputs. Test with two numbers before you draw.
  • Code converters: leaving don't-cares as 0. Use them to enlarge groups.
  • Gray → binary: XORing Gray bits only (that gives binary → Gray). Gray → binary needs the binary bit above.
  • Parity: even versus odd. Odd parity generator = XNOR, odd checker flags an even count.
  • When the question's table is unclear (2021–22), write the assumption in one line before you start.
