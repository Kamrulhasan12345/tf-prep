1. Number systems and conversions

A number system has a base (radix) r and digits 0 … r−1. Value = Σ digit × rposition; positions right of the point are negative powers.

  1. Any base → decimal: multiply each digit by its power of r and add. (0110)₂ = 0·8 + 1·4 + 1·2 + 0 = 6.
  2. Decimal integer → base r: divide by r repeatedly. Write quotient, remainder. Read the remainders bottom (MSB) to top (LSB). 13 → 6 r1, 3 r0, 1 r1, 0 r1 → 1101.
  3. Decimal fraction → base r: multiply the fraction by r repeatedly. The integer part of each product is the next digit, top to bottom. 0.625 × 2 = 1.25 (1); 0.25 × 2 = 0.5 (0); 0.5 × 2 = 1.0 (1) → (0.101)₂. 41.6875 = 101001.1011 (41 → 101001; 0.6875 → 1011).
  4. Binary ↔ octal / hex: group bits in 3s / 4s from the point outwards, padding zeros at the far ends. (10110.01)₂ → 0001 0110 . 0100 → (16.4)₁₆. (26.2)₈ → 010 110 . 010 → regroup in 4s → (16.4)₁₆.

2. Complements

(r−1)'s complement of N
(rⁿ − 1) − N for an n-digit number: subtract each digit from r−1. Decimal: 9's complement of 546700 = 453299. Binary: 1's complement = flip every bit; 1011000 → 0100111.
r's (radix) complement of N
rⁿ − N (0 if N = 0) = (r−1)'s complement + 1. Decimal: 10's complement of 246700 = 753300. Binary: 2's complement = flip and add 1. Shortcut: copy bits from the right up to and including the first 1, then flip all bits to its left: 10110000 → 01010000.

The number of digits n is fixed. If M has more digits than N, pad N with leading zeros before complementing. With a radix point, n counts the integer digits, and the fraction digits just come along (in ulps of the last place).

r's against (r−1)'s (2 marks): they differ by 1 in the last place. r's has one zero (no −0) and no end-around carry; (r−1)'s needs an end-around carry and has two zeros (+0 = 00…0 and −0 = 11…1).

3. Subtraction M − N by complements (the most repeated question)

Ma'am's wording, for two n-digit unsigned numbers M and N in base r. r's complement version (2017–18, 2021–22, CT1):

  1. Take the r's complement of N: rⁿ − N.
  2. Add it to M: Sum = M + (rⁿ − N) = (M − N) + rⁿ.
  3. If an end carry occurs (M ≥ N): discard it. What is left is M − N.
  4. If no end carry (M < N): the answer is negative. M − N = −(r's complement of Sum). Put a minus sign in front.

(r−1)'s complement version (2022–23 Q1a): the same, except step 1 uses (r−1)'s complement and:

  1. Add M + [(r−1)'s complement of N].
  2. End carry (M ≥ N): add that carry to the least significant digit (end-around carry). The result is M − N.
  3. No end carry (M < N): M − N = −((r−1)'s complement of Sum).

Why it works: rⁿ − N added to M gives M − N + rⁿ. The extra rⁿ is the end carry. If M < N the sum is rⁿ − (N − M), which is the r's complement of the magnitude, so we complement it back. In the (r−1)'s case the stored value is one less, so the carry has to be put back.

Answer

Rules (2 marks): the four numbered steps of the r's complement version above, with the two cases separated.

The calculation (5 marks). Assumption: the expression is read left to right, (9 − 6.9) − 9.8, all in hexadecimal. This gives one M ≥ N case and one M < N case, which is clearly what the examiner wants. Use n = 1 integer digit, one fraction digit. 6.9₁₆ means 6 + 9/16.

Step 1: 9 − 6.9. M = 9.0, N = 6.9. 15's complement of 6.9 = 9.6; add 1 in the last place: 16's complement = 9.7. M + that = 9.0 + 9.7 = 1 2.7 → end carry, discard → 2.7.

4. Signed numbers and overflow

Ma'am uses signed 2's complement: the leftmost bit is the sign (0 = +, 1 = −), a negative number is stored as the 2's complement of its magnitude. An n-bit number holds −2n−1 … +2n−1−1 (8 bits: −128 … +127; 4 bits: −8 … +7).

  1. Addition: add all n bits including the sign bit. Discard any carry out of the sign bit.
  2. Subtraction A − B: take the 2's complement of B (sign bit included) and add. A − (+B) = A + (−B), A − (−B) = A + (+B).
  3. Her examples (8-bit): (+5) + (−11): 00000101 + 11110101 = 11111010 = −6. (−5) + (−11): 11111011 + 11110101 = 1 11110000 → drop carry → −16. (−6) − (−13) = (−6) + 13: 11111010 + 00001101 = 1 00000111 → +7.
Overflow
The true result does not fit in the n bits, so the stored result is wrong. The adder cannot signal it by itself.
Unsigned numbers
Overflow = a carry out of the MSB (for A + B).
Signed numbers
The end carry does not mean overflow. Overflow can happen only when the two operands have the same sign, and it has happened when the sum's sign differs from them. Equivalent hardware test: V = (carry into the sign bit) XOR (carry out of the sign bit). For subtraction, A − B is done as A + B' + 1 and the same test is applied to that addition.

Truth table (ma'am's slide): A sign 0, B sign 0, carry in 1 → carry out 0, sum sign 1 → overflow. A sign 1, B sign 1, carry in 0 → carry out 1, sum sign 0 → overflow. Opposite signs can never overflow.

Answer

Definition and the rule from the box above. Then examples, 4-bit signed (range −8 … +7). The table is computed live; read the last two columns:

Rows 1 and 2: two positives or two negatives whose sum leaves the range, so the sign comes out wrong and carry-in ≠ carry-out → overflow. Row 3: (+5) + (−3) has a carry out and a carry in, equal, so no overflow although there is an end carry. 5. Codes

Weighted and decimal codes

A weighted code gives each bit position a weight; the digit is the sum of the weights of the 1 bits. BCD is weights 8, 4, 2, 1. The codes 1010–1111 are unused in BCD (six invalid combinations). Excess-3 is not weighted: each digit is BCD + 3 (0011), and it is self-complementing. Live table (every row is computed or checked from the weights):

  1. Build a weighted code for given weights (CT1 Q2): list all bit patterns, compute weight sums, assign one pattern per digit, mark leftovers as unused.
  2. Decode a given string by splitting it into groups of 4 and summing the weights of the 1s.

Answer

BCD addition (her method)

  1. Add the two 4-bit digits as binary (with the carry from the lower digit).
  2. If the result is 1010–1111 or there is a carry out, the digit is invalid: add 0110 (6), which skips the six unused codes. The carry goes to the next digit.

Example 184 + 576: digit 4 + 6 = 1010 invalid → + 0110 = 1 0000: digit 0, carry 1. Digit 8 + 7 + 1 = 10000 → carry, + 0110 → 0110, carry 1. Digit 1 + 5 + 1 = 0111. Answer 0111 0110 0000 = 760. The adder circuit is in chapter 6.

Gray code against binary (2022–23 Q1b, 9 marks)

Binary → Gray: gn−1 = bn−1, gi = bi+1 ⊕ bi. Gray → binary: bn−1 = gn−1, bi = bi+1 ⊕ gi (running XOR from the MSB). For 3 bits: b₂ = g₂, b₁ = g₂ ⊕ g₁, b₀ = g₂ ⊕ g₁ ⊕ g₀. (Ma'am's notes and slides give only the table and the "one bit changes" property; these conversion rules are the standard ones, and the K-map check is in chapter 7.)

Parity bit (error detection)

Add one extra bit to a code word so that the total number of 1s is even (even parity) or odd (odd parity). A receiver counts the 1s: wrong parity means an error. It detects any single-bit error (and any odd number of flipped bits), but cannot say which bit, cannot correct, and misses two flipped bits. ASCII uses 7 bits plus a parity bit. Examples: 'A' = 1000001 has two 1s: even-parity bit 0 (01000001), odd-parity bit 1 (11000001). 'T' = 1010100 has three 1s: even-parity bit 1 (11010100), odd-parity bit 0 (01010100). Rule: even parity bit = 1 when the data has an odd number of 1s, i.e. P = XOR of the data bits. (Her note's wording on p22 reads inverted; her examples and the generator on p84 are right.) The generator and checker circuits are in chapter 7.

Traps that cost marks

  • Not padding N to n digits before taking its complement. 5623 − 65438 needs 05623.
  • Discarding the end carry in the (r−1)'s version. There it must be added back to the LSB.
  • Calling the carry out an overflow in signed arithmetic. Use Cin ⊕ Cout or the sign rule.
  • Forgetting the minus sign and the second complement when there is no end carry.
  • Reading remainders top-to-bottom (integer part) or fraction digits bottom-to-top.
  • BCD: adding 6 only when the sum is above 9 or there is a carry, not always.
  • Grouping binary for octal or hex from the left instead of from the point outwards.
