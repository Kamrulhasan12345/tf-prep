State minimisation 1: equivalent states (completely specified)

Every cell of the state table has a next state and an output. Asked in 2024–25 Q5(c) (12 marks, A–H table, 4 inputs), 2022–23 Q8(c) (11, A–E, "using implication table"), 2020–21 Q7(a) (10, A–H, x = 0/1), 2018–19 Q7(b) (8, A–F, inputs I J K) and 2017–18 Q7(a) (10; the same A–H table as 2024–25 Q5(c)). 2019–20, 2021–22 and 2023–24 asked the incompletely specified version instead (next chapter). Old question-bank items #218, #219, #220, #221 are solved at the end. This is an 8–12 mark question with no thinking in it: follow the procedure and you get full marks.

1. What "equivalent" means, and why we merge

Equivalent states
Adnan sir: states Sx and Sy are equivalent iff for every possible input sequence the circuit gives the same output sequence, whichever of the two is the starting state.
Local test
X and Y are equivalent if (1) their outputs are the same for every input combination, and (2) their next states are equivalent for every input combination. It is recursive, so we need a method that settles it.

Why bother (write this as one line): merging equivalent states gives (1) fewer flip-flops and (2) fewer gates in the combinational part. The external behaviour is unchanged.

Equivalence is reflexive, symmetric and transitive. Transitive means A = B and B = C give A = C. This is the one fact that makes the answer a clean set of classes, and it is what separates this chapter from the incompletely specified one.

Mano vs Adnan sir. Mano §5.7 reduces by matching rows: two rows with the same next states and outputs are one state, delete one, repeat. That is fine for a 4-state table but misses equivalences that only show up deeper. Adnan sir teaches two systematic methods instead: the partition method and the implication table. Use his, and write his notation (P0, P1, …).

2. Method A: the partition method

Idea: start with everything in one block, then split blocks until nothing splits. A block that survives has states that cannot be told apart by any input sequence.

  1. P0 = all states in one block. (Equivalent for input sequences of length 0, trivially.)
  2. P1 = split by output: states stay together only if their output is the same for every input column. (Equivalent for one input.)
  3. Pk+1: inside each block of Pk, keep two states together only if, for every input, their next states lie in the same block of Pk. Otherwise split.
  4. Stop when Pk+1 = Pk ("no change, the algorithm terminates"). The blocks are the equivalence classes.
  5. Name each block with a new state (α, β, γ, …). Rewrite the table: the next state of a block is the block that contains the old next state. The output is copied.

Adnan sir's first example (R p58–59, six states). Step through it and watch (B, D, F) lose F, then (A, C, E) lose E.

His second example (R p59–60, seven states) takes one more round. The result: (A) (F) (BD) (CG) (E), five states.

3. Method B: the implication table

Idea: ask each pair the question "equivalent?" once, and write down what the answer depends on. Then kill pairs whose dependencies are dead.

  1. Draw the staircase: one cell for every pair. Rows are the second state to the last, columns are the first to the second last (rows B…H, columns A…G).
  2. Pass 1, fill column by column (first column first). For a pair XY: if the outputs differ for any input, write X. Otherwise write the implied pairs: for each input, the pair of next states, when the two next states are different. Drop any pair equal to XY itself (self-implication, always true) and any pair of identical states. If nothing is left, write a tick.
  3. Pass 2 and later ("DFS"): look at every uncrossed cell. If any implied pair in it sits in a crossed cell, cross this cell too. Repeat until a pass crosses nothing. (A cycle of pairs that only imply each other is not crossed: "if cycle, don't cross".)
  4. The uncrossed cells are the equivalent pairs.
  5. Draw the merger graph: one vertex per state, one edge per equivalent pair. Because equivalence is transitive, the graph falls apart into disjoint complete pieces (a vertex alone counts). Each piece is one class.
  6. Rename the classes and write the minimal table as in step 5 of Method A.

P0 = (ABCDEFGH)
P1 = (ABEFG)(CDH)
P2 = (AB)(EFG)(CDH)
P3 = (A)(B)(EFG)(CD)(H)

P1: the output is 1 on both inputs for A, B, E, F, G; C, D, H give 0 on x = 0. P2: A and B send x = 0 into (ABEFG) and x = 1 into (CDH); E, F, G send both inputs into (CDH). Traps that cost marks
  • Splitting against the wrong partition. To build Pk+1 look up next states in the blocks of Pk (the previous one), not in the blocks you are currently creating.
  • Stopping early. Stop only when a whole round changes nothing, and write that line.
  • Comparing outputs for one input only. Every input column must match for two states to stay together.
  • In the implication table, a pair that implies itself is a tick (A–F in the 8-state table). Do not leave it as a dependency, or you will cross a good pair.
  • Pass 2 is not optional. A cell with an implied pair in a crossed cell is crossed. Missing this keeps pairs that are not equivalent (in the 8-state table, AD survives pass 1 but not pass 2).
  • Merging a pair without checking transitivity. If BC, BH and CH are all equivalent, the class is (BCH), not three separate merges.
  • Forgetting to rename the next-state entries in the reduced table. A reduced table that still says "B" or "F" in a cell loses the marks.
  • The question says "name the equivalent states" and the answer shows only a table. Write the classes in words.
