1. How a ripple counter works

Only the first flip-flop gets the external clock. The output of each flip-flop is the clock of the next one. Each flip-flop toggles (T = 1), so each output has half the frequency of its clock: the chain divides by 2n. Asynchronous because the flip-flops do not get their clock pulse at the same time. Ripple because the change ripples from one flip-flop to the next.

How to get "toggle" from the flip-flop you are given (his remark: "if the question gives JK, D or SR, make it a T"): T flip-flop: T = 1. JK: J = K = 1. D: D = Q' (connect Q' back to D). SR: S = Q', R = Q (this is the JK-from-SR conversion with J = K = 1).

Which output drives the next clock (this is the one thing to remember):

Flip-flop edgeUp counter: clock of next stageDown counter: clock of next stage
positive edgeQ' of the previous stageQ of the previous stage
negative edgeQ of the previous stageQ' of the previous stage

Reason: an up counter must toggle the next bit when the present bit goes from 1 to 0 (a carry). A falling Q is a rising Q'. A positive-edge flip-flop needs a rising signal, so it takes Q'. A negative-edge flip-flop takes Q (its falling edge). A down counter toggles the next bit when the present bit goes 0 to 1 (a borrow): that is a rising Q, or a falling Q'. His words: up counter passes Q-bar into the next clock (positive edge), down counter passes Q; up-down counter uses a MUX at every step.

4. Mod-N counters: reset when the count reaches N

If N is not a power of two, let the counter run to N, then clear every flip-flop with the asynchronous CLEAR input. The detector is a NAND of the bits that are 1 at N (CLEAR is active-low). Use only as many bits as needed: the first count that makes all those bits 1 must be N itself. Computed by the engine's rule for each N:

His note: with N = 12 the counter shows state 1100 for a very short time (the reset glitch). The valid count is 0 to 11. He draws the NAND from Q3 and Q2 only, because 1100 is the first state with both set.

Glitch (marks in the older question: "problems of this counter"): 11 → 0 passes through 1010 → 1000 → 1100 → 0000. The state 1100 lasts only for the NAND and CLEAR delay, but it is a real, wrong state. Anything that decodes the count sees a short false 12 (and false 8 and 10 on the way).

What to write (ripple counter, 5–10 marks)

  1. One line: "T flip-flops (T = 1 or J = K = 1), positive edge, up counter: Q' of each stage clocks the next."
  2. The circuit: n flip-flops in a row, CLK on the first, Q (or Q') to the next clock, the outputs labelled Q0 (LSB) to Qn−1.
  3. For mod-N: the NAND of the bits that make N, the line to the CLEAR bubbles of the flip-flops that need clearing, and the statement "state N is the first with these bits all 1".
  4. The count table or timing diagram (CLK and every Qi) for at least one full cycle plus one clock.
  5. One sentence on the disadvantage: delay adds up (ripple), and the reset state glitches.

5. Mod-13 up/down (2021–22 Q6(c))

2021–22 Q6(c) · 5 marks

MOD-13 counter 0000 to 1100, ripple up/down counter, positive-edge JK.

Answer

Assumption: "up/down" means one counter with a control line UP (1 = count up, 0 = count down), so a MUX is used in each clock path (his method).

  1. Clock chain as in section 3: each stage's clock = MUX(Q for down, Q' for up).
  2. Up: after 12 (1100) the next count is 13 (1101). Detect it with the NAND of Q3 Q2 Q0 (Q3 Q2 Q0) and UP, and clear all four flip-flops. Without UP the gate would also fire on 1111 while counting down.
  3. Down: after 0 (0000) the next count is 15 (1111), but it must be 12 (1100). Detect 1111 with a NAND of Q3 Q2 Q1 Q0 and clear only Q1 and Q0, which leaves 1100 = 12. In up mode 1111 is never reached.
  4. CLEAR of Q3, Q2 = gate A. CLEAR of Q1, Q0 = A AND B (either gate low clears them).
Mod-13 ripple up/down counter. Gate A (NAND of Q3 Q2 Q0 UP) detects 13 while counting up and clears all four. Gate B (NAND of Q3 Q2 Q1 Q0) detects 15 while counting down. AND of A and B clears Q1 and Q0 only (down: 1111 → 1100 = 12).

Counts: up 0, 1, ..., 12, 0, 1; down 12, 11, ..., 0, 12, 11.

6. BCD ripple down counter with D flip-flops (2018–19 Q5(c), 2020–21 Q5(c))

2018–19 Q5(c) · 7 marks · 2020–21 Q5(c) · 5 marks

Design a BCD ripple down counter using D flip-flops.

Answer
  1. BCD down counter: 9, 8, 7, ..., 0, 9, ... (1001 down to 0000).
  2. Four D flip-flops, positive edge, D = Q' on each so that they toggle. Down counter, positive edge: the Q of each stage clocks the next.
  3. After 0000 the natural next count is 1111. We want 1001. Detect 1111 with a NAND of Q3 and Q2 (the first state with both set while counting down is 1111) and use it to clear Q2 and Q1. Q3 and Q0 are already 1, so the result is 1001 = 9.
  4. Start-up: preset to 1001 (preset Q3 and Q0, clear Q2 and Q1).

Honest caveat (one line for the script). Counting down from 8 to 7 the counter ripples through 1001, 1011, 1111 before Q3 falls. The reload gate sees 1111 for a moment there too. It works only if the NAND + clear path is slower than one flip-flop delay, so the glitch is too short to act. The idealised answer above is what the exam expects. Never claim the design is glitch free.

7. Mod-100 ripple down counter with JK (2023–24 Q6(c))

2023–24 Q6(c) · 6 marks

Modulo-100 ripple down counter with J-K flip-flops and basic gates.

Answer
  1. 100 states need 7 flip-flops (26 = 64 < 100 ≤ 128). Count 99 down to 0. 99 = 1100011.
  2. JK with J = K = 1, positive edge, down counter: Q of each stage clocks the next.
  3. After 0000000 the natural next count is 127 = 1111111. We want 99 = 1100011. The bits Q6 Q5 Q1 Q0 are already 1, so only Q4, Q3, Q2 must be cleared.
  4. Detector: a 3-input NAND of Q6 Q5 Q4. Counting down from 99 no count has all three set (112 and above are never reached), so the first time Q6 Q5 Q4 = 111 is the wrap to 127. Its output drives the active-low CLEAR of Q4, Q3, Q2.
  5. Start-up: preset to 1100011.
Mod-100 ripple down counter, 7 positive-edge JK flip-flops (J = K = 1), Q of each stage clocks the next. Count 99 down to 0. After 0 the count would go to 127 (1111111). The NAND of Q6 Q5 Q4 clears Q4, Q3, Q2, which leaves 1100011 = 99.

Alternative accepted by some answers: two cascaded BCD (decade) down counters, units and tens, the tens stage clocked by the borrow of the units stage. The binary form above needs fewer parts.

Same glitch caveat as section 6: at 64 → 63 the counter briefly passes 1111111. State it in one line.

8. Frequency division (2017–18 Q5(c), 10 marks)

2017–18 Q5(c) · 10 marks

Given a 100 MHz clock, design a circuit using D flip-flops to generate 50 MHz and 25 MHz. Draw the timing diagram for all three signals.

Answer
  1. One toggling stage halves the frequency. Two stages divide by 4.
  2. D flip-flop with D = Q' is a divide-by-2 stage (it toggles at each rising edge).
  3. Stage 1: clock = 100 MHz, output Q1 = 50 MHz. Stage 2: clock = Q1, output Q2 = 25 MHz.
Two D flip-flops, each with D = Q' (a divide-by-two stage). The first is clocked by the 100 MHz clock, the second by Q1.
Q1 toggles at every rising edge of the 100 MHz clock (period 10 ns becomes 20 ns). Q2 toggles at every rising edge of Q1 (period 40 ns = 25 MHz). Small shifts are the flip-flop delays.

Periods: 100 MHz is 10 ns, 50 MHz is 20 ns, 25 MHz is 40 ns.

9. Disadvantages: delay and glitches

Question wording: "what are the problems of this counter" (3 marks in the older paper) or "why is it slower than a synchronous counter". Write these:

  1. Accumulated propagation delay. Qi settles about (i + 1) × tpd after the clock edge. For n flip-flops the count is valid only after n × tpd. The clock period must be longer than this, so the maximum frequency is about 1/(n × tpd). For four flip-flops of 10 ns each that is about 25 MHz (a synchronous counter would be limited by one flip-flop and a gate).
    2. Count 7 to 8 (0111 → 1000) with a delay of one unit per flip-flop. The counter passes through 0110, 0100 and 0000 before it settles at 1000: any gate that decodes these states can glitch.
  2. Wrong intermediate states (decoding glitches). During 7 → 8 the counter passes 0110, 0100, 0000. A decoder or AND gate connected to the outputs can produce false short pulses. Outputs cannot be used as clean enables without a strobe.
  3. Reset glitch in mod-N counters. State N exists briefly. For mod-12, the counter shows 1010 → 1000 → 1100 → 0000 on its way to 0.
  4. Not synchronous. The outputs do not change together, so it cannot drive a synchronous design directly. Also it gets worse with more bits.
  5. Advantages: simple (n flip-flops, no gates for a binary count), low power, easy frequency division.

Traps that cost marks

  • Positive-edge up counter takes Q' to the next clock. Negative-edge up counter takes Q. Down counter is the opposite. Write which edge you assume.
  • The first flip-flop gets the external clock. Do not wire the clock to every stage: that is a synchronous counter.
  • Mod-N: the NAND goes to the active-low CLEAR. Clear every flip-flop for an up counter. For a down counter clear only the bits that must become 0.
  • Count the NAND inputs: only the 1-bits of N, and stop when the first count with those bits all 1 is N.
  • Draw J = K = 1 (or T = 1, or D tied to Q') on every flip-flop. A flip-flop with nothing on its inputs loses the marks.
  • A down counter does not start at 0. It wraps from 0 to the top value, so the reload is the whole point of a mod-N down counter.
  • For the timing diagram mark the counts and show the clock, the number of clocks, and one cycle plus one clock to show the wrap.
  • Do not call the mod-N design "glitch free". Say the reset state N appears briefly.
