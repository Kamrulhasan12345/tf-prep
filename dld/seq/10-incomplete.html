State minimisation 2: incompletely specified machines

Some next states or outputs are don't-cares ("–"). Asked in 2023–24 Q7(a) (23 marks, A–G), 2021–22 Q7(b) (15, A–E, inputs I1 I2 I3), 2020–21 Q7(b) (25, A–G, two inputs, two outputs), 2019–20 Q3(b) (25, A–G) and 2017–18 Q7(b) (15, the identical A–G table as 2019–20 Q3(b)), 2018–19 Q7(a) (20, A–G). Not asked in 2022–23 and 2024–25 (they asked the completely specified version, previous chapter). An older one (2014–15, a primitive flow table, 10+5+5) is at the end. Adnan sir's own notes call this a 20–25 mark question (R p72, CT #1 is marked "20 mark question"), and his exam notes (R p89) put state minimisation in the term-final list. It is the single biggest mechanical question in Section B. Every task is the same: implication table, maximal compatibles, maximal incompatibles, bounds, minimal machine.

1. Compatible is not equivalent

Compatible
Adnan sir: Si and Sj are compatible iff for every input sequence the same output sequence is produced whenever both outputs are specified, whichever is the starting state. Where one output is a dash, there is nothing to disagree about.
Equivalent
All outputs must match. Compatibility is weaker.

Compatibility is reflexive and symmetric, but not transitive. His own example (R p64): A and B are compatible (B has no outputs where A has), B and E are compatible, but A and E are not (both specify an output on I2 and I3, and they differ). This breaks the clean picture of the last chapter: the merger graph no longer falls into disjoint complete pieces. Pieces overlap, and that is where all the extra work comes from.

Because you may choose the don't-cares, the minimal machine is not unique (Adnan sir, on his two valid covers in section 6: "both can be the answer"). Any cover that is closed, covering and has the minimum number of sets earns full marks.

2. The recipe (Adnan sir's official list, R p71)

  1. Implication table (for compatibility).
  2. Merger graph for compatibles, and from it the set of maximal compatibles (maximal cliques).
  3. Merger graph for incompatibles, and the set of maximal incompatibles.
  4. Bounds: upper bound u = min(number of states, number of maximal compatibles). Lower bound l = the size of the largest maximal incompatible. Then l ≤ k ≤ u, where k is the number of states of the minimal machine.
  5. Trial and error, starting from l: find a set of compatibles that is (a) minimum, (b) closed, (c) covering.
  6. State table of the minimal machine.

3. Step 1: the implication table

Same staircase as the last chapter, with these differences.

  1. Pass 1. For every pair XY and every input: if the outputs of X and Y are both specified and different, cross the cell (×). A dash never conflicts.
  2. Otherwise write the implied pair for each input where both next states are specified and different. Drop the pair XY itself and identical pairs. No implied pair: tick.
  3. Pass 2 and later. Cross any cell that lists a crossed pair. Repeat until nothing changes. Rule from his notes: "if cycle, don't cross". AB needing BD and BD needing AB do not kill each other.
  4. Uncrossed cells = compatible pairs.

This is his "CT #1" (R p68–71, scribbled "20 mark question"). Step through the widget: it shows every pass, the maximal compatibles and incompatibles, the bounds and the closed cover with the minimal table.

4. Steps 2 and 3: the merger graphs

Put the states on a circle. Compatibles graph: an edge for every uncrossed cell. Incompatibles graph: an edge for every crossed cell. The two graphs together are the complete graph (every pair is one or the other), so each is the complement of the other, and you can read one off the table that you already drew.

A clique is a set of vertices with every pair joined (a vertex, an edge, a triangle, a 4-clique…). A maximal clique cannot be made bigger. List all of them, including lone vertices and lone edges that sit in no larger clique. Maximal cliques overlap, and that is allowed.

The same machine (CT #1). In the compatibles graph, the edge labels are the implied pairs from the table. A, B, D form a triangle, B–C is an edge, and E and F are isolated (their cells were all crossed). So the maximal compatibles are (ABD)(BC)(E)(F). The incompatibles graph has the maximal cliques (ACEF), (CDEF), (BEF).

Why the maximal set is "automatically closed". Every pair that a compatible depends on is itself a compatible pair, so it lies inside some maximal compatible. Adnan sir: "dependencies need not be added by hand". So the set of all maximal compatibles is always a valid closed and covering set. The problem is only that it is often not minimum.

5. Step 4: the bounds

  • u = min(NSOC, NSMC): number of states in the original circuit, and number of sets in the maximal compatibles. The maximal solution itself is a legal machine with NSMC states, so the minimum cannot be bigger.
  • l = max NSMI: size of the largest maximal incompatible. The states of one maximal incompatible are pairwise incompatible, so they need different rows.
  • For CT #1: u = min(6, 4) = 4 and l = max{4, 4, 3} = 4. l = u, so no trial and error: the maximal solution is the answer.

The bounds exist "to reduce trial and error". Always compute both before searching.

6. Step 5: closed covering, trial and error from l

Three properties (R p68): covering (every state is in some chosen set), closed (for each chosen set and each input, the set of next states lies inside some chosen set; a set that only implies itself is fine), minimum (fewest sets).

The set of all maximal compatibles is closed and covering but may be too big. You shrink it by dropping sets or using smaller subsets, and every shrink can break closure. That is why you must check each trial. Adnan sir's six-state example (R p64–67) shows it. Table, inputs I1 to I4:

When the closed-cover search is hard: the compatibility graph

For the six-state machine of R p74–75 (section 9 below) Adnan sir draws a compatibility graph: one node per compatible pair, and an arrow X → Y when X depends on Y. A closed set is a part of the graph with no arrow leaving it. Pick the smallest such part that contains every state, merge overlapping pairs into cliques, and you have the cover. It is a way to organise the search, nothing more.

7. Step 6: write the minimal table

  1. Name the chosen sets α, β, γ, … with their members.
  2. For each set and input: collect the next states of its members that are specified. The next state of the new row is the chosen set that contains all of them. If no member specifies one, write "–".
  3. The output of the new row is the output given by whichever member specifies it ("–" if none does). Members never disagree, because they are compatible.
  4. If the next states fit inside two chosen sets, either choice is correct. Adnan sir marks such a cell with "?" and says it is a free choice.
If your cover differs from the textbook's. It will, often. Both are right if both are covering, closed and have the same (minimum) number of sets. To check: write each set's next-state sets per input (the closure table, as above) and see that every one lies inside a chosen set. The tables on this page come from an exhaustive search by the same engine as the widgets, and I checked each closure table by hand.

What to write (20–25 marks, every year)

  1. Copy the table.
  2. Implication table: the staircase, X for output conflicts, implied pairs, ticks. Show pass 2 (a second colour or "2nd pass" tags).
  3. One line: "Compatible pairs: …".
  4. Merger graph for compatibles: states on a circle, edges for uncrossed cells. Then "Maximal compatibles: (…)(…)…", including lone states.
  5. Merger graph for incompatibles: edges for crossed cells. Then "Maximal incompatibles: (…)…".
  6. Bounds: "u = min(n, number of maximal compatibles) = …; l = max size of a maximal incompatible = …; so l ≤ k ≤ u".
  7. If l = u: "The maximal compatibles are the minimal cover". Otherwise a trial table, starting at l: candidate, closed?, covering?, with the dependency that fails.
  8. The chosen cover, with the closure table (each set's implied sets and the chosen set that contains each).
  9. The minimal state table with new names, "–" where no member specifies.
  10. One line: "The minimal machine is not unique when don't-cares are present."
Traps that cost marks
  • Crossing a cell because one output is "–". A dash never conflicts. Only two specified, different outputs cross a cell.
  • Treating compatibility as transitive. A–B and B–C do not give A–C. Take cliques, not chains.
  • Forgetting the cycle rule: AB needing BD and BD needing AB are both kept.
  • Leaving lone states out of the maximal compatibles or incompatibles. A state that is compatible with nothing is still a set (E and F in CT #1).
  • Taking u = number of states. It is the smaller of the number of states and the number of maximal compatibles.
  • Trying to shrink the maximal compatibles without checking closure. (ABCD)(EF) looked fine and was not closed.
  • Stopping when you find a closed cover without checking it is also covering (every state in some set).
  • Writing an output in a merged row that one member does not allow. Members are compatible, so take the specified one; if none, "–".
  • Skipping the table. The last step is a mark of its own. Rename the next states in the table to the new names.

Mandatory practice
